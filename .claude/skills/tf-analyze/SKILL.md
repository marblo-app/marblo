# Marblo 요구사항 분석

> 코드를 쓰기 전에 요구사항을 분석하고 구조를 파악하는 단계입니다.
> 이 스킬은 태스크를 생성하지 않습니다. 분석만 수행합니다.
> 분석이 완료되면 `/tf-create-tasks`로 태스크를 생성합니다.

---

## ⛔ 필수 규칙: Marblo MCP 전용

> **절대 Claude Code 내장 도구(TaskCreate, TaskList, TaskUpdate, TaskGet)를 사용하지 마세요.**
> 모든 태스크 관련 작업은 반드시 **Marblo MCP 도구**를 사용합니다.

---

## Phase 1: 요구사항 수집

사용자의 입력(자연어, 문서, URL 등)을 받아 핵심을 파악합니다.

### 필수 확인 사항

1. **목표**: "이 프로젝트/기능이 해결하는 문제가 뭔가요?"
2. **사용자**: "누가 쓰나요?"
3. **핵심 기능**: "반드시 있어야 하는 기능 3개?"
4. **기술 스택**: 기존 프로젝트면 코드베이스 분석, 신규면 추천
5. **범위**: MVP vs 풀 기능

---

## Phase 2: 코드베이스 분석 (기존 프로젝트인 경우)

기존 프로젝트에 기능을 추가하는 경우, 코드베이스를 먼저 분석합니다.

1. **프로젝트 구조** 파악: `Glob`으로 디렉토리 트리 확인
2. **기술 스택** 확인: package.json, requirements.txt 등
3. **기존 패턴** 파악: API 라우팅, DB 모델, 컴포넌트 구조
4. **영향 범위** 식별: 변경이 필요한 파일/모듈 목록

---

## Phase 3: 분석 결과 출력

```
🔍 요구사항 분석 완료
━━━━━━━━━━━━━━━━━━━━

📦 프로젝트: {project_name}
🎯 목표: {한 줄 요약}

📐 컴포넌트 분석:
  Backend:
    - {컴포넌트 1}: {설명}
    - {컴포넌트 2}: {설명}
  Frontend:
    - {컴포넌트 1}: {설명}

👤 역할 필요:
  - backend: {N}개 태스크 예상
  - frontend: {N}개 태스크 예상
  - test: {N}개 태스크 예상

🔗 의존성 그래프:
  Layer 1 (기반): DB 스키마, 프로젝트 세팅
  Layer 2 (API): 핵심 엔드포인트
  Layer 3 (UI): 화면 구현
  Layer 4 (통합): 테스트, 배포

⚠️ 리스크/고려사항:
  - {리스크 1}
  - {리스크 2}

💡 다음 단계: `/tf-create-tasks`로 태스크를 생성하세요.
```

---

## 주의사항

- 분석 단계에서는 코드를 작성하지 않습니다
- 모호한 부분은 반드시 사용자에게 질문합니다
- 기존 `/tf-plan`과의 차이: `/tf-plan`은 PRD 문서까지 작성, `/tf-analyze`는 빠른 분석만 수행
