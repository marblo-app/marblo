# Marblo v3.0.17 Release Notes

검증 기준: 2026-07-18 `origin/main` HEAD `d39b8f7f` 기준. 이 릴리스에 포함되는 PR
#461, #463, #464, #465, #468, #469, #470, #471, #475, #476, #477, #478, #479, #480 은 **전부 머지 확인 완료**다.

이 문서는 두 축을 엄격히 구분한다.

- **이미 라이브(서버)** — Firebase Functions/BigQuery 배포로 **이미 동작 중**. 3.0.17 설치 여부와 무관하다.
- **이 빌드로 활성화(클라)** — Electron 클라이언트 코드라 **3.0.17 설치앱이 나가야 비로소 사용자에게 도달**한다.

혼동 주의: PR #470 은 **양쪽에 모두** 등장한다. 서버측 `appVersion` 폴백 수정은 이미 라이브지만,
클라이언트가 `appVersion` 을 **실어 보내는** 부분은 이 빌드로만 활성화된다.

## 1. 이미 라이브 (서버 Firebase Functions 배포됨 — 3.0.17 불필요)

- **PR #463**: 어드민 `requireAdmin` 의 `ADMIN_UID` 누락 케이스를 명확히 실패 처리하고 predeploy 게이트를 추가.
  - 효과: 어드민 함수 배포 전 필수 환경변수 누락을 사전 차단해 운영 중 403/INTERNAL 원인 추적 시간을 줄인다.

- **PR #465**: 어드민 BigQuery 쿼리의 `completedAt` TIMESTAMP 비교 수정.
  - 효과: Usage/Model 탭 INTERNAL 오류 해소, 어드민 사용량/모델 분석 화면 정상 조회.

- **PR #468**: 파운더 grant materialization 갭을 선정/가입 양방향 공통 헬퍼 + upsert 트랜잭션으로 근본 수정.
  - 운영 결과: 파운더 13명 Pro 백필 실행 완료 (`verifiedActiveFounderGrant=13`, `mismatches=0`).
  - 효과: 선정→가입, 가입→선정 어느 순서에서도 Pro grant 가 누락되지 않는다.

- **PR #469**: 어드민 구독지표 그룹(활성/연속구독자, 성장/이탈) 추가 + `paidPro` stomp READ 문제 수정.
  - 효과: 활성/연속 구독자, 성장/이탈 지표를 어드민에서 직접 확인 가능하고 paid Pro 상태 조회가 덮이지 않는다.

- **PR #470 (서버측)**: 서버 `appVersion` 폴백을 `"3.0.0"` → `null` 로 수정.
  - 효과: 미표기 이벤트가 3.0.0 으로 **잘못 집계되지 않고** unknown(`null`)으로 남아 릴리스별 분석 왜곡이 제거된다.

- **텔레메트리 게이트**: PR #397 기준 프로덕션 **default-ON 이 이미 적용된 상태**다.
  - 비고: `VITE_FIRST_PARTY_TELEMETRY` 는 죽은 no-op 이며, #470 은 문서/테스트를 실제 동작에 맞게 보정한 것이다.

## 2. 이 빌드로 활성화 (3.0.17 클라이언트/Electron 빌드 필요)

아래는 **설치앱에 미반영 상태**이며 3.0.17 이 나가야 사용자에게 도달한다.

### 2-1. 텔레메트리 — 실사용자 유입 개시

- **PR #470 (클라측)**: 클라이언트 이벤트 payload 에 `appVersion` 추가, `__APP_VERSION__` 을 flush 경로에서 주입.
  - 효과: 실사용자 이벤트에 **정확한 앱 버전**이 찍혀 DAU/세션/리텐션/기능 사용량을 릴리스별로 분리 분석할 수 있다.
  - ★ 서버 게이트는 이미 ON 이지만 **실사용자 유입은 서명 릴리스 후행**이다. `firebase deploy` 만으로는 유입이 생기지 않는다.
    이 릴리스가 나가야 행동지표 축적이 실제로 시작된다.

### 2-2. 라우팅 데이터 라벨 — ★데이터 해자 조기점화

- **PR #480**: 머지결과를 ML 라벨로 캡처 — 기존 `events` 테이블에 `task:merged` 이벤트 적재.
  - 설계: `docs/bigquery-ml-readiness.md`. 선행 티켓에서 `task_outcomes`, `cost_logs.taskId` 연결키,
    `dispatch:decision` 스냅샷, `events` ML 컬럼은 **이미 라이브**였고, 넷-뉴 갭은 머지결과 캡처 하나였다.
  - 단일소스 원칙: 머지 chokepoint(`recordMergeHistory`)에서 diff 특징을 **1회** 산출해 텔레메트리와 `merge_history`
    양쪽에 흘린다. 파생 특징만 기록하며 raw diff 는 남기지 않는다. **BigQuery 마이그레이션 0건**.
  - ★ 전략적 의미: **학습은 중기지만 수집은 지금 켠다 — 데이터는 시간의 함수다.**
    이 빌드가 라우팅 학습 라벨 축적의 시작점이며, 늦어질수록 해자 형성이 그만큼 밀린다.
  - 배포 비고: PR #480 은 backend 배포 불필요 = **릴리스 게이트**다(클라 빌드가 유일한 경로).

### 2-3. 워크트리 UX / diff-A / 워크스페이스 셸

- **PR #475**: 워크트리 위생 — root 셀렉터를 활성/온고잉만 노출 + 아카이브(숨김/복원).
  - 효과: 워크트리 119개가 통째로 노출되던 CodeTab "Root" 셀렉터가 실사용 가능해진다.
    아카이브는 **숨김일 뿐 물리 삭제가 아니며**, `cleanupStale` 은 별개의 신중한 액션으로 유지된다.

- **PR #476**: 티켓 "이 워크트리 보기" → 파일트리 전환 + Agents 탭 에이전트 선택.
  - 효과: 워크트리 확인이 버튼 한 번으로 끝난다(★자동 아님, 트리거 기반). 기존 DOM 합성클릭 해킹을 정식 경로로 대체.
    전체 pane 통째전환이 아니라 좌측 파일트리 + 하단 에이전트 선택만 바뀌고 Board/오케 중심은 그대로다.

- **PR #478**: diff-A(`DiffSurface`)를 Code 탭 **기본 diff 로 승격 — 모든 사용자 기본**.
  - 효과: Monaco 인라인 코멘트를 오케스트레이터로 바로 라우팅할 수 있다. 레거시 `DiffViewer` 는 폴백으로만 잔존.
  - ★ 이 릴리스에서 **모든 사용자가 체감하는 기본 경험 변화**는 이 항목이다(아래 #477 셸과 달리 옵트인이 아니다).

- **PR #477**: 옵트인 Workspace 셸 — **단일 플래그, 기본 OFF**.
  - 효과: 크롬탭식 pane 분할 + 오케 척추 + 에이전트 도킹 + 브라우저 pane 을 원하는 사용자만 켜서 쓴다.
  - ★ **OFF 안전 불변식**: `App.tsx` 단일 분기이며 `Layout`/`TabBar`/`OrchestratorPanel`/`AgentListPanel`/`DiffViewer`
    **무수정**. 기본값 OFF 이므로 기존 사용자 경험은 변하지 않는다.

### 2-4. 오케스트레이터 안정성 · 재연결

- **PR #479**: 오케↔에이전트 통신 신뢰성 — 크래시루프 재시작 예산 + PTY reuse 서브트리 kill.
  - 픽스 2건: ① `restartCount` 가 `stop()` 에서만 리셋되던 **평생예산 버그**(독립 크래시 4번째에 영구 error 고착),
    ② create-reuse 시 **서브트리 kill 갭**(grandchild orphan → MCP -32000/409).
  - 효과: 장시간 세션에서 에이전트가 영구 error 상태로 죽는 경로와 고아 프로세스로 인한 MCP 실패가 제거된다.
  - ★ 전략적 의미: 오케스트레이션이 primary 서사인 이상 **안정성 = 전략**이다(오케 회귀는 서사 자기반박).

- **PR #464**: 코덱스 오케 재시작 시 세션 재연결 — 모델 인지 resume id 사용.
  - 근본 원인: `resolveOrchestratorResumeId` 가 claude 전용(`~/.claude`)인데 모델 인지 없이 호출되어
    **codex 에 claude UUID 를 먹여 재시작마다 `exit 1` 즉사**시켰다.
  - 효과: 코덱스 오케 재시작/전환 시 대화 연속성이 유지된다.

- **PR #461**: 텔레그램 폴러 — PTY 전환 구간 inbound 유실 방지.
  - 근본 원인: `injectMessage` 가 PTY 전환 시 `expectPty` 불일치로 **throw 없이 조용히 drop**,
    poller 방어선이 "전달 성공"으로 오판해 offset 을 진행시켜 **완전 유실**(재전송 없음).
  - 효과: PTY handoff 중 들어오는 텔레그램 명령/알림이 유실되지 않는다.

- **PR #471**: 본 릴리스 노트 문서.

## 3. 릴리스 후 기대효과 요약

- **데이터**: 실사용자 텔레메트리가 정확한 `appVersion` 과 함께 축적 시작 + 라우팅 학습 라벨(`task:merged`) 수집 개시.
- **UX**: diff-A 가 전 사용자 기본 경험이 되고, 워크트리 선택/전환이 실사용 가능해진다. 워크스페이스 셸은 옵트인으로 열린다.
- **안정성**: 오케↔에이전트 크래시루프·고아 프로세스·코덱스 재연결·텔레그램 inbound 유실 경로가 모두 닫힌다.
- **운영 가시성**(이미 라이브): 어드민 Usage/Model 및 구독지표 화면, 파운더 Pro grant materialization.

## 4. 운영 액션 기록

- 파운더 13명 Pro 백필은 **비가역 운영 액션으로 완료**됨 (`verifiedActiveFounderGrant=13`, `mismatches=0`).
- 텔레메트리 게이트는 PR #397 기준 프로덕션 default-ON 이 **이미 적용된 상태**다.
- PR #480 은 backend 배포가 불필요하며, 클라이언트 릴리스가 유일한 활성화 경로다.
