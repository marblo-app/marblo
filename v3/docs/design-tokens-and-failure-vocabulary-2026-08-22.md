## 3. ② ★"안 될 때" 의 어휘 — 6상태 계약

### 3-1. 먼저: 새로 만들지 않는다. 백엔드에 이미 있다.

`functions/src/teamUsage.ts:1319-1331` 이 이렇게 써 있습니다:

그리고 ko 문구도 이미 배포돼 있습니다:

### 3-2. 렌더러 상태 어휘 — 6종

티켓은 4종을 지시했습니다. **6종을 제안합니다.** 늘리는 게 아니라, **4종으로 접으면 사장님이 어드민에서 일곱 번 물으신 그 혼동이 그대로 재생산되기 때문**입니다: `미수집`·`적재 전` 을 `empty` 로 접으면 "0 이 아니라 미수집" 이라는 배포된 백엔드 계약이 화면에서 다시 0이 됩니다.

| # | 상태 | 뜻 | ★화면이 하는 말 | ★다음 행동 (없으면 상태를 그리지 마라) |
|---|---|---|---|---|
| 1 | `loading` | 요청 중 | **형태를 유지한다** — 최종 레이아웃과 **같은 높이**의 골격 | 없음. 단 5초 초과 시 "계속 시도 중" + 취소 |
| 2 | `empty` | 행 0, **정상** | "아직 ○○가 없습니다" + **만드는 법 한 문장** | **첫 항목 만들기** (primary 하나) |
| 3 | `failed` | 요청 실패 | ★**숫자도 0도 그리지 않는다.** "○○를 불러오지 못했습니다" + 사유 한 문장 | **다시 시도** (+ 접힌 상세) |
| 4 | `denied` | 권한 없음 | "권한이 없어 읽지 못했습니다 — **0 이 아니라 알 수 없음입니다**" | **누구에게 요청하는지**(오너 이름/버튼) |
| 5 | `not_ready` | 미수집 · 적재 전 | 수치 자리에 **상태 라벨**("아직 수집되지 않음") | **언제 생기는지** 또는 **켜는 법** |
| 6 | `partial` | 잘렸다 | "**{shown}/{total} 만 그렸습니다**" | **더 보기 / 범위 넓히기** |

**백엔드 5상태 ↔ 렌더러 6상태 매핑**(양쪽이 어긋나지 않게 못박습니다):

| 백엔드 `TeamUsageState` | 렌더러 |
|---|---|
| `complete` (행 있음) | 정상 렌더 |
| `complete`/`partial` + 합 0 | `empty` — ★**진짜 0. 이때만 0을 그린다** |
| `partial` | `partial` |
| `empty` | `empty` |
| `not_provisioned` | `not_ready` |
| `disabled` | `denied` (게이트 사유가 권한일 때) / `not_ready` (배선일 때) |
| (백엔드에 없음 — 전송/파싱 실패) | `failed` |
| (백엔드에 없음) | `loading` |

### 3-3. 스토어 계약 — 이게 진짜 변경점이다

지금 실패가 사라지는 이유는 화면이 아니라 **스토어에 실패를 담을 자리가 없어서**입니다(`taskStore.ts:47-53` 의 `catch { set({ loading: false }) }`).

```ts
// components/common/loadState.ts (신규)
export type LoadState =
  | { kind: "loading" }
  | { kind: "ready" }
  | { kind: "failed";    reasonCode: string; detail?: string; retry: () => void }
  | { kind: "denied";    reasonCode: string; askWhom?: string }
  | { kind: "notReady";  reasonCode: string }
  | { kind: "partial";   shown: number; total: number };
```

규칙 넷:
1. **`loading: boolean` 을 새로 추가하지 않는다.** 새 스토어는 `state: LoadState` 하나만 가진다. 기존 스토어는 `error` 필드를 더하는 대신 이 타입으로 옮긴다(파일 단위, 점진).
2. **`catch` 는 반드시 `kind` 를 세팅한다.** console 만 찍고 끝나는 39곳이 이 규칙 하나로 잡힌다.
3. **`reasonCode` 는 i18n 키다.** `err.message` 원문을 사용자에게 그대로 보이지 않는다(지금 `ConnectionStatusPanel.tsx:290,329,362,385,412` 가 노출 중). 원문은 **접힌 상세** 안에만 둔다.
4. **`retry` 는 선택이 아니다.** `failed` 를 만들 때 재시도 함수를 못 넘기면, 그건 `failed` 가 아니라 설계 미완이다.

### 3-4. 화면 계약 — `StateBlock` 세 형태 (★시안이 아니라 배치 규칙)

| 형태 | 언제 | 구성 |
|---|---|---|
| `block` | 리스트·패널 **전체**가 그 상태 | 눈썹 라벨(`SectionLabel`) + 한 문장 + **행동 버튼 1개** |
| `inline` | 수치 **한 칸**만 그 상태 | 숫자 자리에 상태 라벨 + 물음표 툴팁(사유) |
| `banner` | 데이터는 있는데 **오래됐거나 잘렸다** | 패널 상단 한 줄 + 행동 |

**금지 다섯 (이게 문서의 실행 가능한 부분입니다):**

1. ★**실패를 `0` 으로 그리지 마라.** `CostWidget.tsx:69` 의 `if (totalCost === 0) return null` 은 실패와 진짜 0을 같은 결과(위젯 소멸)로 만든다.
2. ★**`catch` 에서 console 만 찍지 마라** (39곳).
3. ★**`err.message` 원문을 본문에 쓰지 마라.** 사용자 문장 + 접힌 상세.
4. ★**다음 행동이 없는 상태는 그리지 마라.** 그건 예쁜 빈 화면이다. 행동을 못 정하겠으면 화면이 아니라 배선을 고쳐야 한다는 신호다.
5. ★**로딩에서 레이아웃이 튀면 그건 로딩이 아니라 깜빡임이다.** 골격의 높이는 최종 높이와 같아야 한다. (현재 `Skeleton` 컴포넌트는 **0개**, `animate-pulse` 를 쓰는 파일이 13개 — 각자 다른 모양이다.)

### 3-5. 라벨 통일 — 지금 재시도 버튼 이름이 4종

실측: `다시 시도` 46 · `재시도` 29 · `Retry` 49 · `Try again` 6. **같은 버튼이 네 이름을 갖고 있습니다.**

정정안: 한국어 **`다시 시도`** 하나(영문 `Retry`). 상태별 표준 문구도 locale 에 **6키 한 벌**로 박습니다 — 지금처럼 화면마다 새로 쓰면 어휘가 다시 갈라집니다.
