## 2. 실효 마진 산식

### 2-A. 변수

| ----------- | --------------------------------------- | ------------------ | -------------------- |

| `e`         | 계량·정산 누수(우리 손해 방향)          | 1.0% [제안]        | §5-B                 |
| `v`         | VAT 부담 = `1/11`(총액표시 시)          | 0 또는 **9.09%p**  | §4-C                 |

### 2-B. 유도

충전 1건에 대해 —

```
수취        = T × (1 − p)
벤더원가    = T × (1+f) × δ / m          ← ★δ 가 #883 에는 없다(고정 1 로 가정)
누수(원가측)= 벤더원가 × (c·b + g·b_g + e)
누수(PG측)  = T × p × (r_ref + c + g)     ← 환불·CB 때 PG 수수료를 우리가 먹는다
VAT         = T × v
```

정리하면 **한 줄**:

```
실효마진(m, δ) / T  =  (1 − P − v)  −  (1+f)·δ·L / m

  L = 1 + c·b + g·b_g + e            (원가 누수 승수)
  P = p × (1 + r_ref + c + g)        (실효 PG 부담)
```

기준값 대입: **`L = 1.0400`** · **`P = 4.133%`** · `1−P = 0.9587`(VAT 별도) / `0.8678`(VAT 포함)

**손익분기 마크업**: `m* = (1+f)·δ·L / (1 − P − v)`

### 2-C. 정합 확인 — #883 §3-C 를 재현하는가

누수·FX·VAT 를 전부 끄면(`L=1, P=p, v=0, δ=1`) `m* = 1.015/0.9626 = 1.0544` → **#883 의 "손익분기 5.4%" 와 일치**. `m=1.3` 이면 마진 `0.9626 − 1.015/1.3 = 0.1818` → **₩1,818(18.2%)**, #883 §3-C 표와 **정확히 같다.** 즉 이 산식은 #883 의 **상위집합**이고, 새 항을 끄면 원래 표로 되돌아온다.

## 3. 축 1 — FX 갭 (`δ`)

### 3-A. 왜 갭이 생기나 — 선불이라 노출 창이 길다

| 시점      | 무슨 통화                                                                  |
| --------- | -------------------------------------------------------------------------- |
| 충전 `t0` | 유저가 **KRW** 결제 → 포트원 → 우리 원화 계좌                              |
| 원장 적재 | ★**USD 마이크로달러**(#897 §6-F: "₩10,000어치 토큰"이 아니라 **USD 예산**) |
| 소진 `t1` | 프록시가 벤더에 **USD** 청구 발생                                          |
| 벤더 정산 | 법인카드 **USD 결제** → 카드사 환율 + 해외이용수수료(`f`)                  |

★**우리는 `t0`~`t1` 동안 KRW 롱 / USD 숏이다.** #897 §6-F 가 원장을 USD 로 둔 것은 **벤더 단가 인상을 흡수하지 않기 위한 옳은 결정**(R11)이지만, 그 대가로 **환율 변동을 우리가 통째로 진다.** 두 리스크는 맞바꿔진 것이지 사라진 게 아니다.

> **반대 방향도 있다**: KRW 강세면 우리가 이득이다. 그러나 **비대칭**이 있다 — 이미 판 크레딧은 리프라이스할 수 없고, 환불은 **KRW 액면가**로 나간다. 즉 유리한 쪽은 잔액이 소진돼야 실현되고, 불리한 쪽은 잔액이 남아 있는 내내 커진다.

### 3-B. ★노출은 가장 전환 안 되는 잔액에 몰린다

| 소진 패턴                   | 노출 창     | δ 대역 [추정]    | 비중 예상                                      |

| 당일 소진(충전 → 바로 티켓) | < 24h       | ≈ 1.00           | 활성 유저                                      |
| 1주 \~ 1개월                | 주 단위     | 1.01 \~ 1.03     | 정상                                           |

| 잔액 꼬리(1홀드 미만, §6-D) | 무기한      | 무제한           | 구조적으로 남는다                              |

★**이게 핵심 함의다.** 활성 유저의 잔액은 빨리 타서 FX 노출이 없고, **이탈 유저의 잔액이 오래 남아 노출을 만든다.** 즉 FX 리스크와 활성화 실패는 **같은 방향으로** 붙어 있다 — 온램프가 실패할수록 FX 노출이 커진다.

★**M-FX1 이 유일하게 공짜에 가깝다.** #897 §7 이 이미 `completePortOnePayment` 성공 트랜잭션 안에서 `topup` 원장 1행을 만들기로 했으니, **같은 훅에 "USD 선매입 큐 적재"를 하나 더 붙이는 것**이 전부다(비동기 배치 가능 — 당일 마감 매입이면 δ≤1.01).

**M-FX1 의 금전 가치**: δ 1.15 → 1.01 이면 `m=1.5·VAT 포함`에서 마진 ₩585 → ₩1,570 (**+₩985/충전, 2.7배**). 필요 마크업으로 환산하면 **약 0.1\~0.2×** 다.

## 4. 축 2 — PG · 원화결제 갭

### 4-A. 요율 자체는 지배변수가 아니다

#883 §3-C 의 `p=3.74%`(토스 일반 카드 3.4% + 수수료 VAT)를 승계한다. 다만 **실효 요율은 가맹점 계약별**이고 경로마다 다르다 — 간편결제(카카오/네이버페이)와 해외카드는 통상 더 높다 [추정, 계약 미확인]. 민감도를 재 보면 `p` 3.74% → 4.40% 의 마진 영향은 **−₩73/충전**(§9)으로 **작다.** ★요율 협상은 이 판정을 바꾸지 못한다.

### 4-B. ★비대칭 3종 — 이게 #883 에 없다

| #    | 비대칭                                                                                                                                                                            | 모델 항목        |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| PG-1 | **환불해도 PG 수수료는 안 돌아온다**(통상). #897 §6-F 가 "누가 먹는지 약관에 명시"라고 적은 그 항목 — **명시 안 하면 기본값이 우리 부담**이고 충전당 ₩374 순손실                  | `p × r_ref`      |
| PG-2 | ★**Chargeback 은 마진이 아니라 원가 전액을 친다.** 이미 소진된 토큰은 되돌릴 수 없다(#897 §9 A1). ₩10,000 이 100% 소진된 뒤 지급거절 = **우리 현금 −₩7,808 + 수수료 미환급 ₩374** | `p·c + 원가·c·b` |
| PG-3 | **거래는 KRW·정산은 KRW, 그러나 원장은 USD** — 결제 레일 자체는 갭을 만들지 않지만, **레일이 KRW 라서 §3 의 δ 가 생긴다.** 두 축은 같은 뿌리다                                    | §3               |

### 4-C. ★VAT 총액표시 — 경고만 있고 계산이 없던 항목

#883 §3-E 와 #897 §10-B 는 **"§3-C 표는 VAT 별도 기준"** 이라고 경고만 하고 넘어갔다. 그런데 **B2C 소비자 대상 가격은 부가세 포함 총액으로 표시하는 것이 사실상 강제**다 [확인필요 — 표시광고 규제 세부는 법률 검토 필요]. 그러면:

```
표시가 ₩10,000 (VAT 포함)  →  실제 매출 ₩9,091 · 부가세 ₩909 (국고)
PG 수수료는 총액 ₩10,000 에 부과된다 (₩374)
```

→ **`v = 1/11 = 9.09%p` 의 순감소.** 매입세액 공제는 **가정하지 않았다** — 해외 벤더 API 매입은 대리납부/역과세 대상 여부가 [확인필요](#897 §10-B)이고, 공제가 된다면 이 항목은 완화된다.

★**이 한 항목이 §9 민감도에서 1위다** — δ 보다도 크고, 확률적이지 않은 **결정론적** 항목이다. 즉 "운이 나쁘면"이 아니라 **켜는 순간 확정으로 −9.1%p**.

## 5. 축 3 — 안전 버퍼

### 5-A. ★캐시 파손은 마진을 깎지 않는다 — #897 §4-A 프레이밍 정정

#897 §4-A 는 이렇게 적었다:

> "마크업 30% 가 티켓당 버는 돈은 ≈$3, 캐시 파손의 대가는 +$53. **마진의 17배가 캐시 한 조각에 걸려 있다.**"

**그런데 #897 §4-B 가 같은 문서에서 정한 규칙과 충돌한다**: _"입력·출력·캐시읽기·캐시쓰기 **네 종류 전부에 동일 배수**를 적용한다."_ 균일 마크업이면 —

| 시나리오  | 우리 원가 | 유저 차감(1.3×) | **우리 마진** | 마진율 |
| --------- | --------: | --------------: | ------------: | -----: |
| 캐시 보존 |     $9.85 |          $12.81 |     **$2.96** |    30% |
| 캐시 파손 |    $63.10 |          $82.03 |    **$18.93** |    30% |

★**파손 원가는 유저 잔액에서 나간다. 우리 마진율은 그대로고 절대액은 오히려 6.4배가 된다.** #897 의 "마진의 17배가 걸려 있다"는 **손익 문장으로는 성립하지 않는다.**

**그러면 무엇이 손실인가 — 두 가지, 그리고 둘 다 진짜다:**

| 손실                | 메커니즘                                                                                                                                                                                      | 모델 항목 |
| ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| **B-1 굿윌 환불**   | ₩10,000 이 약속한 1.55티켓 대신 **0.24티켓**을 주고 잔액이 마른다. 이건 유저 잘못이 아니라 **우리 프록시 결함**이다 → 전액 환불이 **도의적 기본값**. 이미 소진된 토큰은 우리 현금이 나간 뒤다 | `g`       |
| **B-2 hold 오버런** | §5-B                                                                                                                                                                                          | `e`       |

★**그래서 "캐시 파손 버퍼"는 원가 항목이 아니라 환불률 항목으로 모델에 들어간다.** 이 문서가 `g`(굿윌 환불) 를 별도 변수로 둔 이유다. 기준값 5% [제안], G-P1 통과 전 스트레스는 20%(§7-A).

> ★그리고 #897 §4-A 의 **엔지니어링 결론(G-P1 을 첫 관문으로)은 그대로 옳다.** 바뀌는 건 이유다 — "마진이 날아가서"가 아니라 **"제품이 약속을 못 지켜서"** 다. 결과적으로 우선순위는 동일하고 오히려 더 강해진다(마진은 회복 가능하지만 첫인상은 아니다).

### 5-B. ★hold 사이징 — #897 §6-D 에 숨은 모호성

#897 §6-D 는 예약액을 이렇게 정의한다:

```
reserved = est_input_tokens × rate_in + max_tokens × rate_out
```

★**`rate_in` 이 캐시 적용가인지 정가인지가 안 적혀 있다.** 그런데 이 워크로드는 입력의 **99.2% 가 캐시 재읽기**(#885 §3)다. 즉 —

| `rate_in` 을 무엇으로 잡나 | 캐시 보존 시              | **캐시 파손 시**                                             |
| -------------------------- | ------------------------- | ------------------------------------------------------------ |
| 캐시 재읽기가(0.1×)        | 딱 맞는다                 | ★**실사용이 hold 를 6.4배 초과** → §6-D 대로 **우리가 흡수** |
| **정가 입력가(1.0×)**      | 과다 예약(잔액 꼬리 커짐) | ✅ 절대 오버런 안 남                                         |

**[제안] 규율**: `rate_in = 정가 입력단가(캐시 미적용)`. 오버런을 흡수하는 쪽이 우리이므로 **보수적 과대예약이 옳다.** 대가는 잔액 꼬리가 커지는 것이고, 그건 UI 문구(#897 §8)와 환불 경로로 처리 가능한 **가역적** 비용이다. 오버런 흡수는 비가역적 현금이다.

### 5-C. `e` — 계량·정산 누수의 구성

| 누수원                                                                                                                                                                 | 방향                                |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------- |
| **스트림 도중 5xx** — #897 §5-E 는 "보통 과금 없음 → debit 0, hold 해제". 벤더가 생성분을 청구하면 그 차액은 **전액 우리 손실** [확인필요 — 벤더 부분과금 정책 미확인] | 우리 손해                           |
| hold 오버런 잔여분(§5-B 규율 적용 후에도 `max_tokens` 초과 경로가 있으면)                                                                                              | 우리 손해                           |
| `hold_expired` 스윕이 `reserved` 를 debit 으로 확정할 때 **reserved < 실사용**                                                                                         | 우리 손해                           |
| 재시도가 캐시 TTL(5분)을 넘겨 캐시 쓰기(1.25×) 반복                                                                                                                    | 유저 전가                           |
| 반대로 `reserved > 실사용` 로 확정 → 유저 과다차감                                                                                                                     | ★유저 손해 → 분쟁·환불로 되돌아온다 |

**[제안] `e = 1.0%`.** 도출값이 아니라 버퍼다. #897 T-14 의 **일일 대조(원장 ↔ 벤더 청구서)** 가 이 값을 실측으로 대체해야 한다.

## 7. 권장 마크업

### 7-A. 결정규칙 [제안]

> **보수적 급변(δ=1.15)이 오고, VAT 를 총액으로 부담하고, G-P1 이전이라 굿윌 환불이 높은 상태(g=20%)에서도 실효 마진이 0 을 넘을 것. 그리고 정상 운영(헤지 δ=1.01 · g=20%)에서 ≥10% 를 지킬 것.**

`g` 를 20% 로 두는 이유: L2 출시 초기는 프록시가 **아직 실증되지 않은** 구간이고(§11 G-P1 은 PoC 통과만 보장하지 운영 안정성을 보장하지 않는다), 캐시 파손 1회 = 굿윌 전액 환불 1건(§5-A)이기 때문이다.

**스트레스 판정** (VAT 포함 · δ=1.01 · **g=20%**):

| 마크업   |          실효 마진 |         판정 |
| -------- | -----------------: | -----------: |
| **1.3×** |  **−₩171 (−1.7%)** |      ❌ 적자 |
| **1.5×** | **₩1,001 (10.0%)** | ✅ 규칙 충족 |

| **1.15** |   1.414× | **1.581×** |

**★"1.5× 는 유저에게 너무 비싸지 않은가"에 대한 답**: #883 §3-A 대로 **도매가가 없으므로 마크업은 그대로 "직접 사는 것보다 비쌈"** 이다. 1.3×→1.5× 는 유저가 받는 티켓이 opus-5 기준 1.08 → 0.93 건으로 줄어드는 것이고, **§8-A 의 기본 모델 변경(opus-5 → sonnet-5)이 그 손실을 상쇄하고 남는다**(1.79 → 1.55 건, 여전히 1건 이상). 즉 **마크업을 올리면서도 "₩10,000 = 첫 티켓 1건 이상" 이라는 제품 약속은 지킬 수 있다.**

### 7-C. 반대로, 1.5× 가 바꾸지 **않는** 것

#897 §4-C 의 결론은 **그대로 유효하고 오히려 강해진다**: 이건 매출이 아니라 **CAC** 다. 1.5× 에서도 유저당 마진은 ₩1,500\~3,100 이고, 월 23\~45건이면 연 매출총이익 **₩40\~100만** 수준이다. **매출 KPI 를 걸지 않는다. 성공지표는 여전히 구독 전환율이다.**

## 9. 민감도 — 무엇이 진짜 지배변수인가

기준: `m=1.5` · VAT 별도 · δ=1.05 · 마진 **₩2,198**. 한 번에 한 변수만 움직였다.

| 변수               | 변화            | 마진 영향 | 성격                        |
| ------------------ | --------------- | --------: | --------------------------- |
| **★VAT 처리**      | 별도 → 총액포함 | **−₩909** | **결정론적**(법·표시 규제)  |
| **★FX 드리프트 δ** | 1.05 → 1.15     | **−₩704** | 확률적·**헤지 가능**(M-FX1) |
| 굿윌 환불 `g`      | 5% → 15%        |     −₩393 | 프록시 품질(G-P1)에 종속    |
| Chargeback `c`     | 0.5% → 2%       |     −₩112 | PG 위험관리로 통제          |
| PG 요율 `p`        | 3.74% → 4.40%   |      −₩73 | 계약 협상 — **거의 무관**   |
| 해외결제 `f`       | 1.5% → 2.0%     |      −₩36 | **무관**                    |

★**#883·#897 이 상수로 고정해 둔 두 변수(VAT 처리 · 환율)의 합(−₩1,613)이 나머지 넷의 합(−₩614)의 2.6배다.** 마진 논쟁의 무게중심은 "마크업 몇 %"가 아니라 **"이 둘을 어떻게 처리하느냐"** 에 있다:

- VAT → **결정론적**이므로 **확인해서 확정**한다(§10 신규 게이트).
- δ → **확률적이지만 헤지 가능**하므로 **운영으로 없앤다**(M-FX1).

둘 다 처리하면 필요 마크업은 **1.389×** 로 내려가고, 1.5× 는 편안한 여유가 된다. 둘 다 방치하면 **1.581×** 가 필요하다. **마크업 0.2× 의 차이가 이 두 결정에 달려 있다.**

## 11. 한계 · 정직성

- **★라이브 환율을 조회하지 않았다.** `FX0=₩1,400/$` 은 #883 §3-C 의 [가정] 승계값이고, δ 는 그 대비 **드리프트 배수**다. 시나리오 대역(1.02\~1.25)은 [추정]이며 KRW/USD 시계열로 검증하지 않았다. **환율 예측이 아니라 스트레스 시나리오다.**
- **`r_ref`(5%) · `c`(0.5%) · `g`(5%/20%) · `e`(1.0%) 는 전부 [제안]이고 도출값이 아니다.** 우리는 크레딧을 판 적이 없어 실측이 없다. 이 넷이 마진의 −₩505/충전(기준 시나리오)을 만든다. **G-P1 통과 후 첫 3개월 실측으로 교체해야 한다.**
- **VAT 총액표시가 법적으로 강제인지 이 문서는 확정하지 못했다** [확인필요]. `v=1/11` 은 **최악 가정**이고, 매입세액 공제(해외 API 매입의 대리납부/역과세)가 인정되면 완화된다. **민감도 1위 항목이 미확정이라는 사실 자체가 §10 C-5 의 이유다.**
- **PG 실효요율 3.74% 는 #883 의 [출처]값**이고 실제 포트원/토스 가맹점 계약서를 보지 않았다. 간편결제·해외카드 경로의 요율 차이도 반영하지 않았다. 다만 §9 대로 **이 항목은 지배변수가 아니다.**
- **§5-C 의 "스트림 도중 5xx 시 벤더 부분과금 여부"는 확인하지 못했다** [확인필요]. `e` 안에 버퍼로만 들어가 있다.
- **M-FX1(당일 USD 선매입)의 실행 가능성을 검증하지 않았다** — 벤더 선불 크레딧의 **유효기간·최소 매입단위·환불 가부**를 확인해야 한다 [확인필요]. 이게 막히면 §7-B 대로 **1.6×** 로 간다.
- **M-FX3(크레딧 유효기간)은 전자상거래법상 미사용 잔액 환불 의무와 충돌 소지**가 있고 법률 검토가 필요하다 [확인필요]. 이 문서는 법률·세무 자문이 아니다.
- **티켓 단가($5.11/$3.07)는 #883 §3-B 의 [추정]** 이다(중앙값 $5.11 을 opus-5 in:out=20:1 로 역산한 프로필을 타 모델에 대입). sonnet-5 가 같은 태스크를 **같은 토큰 수로** 끝낸다는 가정이 들어 있고, 실제로는 더 많은 턴이 필요할 수 있다 → §8-A 의 "1.55티켓"은 **낙관 상한**이다.
- **§5-A 의 마진 정정은 #897 §4-B(균일 마크업)가 유지된다는 전제**에 선다. 마크업을 토큰 종류별로 차등하기로 하면 §5-A 를 다시 해야 한다.
- **고정비 ₩69,367/월은 게이트웨이+토스만**이다. 인건비·Cloud Run 트래픽 변동비·Firestore 비용·PG 초기 설치비는 넣지 않았다 — 즉 §6-C 의 필요 건수는 **하한**이다.
- 날조 없음. `[코드]` 인용은 파일·행으로 확인 가능하고, `[문서]` 수치는 §12 선행문서가 1차 출처를 들고 있다. 모든 산술은 §2 산식으로 재현 가능하다.
