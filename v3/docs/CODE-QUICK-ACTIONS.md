## 1. 무엇을 만드는가 / 왜 커서가 아닌가

사장님 요구는 "커서까지는 아니더라도 **에디터에 값어치**"였다. 그래서 목표를 **커서의 인라인 자동완성과 정면으로 붙지 않는 자리**로 옮겼다.

|                 | 커서(Cursor) 탭 자동완성                     | 마블로 코드탭 퀵액션                                     |
| --------------- | -------------------------------------------- | -------------------------------------------------------- |
| **트리거**      | 타이핑할 때마다 **암묵적·연속**              | 선택 → 버튼/우클릭, **명시적·온디맨드**                  |
| **추론 횟수**   | 커서 이동·키 입력마다 (세션당 수백~수천 회)  | **클릭 1회 = 추론 1회**                                  |
| **모델**        | 자체 학습·번들한 저지연 FIM 모델(홈그라운드) | **사용자가 이미 연결한 CLI**(Claude Code / Codex) 그대로 |
| **지연 예산**   | 20~80ms 안에 안 나오면 제품이 아님           | 수 초 허용 (사용자가 "지금 물어본" 것)                   |
| **비용 주체**   | 벤더가 부담 (구독에 녹임)                    | 사용자의 기존 CLI 구독 — **마블로가 새로 태우는 비용 0** |
| **필요 인프라** | 자체 모델 서빙·캐시·컨텍스트 인덱서          | **없음** (기존 PTY 파이프 재사용)                        |

핵심 판단 두 가지:

1. **연속 추론은 홈그라운드다.** 자체 FIM 모델 없이 CLI 왕복(수 초)으로 자동완성을 흉내내면 지연·비용 둘 다 진다. 그래서 **연속 추론은 하지 않는다**(비목표가 아니라 **금지**).
2. **온디맨드는 우리가 이미 가진 것으로 이긴다.** 마블로 사용자는 이미 CLI를 연결해 두었다(시작하기 ①②단계). "선택 → 설명해줘 / 고쳐줘"는 그 CLI 한 번이면 끝나고, 결과를 **에디터 안에서 바로 적용**하는 부분만 우리가 더해주면 된다.

### 1.1 비용 모델 (연속 vs 온디맨드)

연속 추론은 사용자가 **아무것도 요청하지 않아도** 토큰을 태운다. 온디맨드는 클릭 수 = 호출 수라 상한이 사용자 손에 있다. 유휴 상태 비용이 **정확히 0**이라는 성질이, 무료 설치자에게 에디터 가치를 주면서도 쿼터 사고가 나지 않는 이유다. 백그라운드 프리페치·투기적 실행은 이 성질을 깨므로 **넣지 않는다**.

## 2. UI

### 2.1 트리거 — 선택 시 플로팅 툴바

Monaco에서 텍스트를 선택하면 선택 지점에 **content widget** 툴바가 뜬다. (뷰 존이 아니라 content widget인 이유: 이 에디터는 편집 가능해서 뷰 존은 실제 코드를 아래로 밀어낸다.)

```
   const total = items.reduce((a, b) => a + b.price, 0)
   ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔  ← 선택
   ┌───────────────────────────────────────────┐
   │ ✨ 설명   ✨ 이거 고쳐   ✦ 오케에게 요청 │
   └───────────────────────────────────────────┘
```

- `✨ 설명` / `✨ 이거 고쳐` — **이 문서가 정의하는 퀵액션**(연결 CLI 1회 호출).
- `✦ 오케에게 요청` — **기존 기능 그대로**. 선택 코드를 인용해 오케스트레이터 PTY로 보내는 경로(`useOrchestratorDiffComment`)로, 큰 작업·티켓화가 필요할 때 쓴다. 퀵액션이 이걸 대체하지 않는다.

우클릭 컨텍스트 메뉴에도 같은 두 액션을 등록해, 마우스 습관이 다른 사용자도 같은 자리에서 찾는다.

### 2.2 결과 — 액션별로 표면이 다르다

| 액션          | 결과 표면                                                                        |
| ------------- | -------------------------------------------------------------------------------- |
| **설명**      | 에디터 우측 **사이드 패널**(오버레이). 읽고 닫으면 끝 — 코드를 건드리지 않는다.  |
| **이거 고쳐** | 선택 지점에 앵커된 **인라인 diff 위젯** — `-` 빨강 / `+` 초록 + `[적용] [취소]`. |

"고쳐"의 결과를 파일에 **먼저 쓰지 않는 것**이 이 설계의 안전선이다. `[적용]`을 눌러야 `executeEdits`가 선택 범위를 정확히 치환하고(=Cmd+Z로 되돌아감), 그 편집이 기존 `onChange → updateContent` 경로를 타 더티 표시가 뜬다. 저장은 여전히 Cmd+S다. `[취소]`는 위젯만 걷어낸다 — 파일은 한 바이트도 바뀌지 않은 상태다.

### 2.3 연결 CLI가 없을 때

퀵액션은 CLI 없이는 성립하지 않는다. 이때 조용히 실패하지 않고 패널에 **"연결된 CLI가 없습니다"** + `[설치·사인인 하러 가기]`를 띄우고, 클릭하면 기존 `marblo:open-cli-setup` 이벤트를 디스패치한다 — 즉 afW5(원클릭 모두 설치·자동 사인인)의 **그 표면 그대로**로 유도된다. 새 온보딩 화면을 만들지 않는다(스플릿 셸은 시작하기 탭 배너, 레거시 셸은 위저드 — 둘 다 이 이벤트 하나가 처리한다).

## 3. 엔진 — "온디맨드 1회 추론"의 실체

### 3.1 무엇을 재사용하는가

- **연결 CLI 그대로**: 어떤 CLI가 준비됐는지는 `cliSetupStore`(= `harness:cliAuthCheck` 프로브, 스폰 게이트가 쓰는 바로 그 프로브)에서 읽는다. 별도 판정 로직 없음.
- **기존 PTY IPC 그대로**: `pty:create` / `pty:replay` / `pty:data` / `pty:exit` / `pty:kill`. **메인 프로세스 코드 0줄 추가.**
- **새 모델·새 서빙·새 자동완성 엔진 0.**

### 3.2 흐름

```
선택 + 클릭
   │
   ├─ ① 준비된 CLI 고르기 (claude 우선 → codex)      cliSetupStore.results
   │      없으면 → needs-cli (§2.3)
   │
   ├─ ② 프롬프트 1개 조립                            quickActions.buildQuickActionPrompt
   │      파일경로 · 언어 · 선택 범위(줄번호) · 선택 코드 · 주변 컨텍스트 · 액션별 출력 규약
   │
   ├─ ③ 헤드리스 1회 실행 (기존 pty IPC)
   │      claude : claude --print <prompt>
   │      codex  : codex exec --json --color never --sandbox read-only
   │                    --skip-git-repo-check <prompt>
   │      cwd = 코드탭 루트(에디터가 보고 있는 워크트리/프로젝트 루트)
   │
   ├─ ④ 출력 파싱                                    quickActions.parseHeadlessOutput
   │      claude : ANSI 제거 + CRLF 정규화된 stdout 전체
   │      codex  : JSONL 이벤트에서 agent_message 만 추출
   │
   └─ ⑤ 결과 적용
          설명 → 사이드 패널에 텍스트
          고쳐 → 펜스 코드블록 추출 → 줄 단위 diff → 인라인 위젯 → [적용]에서 executeEdits
```

프로세스는 **한 번 뜨고 끝난다**. 세션도 재개도 없고, 다음 클릭은 완전히 새 프로세스다. 이것이 "연속 추론 없음"의 물리적 보증이다.

### 3.3 왜 에이전트 스폰(dispatch)이 아니라 헤드리스인가

티켓의 취지는 "**새 모델·새 인프라 없이, 이미 연결된 CLI를 재사용해 1회 추론**"이다. 그 취지를 만족하는 방법이 둘인데, 완료 기준(인라인 diff 적용/취소)까지 만족하는 건 하나뿐이었다.

| 후보                                         | 결과 회수                                                                                                                                                                                         | 판정                          |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------- |
| `agent:launch`(에이전트 PTY + 초기 프롬프트) | 결과가 **TUI 화면**에 그려진다. raw PTY 버퍼엔 개행이 거의 없고 ANSI 커서 이동이 섞여 텍스트를 신뢰성 있게 못 뽑는다. 게다가 워크트리·티켓·에이전트 카드까지 딸려온다 — "설명해줘" 하나에 과하다. | ✗ 결과를 에디터로 못 되돌린다 |
| **헤드리스 1회 (print/exec)**                | stdout이 **평문/JSONL**. 파싱 가능 → 설명은 패널, 수정은 diff로 바로 꽂힌다.                                                                                                                      | ✓ 채택                        |

헤드리스 print 모드는 새로 들여온 개념이 아니다 — 리포에 이미 세 군데 선례가 있다: `mcp-server/tools.ts`(`run_skill`), `mission-engine/skill-runner-impl.ts`, `claude-usage-probe.ts`. 퀵액션은 그 패턴을 **렌더러에서 기존 pty IPC로** 쓰는 것뿐이다.

무거운 작업(여러 파일, 티켓화, 리뷰)은 여전히 `✦ 오케에게 요청` → 오케스트레이터 → dispatch → 에이전트 스폰이라는 원래 파이프라인으로 간다. 퀵액션은 그 경로를 **대체하지 않고, 그 아래 체급을 채운다.**

### 3.4 안전 성질

- **파일 쓰기 없음**: 두 액션 모두 프롬프트에 코드를 넣어 보내고 **텍스트만** 받는다. 도구 사용이 필요 없으므로 권한 프롬프트도 뜨지 않는다. codex는 여기에 더해 `--sandbox read-only`로 못을 박는다.
- **argv 직접 전달**: `pty.spawn(file, args)`는 셸을 거치지 않는다. 프롬프트에 줄바꿈·따옴표·백틱이 들어가도 셸 해석이 없다.
- **타임아웃 + 취소**: 120초 상한, 사용자가 언제든 `[취소]`로 PTY를 kill. 어느 쪽이든 리스너를 걷고 세션을 정리해 fd를 남기지 않는다.
- **선택 길이 상한**: 200줄. `설명`은 넘으면 잘라 보내고 "잘림"을 표시하고, `이거 고쳐`는 **거부한다** — 잘린 선택으로 만든 치환은 범위와 어긋나 코드를 깨기 때문이다.
- **동시 실행 1건**: 실행 중에는 트리거가 잠긴다. 연타로 프로세스를 쌓지 않는다.

### 3.5 알려진 한계 (MVP)

- **CLI 2종**: claude / codex. grok·antigravity는 헤드리스 계약이 각자 달라 후속. 준비된 CLI가 둘 다 없으면 §2.3의 유도 화면.
- **claude 바이너리는 `claude:version`이 해석한 경로**를 쓰지만(구버전 가림 방지), **codex는 PATH의 `codex`**를 쓴다. 패키징 앱에서 PATH가 빈약하면 codex 경로만 실패할 수 있다 — 그 경우 에러 본문이 그대로 패널에 표시된다(조용한 실패 없음).
- **비용 계측 미편입**: 헤드리스 1회는 `agent-*` 세션 id가 아니라 `cost-tracker`의 킥오프 트리거를 타지 않는다. 퀵액션 비용은 현재 `cost_logs`에 안 잡힌다. 계측이 필요해지면 별도 티켓(하네스 킥오프 트리거와 같은 자리).

## 4. 모듈 지도

| 파일                                    | 역할                                                                            |
| --------------------------------------- | ------------------------------------------------------------------------------- |
| `components/code/quickActions.ts`       | **순수 로직** — 프롬프트 조립, CLI 호출 스펙, 출력 파싱, 코드블록 추출, 줄 diff |
| `components/code/useCodeQuickAction.ts` | 엔진 훅 — CLI 선택 → pty 1회 실행 → 상태 머신(running/done/error/needs-cli)     |
| `components/code/QuickActionPanel.tsx`  | 사이드 패널 — 실행 중 / 설명 결과 / 에러 / CLI 없음 CTA                         |
| `components/code/CodeEditor.tsx`        | 트리거 툴바 · 컨텍스트 메뉴 · 인라인 diff 위젯 · 적용/취소                      |
| `locales/{ko,en}/code.ts`               | `code.quickAction.*`                                                            |
| `tests/codeQuickActions.test.ts`        | 순수 로직 단위 테스트                                                           |

부수 효과가 없는 것은 전부 `quickActions.ts`에 모아 노드 환경 vitest로 검증한다(렌더러 DOM 없이). 훅과 컴포넌트에는 **판단이 남지 않게** 한다.

## 5. 후속 (이번 범위 아님)

- 액션 확장: `주석 추가`, `테스트 추가` — 프롬프트 + 결과 배치(테스트는 새 파일)만 추가하면 되는 자리로 이미 열려 있다(`QUICK_ACTIONS` 테이블).
- grok / antigravity 헤드리스 계약 편입.
- 퀵액션 비용 계측(`cost_logs`) 편입.
- 결과 캐시(같은 선택 + 같은 액션 재클릭). 온디맨드 성질을 깨지 않는 선에서.
