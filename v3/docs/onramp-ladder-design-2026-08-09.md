| 대표 실패모드        | "연출이잖아" 불신 · 지루함 | 어색한 티켓 제목                                  | **조용히 틀린 분해** + 네트워크 실패 + 콜드 지연           |

**C 의 원가 산식 [추정]**: 시스템 프롬프트(분해 규칙+출력 스키마) ≈1.2k + 유저 문장 ≈0.2k = **입력 1.4k**, 티켓 5~7개 JSON = **출력 0.6k**. Qwen3-32B DeepInfra($0.08/$0.28 per 1M, #885 §4-A) → `1.4k×0.08/1M + 0.6k×0.28/1M` = **$0.00028**. haiku-4.5($1/$5) → **$0.0044**.

> ★**여기서 나오는 중요한 사실 하나**: 분해 1콜(1.4k 입력)은 #885 §3 의 태스크 중앙값(7.39M 입력)의 **1/5,300** 이다. 즉 **원가는 C 를 배제하는 이유가 못 된다.** C 를 미루는 이유는 돈이 아니라 **서버 표면·지연·인젝션**이다. 이 구분을 흐리면 "싸니까 하자" 로 잘못 간다.

### 4-B. ★추천 — **B 를 착지시키고, C 를 같은 seam 뒤 옵션으로 남긴다. A 는 재판정한다.**

이유 다섯:

1. **A 는 이미 있고, 그 퍼널은 이미 계측돼 있다.** `onboarding:demo_started` / `demo_completed` / `demo_cta_click` 세 이벤트가 이미 흐른다 [코드]. ★그러므로 **첫 할 일은 B 를 만드는 게 아니라 그 3개를 BQ 에서 읽는 것**이다 — A 가 이미 답을 갖고 있을 수 있고(대본 시청만으로 연결 전환이 나온다면), 그러면 B 의 기대이득이 절반으로 준다. 이 문서는 A 가 실패했다고 **주장하지 않는다**. 아직 안 읽었을 뿐이다(§12 한계).
2. **B 는 서버가 0이다.** #885 §8 이 출시조건으로 못박은 통제 8종(단명토큰·하드캡·동시성·모델 allowlist·**전역 예산 킬스위치**·이상탐지·데모 스코프 고정)이 **하나도 필요 없다.** 불변식 I1 을 구조적으로 만족한다.
3. **B 가 겨냥하는 지문은 딱 하나다** — "내가 방금 쓴 문장이 카드 6장이 되어 보드에 꽂혔다". 이 아하는 A(남의 대본 시청)에 **구조적으로 없다.**
4. **C 의 증분 이득 크기를 우리는 모른다.** "제목이 더 자연스럽다"가 전환을 얼마나 올리는지 데이터가 없다. B 를 같은 seam 뒤에 두면 그 미지를 나중에 **A/B 로** 살 수 있다(§4-C).
5. **선례가 있다.** 온보딩 프리뷰(#882)가 "뷰모델만 갈아끼우고 실 IPC·PTY·firestore·키체인을 한 번도 안 부른다"는 규율로 착지했다 [코드]. B 는 그 규율을 한 칸 옮긴 것이다 — 다만 §4-D 대로 **firestore write 는 진짜로 한다**(불변식 I3).

**A 의 처분**: 삭제하지 않는다. **L(-1) 로그인 전 표면으로 유지**하고 L0 와 역할을 가른다 — A=본다, B=만든다. 같은 것을 두 번 만들지 않는다.

### 4-C. `decompose()` — 이 설계의 유일한 seam

C 로 갈아탈 수 있게 하는 것이 B 설계의 핵심이다. env-swap 축이 벤더를 행 1개로 바꾸는 것과 **같은 발상**이다.

```ts
// v3/src/lib/onrampDecompose.ts  (순수 모듈 — React·DOM·타이머·네트워크 없음)
export interface TicketDraft {
  title: string;
  description: string;
  role: "frontend" | "backend" | "devops" | "qa" | "design";
  order: number;
  /** 선행 초안의 order. 룰이 확신할 때만 채운다(없으면 undefined). */
  dependsOnOrder?: number;
}

export interface DecomposeResult {
  drafts: TicketDraft[];
  /** 어떤 규칙이 걸렸나 — 계측·디버깅용. LLM 모드면 "llm". */
  matchedRule: string;
  /** 규칙이 확신하지 못해 일반 골격으로 떨어졌는가. UI 문구가 이걸 읽는다. */
  fallback: boolean;
}

export type Decomposer = (
  input: string,
  locale: "ko" | "en",
) => DecomposeResult;

/** B — 로컬 룰. 기본값. */
export const ruleDecomposer: Decomposer;
/** C — 서버 1콜. 나중에. 같은 시그니처의 async 판을 별도 타입으로 둔다. */
```

**seam 규율 3가지**

| #   | 규율                                                               | 왜                                                                                           |
| --- | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------- |
| D1  | `decompose` 는 **순수함수**다 — 네트워크·스토어·i18n 부수효과 금지 | `demoScript.ts` 가 이미 이 이유로 쪼개져 있다(v3 vitest 는 `environment:"node"`, jsdom 없음) |
| D2  | 화면은 `DecomposeResult` **만** 읽는다                             | B→C 교체가 화면 변경 0이 된다                                                                |
| D3  | `matchedRule` 을 계측에 싣는다                                     | "어떤 입력이 fallback 으로 떨어지는가"가 다음 룰의 근거가 된다                               |

### 4-D. 룰 설계 — B 가 실제로 무엇을 하는가

**입력**: 유저가 비기너 챗에 쓴 한 문장~한 문단. **출력**: 티켓 초안 3~7장.

| 층  | 무엇                   | 예                                                                          |
| --- | ---------------------- | --------------------------------------------------------------------------- |
| R1  | **의도 키워드 사전**   | "로그인/인증", "결제", "랜딩/홈", "API", "버그/안 돼", "테스트", "배포"     |
| R2  | 의도별 **골격 템플릿** | 로그인 → ①화면 ②API ③세션저장 ④에러처리 ⑤테스트                             |
| R3  | **유저 어휘 재사용**   | 유저 문장에서 명사구를 뽑아 제목에 그대로 박는다("**결제창** 만들기")       |
| R4  | 역할 배정              | 템플릿에 role 고정(화면=frontend, API=backend, 테스트=qa)                   |
| R5  | 의존성                 | 템플릿이 확신하는 경우만(②API → ③세션). 애매하면 **비운다**                 |

**★정직성 규칙(가장 중요)**: `fallback === true` 면 화면이 **그렇게 말한다** — "대략 이런 모양으로 쪼갤 수 있어요. 계정을 연결하면 오케스트레이터가 실제 코드를 읽고 **다시** 쪼갭니다." 초안을 완성품처럼 팔지 않는다. #885 §7-B 가 경고한 실패모드("조용히 틀린 일을 열심히 하는 팀")를 **말로** 막는 것이 룰베이스에서 유일하게 가능한 방어다.

### 7-B. ★크레딧이 비싼 이유는 결제가 아니라 프록시다

#883 §5-A·§5-D 의 판정을 그대로 승계한다:

1. **데스크탑이라 우리 벤더 키를 유저 머신에 못 내린다** — env 로 내려간 크레덴셜은 `ps -E`/프로세스 덤프로 읽힌다. 내려보내는 순간 모양 B(= 전 벤더 NO-GO)가 된다.
2. **`cost_logs` 는 원장이 아니다** — 15초 폴 델타 · **멱등키 없음**(8월 32%가 중복) · `taskId=null` 행 존재 · `totalCost` 는 list-price 추정치. 이걸로 돈을 깎으면 **오차가 곧 손실**이다.

→ **차감은 반드시 프록시가 자기 응답의 `usage` 로 직접 기록한다.** 프록시는 편의가 아니라 **과금의 전제조건**이다.

### 7-C. 크레딧 원장 설계 — 기존 불변원장 규율 위에

**컬렉션 2개.** 원장(진실)과 계정(파생 캐시)을 분리한다.

#### `creditLedger/{entryId}` — 불변 · append-only

| 필드                   | 타입                                       | 비고                                                                       |
| ---------------------- | ------------------------------------------ | -------------------------------------------------------------------------- |
| `userId`               | string                                     |                                                                            |
| `kind`                 | `topup` \| `debit` \| `refund` \| `adjust` |                                                                            |
| `amountMicroUsd`       | number (부호 있음)                         | ★**USD 마이크로달러**가 회계 단위다(§7-D)                                  |
| `balanceAfterMicroUsd` | number                                     | 감사용. 계정 캐시와 대조하면 드리프트가 드러난다                           |
| `source`               | `portone` \| `proxy` \| `ops`              |                                                                            |
| `vendor`,`modelId`     | string?                                    | debit 만                                                                   |
| `usage`                | `{input,output,cacheRead,cacheWrite}`      | debit 만. **프록시 응답 원문 기준**                                        |
| `unitRateMicroUsd`     | `{in,out,cacheRead,cacheWrite}`            | ★**그때의 단가를 행에 박는다** — 단가가 바뀌어도 과거 행이 흔들리지 않는다 |
| `markupBps`            | number                                     | 예: 3000 = 30%                                                             |
| `taskId`,`agentId`     | string?                                    | 비용축 정합화 메모 대로 **`taskId` 만이 정합한 다리**다                    |
| `krwAmount`,`fxRate`   | number?                                    | topup 만. 환율을 행에 박는다                                               |
| `createdAt`            | serverTimestamp                            |                                                                            |

**결정적 `entryId` = 멱등키**

| kind   | entryId                     | 왜                                                                                          |
| ------ | --------------------------- | ------------------------------------------------------------------------------------------- |
| topup  | `topup_portone_{paymentId}` | `billingCharges/portone_{paymentId}` 와 **1:1**. 웹훅 재전송·재시도가 두 번 충전하지 못한다 |
| debit  | `debit_{proxyRequestId}`    | 프록시가 요청당 1회 발급하는 uuid. **응답 1건 = 원장 1행**                                  |
| refund | `refund_{paymentId}_{seq}`  | 부분환불 가능                                                                               |
| adjust | `adjust_{opsTicketId}`      | 사람 조작은 반드시 티켓 근거를 남긴다                                                       |

**Firestore rules [설계]**

```
match /creditLedger/{entryId} {
  allow read:   if isAuthenticated() && resource.data.userId == request.auth.uid;
  allow create: if false;   // 프록시·Functions(Admin SDK)만
  allow update: if false;   // ★행은 태어날 때 최종값이다
  allow delete: if false;
}
match /creditAccounts/{userId} {
  allow read:  if isAuthenticated() && isOwner(userId);
  allow write: if false;    // subscriptions/{userId} 와 같은 자세
}
```

> **★"불변원장 vs 멱등재시도"는 가짜 긴장이다**(사내 메모 `immutable_ledger_idempotent_retry_rule`). 결정적 id + `create` 만 허용이면 재시도가 `ALREADY_EXISTS` 로 죽고 **그게 곧 멱등**이다. 그래서 크레딧 원장은 `billingCharges`(pending→succeeded 전이가 필요해 `merge:true` 를 쓴다 [코드])보다 **더 엄격하게** `update:if false` 로 갈 수 있다 — 크레딧 행에는 상태 전이가 없다.

#### `creditAccounts/{userId}` — 파생 캐시

`balanceMicroUsd` · `lifetimeToppedUpMicroUsd` · `lifetimeSpentMicroUsd` · `ticketsDoneOnCredit` · `updatedAt`.

**트랜잭션 불변식**: 원장 create 와 계정 increment 는 **한 트랜잭션**. 원장 행이 이미 있으면 increment 를 **건너뛴다**. 계정은 언제든 원장 재집계로 재생성 가능해야 한다(진실은 원장뿐).

### 7-D. 회계 단위와 가격

| 결정                  | 값 · 근거                                                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 원장 단위             | **USD 마이크로달러**. 원가가 USD per-token 이므로 원화로 들면 환율 변동이 원장에 스며든다                              |
| 유저에게 파는 단위    | **원화 충전액**(₩10,000). 표시는 "남은 티켓 수(추정)"                                                                  |
| 마크업                | **30%** [제안] — #883 §3-C: 5.4% 미만은 PG 수수료로 적자, 30%에서 마진율 18.2%                                         |
| ★가격 리스크 전가     | 크레딧을 "₩10,000어치 **토큰**"이 아니라 **"USD 예산"**으로 적재한다. 벤더 단가 인상을 우리가 흡수하지 않는다(#883 R7) |
| 최소 충전             | **₩10,000** — 토스 연 관리비 ₩110,000 회수에 연 61건 필요(#883 §3-E)                                                   |
| 미사용 잔액           | **부채다.** 매출 인식 금지. 환불 경로를 원장에 내장(`kind:"refund"`)                                                   |
| 선불전자지급수단 등록 | **불요**로 판단(발행인 서비스에서만 사용, 면제기준 미달) — 사업 개시 전 확인 필요(#883 §3-E)                           |
| **프레이밍**          | ★**수익이 아니라 CAC.** 유저당 마진 ₩2,000~4,000(#883 §3-D)은 사업이 아니다. 회계도 그렇게 잡는다                      |

### 7-E. 게이트 배선

잔액 게이트는 **`spawnNewAgent` 초크포인트**에 둔다 — `agent:launch` IPC(UI)가 아니라. 이유: dispatch·HTTP·미션 경로가 UI 를 우회한다(사내 결정 #660, `bridge-server.ts:2589,3313` 주석이 그 사각을 이미 적어 놓았다 [코드]).

### 8-B. L2 를 켤 때 반드시 지킬 6가지 (#883 §9 그대로 승계)

1. **모양 A 만** — 유저에게 API 키·엔드포인트를 **어떤 형태로도** 주지 않는다. 모양 B 는 전 벤더 NO-GO.
2. **벤더 1개로 시작** — MiniMax **오픈플랫폼 pay-go** 또는 xAI. ★**현행 env-swap 3벤더(GLM/MiniMax/Kimi) 키는 전부 구독 엔드포인트**다(`model-registry.ts:545,625,726`) — 재판매 경로에 **그대로 쓰면 즉시 위반**. pay-go 플랫폼 키로 **갈아끼운 뒤에만** 켠다.
3. **계량 프록시 필수** + 스폰당 **단명 토큰**.
4. **서버측 하드캡** — 잔액·동시성·RPS. `spawnNewAgent` 초크포인트에(§7-E).
5. **불변 원장 + 멱등키**, `cost_logs` 와 **분리**(§7-C).
6. **우리 약관에 벤더 AUP 전가**(xAI 명시 의무) + 환불 조항.

그리고 **앤트로픽 모델을 이 경로에 태우기 전에는 `sales@anthropic.com` 서면 확인**(#883 §2-B). 확인 전에는 GO 벤더로만 돈다.

### 8-C. 2026-04-04 조치와 우리 층들의 관계 — 헷갈리기 쉬운 자리

| 대상                                                      | 그 조치의 영향                   |

## 12. 한계 · 정직성

- **0층 룰 분해의 품질을 측정하지 않았다.** `fallback` 비율 40% 라는 T4 판정선은 [제안]이지 실측이 아니다. 룰베이스가 "골격은 항상 맞다"는 주장도 설계 의도이지 검증된 사실이 아니다.
- **A(캔드 데모)가 전환을 못 만든다고 주장하지 않는다.** 이벤트가 이미 흐른다는 것만 [코드]로 확인했고, **BQ 를 아직 읽지 않았다.** T2 가 그것을 먼저 한다. A 가 잘 작동하고 있다면 이 문서의 §4-B 추천은 약해진다.
- **L2 의 규모 추정(프록시=L)은 #883 §7 을 그대로 옮긴 것**이고 이 문서가 독립 견적하지 않았다.
- **크레딧 원장 스키마는 설계다.** Firestore rules 초안은 구현·`npm run test:rules` 검증을 거치지 않았다. 특히 `create: if false` + Admin SDK 전용 자세는 #406(메인 프로세스 인증 경로가 렌더러와 다르다)의 실패모드를 다시 밟을 수 있으므로, 쓰는 주체가 프록시(서버)인 것을 **배포 전에 실측**해야 한다.
- **모달 문구는 초안이다.** i18n 키·톤·길이는 디자인 리뷰 대상이고, 특히 M3 의 "구독이 더 쌉니다"는 사장님 승인 사항이다(매출을 스스로 돌려보내는 문구다).
- **G0/G1 임계는 [제안]이다.** 30%는 #885 가 제안한 값을 축을 맞추려고 그대로 쓴 것이고, +15%p 는 이 문서가 처음 놓은 값이다 — 도출된 값이 아니다.
- **환율 ₩1,400/$ · 마크업 30% · 최소충전 ₩10,000 은 가정**이다(#883 §3-C 승계).
- **L1.5(BYOK)가 실제로 얼마나 먹는지 모른다.** "API 키는 있는데 구독은 없는" 사람의 비율을 우리는 안 세어 봤다.
- **선불전자지급수단·부가세 판정은 법 정의 대조 수준**이고 법률 자문이 아니다(#883 §3-E 승계).
- 날조 없음. 코드 인용은 전부 파일·행으로 확인 가능하고, 원가·ToS 수치는 §13 의 선행문서가 1차 출처를 들고 있다.
