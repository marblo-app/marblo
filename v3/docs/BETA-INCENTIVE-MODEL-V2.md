## 1. 한 줄 요약

파운더 베타 인센티브는 **1개월 베타 사용 → 성실 설문 제출(루브릭 채점) → Pro 3개월 지급**으로 단순화한다. 설문 상위 약 10명은 운영자가 별도로 화상 인터뷰를 요청하고, 사용자가 인터뷰에 응하면 **Pro 6개월로 연장**한다.

핵심은 "많이 쓴 사람"이 아니라 **실사용 맥락과 구매/확장 판단에 도움이 되는 통찰을 준 사람**을 선별하는 것이다.

## 2. 확정 모델

### 2.1 기본 플로우

1. 사용자가 Founder Beta에 선정된다.
2. 선정일 또는 활성화일 기준 **1개월 베타 접근권**을 부여한다.
3. 베타 종료 전후에 성실 설문을 요청한다.
4. 운영자가 설문을 21점 루브릭으로 채점한다.
5. 최소 성실 기준을 통과한 설문 제출자에게 **Pro 3개월**을 부여한다.
6. 루브릭 상위 약 10명은 운영자가 화상 인터뷰를 요청한다.
7. 요청받은 사용자가 인터뷰에 응하고 완료하면 **Pro 6개월로 연장**한다.

### 2.2 보상 원칙

| 단계 | 조건 | 보상 | 자동 여부 |
| --- | --- | --- | --- |
| 베타 접근 | Founder Beta 선정 | 1개월 베타 | 운영자 선정 |
| 설문 보상 | 성실 설문 제출 및 루브릭 최소 기준 통과 | Pro 3개월 | 채점 후 부여 |
| 인터뷰 보상 | 상위 약 10명 선별 + 운영자 요청 + 화상 인터뷰 완료 | Pro 6개월로 연장 | 자동 아님 |

### 2.3 커뮤니케이션 프레이밍

- 외부 표현은 **"1개월 베타 + 성실 설문 제출 시 Pro 3개월"**을 기본으로 한다.
- 총 기간을 설명해야 할 때는 **"최대 기본 4개월 혜택(1개월 베타 + Pro 3개월)"**로 표현한다.
- 6개월은 모든 설문 제출자에게 약속하지 않는다.
- 6개월은 **"우수 피드백 제공자 중 일부에게 별도 인터뷰 요청, 인터뷰 완료 시 연장"**으로 표현한다.

## 4. 성실 설문 7문항

설문은 자유서술 중심으로 받되, 사용자가 막히지 않도록 각 문항에 예시 힌트를 붙인다. 문항별 근거는 내부 운영/분석 기준이며 사용자에게 그대로 노출할 필요는 없다.

| # | 질문 | 답변 힌트 | 근거 |
| --- | --- | --- | --- |
| 1 | 이번 베타에서 Marblo를 어떤 작업 맥락에서 사용했나요? | 작업 종류, 프로젝트 규모, 사용한 에이전트 조합, 사용 빈도 | ICP와 실제 사용 환경을 판별한다. |
| 2 | 사용 중 "이건 계속 쓰겠다" 또는 "아하"라고 느낀 순간이 있었나요? | 어떤 화면/흐름/결과였는지, 왜 인상적이었는지 | 핵심 가치가 실제로 전달되는 지점을 찾는다. |
| 3 | 가장 크게 막힌 지점, 버그, 혼란스러웠던 순간은 무엇이었나요? | 재현 단계, 기대 결과, 실제 결과, 개선 제안 | 제품 개선에 바로 연결되는 액션을 얻는다. |
| 4 | Marblo 없이 같은 일을 했다면 어떻게 했을까요? 시간이나 노력은 얼마나 달랐나요? | 기존 방식, 걸리는 시간, 협업/반복 작업 차이 | 대안 대비 가치와 절감 효과를 추정한다. |
| 5 | 이 제품에 돈을 낸다면 누가, 얼마를, 왜 낼 수 있을까요? | 개인/팀/회사카드, 월 가격 범위, 승인 이유/장벽 | WTP와 구매 주체를 확인한다. |
| 6 | 기능을 하나만 남겨야 한다면 무엇을 남기고, 하나만 추가한다면 무엇을 추가할까요? | 남길 기능 1개, 추가 기능 1개, 이유 | 핵심 기능 우선순위와 결손 기능을 분리한다. |
| 7 | 동료에게 추천할 의향은 0~10점 중 몇 점인가요? 그 이유는 무엇인가요? | 점수, 추천 대상, 추천/비추천 이유 | 확산 가능성과 추천 조건을 정량+정성으로 본다. |

## 5. 루브릭

### 5.1 채점 구조

총점은 21점이다. 5개 차원을 0~3점으로 채점하되, "구체성"과 "실사용 근거"는 설문 전체에서 제품 학습의 기반이므로 각각 가중치 2를 둔다.

계산식: `(구체성 * 2) + (실사용 근거 * 2) + 통찰 질 + 액셔너빌리티 + ICP 적합 = 21점 만점`.

| 차원 | 가중치 | 점수 범위 | 최대점 |
| --- | --- | --- | --- |
| 구체성 | 2 | 0~3 | 6 |
| 실사용 근거 | 2 | 0~3 | 6 |
| 통찰 질 | 1 | 0~3 | 3 |
| 액셔너빌리티 | 1 | 0~3 | 3 |
| ICP 적합 | 1 | 0~3 | 3 |
| **합계** |  |  | **21** |

### 5.2 차원별 기준

| 점수 | 구체성 | 실사용 근거 | 통찰 질 | 액셔너빌리티 | ICP 적합 |
| --- | --- | --- | --- | --- | --- |
| 0 | 빈 답변, 일반론 | 실제 사용 없음 | 판단 근거 없음 | 실행 단서 없음 | 대상 사용자가 아님 |
| 1 | 일부 상황만 언급 | 짧게 실행해 봄 | 표면적 감상 | 방향만 있음 | 약한 관련성 |
| 2 | 작업/상황/결과가 명확 | 실제 작업 1개 이상 근거 | 원인이나 비교가 있음 | 개선 지점이 구체적 | 개인/팀 개발 워크플로우와 관련 |
| 3 | 재현 가능한 수준의 맥락 | 반복 사용 또는 실제 산출물 근거 | 구매/유지/확장 판단에 도움 | 우선순위와 해결 힌트가 명확 | 초기 타깃 ICP에 강하게 부합 |

### 5.3 통찰 기준

통찰은 분량으로 채점하지 않는다. 짧아도 아래 조건을 만족하면 높은 점수를 줄 수 있다.

- 실제 업무 맥락이 있다.
- 기존 대안과 비교가 있다.
- 왜 좋았는지 또는 왜 막혔는지 원인이 있다.
- 운영자가 다음 제품/가격/온보딩 결정을 내리는 데 쓸 수 있다.

긴 답변이라도 감상, 홍보성 문장, 일반적인 칭찬/불만만 있으면 낮게 채점한다.

### 5.4 선정 컷

권장안은 **최소 기준 + 상위 N**의 혼합 방식이다.

| 목적 | 컷 방식 | 권장 |
| --- | --- | --- |
| Pro 3개월 지급 | 21점 중 10점 이상 또는 운영자 예외 승인 | 성실 제출 기준으로 넓게 인정 |
| 인터뷰 후보 | 14점 이상 중 상위 약 10명 | 인터뷰 품질과 운영 시간을 균형화 |
| 동점 처리 | ICP 적합 → 실사용 근거 → 액셔너빌리티 순 | 구매/확장 학습 가치 우선 |

점수만으로 자동 선정하지 않는다. 운영자는 허위/저품질/중복 응답을 제외할 수 있다.

## 6. 화상 인터뷰 가이드

### 6.1 목적

상위 약 10명 인터뷰의 목적은 보상 지급이 아니라 **WTP, ICP, 확장 가능성**을 검증하는 것이다.

- WTP: 누가 어떤 예산으로 살 수 있는지 확인한다.
- ICP: 어떤 직무/팀/작업에서 강하게 맞는지 확인한다.
- 확장: 동료 추천, 팀 도입, 반복 사용 조건을 확인한다.

### 6.2 진행 팁

- 30분을 기본으로 잡는다.
- 사용자의 최근 실제 작업을 시간순으로 복기하게 한다.
- "좋았다/별로였다"보다 "그때 무엇을 하려 했고, 무엇이 달라졌는가"를 묻는다.
- 가격 질문은 기능 설명 뒤가 아니라 실제 가치와 대안 비용을 들은 뒤 묻는다.
- 인터뷰어는 반박하지 말고 맥락, 원인, 대안을 캐묻는다.
- 녹화/기록 동의 여부를 먼저 확인한다.

### 6.3 10문항 스크립트

| # | 질문 | 목적 |
| --- | --- | --- |
| 1 | 간단히 하시는 일, 팀 규모, 개발/운영 환경, Marblo 전의 작업 방식을 알려주세요. | 워밍업 및 ICP 파악 |
| 2 | Marblo를 처음 알게 된 경로, 첫 세션에서 기대한 것, 실제와 달랐던 점은 무엇인가요? | 첫인지/첫경험/기대 차이 |
| 3 | 최근 Marblo로 처리한 실제 작업 하나를 처음부터 끝까지 이야기해 주세요. | 실제 사용 플로우 재구성 |
| 4 | 그 작업에서 가장 막힌 순간은 언제였고 어떻게 대응했나요? | 장애물과 회피 전략 파악 |
| 5 | Marblo가 없었다면 같은 일을 어떻게 했고 시간/노력은 얼마나 들었을까요? | 대안 비용과 가치 추정 |
| 6 | Marblo를 안 쓰게 되는 순간이 있다면 어떤 이유일까요? | 이탈 요인 파악 |
| 7 | 적정 가격은 얼마라고 느끼나요? 개인 결제와 회사카드 승인 조건은 각각 무엇인가요? | WTP와 구매 장벽 확인 |
| 8 | 동료에게 설명한다면 뭐라고 말할까요? 누구에게 추천하고 누구에게는 추천하지 않을까요? | 포지셔닝과 추천 대상 확인 |
| 9 | 하나만 고칠 수 있다면 무엇을 고치겠나요? | 최우선 개선점 도출 |
| 10 | 제가 묻지 않았지만 꼭 말하고 싶은 것이 있나요? | 누락된 통찰 수집 |

## 7. 설문 전달 및 운영 흐름

### 7.1 전달 채널

| 채널 | 역할 |
| --- | --- |
| marblo-web `/[locale]/beta-survey` | 로그인 가드가 있는 정식 설문 제출면 |
| Resend 이메일 | 베타 종료 전/후 설문 요청 및 리마인드 |
| 인앱 프롬프트 | 실제 사용 직후 설문 진입 유도 |
| 어드민 화면 | 채점, 인터뷰 후보 선정, 보상 상태 확인 |

설문 URL은 locale을 유지한다. 예: `/ko/beta-survey`, `/en/beta-survey`, `/ja/beta-survey`.

### 7.2 어드민 운영 단계

1. 베타 사용자 목록에서 `betaExpiresAt` 임박자를 확인한다.
2. 설문 제출 여부를 확인한다.
3. 루브릭 5차원을 채점해 `rubricScore`를 저장한다.
4. Pro 3개월 대상자를 확정한다.
5. 상위 약 10명을 인터뷰 후보로 표시하고 `interviewRequested`를 저장한다.
6. 인터뷰 완료 시 `interviewCompleted`를 저장하고 Pro 6개월 연장 여부를 확정한다.

| 기존 의미 | V2 의미 |
| --- | --- |
| `feedbackSubmittedAt` | 설문 제출 시각. 단독으로 보상 확정 근거가 아님 |
| `interviewedAt` | `interviewCompletedAt`으로 매핑 가능 |
| `status = feedback_submitted` | 채점 대기 또는 Pro 3개월 후보 |
| 6문항 답변 | legacy feedback으로 보존, V2 7문항과 구분 |

### 8.3 권한/보안 원칙

- 사용자는 자기 설문만 생성/조회할 수 있다.
- 루브릭 점수, 인터뷰 요청, 보상 개월 수는 어드민만 수정할 수 있다.
- 설문 답변은 구매/제품 판단용 민감 정보이므로 공개 클라이언트 목록 조회를 허용하지 않는다.
- 이메일 발송 상태와 보상 지급 상태는 운영 감사가 가능하도록 timestamp를 남긴다.

## 9. 롤아웃

### 9.1 기존 베타 유저 영향

이미 구모델 안내를 받은 사용자는 신뢰 손상을 피해야 한다. 권장안은 아래와 같다.

- 구모델 약속을 명시적으로 받은 사용자는 기존 약속을 보존한다.
- 아직 개별 안내를 받지 않은 사용자는 V2로 전환한다.
- 경계 사례는 운영자가 `legacyIncentiveModel` 플래그 또는 메모로 관리한다.

### 9.2 메시지 변경

| 표면 | 변경 전 | 변경 후 |
| --- | --- | --- |
| 선정 이메일 | 3개월 베타 / 3일 내 피드백 / 인터뷰 시 6개월 | 1개월 베타 / 성실 설문 시 Pro 3개월 / 우수 응답자 인터뷰 완료 시 6개월 연장 |
| 설문 페이지 | 6문항 피드백 | 7문항 성실 설문 + 루브릭 기반 운영 채점 |
| 어드민 | 제출/인터뷰 여부 중심 | 점수/선정/요청/완료 상태 중심 |

### 9.3 구현 순서

1. marblo-web 설문 라우트 `/[locale]/beta-survey`를 V2 7문항으로 정의한다.
2. 로그인 가드와 제출 중복 방지 정책을 붙인다.
3. feedback 데이터 모델에 루브릭/인터뷰 필드를 추가한다.
4. Resend 이메일 카피를 V2로 교체한다.
5. 인앱 프롬프트에서 베타 종료 전 설문을 안내한다.
6. 어드민 채점/선정 화면을 추가한다.
7. 기존 베타 유저를 legacy/V2 대상으로 분류한다.

## 10. 열린 질문과 권장안

| 질문 | 선택지 | 권장안 | 근거 |
| --- | --- | --- | --- |
| 설문 문항 수 | 7문항 vs 5문항 | 7문항 유지 | 베타 표본이 작으므로 WTP/추천/기능 우선순위를 분리해 받아야 한다. |
| Q5 지불의사 포함 여부 | 포함 vs 제외 | 포함 | Founder beta의 핵심 학습은 "좋다"보다 "누가 왜 돈을 내는가"다. |
| 인터뷰 컷 방식 | 상위 N vs 점수 이상 | 최소 14점 이상 중 상위 약 10명 | 품질 하한과 운영 가능한 인터뷰 수를 동시에 만족한다. |
| Pro 3개월 자동화 | 제출 즉시 vs 채점 후 | 채점 후 | 저품질/허위 응답을 제외해야 인센티브가 설문 품질을 망치지 않는다. |
| 6개월 표현 | 공개 약속 vs 선별 보상 | 선별 보상 | 자동 보상처럼 보이면 운영 부담과 기대치가 커진다. |

## 11. 결정 요약

- V2는 **1개월 베타 + 성실 설문 통과 시 Pro 3개월**이 기본 모델이다.
- 6개월은 폐지된 것이 아니라 **상위 약 10명 선별 + 화상 인터뷰 완료 조건의 연장 보상**으로 재정의한다.
- 설문은 7문항으로 운영하고, 21점 루브릭은 분량보다 실사용 근거와 통찰 품질을 본다.
- 데이터 모델은 `rubricScore`, `interviewRequested`, `interviewCompleted`, `betaExpiresAt`, `proExpiresAt`를 명시적으로 추적한다.
- 기존 구모델 약속을 받은 사용자는 별도 legacy 처리하고, 신규 안내부터 V2를 적용한다.
