# Marblo v3 베타 배포 1개월 계획

> ⚠️ **베타 일정·결제·도메인·가격의 단일 진실원은 [v3.1*런칭*마스터플랜.md](./v3.1_런칭_마스터플랜.md) §1 (일정) / §2 (가격) / §3 (도메인) / §4 (결제) 입니다. 본 문서와 충돌 시 마스터플랜이 이깁니다.**

> 최종 업데이트: 2026-04-03

## 개요

마블로(Marblo) v3 Electron 데스크톱 앱의 **베타 배포 1개월 계획서**.
개발 완료된 핵심 기능을 안정화하고, 결제 시스템 연동 후 marblo.io 웹사이트를 통해 첫 유료 베타 사용자를 확보하는 것이 목표.

### 베타 배포 목표

| 항목                         | 목표                  |
| ---------------------------- | --------------------- |
| 베타 사용자                  | 100명 (얼리버드 포함) |
| 유료 전환                    | 30% (Pro 플랜 기준)   |
| 크리티컬 버그                | 0건                   |
| 앱 크래시율                  | < 1%                  |
| 평균 설치→첫 에이전트 Launch | 5분 이내              |

## Phase 2: TossPayments 결제 시스템 (Week 1-2)

### 사업자 인증 절차

| 단계 | 작업                                  | 소요 시간       |
| ---- | ------------------------------------- | --------------- |
| 1    | TossPayments 가입 (사업자등록증 제출) | 1일             |
| 2    | 심사 및 승인                          | 3-5 영업일      |
| 3    | API 키 발급 (테스트/라이브)           | 승인 즉시       |
| 4    | 정기결제(빌링) 심사 신청              | 추가 2-3 영업일 |
| 5    | PG 계약 완료                          | 총 ~7-10 영업일 |

### Cloud Functions 구현

```
functions/
├── toss-webhook.ts          — TossPayments Webhook 수신
│   ├── 결제 승인 (DONE)
│   ├── 결제 취소 (CANCELED)
│   ├── 정기결제 갱신 (BILLING)
│   └── 결제 실패 (FAILED)
│
├── paddle-webhook.ts        — Paddle Webhook 수신
│   ├── subscription.created
│   ├── subscription.updated
│   ├── subscription.canceled
│   └── transaction.completed
│
├── coupon-redeem.ts          — 쿠폰 검증 + 적용
├── subscription-check.ts     — 구독 만료 체크 (매일 크론)
└── billing-retry.ts          — 결제 실패 시 재시도 로직
```

## Phase 3: 앱 안정화 (Week 2-3)

### 에러 핸들링 강화

| 영역               | 현재 이슈                             | 해결 방안                                          |
| ------------------ | ------------------------------------- | -------------------------------------------------- |
| **터미널 연결**    | 유휴 시 WebSocket 끊김                | heartbeat 적용됨 (5초 간격), 자동 재연결 로직 추가 |
| **PTY 프로세스**   | 에이전트 비정상 종료 시 좀비 프로세스 | graceful shutdown + 프로세스 감시 타이머           |
| **Firestore 연결** | 오프라인 전환 시 데이터 손실          | enablePersistence + 오프라인 큐                    |
| **Firebase Auth**  | 토큰 만료 후 API 실패                 | onAuthStateChanged 리스너 + 자동 토큰 갱신         |
| **Monaco Editor**  | 대용량 파일 렌더링 지연               | 파일 크기 제한 (1MB) + 가상화                      |
| **Flow 실행**      | 노드 실행 중 앱 종료 시 상태 불일치   | 실행 상태 Firestore 동기화 + 복구 로직             |
| **메모리 누수**    | 장시간 사용 시 메모리 증가            | xterm.js dispose + React cleanup                   |

### 에이전트 테스트 매트릭스

| 테스트 시나리오                              | 통과 기준                |
| -------------------------------------------- | ------------------------ |
| 에이전트 1개 Launch → 태스크 수행 → 완료     | 정상 동작                |
| 에이전트 5개 동시 Launch                     | 크래시 없음, CPU < 80%   |
| 에이전트 Launch → 네트워크 끊김 → 복구       | 자동 재연결              |
| MCP 도구 13개 순차 호출                      | 모두 정상 응답           |
| Flow 5노드 파이프라인 실행 → 완료            | 전체 노드 통과           |
| 오케스트레이터 → 태스크 분해 → 에이전트 할당 | 자동 분배 동작           |
| 칸반 드래그 앤 드롭 (100개 태스크)           | UI 지연 < 100ms          |
| 파일 트리 + Monaco 탭 20개                   | 메모리 < 500MB           |
| 24시간 연속 실행                             | 메모리 안정, 크래시 없음 |

  - 사용자 동의 후 크래시 리포트 자동 전송
  - Source Map 업로드 (빌드 시)

## Phase 4: 앱 패키징 + 베타 배포 (Week 3-4)

### 빌드 설정

#### macOS

```yaml
# electron-builder.yml (macOS 섹션)
mac:
  target:
    - target: dmg
      arch: [universal] # Intel + Apple Silicon
    - target: zip
      arch: [universal]
  category: public.app-category.developer-tools
  icon: resources/icon.icns
  hardenedRuntime: true
  gatekeeperAssess: false
  entitlements: resources/entitlements.mac.plist
  entitlementsInherit: resources/entitlements.mac.plist
  notarize:
    teamId: ${APPLE_TEAM_ID}

dmg:
  sign: false
  contents:
    - x: 130
      y: 220
    - x: 410
      y: 220
      type: link
      path: /Applications
```

#### Windows

```yaml
# electron-builder.yml (Windows 섹션)
win:
  target:
    - target: nsis
      arch: [x64, arm64]
  icon: resources/icon.ico
  signingHashAlgorithms: [sha256]
  certificateFile: ${WIN_CERT_FILE}
  certificatePassword: ${WIN_CERT_PASSWORD}

nsis:
  oneClick: false
  perMachine: false
  allowToChangeInstallationDirectory: true
  deleteAppDataOnUninstall: true
```

#### Linux

```yaml
# electron-builder.yml (Linux 섹션)
linux:
  target:
    - target: AppImage
      arch: [x64, arm64]
    - target: deb
      arch: [x64]
  icon: resources/icons
  category: Development
```

## 작업 우선순위

### P0 (Must Have — 베타 출시 블로커)

1. **marblo.io 웹사이트** — 다운로드 + 가격 페이지 없으면 배포 불가
2. **결제 시스템** — Paddle(해외) + TossPayments(국내) 중 최소 1개
3. **앱 크래시 해결** — 크리티컬 크래시 0건이 목표
4. **macOS 빌드 + 공증** — macOS 사용자가 주 타겟

### P1 (Should Have — 베타 품질 향상)

5. **Windows 빌드 + 서명** — 두 번째 타겟 플랫폼
6. **쿠폰 시스템** — 강의 구매자 전환에 필수
7. **Sentry 크래시 리포팅** — 베타 피드백 수집
8. **자동 업데이트 (electron-updater)** — 핫픽스 배포 속도

### P2 (Nice to Have — 베타 후 개선)

9. **Linux 빌드** — 수요 확인 후
10. **Blog / Docs 페이지** — 베타 기간 중 점진적 추가
11. **Google Analytics + Mixpanel** — 유저 행동 분석
12. **리퍼럴 프로그램** — 유기적 성장 채널
