## 0. 이 문서 사용법 · 선행 검증 결과

### 0.1 누가·언제 쓰나

- **재집필 담당 에이전트(또는 U1)** 가 v2 커리큘럼으로 "무엇을" 정한 뒤, 본 청사진으로 "각 파일을 어디서 가져와 어떻게 고쳐 쓸지"를 보고 실제 스크립트를 집필한다.
- 각 레슨 블록(§2)은 그대로 **재집필 티켓 1장**으로 떼어 배정할 수 있게 자족적으로 작성했다.

## 1. 공통 작성 원칙 · 컨벤션 (모든 레슨 공통)

### 1.1 새 파일명 규칙

- 형식: `{새번호}_{핵심키워드}.md` (기존 컨벤션 유지, 한글 스네이크).
- 구 파일을 **재구성**할 때도 새 번호의 새 파일을 만들고, 구 파일은 그대로 두되 §3 일람표대로 처리(부록 이동/폐기 표시). HOME.md의 위키링크를 새 파일로 갱신.
- 36개 새 파일명은 §2 각 블록 헤더에 명시.

### 1.2 레슨 파일 표준 헤더(집필 시 채울 4요소)

각 스크립트 상단에 v2와 동일한 4요소 메타를 둔다: `학습목표 / 시연할 마블로 화면·기능 / 진행할 프로젝트 단계(P1·P2·P3) / 핵심 메시지`. 그 아래 본 청사진의 **레슨 아웃라인(섹션 헤딩)** 순서대로 본문을 쓴다.

### 1.3 전역 치환 규칙 (재사용 텍스트에 일괄 적용 — "신규집필"이 아니어도 반드시 통과)

| 구 표현(폐기)                                                      | 신 표현                                                                | 근거                  |
| ------------------------------------------------------------------ | ---------------------------------------------------------------------- | --------------------- |
| "Claude + Gemini + GPT", "Claude+Gemini+Codex 동시 스폰"           | **"Claude Code + Codex (+ Antigravity)"**                              | fleet 사실            |
| fleet 멤버로서의 **Gemini**                                        | 삭제, 또는 **Antigravity**(Gemini 후신)로 교체                         | spawn UI soft-removed |
| 서비스 LLM "Gemini Flash/3.1"                                      | **"저비용 모델 1개로 추상화 + 1줄 교체"** (서비스 API는 자유)          | 혼선 제거(6-5)        |
| "4탭 Board/Code/Agents/Flows"                                      | **9개 프로덕션 탭** + 하단 오케 PTY + 레인 그리드                      | TabBar 실측           |
| 수동 `npm i -g …`, `~/.claude.json`·`.mcp.json` 직접 편집          | **하네스 스토어 원클릭 설치**(설치 방식 git/mcp/npm-global/shell 라벨) | HarnessStore          |
| "AI YouTube 인사이트"                                              | **ReachWave**(P3, 콜드메일 자동화)                                     | 드리프트 정리         |
| "Stitch MCP" 필수 의존                                             | **"가용 시"** 선택 → 없으면 **에이전트 직접 구현**(디자인→코드)        | 가용성 불확실         |
| 고정 단가표(Opus $/1M 등)                                          | **사용량 탭 실측 + "단가는 변동, 측정·배치가 핵심"**                   | 5-1/5-5 stale         |
| 구 설치 URL/CLI 명령 목록(`/compact` 등), 라이브러리명(React Flow) | 집필 직전 **현행 확인 후 기재**(@xyflow/react 등)                      | 버전 드리프트         |

### 1.4 재사용/신규 표기 (각 레슨 "구간 표시"에서 사용)

- **♻재사용** = 구 파일 특정 섹션 텍스트/도식/코드 거의 보존(치환 규칙만 적용).
- **🔧개작** = 구 텍스트 골격은 쓰되 화면·도구를 신 UI로 갈아끼움.
- **⭐신규집필** = 대응 구 자료 없음, 처음부터 작성(주로 화면 캡처 시나리오).

### 1.5 슬라이드 최소화 / 화면 우선

이론(MCP 개념·아키텍처·상태머신 코드)은 **부록 A**로 강등하거나 실연 속 1장면으로 압축한다(§4). 본편은 "실제 탭을 도는 화면"이 기본.

## 5. 재집필 실행 순서 권고 (모듈 우선순위·의존·fleet 분담)

### 5.1 집필 우선순위 (의존도 기준)

1. **공통 자산 먼저(블로커 제거):** §1 치환 규칙을 "전역 용어 시트"로 확정 → 모든 재사용 텍스트가 이걸 통과해야 함. **부록 A** 분리(이론 텍스트 이동)로 본편이 가벼워짐.
2. **재사용률 높은 모듈부터(빠른 진척):** **M5(P3)** = 구 4-_/5-_ 자산 최다 재사용(치환 위주) → **M4(P2)** = 구 3-_ 승격 → **M7** = 구 6-_/7-\* 유지. 여기까지는 "고쳐 쓰기"라 속도가 난다.
3. **신규집필 모듈 나중에(품질 집중):** **M1·M2**(가이드 온보딩·하네스·설정·워크트리 = ⭐신규 다수, 실제 UI 캡처 시나리오 필요) → **M3**(레인 중심 신규) → **M6**(사용량 탭·멀티윈도우 신규) → **M8**(베타 미리보기).
4. **마지막:** HOME.md 목차·위키링크 재배선 + 촬영가이드 동기화(§6).

> 근거: 신규 화면(레인/워크트리/사용량/가이드/하네스) 레슨은 실제 앱 화면 확인이 필요해 리드타임이 길다. 재사용 모듈을 먼저 끝내 "보이는 진척"을 만들고, 신규는 화면 검증과 병행한다.
