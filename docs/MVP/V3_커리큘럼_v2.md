## 1. 프로젝트 로드맵 (난이도 점증, 3개)

강의 전반을 관통하는 **"작은 것 → 복잡한 것"** 프로젝트 사다리. 각 프로젝트가 새 마블로 기능을 단계적으로 노출한다.

| #      | 프로젝트                                                | 난이도 | 등장 모듈 | 에이전트 구성                                     | 새로 노출되는 마블로 기능                                                                                            |
| ------ | ------------------------------------------------------- | ------ | --------- | ------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| **P1** | **할 일(Todo) 웹앱** — 프론트 단독, localStorage        | ★☆☆☆   | M3        | Claude 1대(단일 레인)                             | 오케 자연어 요청 · 보드 카드 · 단일 레인 · 워크트리 머지(첫 풀사이클)                                                |
| **P2** | **날씨 대시보드** — FastAPI + Next.js + OpenWeather API | ★★☆☆   | M4        | Claude(설계/백엔드) + Codex(프론트/테스트), 2~3대 | 병렬 레인 · 에이전트별 워크트리 격리 · 의존성 체인 · 리뷰 반려/거버넌스                                              |
| **P3** | **AI SaaS — ReachWave**(콜드메일 자동화)                | ★★★★   | M5·M6·M7  | Claude + Codex(+ Antigravity), 4~5대 이종 팀      | 요구분석·`create_tasks_bulk` · dispatch 스코어링 자동배정 · 상황대응(FAILED/BLOCKED) · 사용량/비용 · GCP 배포 · 런칭 |

> **설계 의도**: P1은 "5분 만에 첫 카드가 DONE까지" 가는 성취감(=리텐션), P2는 "두 에이전트가 동시에 일하는" 멀티에이전트 핵심 체험, P3는 "실제 돈 받는 SaaS를 팀으로 출시"하는 졸업 작품. **P2·P3는 기존 자료(`3-*`, `4-*`)를 재사용**해 제작 부담을 낮춘다.
>
> **서비스 LLM ≠ 코딩 에이전트 모델** (P3에서 명시적으로 가르치는 개념): 우리가 _만드는_ 서비스 안에서 도는 LLM(예: 저비용 1개 — Claude Haiku 또는 GPT-4o-mini)과, 우리를 _도와 코딩하는_ 마블로 에이전트의 모델(Claude/Codex)은 별개다. 구 강의의 "서비스 LLM = Gemini Flash" 표기는 **Gemini가 fleet에서 빠졌어도 무관**하지만(서비스 API는 자유), 혼선을 줄이기 위해 **저비용 모델 1개로 추상화**하고 "1줄로 교체 가능"하다는 메시지를 유지한다.

**1-1 왜 '에이전트 한 명'이 아니라 '팀'인가 (15분)** ♻

- 학습목표: 단일 AI 페어코딩과 멀티에이전트 팀의 차이, 마블로가 푸는 문제를 이해한다.
- 시연: (슬라이드) 혼자 코딩 vs 보드 위에서 여러 에이전트가 동시에 카드를 처리하는 30초 타임랩스 미리보기.
- 프로젝트: —
- 핵심 메시지: "당신은 코더가 아니라 **PM/팀리더**가 된다." (구 1-1 유지, "Claude+Gemini+GPT" 문구는 **"Claude Code + Codex"**로 교체)

**1-2 마블로 한 바퀴 — 실제 탭 투어 (25분)** ♻

- 학습목표: 현재 제품의 탭 구조와 각 탭의 역할을 머릿속에 지도화한다.
- 시연: 실제 탭바를 순서대로 — **가이드 · 보드 · 레인 · 코드 · 에이전트 · 사용량 · 워크트리 · 하네스 · 설정**. 하단 **오케스트레이터 PTY 패널**과 레인 그리드 위치 설명.
- 프로젝트: —
- 핵심 메시지: "마블로 = **칸반 보드 + 에이전트 터미널 + 워크트리**가 한 화면에." (구 1-2의 "4탭 Board/Code/Agents/Flows" 표기 폐기 → 실제 9개 프로덕션 탭으로 갱신)

**1-3 가이드 탭 온보딩 — 처음 켰을 때 길 찾기 (20분)** ⭐

- 학습목표: 첫 실행 시 표시되는 가이드 탭으로 스스로 다음 행동을 찾을 수 있다.
- 시연: **가이드 탭**(GuideTab) 8개 섹션 — What is Marblo / Getting Started / `/tf-*` 슬래시 명령 / Marblo MCP / 멀티윈도우 / 하네스 스토어(⌘⇧H) / 텔레그램 알림 / Next Steps.
- 프로젝트: —
- 핵심 메시지: "막히면 **가이드 탭**으로 돌아오면 된다." (완전 신규 — 구 강의에 온보딩 화면 부재)

**1-4 큰 그림 — 오케 → 보드 → 레인 → 워크트리 → 머지 (30분)** ⭐

- 학습목표: 자연어 한 줄이 태스크·에이전트·코드 변경으로 이어지는 전체 파이프라인을 그린다.
- 시연: (개념도 → 실제 화면 짧게) 오케스트레이터에 요청 → 보드에 카드 생성 → 레인에서 에이전트 진행 → 워크트리 diff → REVIEW → 머지. 상태머신 **TODO→CLAIMED→IN_PROGRESS→REVIEW→DONE**(+BLOCKED/FAILED) 한 장으로.
- 프로젝트: — (M3에서 직접 실행할 흐름의 예고편)
- 핵심 메시지: "오늘 배울 모든 기능은 **이 한 줄 파이프라인**의 일부다." (구 2-3 상태머신 슬라이드를 여기로 흡수·압축)

- 핵심 메시지: "레인 = **한 에이전트의 작업대**. 터미널을 열어 안을 들여다본다." (신규 Lanes 기능 — 구 강의의 막연한 '터미널 패널'을 레인으로 구체화)

**3-4 리뷰 → 워크트리 머지 → 완료 (30분)** ♻

- 프로젝트: **P1 완성**(첫 머지).
- 핵심 메시지: "**칸반 거버넌스** — 머지 권한은 끝까지 내가 쥔다." (구 3-3/3-4 + 상태머신 실연 통합)

### 모듈 4 — 멀티에이전트 협업: Claude + Codex로 풀스택 (P2) (2.5h)

> 두 모델이 **동시에** 일하는 것을 처음으로 본다. 날씨 대시보드(기존 `3-*`·`실습_날씨대시보드.md` 재사용).

**4-1 풀스택 기획 + 역할 설계 (25분)** ♻

- 학습목표: 한 프로젝트를 설계/구현/리뷰 역할로 나눈다.
- 시연: 오케에 요구 입력 → 백엔드/프론트/테스트 태스크 분해. **Claude=설계·백엔드, Codex=프론트·테스트** 역할 배정 의도 설명.
- 프로젝트: **P2** 시작 (FastAPI + Next.js + OpenWeather).
- 핵심 메시지: "모델마다 잘하는 일이 다르다 — **역할로 나눠라**." (구 3-1 + 5-3 역할분담 재구성)

**4-2 의존성 체인 + 병렬 레인 (35분)** ♻

- 학습목표: 백엔드→프론트→테스트 의존성과 병렬 실행을 이해한다.
- 시연: **레인 탭**에 Claude·Codex 레인 2~3개 동시 가동. 백엔드 DONE 시 프론트 태스크가 자동 available 되는 흐름.
- 프로젝트: P2 백엔드+프론트 병렬.
- 핵심 메시지: "**의존성은 막고, 독립 작업은 동시에.**" (구 4-4 병렬처리 재구성)

**4-3 에이전트별 워크트리 격리 (25분)** ⭐

- 학습목표: 각 에이전트가 자기 워크트리에서 일하고 따로 머지됨을 본다.
- 시연: **워크트리 탭** — 레인별 워크트리 상태(behind/mergeable), Rebase로 main 따라잡기, 충돌 시 Resolve(리졸버 에이전트 스폰).
- 프로젝트: P2 통합 준비.
- 핵심 메시지: "병렬로 일해도 **워크트리가 격리**해 안전하다." (신규 — 워크트리 거버넌스)

**4-4 리뷰 거버넌스 — 반려와 재작업 (35분)** ♻

- 학습목표: REVIEW에서 피드백을 주고 카드를 되돌리는 흐름을 익힌다.
- 시연: REVIEW 카드 → 코드 diff 검토 → 부족 시 IN_PROGRESS로 반려(피드백 코멘트) → 에이전트 재작업 → 재제출. FAILED/BLOCKED 컬럼도 소개.
- 프로젝트: P2 품질 보정.
- 핵심 메시지: "에이전트는 **틀릴 수 있다 — 게이트는 사람이.**" (구 4-6 상황대응 일부 + 2-3 상태전환 흡수)

**4-5 통합 + 회고 (30분)** ↩

- 학습목표: 전체를 머지해 동작을 확인하고 흐름을 회고한다.
- 시연: 워크트리 일괄 머지 → 앱 실행 확인 → 보드로 의존성 흐름 복기.
- 프로젝트: **P2 완성**.
- 핵심 메시지: "두 에이전트, 하나의 동작하는 앱." (구 4-5/4-7/3-4 재배치)

### 모듈 5 — 칸반 거버넌스로 실전 SaaS 스프린트 (P3) (3h)

> 졸업 작품. 기존 `4-1`~`4-7`(ReachWave) 자산 재사용, 단 **코딩 에이전트 = Claude + Codex**로 갱신.

**5-1 요구사항 분석 + 페르소나 (30분)** ↩

- 학습목표: 실전 SaaS의 페르소나·가치가설·태스크 범위를 정의한다.
- 시연: 오케 + `/tf-analyze` → 18~22 태스크 윤곽. (슬라이드 최소, 화면 위주)
- 프로젝트: **P3** 기획 (ReachWave — CSV 리드 → 분석 → 톤별 콜드메일 생성 → 발송/A·B).
- 핵심 메시지: "코드 전에 **문제와 사용자**부터." (구 4-1 유지)

**5-2 태스크 일괄 생성 + 이종 에이전트 배정 (25분)** ♻

- 학습목표: `create_tasks_bulk`로 태스크를 만들고 모델별로 배정한다.
- 시연: **보드** 일괄 생성 → **에이전트 탭**에서 Claude·Codex(+선택적 Antigravity) 스폰 → 역할별 자동 배정.
- 프로젝트: P3 백로그 구성.
- 핵심 메시지: "팀 편성 = **태스크 성격 × 모델 강점.**" (구 4-2 + 5-3, Gemini 제거)

**5-3 Sprint 1 — 백엔드 라이브 빌딩 (40분)** ↩

- 학습목표: 핵심 API를 에이전트로 구현하며 activity·REVIEW 흐름을 운영한다.
- 시연: 레인에서 Claude 백엔드 라이브 빌딩, add_activity 기록, REVIEW 제출.
- 프로젝트: P3 백엔드.
- 핵심 메시지: "라이브로 — **에러도 교육 자료.**" (구 4-3 유지)

**5-4 Sprint 2 — 프론트 병렬 + 통합 (40분)** ↩

- 학습목표: 백엔드 완료분에 프론트를 병렬로 붙여 통합한다.
- 시연: Codex 프론트 레인 + DevOps 세팅, 일괄 `/tf-review`.
- 프로젝트: P3 프론트+통합.
- 핵심 메시지: "의존성 풀리는 순간 **속도가 붙는다.**" (구 4-4/4-5 유지)

**5-5 상황별 대응 — PM이 개입하는 순간 (25분)** ↩

- 학습목표: FAILED/BLOCKED/세션 끊김/새 기능 추가/정리 상황을 처리한다.
- 시연: 카드 FAILED → Restart, BLOCKED 해소, 에이전트 reuse/cleanup, 새 요청 끼워넣기.
- 프로젝트: P3 운영 중 돌발 대응.
- 핵심 메시지: "**막힘은 정상.** 마블로엔 각각의 손잡이가 있다." (구 4-6 유지)

**5-6 통합 리뷰 + 스프린트 마무리 (20분)** ↩

- 학습목표: 전체 리뷰로 스프린트를 닫는다.
- 시연: 보드 전 카드 DONE 정리, 결과물 요약.
- 프로젝트: P3 1차 완성(로컬 동작).
- 핵심 메시지: "보드가 비면 **한 스프린트 끝.**" (구 4-7 유지)

### 모듈 6 — 플릿·오케 심화 + 사용량/비용 관리 (2h)

> 구 모듈 5(멀티모델)를 **Claude+Codex(+Antigravity) 시대로 재구성**. 사용량 탭을 정식 편입.

**6-1 모델별 강점 — Claude vs Codex vs Antigravity (20분)** ♻

- 학습목표: 현재 fleet 세 모델의 강·약점을 구분한다.
- 시연: (간단 표 + 에이전트 탭) Claude(복잡 로직·코드품질·MCP), Codex/GPT(풀스택·테스트·속도), Antigravity(신규, Gemini 후신).
- 프로젝트: P3 회고 맥락.
- 핵심 메시지: "**Gemini는 빠졌다.** 기본 2인 + 떠오르는 3번째." (구 5-1 갱신: Gemini 강점 슬라이드 → Antigravity로 교체)

**6-2 dispatch 스코어링 + 자동 배정 (25분)** ↩♻

- 학습목표: 오케가 태스크를 점수화해 모델을 고르는 원리를 이해한다.
- 시연: dispatch 스코어링(role·태그 가중치) → dispatch_task. (코드 한 조각만 짧게)
- 프로젝트: P3 배정 복기.
- 핵심 메시지: "배정은 **규칙 기반 + 사람 보정.**" (구 5-4 유지·갱신)

**6-3 에이전트 재활용·정리·멀티윈도우 (25분)** ⭐

- 학습목표: reuse/cleanup과 멀티윈도우로 여러 프로젝트를 동시에 굴린다.
- 시연: **에이전트 탭** reuse/cleanup, 멀티윈도우로 P2·P3 동시 운영(프로젝트 격리).
- 프로젝트: P2 + P3 병행.
- 핵심 메시지: "에이전트는 **재활용**, 프로젝트는 **창으로 분리.**" (신규 — 멀티윈도우)

**6-4 사용량 탭 — 토큰·비용 추적과 최적화 (30분)** ⭐

- 학습목표: 사용량 탭으로 비용을 읽고 줄인다.
- 시연: **사용량 탭**(UsagePage) — 실시간 + BigQuery 히스토리, 모델별/일자별/에이전트별, rate-limit(Codex plan). 비용 절감 전략(저비용 모델로 단순 작업).
- 프로젝트: P3 비용 점검.
- 핵심 메시지: "**비용은 측정되는 순간 통제된다.**" (구 5-5 비용 시뮬을 실제 사용량 탭으로 대체·갱신; Gemini 단가 예시 → Claude/Codex/Antigravity로)

**6-5 서비스 LLM vs 코딩 에이전트 모델 (20분)** ↩

- 학습목표: 내 SaaS의 LLM과 코딩 도우미 모델을 구분한다.
- 시연: P3 코드에서 서비스 LLM 호출부 = 저비용 1개로 추상화, "1줄 교체" 데모.
- 프로젝트: P3 서비스 LLM 정리.
- 핵심 메시지: "**둘은 다른 축이다.**" (구 4-1의 핵심 교훈을 독립 레슨으로 승격)

### 모듈 7 — 배포 + 런칭: P3를 프로덕션으로 (2h)

**7-1 워크트리 통합 → main 머지 (20분)** ⭐♻

**7-2 에이전트 주도 GCP Cloud Run 배포 (35분)** ↩

- 학습목표: 에이전트로 Dockerfile·배포 스크립트를 만들어 Cloud Run에 올린다.
- 시연: DevOps 에이전트 → Dockerfile → `gcloud run deploy`. (Deploy 탭은 **베타/dev-only**이므로 CLI 주도로 진행, 탭은 "곧 정식화될 미리보기"로만 언급)
- 프로젝트: P3 클라우드 배포.
- 핵심 메시지: "배포도 **에이전트가**, 나는 확인만." (구 6-1/6-2 재구성)

**7-3 크론잡 / CI·CD 자동화 (25분)** ↩

- 학습목표: 스케줄러·파이프라인으로 운영을 자동화한다.
- 시연: Cloud Scheduler + GitHub Actions → Cloud Build, PR 머지 자동 배포.
- 프로젝트: P3 자동화.
- 핵심 메시지: "한 번 만들면 **알아서 돈다.**" (구 6-3/6-4 유지)

**7-4 랜딩페이지 + 런칭 체크리스트 (40분)** ↩

- 학습목표: 마케팅 랜딩을 만들고 런칭 점검을 병렬 처리한다.
- 시연: 랜딩 프론트 생성(디자인→코드), 보드에 런칭 체크리스트(도메인/SSL/모니터링/법적페이지) 병렬 카드.
- 프로젝트: **P3 런칭 준비 완료**.
- 핵심 메시지: "코드가 끝이 아니라 **출시가 끝.**" (구 7-1/7-2 유지. ※ 구 'Stitch MCP' 의존은 가용 시에만, 없으면 에이전트 직접 구현으로 대체)

## 4. 촬영 가이드 갱신 포인트 제안

> 대상: `docs/MVP/V3_촬영가이드.md` + `docs/lectures/v3/V3_촬영가이드.md`. 아래는 **갱신 제안 목록**(실제 영상·편집은 U1).

1. **촬영 순서에 '셋업 0부터' 추가**

   - 구 가이드는 모듈 4(메인)부터 라이브로 찍는 순서. 신 강의는 **깨끗한 맥북에서 하네스 설치·CLI 인증·프로젝트 연결(M2)을 실제 0부터** 별도 세션으로 녹화(설치/인증 대기는 타임랩스).
   - 권장 순서: ①M5(P3 메인 라이브, 최장) → ②M3·M4(P1·P2) → ③M1·M2(온보딩/셋업, 깨끗한 환경 필요) → ④M6 → ⑤M7·M8.

2. **화면 레이아웃 도식 교체 (필수)**

   - 구 도식의 `[마블로] Board Code Agents Flows` 4탭 → **실제 탭바**: `가이드 · 보드 · 레인 · 코드 · 에이전트 · 사용량 · 워크트리 · 하네스 · 설정` + 하단 **오케스트레이터 PTY 패널** + **레인 그리드**.
   - 멀티에이전트 장면은 구 "Agents 탭 3개 모델" → **레인 탭에서 Claude·Codex 레인 병렬** 캡처로 교체.

3. **멀티모델 표기 전면 갱신 (필수)**

   - 구 "Claude + Gemini + Codex 동시 스폰", "멀티모델 지원(Claude+Gemini+GPT+Custom)" → **"Claude Code + Codex (+ Antigravity)"**.

   - 구 `V3_촬영가이드.md`의 "AI YouTube 인사이트" 잔재 → 커리큘럼과 일치하도록 **ReachWave(P3)** 로 통일. P1(할 일 웹앱)·P2(날씨 대시보드) 리허설 항목 추가.
