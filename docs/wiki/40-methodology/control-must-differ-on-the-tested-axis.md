# 대조군이 실험군과 다른 축을 건드리는지 먼저 확인하라

> **한 줄 판정**: ★채택 — 실험군에 이미 걸려 있는 것과 **같은 축**을 한 겹 더 얹는 대조 실험은 정보량이 **0** 이다. 그런데 결과가 "그래도 재현됐다"로 나오면 사람은 그것을 **배제 근거로 읽는다.** 실측 1건에서 이 오독이 유력 가설 하나를 **약 이틀** 동안 후보에서 빼놨다.

## 무엇을 물었나

"X를 막았는데도 증상이 재현됐다 → 원인은 X가 아니다"라고 써도 되는가. 어떤 조건에서 이 추론이 성립하고, 어떤 조건에서 무효인가.

## 무엇을 했나

실제로 무효였던 대조 실험 1건을 사후 분해했다. 사건의 수치·명령은 원본에 있고, 여기서는 재사용 가능한 규칙만 뽑는다.

## 결과 (수치)

### 무효였던 실험

| 항목                       | 값                                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------------------- |
| 증상                       | Electron main 프로세스 타이머가 15~17분 지각, 인바운드 12~15시간 끊김                               |
| 의심 가설                  | 프로세스 단위 절전(App Nap 계열)                                                                    |
| 실험군이 이미 들고 있던 것 | `powerSaveBlocker("prevent-app-suspension")` = **IOPM assertion** (`kIOPMAssertionTypeNoIdleSleep`) |
| 대조로 추가한 것           | `caffeinate -dimsu` = **IOPM assertion** (`PreventUserIdleSystemSleep` 외)                          |
| 두 축이 같은가             | ★**같다.** 이미 걸린 층에 같은 층을 한 겹 더 얹었다                                                 |
| 결과                       | "화면 켜 뒀는데도 재현됨"                                                                           |
| 그 결과가 배제한 것        | **없음.** 정보량 0                                                                                  |
| 그런데 실제로 취급된 방식  | "절전은 배제됐다"로 약 이틀간 후보에서 제외                                                         |

### 무엇을 놓쳤나 — 대조가 아예 안 건드린 축

`caffeinate -dimsu` 는 화면을 **켜 두지만 화면 잠금은 막지 못한다.** 화면이 켜진 채로 잠겨 있을 수 있다. 사후에 `loginwindow` 로그를 뜨니 잠금 창이 **14시간 57분**으로 증상 창을 통째로 덮고 있었다 — 대조 실험이 배제했다고 믿어진 축이 실은 **측정된 적조차 없었다.**

표본: 사건 n=1 의 사후 분해다. 통계적 유의성이 아니라 **설계 결함의 구조**가 근거다. 같은 구조는 축이 층으로 갈리는 모든 곳(전원·캐시·권한·네트워크·피처플래그)에서 재현된다.

## 왜

"막았는데도 재현됨"이 배제 근거가 되려면 **대조가 그 축을 실제로 움직였어야** 한다. 축이 안 움직였으면 결과는 가설에 대해 아무 말도 하지 않는다 — 그런데 문장의 **모양**은 배제와 똑같다("X 했는데도 Y"). 사람은 모양을 보고 읽으므로, 무효한 실험이 유효한 반증으로 승격된다. 이게 비싼 이유는 실패가 조용하기 때문이다: 아무도 틀린 값을 보지 않고, 살아 있는 가설 하나가 목록에서 사라질 뿐이다.

여기에 더해, 도구 이름이 축을 가린다. `caffeinate`("잠들지 마라")와 App Nap("프로세스를 재운다")은 **말이 같아 보여서** 층이 다르다는 사실이 눈에 안 띈다.

## 한계 / 정직성

- n=1 이다. 빈도를 주장하지 않는다. 주장하는 것은 "이 구조는 조용히 실패하므로 사전 점검이 싸다"이다.
- 이 노트는 **원 증상의 원인을 규명하지 못했다.** 대조가 무효였다는 것이 곧 가설이 참이라는 뜻은 아니다 — 무효한 실험은 어느 방향으로도 근거가 되지 않는다. 실제로 그 가설(App Nap)은 이후 Apple 문서로 **따로** 약화됐다.
- ★**2026-09-04 후속 실측이 이 노트의 규칙을 양쪽에서 확인했다.** 무효한 대조가 **잘못 배제**했던 절전 가설도, 그 자리를 대신 채웠던 **화면 잠금 가설**도 결국 둘 다 원인이 아니었다(`driftMs` 최대 21ms, `possibleSuspendGap` 0건인 구간에서 증상 재현). 무효한 실험은 어느 방향으로도 근거가 되지 않는다는 것이 요점이지, 무효한 실험이 배제한 쪽이 참이라는 뜻이 아니다 — 이 사건에서는 **양쪽 다 틀렸고 원인은 제3의 축**(폴러의 단일 소비자 계약 위반)에 있었다. 원본 §0-A.
- **수치·명령이 갈리면 원본이 옳다.**

## 실제 영향

방법론 채택. 코드 무변경. 이후 "A를 막았는데도 B가 났다"를 쓰기 전에 아래 세 줄을 먼저 통과시킨다.

| #   | 점검                                                                           | 통과 못 하면               |
| --- | ------------------------------------------------------------------------------ | -------------------------- |
| 1   | 실험군이 그 축에 대해 **이미 무엇을 들고 있나**                                | 대조가 중복이면 정보량 0   |
| 2   | 대조 도구가 실제로 거는 것이 **가설의 축과 같은 층인가** (이름 말고 실제 호출) | 다른 층을 막고 있는 것이다 |
| 3   | 축이 움직였다는 **관측값**이 있나 (`pmset -g assertions` 처럼 OS 에 되물은 값) | 안 움직였을 수 있다        |

셋 중 하나라도 답을 못 하면 결과에 "배제"라고 쓰지 않고 **"판정불가"**로 남긴다 — 기각과 판정불가를 섞지 않는다.
