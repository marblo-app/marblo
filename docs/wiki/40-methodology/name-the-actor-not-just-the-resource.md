# 계수기를 자원 키로만 묶으면 "혼자 계속 진다"와 "우리끼리 싸운다"가 구별되지 않는다

> **한 줄 판정**: ★채택 — 계수기를 **자원**(프로젝트·채널·봇) 키로만 묶으면, 그 자원을 다루는 **행위자가 둘**일 때 둘이 같은 칸에 겹쳐 쓴다. 그래서 "행위자 하나가 외부 경쟁자에게 계속 진다"와 "우리 행위자 둘이 서로를 걷어찬다"가 **완전히 같은 시계열**로 찍힌다. 실측 1건에서 이 모호함이 조사 **3회**를 실측 대신 추론으로 끝냈다. 한 칸(행위자 ID)이면 갈린다.

## 무엇을 물었나

시계열 저널이 이미 있는데도 왜 원인이 안 잡히나. 표본에 무엇이 더 있어야 "관측했다"가 되는가.

## 무엇을 했나

3회 연속 실패한 조사 1건을 사후 분해했다. 저널 필드 목록과, 그 필드들로 **구별 불가능한 두 상태**를 대조했다. 사건의 수치는 원본에 있고 여기서는 재사용 가능한 구조만 뽑는다.

## 결과 (수치)

### 구별되지 않던 두 상태

텔레그램 `getUpdates` 는 봇당 **단일 소비자**다. 소비자가 둘이면 HTTP 409 가 난다. 저널의 모든 필드가 `projectId` 키 하나로만 묶여 있었다.

| 저널이 본 것                     | 상태 A: 우리 루프 1개가 **외부** 경쟁자에게 진다 | 상태 B: 우리 루프 **2개**가 서로를 걷어찬다 |
| -------------------------------- | ------------------------------------------------ | ------------------------------------------- |
| `loopRunning`                    | `true`                                           | `true` (둘 다 등록돼 있진 않아도 true)      |
| `consecutivePollErrors` 단조증가 | ✅                                               | ✅                                          |
| `pollError = http-409`           | ✅                                               | ✅                                          |
| 가끔 성공해 리셋                 | ✅                                               | ✅                                          |
| **구별 가능?**                   | ❌ **불가**                                      | ❌ **불가**                                 |

두 상태는 **고치는 방법이 정반대다**(밖을 찾는다 / 안을 고친다). 그런데 저널로는 안 갈렸다.

### 비용

| 항목                                     | 값                                                     |
| ---------------------------------------- | ------------------------------------------------------ |
| 같은 증상으로 돈 조사                    | **3회** (#1397 · #1406 · 본건)                         |
| 그 조사들이 세운 가설                    | App Nap → 화면 잠금 → "배달 주체와 저널 주체가 다르다" |
| 실측으로 살아남은 가설                   | **0개**                                                |
| 원인 특정에 필요했던 추가 필드           | **1개** (행위자 ID)                                    |
| 그 필드 없이 소비자 중복을 볼 수 있는 곳 | 패킷 캡처뿐                                            |

표본: 사건 n=1 의 사후 분해다. 통계가 아니라 **구조**가 근거다 — 같은 모양은 단일 소비자/단일 리더/단일 라이터 계약을 쓰는 모든 곳(락, 큐 컨슈머, 웹훅, 폴러, 소켓)에서 재현된다.

## 왜

계수기의 키는 **누가 썼는지가 아니라 무엇에 대한 것인지**만 기록한다. 행위자가 하나뿐이라는 가정이 참인 동안에는 이 둘이 같아서 문제가 없다. 그런데 **그 가정이 깨졌는지를 확인하려고 저널을 보는 순간**, 저널은 그 가정을 이미 전제하고 있어서 답을 줄 수 없다. 자기가 검증해야 할 것을 전제로 깔고 있는 관측이다.

게다가 두 행위자가 같은 칸에 쓰면 서로의 흔적을 지운다 — 한쪽의 성공이 다른 쪽의 실패 연속을 리셋해 버려서, 시계열이 실제보다 건강해 보인다.

## 한계 / 정직성

- n=1 이다. 빈도를 주장하지 않는다. 주장하는 것은 "이 모호함은 조용하므로 사전에 한 칸 넣는 것이 싸다"이다.
- 행위자 ID 를 넣는다고 원인이 자동으로 나오지는 않는다. 나오는 것은 **"안이냐 밖이냐"** 한 갈래뿐이다. 그 한 갈래가 이번에 3회를 잡아먹은 갈래였을 뿐이다.
- 본건에서 넣은 계측이 실제로 원인을 지목하는지는 **아직 관측 전이다.** 경로가 존재하고 재현된다는 것까지가 확정이고, 그 경로가 이번 구간을 만들었다는 것은 미확정이다.
- **수치가 갈리면 원본이 옳다.**

## 실제 영향

코드 변경 있음. 폴러의 route health 와 시계열 저널에 행위자 축을 넣었다 — `loopId`(pid + 자원 + 세대), `concurrentLoops`, `loopStarts`, `lastPollLoopId`, `lastDeliveredLoopId`. `concurrentLoops > 1` 이거나 `lastPollLoopId` 가 두 값 사이를 오가면 그게 곧 "안"이고, 둘 다 아니면 "밖"이다. 토큰·chatId·본문은 담지 않는다(pid + 자원키 + 세대번호뿐).

같은 커밋에서 중복 소비자가 생기던 경로도 닫았다: **단일 소비자 가드는 등록 항목이 아니라 자원의 실제 점유 수명을 덮어야 한다.** 은퇴를 요청받은 폴러가 진행 중인 롱폴을 25초까지 계속 물고 있는데 등록에서는 먼저 지워졌고, 그 창에서 두 번째 폴러가 떴다.

앞으로 "단일 X" 계약(단일 소비자·단일 리더·단일 라이터)을 쓰는 곳에서는 두 가지를 같이 확인한다.

| #   | 점검                                                                | 통과 못 하면                          |
| --- | ------------------------------------------------------------------- | ------------------------------------- |
| 1   | 계수기·로그가 **행위자**를 적나, 자원만 적나                        | 위반을 관측할 수 없다 — 추론만 남는다 |
| 2   | 중복 방지 가드가 자원의 **실제 점유 수명**을 덮나, 등록 항목만 덮나 | 등록에서 지워진 뒤에도 점유가 남는다  |
