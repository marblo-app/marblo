# B2B 웹 우선 온보딩 — 새 기능이 아니라 설치·소속 순서 교정

> **한 줄 판정**: ★채택 — 조직 온보딩은 새 전달 메커니즘이 아니라 현행 “설치 먼저, 소속 나중”의 역순을 바로잡는다. 웹에서 수락하면 앱 첫 로그인은 이미 계정 축에 붙어 있으며, 초대 토큰을 다운로드에 싣지 않는다.

## 무엇을 물었나

팀 초대를 받은 사람이 설치 전에 소속과 준비물을 알게 하면서, 개인 다운로드 경로와 익명 설치 축을 훼손하지 않는 방법.

## 결과

- 초대 URL은 조직 슬러그가 아닌 `/join/<난수토큰>`이다. 조직 존재를 노출하지 않고 이메일 결속·피싱 방어를 유지한다.
- 수락 콜러블이 계정 축의 조직/프로젝트 멤버십을 만든다. 같은 계정으로 앱에 로그인하면 서버 착지 규칙이 이를 도출하므로 다운로드 파일·링크백에 토큰을 전달할 이유가 없다.
- 개인 `/download`는 그대로 둔다. 조직 문맥은 한 줄 배너만 더하며, 가이드는 기존 페이지 앵커와 설치 전·팀 작업 진입점으로 충분하다.

### 첫 고객 한 팀의 최소

| 최소 조각 | 범위 |
| --- | --- |
| 웹 화면 3 | 조직 정보, `/join/<token>`, 소속 확인·수락 |
| 콜러블 2 | 초대 해석, 원자적·멱등 수락 |
| 문서 필드 1 | `firstAppLoginAt` |
| 발송 | 메일 인프라 대신 관리자가 **초대 링크 복사** |

이 v0은 Phase 1 조직 뼈대 위의 증분이다. 메일 자동 발송·퍼널 카드·리마인더는 고객이 생긴 뒤 v1 이상으로 미룬다.

## 왜

현행은 초대 메일 배선이 없어 팀원이 앱의 배너를 보려면 먼저 다운로드·설치·로그인해야 한다. 웹 선행은 화면을 늘려서가 아니라, 설치 후 발견되는 소속 문제와 준비 없는 설치 이탈을 앞에서 없앤다. 사람별 설치 파일은 정적 릴리스 자산과 익명/계정 축 분리 모두에 맞지 않는다.

## 한계 / 정직성

- 외부 실사용 팀은 아직 0이다. 이 노트는 첫 팀을 받기 위한 설계이지 전환율 실측이 아니다.
- 설치 링크백은 익명 축으로 계속 돈다. 웹을 거쳤다고 사람 축 조인이 자동으로 생기지는 않는다.
- 슬러그는 Phase 5의 고객 요구가 생길 때까지 우선순위를 올리지 않는다.

## 실제 영향

문서 변경만. 앱 안 초대 배너도 레거시·개인 협업 경로를 위해 유지한다.
