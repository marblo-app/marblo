# 2026-09-01 착지분 — 무엇이 배포됐고 무엇이 아직인가

> **한 줄 판정**: ★하루에 B2B 조직 층이 **만들 수 있는 상태**까지 왔다 — 요금제 게이트·좌석 강제·조직 생성·초대 이관·조직 롤업·성공률 각인이 전부 배포됐다. 다만 **고객 조직 인스턴스는 0건**이고, 배선의 존재를 고객의 존재로 읽으면 안 된다.

## 무엇을 물었나

다음 오케가 이 세션을 이어받을 때, 오늘 무엇이 실제로 프로덕션에 나갔고 무엇이 아직인지.

## ★함정 — 다음 오케가 반드시 알아야 할 것

1. **`firebase deploy` 는 `npx firebase-tools@13` 으로 하라.** brew 의 `firebase-cli` 15.28.2 는 `deploy` 명령이 1초 만에 SIGKILL 로 즉사한다(`functions:list` 는 되는데 `deploy --help` 조차 죽는다).
2. **`v3/functions/.env.marblo-2253d` 는 배포본에서 복구한 26키다.** 원본이 이 기기에서 사라져 있었고 백업도 없었다. ★가드(`check:deploy-env`)는 3개만 검사하므로, 손으로 3키짜리 파일을 만들면 나머지 23개(GitHub App 개인키·포트원 채널키·Resend·텔레그램)가 조용히 날아간다.
3. **BQ 날짜 파라미터에 `types: {…: "DATE"}` 를 쓰지 마라.** `@google-cloud/bigquery` 8.3.1 이 STRING 값에 DATE 타입을 명시하면 파라미터를 조용히 NULL 로 바인딩한다 — `day >= NULL` → 0행, 에러 없음. 팀 사용량 화면이 이것 때문에 계속 빈칸이었다(수정 후 362행).
4. **rules 변경은 CI 가 검증하지 않는다.** 워크플로우 어디에도 `test:rules` 가 없다. 로컬에서 돌려야 한다 — `nvm use 20` + JDK 17 + `npx --yes firebase-tools@13 emulators:exec --only firestore "npx vitest run --config vitest.rules.config.mjs"`. 기준선 **361 케이스**.
5. **순서 제약**: 초대 콜러블 이관 → 릴리스 도달 → **그 다음에** rules 조이기. `invitations` create 를 rules 에서 먼저 막으면 구버전 앱(사용자에게 나간 최신은 v3.0.35) 사용자의 초대가 통째로 죽는다.

## 아직 아닌 것

- **고객 조직 0건** — `organizations`·`org_members`·`org_teams`·`org_projects`·`orgInvitations` 전부 0. 화면은 있으나 아무도 안 만들었다.
- **Phase 3**(멤버 × 모델 드릴다운) 미착수. Phase 1·2 와 병렬 가능하다.
- **사람 축 모수 2~4명** — 배선은 100%다(08-30 이후 이벤트 전량에 `userKey` 각인). 늘리는 건 베타 홍보 영역이다.
- **`task_outcomes.userKey` T0 = 2026-09-01 배포 시각.** 그 이전 1,845행은 영영 사람 축으로 안 붙는다(forward-only).

## 한계 / 정직성

- 배포 시각은 이 세션의 배포 로그 기준이다. 수치가 갈리면 라이브 조회가 옳다.
- 조직 대시보드는 조직이 0건이라 **빈 상태만 확인됐다.** 실수치 검증은 첫 조직이 생긴 뒤다.
