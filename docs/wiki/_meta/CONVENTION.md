# 위키 규약

규범 원본은 **위키 시스템 사양서**다. 위치는 아래 값 절에 있다. 갈리면 사양서가 옳다.

이 문서가 하는 일은 두 가지뿐이다.

1. 사양서가 **프로젝트에 위임한 값**을 채운다 — 아래 "프로젝트가 채우는 값" 절 하나.
2. 사양서에 **없는 조항**을 규정한다 — 위키 규약이 어디까지 적용되는가(제작물 경계)와 그 경계를 넘는 정직성 조항.

그 밖의 규칙은 여기서 다시 쓰지 않는다. 같은 규칙을 두 곳에 적으면 반드시 갈리고, 갈린 규범은 아무도 안 믿는다.

## 사양서가 정하는 것 — 여기서 재서술하지 않는다

| 무엇                                                               | 어디                       |
| ------------------------------------------------------------------ | -------------------------- |
| 불변 규칙 5                                                        | 사양서 §5                  |
| frontmatter 5필드·순서·`status` 값                                 | §2.1                       |
| 자체완결 기준 R1~R6                                                | §2.2                       |
| 원본 무변경 P1~P6 (복사 + 링크만, 원장 읽기 전용)                  | §2.3                       |
| 정직성 — 기각을 지우지 않는다, "기각"과 "판정불가"를 섞지 않는다   | §2.4                       |
| 태그 네임스페이스와 판정 4값                                       | §2.6 · [[TAXONOMY]]        |
| 슬러그 링크 문법 · 슬러그 전역 유일 · README 예외                  | §1.4 · §3.1                |
| Backlinks 대칭 · 링크 등록부 5절                                   | §3.2 · §3.3 · [[LINK-MAP]] |
| 도구 소유 파일(`index.md` `log.md` `MEMORY.md`) · `root_path` 고정 | §3.5                       |
| 린트 코드와 심각도                                                 | [[LINT]]                   |

## 프로젝트가 채우는 값

★**낯선 저장소에 이 문서를 복사했을 때 고칠 곳은 이 절 하나다.** 아래는 이 저장소의 현재 값이자 채워진 예시다.

| 채울 것               | 이 저장소의 값                                                                                                                        |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 규범 원본 사양서      | [docs/WIKI_system/WIKI-SYSTEM.md](../../WIKI_system/WIKI-SYSTEM.md)                                                                   |
| 위키 루트             | `docs/wiki/` **하나**. 형제 프로젝트(마케팅·강의)는 자기 위키를 만들지 않고 여기를 참조한다                                           |
| 위키 도구 `root_path` | `<repo>/docs/wiki`                                                                                                                    |
| 원본이 어디 있나      | `docs/*.md` · `v3/docs/` · `docs/lectures/`. 노트 `## Evidence` 가 상대경로로 가리킨다                                                |
| 읽기 전용 원장        | 포지셔닝 SSoT 는 [v3/docs/CONTROL-PLANE.md](../../../v3/docs/CONTROL-PLANE.md). 번호 조항 단일 원장은 없고, 위키 노트가 결론의 집이다 |
| 제작물이 어디 있나    | `docs/lectures/` · `marblo-web` 카피 · 공개 README · 고객·수강생용 문서                                                               |

### 6개 도메인 슬롯에 무엇을 담나

슬롯 번호와 역할은 사양서 §1.2 가 고정한다. 프로젝트가 정하는 것은 폴더 이름과 **무엇을 담느냐**뿐이다.

| 슬롯      | 폴더                | 이 저장소가 담는 것                                                             |
| --------- | ------------------- | ------------------------------------------------------------------------------- |
| 00 기반   | `00-foundations`    | 스택(Electron/Firestore/MCP/식별자) **그리고** 강의·마케팅이 쓰는 포지셔닝 어휘 |
| 10 주력   | `10-offerings`      | 지금 제공하는 실물 — 제품 **그리고** 커리큘럼, 살아 있는 GTM/SEO                |
| 20 제약   | `20-constraints`    | GUI 검증 금지, 시크릿, 축 순도, 인용 금지 카피                                  |
| 30 탐구   | `30-investigations` | 판정이 남는 시도 — 제품 PoC, 강의 A/B, 카피 실험                                |
| 40 방법론 | `40-methodology`    | 무엇을 근거로 믿나                                                              |
| 50 운영   | `50-operations`     | 배포·CI·인시던트 **그리고** 강의 한 회차 로그, 캠페인 결과, 고객 이슈           |

10 과 50 이 헷갈리면: **10 = 제공하는 것, 50 = 바깥에 부딪힌 결과.** 커리큘럼의 주장은 10, "3회차에서 학생 n명이 X에서 막혔다"는 50.

## 제작물 경계

사양서의 노트 규약(R1~R6, `## Evidence` / `## Backlinks`)은 **위키 안의 판정 노트**에만 적용된다. 위키 밖 독자용 문서에 그대로 적용하면 독자가 읽을 수 없는 문서가 나온다.

|      | (A) 판정 노트                                                                                 | (B) 제작물                                |
| ---- | --------------------------------------------------------------------------------------------- | ----------------------------------------- |
| 어디 | 위키 루트 안                                                                                  | 위키 밖 — 위 값 절의 "제작물이 어디 있나" |
| 독자 | 다음 에이전트와 미래의 우리                                                                   | 우리를 감사하러 오지 않은 사람            |
| 형식 | 사양서 R1~R6 그대로. "무엇을 조사했나 → 무엇을 판정했나 → 근거 → 한계"가 작업을 이어받게 한다 | 아래 표                                   |

제작물은 독자가 써야 할 본문을 먼저 쓴다. 내부 감사 장부가 필요하면 제작물 본문이 아니라 티켓, PR, 위키 판정 노트, 또는 문서 끝 부록 한 곳으로 보낸다.

| 항목            | 제작물 규칙                                                                          | 안 지키면 깨지는 것                                                    |
| --------------- | ------------------------------------------------------------------------------------ | ---------------------------------------------------------------------- |
| `파일:줄` 근거  | 본문 문장이나 모듈 표에 박지 않는다. 꼭 필요하면 문서 끝 `부록: 근거` 한 곳에 모은다 | 독자가 읽어야 할 문장이 내부 좌표로 끊겨 제작물이 감사 로그처럼 읽힌다 |
| "확인 못 한 것" | 방어 섹션으로 넣지 않는다. 모르면 쓰지 않거나 별도 티켓으로 올린다                   | 독자가 제품 대신 우리의 변명을 읽는다                                  |
| "한 줄 판정"    | 해당 없다. 제목·리드·요약은 독자 가치와 행동을 말한다                                | 첫 화면이 독자에게 쓸모없는 내부 결론으로 채워진다                     |

## 위키 안의 노트 종류

사양서 §2.1은 frontmatter를 정확히 5필드로 고정한다. 따라서 이 프로젝트는 필드를
늘리지 않고 사양서가 허용한 태그 축으로 종류를 적는다: `kind/knowledge`,
`kind/archive`. 이 값은 프로젝트 위임값이며, 5필드·순서나
R1~R6을 바꾸는 사양서 개정이 아니다. 기존 노트는 전면 이주 전까지 미분류로 남길 수
있고 린터가 경고만 낸다.

| 종류        | 첫 화면                | 필수 섹션                                     | 쓰는 때                                                |
| ----------- | ---------------------- | --------------------------------------------- | ------------------------------------------------------ |
| `knowledge` | 지금 참인 사실·값·절차 | `지금 무엇이 참인가`, `Evidence`, `Backlinks` | 주제 하나의 현재 지식. 새 사실이 오면 이 노트를 고친다 |
| `archive`   | 조사 당시의 근거       | `Evidence`, `Backlinks`                       | 지식 노트의 Evidence가 가리키는 측정·실험·실패 기록    |

조사 기록은 버리지 않되 표면 탐색의 목적지가 아니다. `archive/` 아래에 두고 지식 노트가
현재 주장에 필요한 기록만 Evidence로 가리킨다. 한 주제에 조사 노트를 계속 늘리는 대신
`knowledge` 하나를 현재 정본으로 유지한다.

제목의 정본은 frontmatter `title`이다. H1은 같은 문장을 되풀이하지 않는다. MCP 위키
유지보수 도구의 인덱스와 질의 제목은 파일 경로 슬러그를 읽으므로 H1을 빼도 인덱스가
깨지지 않는다.

### 정직성의 경계: 필수 사실과 방어 섹션

**다음 사람이 현재 값을 해석·재현·안전하게 적용하는 데 필요한 제약 또는 관측 공백은
사실로 본문에 남긴다.** 값이 왜 나오지 않는지, 어느 축만 측정되는지, 어떤 조건에서
절차가 통하지 않는지는 그 사람이 행동을 바꾸게 하므로 `측정 가능성`·`적용 조건`처럼
구체적인 이름 아래 쓴다.

반대로 **현재 정본의 해석이나 다음 행동을 바꾸지 않고, 이미 고쳐진 과거 오기·승인
경위·자기방어만 설명하는 문단은 본문 방어 섹션이 아니다.** 삭제하지 말고 노트 끝
`## 이력` 한 곳에 날짜·무엇이 바뀌었는지·재발 방지 단서를 보존한다. 이력은 사실을
숨기는 곳이 아니라 현재값과 경쟁하지 않게 과거 사실을 보존하는 곳이다.

## 정직성은 경계를 넘는다

**없는 화면·없는 기능을 "있다" 또는 "곧 된다"로 쓰지 않는다.** 판정 노트든 제작물이든 같다. 이것은 위키 형식이 아니라 정직성이다. 방어 섹션을 지우는 것과 거짓말을 허용하는 것을 섞지 않는다.
