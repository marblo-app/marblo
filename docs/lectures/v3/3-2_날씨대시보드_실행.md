## 도입 (3분)

지난 섹션에서 `/tf-plan`으로 6개 태스크를 만들었죠? 이제 진짜 재미있는 부분입니다. 에이전트를 스폰해서 이 태스크들을 실행시키는 거예요.

화면: 마블로 워크스페이스 — 칸반 보드에 6개 태스크 카드가 TODO 상태

여러분이 할 일은 단 하나 — `/tf-start` 명령 하나면 됩니다. 나머지는 에이전트들이 자동으로 처리합니다. 코드 작성, 파일 생성, 테스트까지요.

하지만 그냥 시작만 해놓고 기다리는 게 아닙니다. **어떻게 진행되는지 관찰하는 것** 자체가 이 섹션의 핵심이에요. 에이전트가 어떤 순서로 일하는지, 칸반 보드가 어떻게 변하는지, 터미널에 뭐가 출력되는지 — 이걸 눈으로 확인해야 나중에 큰 프로젝트에서도 자신 있게 PM 역할을 할 수 있습니다.

---

## 본문

### 태스크 일괄 생성 — `create_tasks_bulk` (5분)

먼저 `/tf-plan`에서 만든 태스크들을 마블로 시스템에 등록해야 합니다.

화면: 마블로 터미널 패널

**(실습)** 터미널에 다음을 입력하세요:

```bash
/tf-start
```

이 명령이 내부적으로 하는 일은 두 가지입니다:

1. **`create_tasks_bulk`** — 6개 태스크를 한 번에 생성
2. **에이전트 자동 스폰** — 태스크 유형에 맞는 에이전트를 자동 배치

화면: 칸반 보드에 6개 카드가 한꺼번에 생성되는 모습

```
✅ 6 tasks created:
  [TASK-001] 날씨 API 프록시 엔드포인트     → TODO
  [TASK-002] 즐겨찾기 도시 저장 API         → TODO
  [TASK-003] 도시 검색 UI                   → TODO (blocked: TASK-001)
  [TASK-004] 날씨 카드 컴포넌트             → TODO (blocked: TASK-001)
  [TASK-005] 5일 예보 차트                  → TODO (blocked: TASK-004)
  [TASK-006] API 연동 테스트                → TODO (blocked: TASK-003, 005)
```

여기서 `blocked`라고 표시된 태스크들 보이시죠? 의존성이 있는 태스크는 아직 시작할 수 없습니다. TASK-001이 완료되어야 TASK-003, 004가 시작 가능해지는 거예요.

이게 마블로의 **의존성 관리** 기능입니다. 에이전트가 알아서 순서를 지켜서 작업하죠.

### 에이전트 자동 스폰 관찰 (5분)

화면: 터미널 패널에 에이전트 스폰 로그가 표시되는 모습

태스크가 등록되면 마블로가 에이전트를 자동으로 스폰합니다:

```
🤖 Spawning agents...
  [Agent-Backend]   → assigned: TASK-001
  [Agent-Frontend]  → standby (waiting for dependencies)

📋 Agent Status:
  Backend Agent   : WORKING on TASK-001
  Frontend Agent  : IDLE (blocked tasks only)
```

지금 단계에서 일할 수 있는 태스크는 TASK-001밖에 없으므로, **Backend Agent 하나만 활성화**됩니다. Frontend Agent는 대기 상태예요.

이 부분이 중요합니다 — 마블로는 무작정 모든 에이전트를 돌리지 않아요. **의존성을 파악해서 필요한 에이전트만 활성화**합니다. 비용도 아끼고, 충돌도 방지하는 거죠.

### 백엔드 에이전트 작업 과정 관찰 (7분)

자, 이제 Backend Agent가 TASK-001을 작업하는 과정을 실시간으로 지켜봅시다.

화면: 터미널 패널 — Backend Agent 로그 스트리밍

에이전트가 하는 일을 단계별로 보면:

**1단계 — 태스크 클레임:**

```
[Backend Agent] Claiming TASK-001: 날씨 API 프록시 엔드포인트
[Backend Agent] Status: TODO → IN_PROGRESS
```

칸반 보드에서 TASK-001 카드가 TODO에서 IN_PROGRESS 열로 이동합니다.

화면: 칸반 보드 — TASK-001 카드가 IN_PROGRESS로 이동

**2단계 — 코드 작성:**

```
[Backend Agent] Creating backend/app/routers/weather.py
[Backend Agent] Adding OpenWeatherMap API integration...
[Backend Agent] Creating Pydantic models for weather response...
```

에이전트가 실제로 파일을 만들고 코드를 작성하는 과정이 터미널에 실시간으로 출력됩니다. 여기서 잠깐 코드를 살펴볼까요:

```python
# backend/app/routers/weather.py
from fastapi import APIRouter, HTTPException
import httpx

router = APIRouter(prefix="/api/weather", tags=["weather"])

OPENWEATHER_BASE = "https://api.openweathermap.org/data/2.5"

@router.get("/{city}")
async def get_current_weather(city: str):
    """도시의 현재 날씨를 반환합니다."""
    async with httpx.AsyncClient() as client:
        resp = await client.get(
            f"{OPENWEATHER_BASE}/weather",
            params={"q": city, "appid": settings.OPENWEATHER_API_KEY, "units": "metric"}
        )
        if resp.status_code != 200:
            raise HTTPException(status_code=resp.status_code, detail="날씨 데이터 조회 실패")
        return resp.json()

@router.get("/{city}/forecast")
async def get_forecast(city: str):
    """도시의 5일 예보를 반환합니다."""
    async with httpx.AsyncClient() as client:
        resp = await client.get(
            f"{OPENWEATHER_BASE}/forecast",
            params={"q": city, "appid": settings.OPENWEATHER_API_KEY, "units": "metric"}
        )
        if resp.status_code != 200:
            raise HTTPException(status_code=resp.status_code, detail="예보 데이터 조회 실패")
        return resp.json()
```

이런 코드를 에이전트가 자동으로 생성하는 겁니다. FastAPI 라우터, Pydantic 모델, 에러 핸들링까지 다 포함되어 있죠.

**3단계 — 활동 기록 + 상태 변경:**

```
[Backend Agent] Activity: "날씨 API 엔드포인트 구현 완료 (GET /api/weather/{city}, GET /api/weather/{city}/forecast)"
[Backend Agent] Status: IN_PROGRESS → REVIEW
```

칸반 보드에서 TASK-001이 REVIEW 열로 이동합니다.

화면: 칸반 보드 — TASK-001이 REVIEW로 이동, TASK-003과 004가 TODO로 활성화

그리고 여기서 중요한 변화가 일어납니다 — TASK-001이 완료되자마자, TASK-003(도시 검색 UI)과 TASK-004(날씨 카드 컴포넌트)의 blocked 상태가 풀립니다! 이제 Frontend Agent가 일을 시작할 수 있어요.

```
[Frontend Agent] Dependencies resolved for TASK-003, TASK-004
[Frontend Agent] Claiming TASK-004: 날씨 카드 컴포넌트
```

보이시죠? **의존성이 자동으로 해소되면서 다음 태스크가 활성화**되는 겁니다. 이게 마블로의 핵심 메커니즘이에요.

### 워크스페이스 전체 화면 설명 (5분)

화면: 마블로 워크스페이스 전체 — 칸반 + 터미널 + 에디터 패널

자, 잠깐 화면 전체를 보겠습니다. 마블로 워크스페이스는 하나의 화면에 모든 정보가 나와요:

**왼쪽 — 칸반 보드:**

- TODO, IN_PROGRESS, REVIEW, DONE 열
- 각 카드에 에이전트 아바타, 태스크 제목, 상태 표시
- 의존성 관계가 선으로 연결

**오른쪽 위 — 터미널 패널:**

- 에이전트별 로그가 탭으로 분리
- 실시간 작업 내용 스트리밍

**오른쪽 아래 — 파일 변경 내역:**

- 에이전트가 생성/수정한 파일 목록
- 클릭하면 diff 확인 가능

이 세 영역을 동시에 보면서 프로젝트 진행 상황을 파악할 수 있습니다. 이게 마블로가 "단일 화면 워크스페이스"를 추구하는 이유예요 — 여러 창을 왔다갔다 할 필요가 없거든요.

## 정리

이번 섹션에서 관찰한 핵심 포인트:

1. **`/tf-start` 한 줄**이면 태스크 생성 + 에이전트 스폰이 동시에 일어난다
2. **의존성 관리**: blocked 태스크는 선행 태스크가 끝나야 활성화된다
3. **에이전트 자동 배치**: 필요한 에이전트만 활성화되어 효율적으로 동작한다
4. **실시간 관찰**: 칸반 보드 카드 이동 + 터미널 로그로 전체 진행 상황을 파악할 수 있다

다음 섹션에서는 여러분이 직접 PM으로서 에이전트의 작업을 리뷰하고, 승인하거나 수정을 요청하는 과정을 해봅니다.
