# 에이전트 재활용 · 정리 · 멀티윈도우

> 모듈 6 · 섹션 6-3 · 약 25분
> 관련: [[6-2_dispatch_스코어링_자동배정]] | [[6-4_사용량탭_비용추적최적화]]

---

## 이 강의에서 다루는 것

- **학습목표:** 일을 끝낸 에이전트를 **재활용(reuse)**하고 불필요한 에이전트를 **정리(cleanup)**하는 운영 습관을 익히고, **멀티윈도우**로 두 프로젝트(P2·P3)를 동시에 굴리는 법을 배운다.
- **시연할 마블로 화면·기능:** 에이전트 탭(reuse·cleanup) + 멀티윈도우(File → New Window).
- **진행할 프로젝트 단계:** **P2 + P3 병행** — 끝난 P2 날씨 대시보드와 진행 중인 P3 콜드메일 SaaS를 한 책상에서.
- **핵심 메시지:** "에이전트는 **재활용**, 프로젝트는 **창으로 분리.**"

---

## 도입 — 에이전트가 쌓인다 (3분)

스프린트를 몇 번 돌리면 에이전트 탭이 슬슬 복잡해집니다. 일을 끝낸 에이전트, 한 번 쓰고 멈춘 에이전트, 지금도 도는 에이전트가 뒤섞이죠.

> 화면: 에이전트 탭 — working / idle 카드가 10개 넘게 쌓인 그리드

여기서 두 가지 운영 기술이 필요합니다.

1. **재활용** — 끝나서 놀고 있는(idle) 에이전트에게 **새 일을 다시 시킨다.** 매번 새로 띄우지 않는다.
2. **정리** — 더는 안 쓸 에이전트를 **한 번에 치운다.** 화면도, 리소스도 가볍게.

그리고 프로젝트가 둘 이상이면 — 끝난 P2를 보면서 P3를 이어가야 한다면 — **멀티윈도우**로 둘을 깔끔하게 분리합니다. 이번 섹션은 이 세 가지, **운영의 기술**입니다.

---

## 본문

### 1. 재활용(reuse) — 띄운 에이전트를 다시 쓴다 (6분)

> 화면: 에이전트 탭 — idle 상태의 Codex 카드에 새 지시를 보내는 모습

에이전트를 새로 spawn 하는 건 공짜가 아닙니다. 프로세스를 띄우고, 워크트리를 붙이고, 컨텍스트를 다시 잡는 시간이 듭니다. 그런데 방금 프론트 태스크를 끝내고 **idle로 놀고 있는 Codex**가 이미 있다면? 그 친구에게 다음 일을 주면 됩니다.

이게 **재활용(reuse)**입니다. 마블로에서는 두 가지 경로로 일어나요.

- **자동** — 6-2의 dispatch 스코어링이 **재사용을 우대**합니다. 새 spawn 보다 idle 에이전트 재사용에 가산점을 줘서, 적합한 idle 에이전트가 있으면 자동으로 그쪽에 일이 갑니다.
- **수동/오케 주도** — 오케스트레이터가 `reuse_agent`로 기존 idle 에이전트에게 새 지시를 보냅니다. 이때 **보드의 태스크를 그 에이전트에 다시 묶어서**, 칸반에 "누가 이 일을 하는지"가 정확히 반영됩니다.

> 💡 재활용의 이점은 셋입니다 — **빠르고**(spawn 대기 없음), **싸고**(프로세스·토큰 절약), **맥락이 이어집니다**(같은 에이전트가 비슷한 일을 연달아 하면 더 정확). 그래서 "끝났으니 죽이고 새로 띄우자"보다 "idle을 다시 쓰자"가 기본값이에요.

### 2. 정리(cleanup) — 안 쓰는 에이전트를 치운다 (5분)

> 화면: 에이전트 탭 — 상단 우측 "정리 (N)" 버튼

재활용해도 결국 **더는 안 쓸 에이전트**가 남습니다. 스프린트가 끝났거나, 실험삼아 띄운 카드들이죠. 이걸 하나씩 지우는 건 번거롭습니다.

에이전트 탭에는 **정리(cleanup) 버튼**이 있습니다. 동작은 명확해요.

```
정리 버튼 = working(작업 중)이 아닌 에이전트를 한 번에 제거
  - idle, 멈춘 카드, 끝난 셸 터미널 → 일괄 정리 대상
  - working 상태 에이전트 → 절대 건드리지 않음 (안전)
```

버튼에는 정리될 개수가 `정리 (3)`처럼 표시되고, 누르면 **확인 창**이 한 번 뜹니다. 그래서 실수로 돌고 있는 작업을 날릴 일은 없어요 — **working은 보호**되니까요.

> ⚠️ 정리는 "지금 일하는 에이전트는 빼고, 노는 것만 치운다"가 핵심입니다. 스프린트 도중에 눌러도 진행 중인 작업은 안전합니다. 다만 idle이어도 **곧 재활용할 생각이면 남겨두세요** — 치우면 다음에 새로 spawn 해야 합니다.

**운영 리듬**으로 정리하면 이렇습니다.

```
스프린트 진행 중 → idle 에이전트는 재활용 (reuse)
스프린트 종료 후 → 정리(cleanup)로 한 번에 비우기
```

### 3. 멀티윈도우 — 프로젝트를 창으로 분리 (8분)

> 화면: 두 개의 마블로 창 — 왼쪽 P2(날씨 대시보드), 오른쪽 P3(콜드메일 SaaS)

이제 진짜 새 기능입니다. 프로젝트가 둘 이상일 때, 한 창에서 프로젝트를 왔다 갔다 하면 헷갈립니다. P2 보드를 보다가 P3 에이전트를 보려고 전환하면, 방금 보던 맥락이 사라지죠.

마블로는 **멀티윈도우**를 지원합니다.

```
File → New Window  (단축키: Cmd/Ctrl + Shift + N)
```

새 창을 열고 거기서 **다른 프로젝트를 선택**하면, 두 창이 **독립적으로** 굴러갑니다.

- **창 A** — P2 날씨 대시보드: 보드·에이전트·터미널이 P2 것만
- **창 B** — P3 콜드메일 SaaS: 보드·에이전트·터미널이 P3 것만

핵심은 **이벤트가 창별 프로젝트로 격리**된다는 점입니다. 창 B에서 spawn 한 에이전트의 상태 변화·로그는 **창 B에만** 뜨고, 창 A를 오염시키지 않아요. 각 창은 자기 프로젝트를 main에 등록해서, "이 PTY 이벤트가 어느 창 것인지"를 정확히 가립니다.

> 💡 비유하자면 **모니터를 두 대 쓰는 것**과 같습니다. 한 화면에서 탭을 휙휙 바꾸는 대신, P2는 왼쪽 창에, P3는 오른쪽 창에 펼쳐두고 **동시에** 봅니다. 끝난 P2의 결과를 곁눈질하면서 P3를 이어가는 거죠.

**(실습)** 직접 해봅시다.

```
1. 지금 창에서 P3(콜드메일 SaaS)를 보고 있다.
2. Cmd/Ctrl + Shift + N → 새 창이 뜬다.
3. 새 창에서 프로젝트를 P2(날씨 대시보드)로 전환.
4. 두 창을 나란히 배치 → P2·P3를 한 책상에서 동시 운영.
```

이제 두 프로젝트의 에이전트가 **서로 간섭 없이** 각자의 창에서 일합니다. 한쪽에서 정리(cleanup)를 눌러도 다른 창의 작업은 멀쩡해요 — 프로젝트가 창으로 갈렸으니까요.

### 4. 세 기술을 묶으면 (3분)

> 화면: 슬라이드 — reuse · cleanup · multi-window 운영 루프

오늘의 세 기술은 따로 노는 게 아니라 **하나의 운영 습관**입니다.

```
프로젝트별로 창을 연다 (multi-window)
   └ 각 창 안에서:
       일이 생기면 → idle 에이전트 재활용 (reuse)
       스프린트 끝 → 노는 에이전트 정리 (cleanup)
```

여러 프로젝트를 굴리는 PM이라면 이 루프가 몸에 배어야 합니다. **창으로 나누고, 안에서 재활용하고, 끝나면 치운다.** 이게 마블로를 여러 프로젝트로 확장하는 기본기예요.

---

## 정리 (1분)

1. **재활용이 기본값.** idle 에이전트에게 새 일을 준다(reuse) — 빠르고·싸고·맥락이 이어진다. dispatch 스코어링도 재사용을 우대한다.
2. **정리는 working을 보호한다.** "정리" 버튼은 작업 중이 아닌 에이전트만 일괄 제거하고, 확인 창이 한 번 뜬다.
3. **프로젝트는 창으로 분리.** File → New Window(Cmd/Ctrl+Shift+N)로 P2·P3를 독립 창에서 동시 운영, 이벤트는 창별 프로젝트로 격리.
4. **운영 루프:** 창으로 나누고 → 안에서 재활용하고 → 끝나면 정리한다.

다음 섹션에서는 이렇게 굴린 에이전트들이 **토큰과 비용을 얼마나 썼는지** — 사용량 탭에서 실측으로 봅니다.
