# 커스터마이즈 — 스킬 파일 · 상태 · 하네스

> 모듈 8 · 섹션 8-3 · 약 20분
> 관련: [[8-2_Ralph_반복자동화]] | [[8-4_베타미리보기_확장_마무리]]

---

## 이 강의에서 다루는 것

- **학습목표:** 에이전트의 **행동을 파일 한 장으로 바꾸는** 커스터마이즈 세 가지 — 역할 스킬 파일 편집, 커스텀 칸반 상태, 하네스에서 MCP 추가 — 를 익힌다.
- **시연할 마블로 화면·기능:** 코드 탭(스킬 파일 편집) + 보드(커스텀 상태) + 하네스 탭(MCP 추가).
- **진행할 프로젝트 단계:** **팀 규칙 튜닝** — 우리 팀에 맞게 에이전트 행동을 조정.
- **핵심 메시지:** "에이전트의 행동은 **파일 한 장**으로 바뀐다."

---

## 도입 (3분)

지금까지 마블로를 "주어진 대로" 써왔습니다. backend·frontend·test 역할이 있고, 칸반 상태는 TODO→DONE이고, MCP 도구는 정해진 게 깔려 있고.

> 화면: 슬라이드 — "이걸 전부 바꿀 수 있다"

그런데 이건 전부 **여러분이 고칠 수 있는 것**들입니다. 에이전트가 어떻게 행동할지, 칸반이 어떤 단계를 거칠지, 에이전트가 어떤 도구를 쓸지 — 코드를 몰라도 바꿀 수 있어요. 이번 섹션은 마블로를 **우리 팀에 맞게 길들이는** 세 가지 손잡이를 다룹니다.

먼저 짚을 게 하나 있습니다. 마블로에는 비슷해 보이는 두 종류의 "스킬"이 있는데, 헷갈리면 안 됩니다.

- **슬래시 스킬** — PM(여러분)이 쓰는 명령. `/tf-start`, `/tf-review` 같은 것. `.claude/commands/` 폴더의 Markdown 파일이고, "어떤 MCP 도구를 어떤 순서로 호출하라"는 **프롬프트 템플릿**입니다. 파일 이름이 곧 명령어 이름(`tf-start.md` → `/tf-start`)이에요. 코드가 아니라 자연어 지시라, 필요하면 직접 만들 수도 있습니다(`.claude/commands/my-cmd.md` → `/my-cmd`).
- **에이전트 스킬 파일** — 에이전트가 스폰될 때 읽는 **행동 규칙**. 오늘 우리가 주로 손볼 건 이쪽입니다.

---

## 본문

### 1. 역할 스킬 파일 — 에이전트의 행동 규칙 (8분)

> 화면: 코드 탭 — skills/ 폴더

에이전트가 스폰되면 가장 먼저 하는 일이 자기 역할의 스킬 파일을 읽는 겁니다.

```
get_agent_skill("backend")  → skills/backend_agent.md 내용을 읽음
```

이 파일에는 그 역할이 **어떻게 행동해야 하는지** — 역할 선언, 기술 스택, 쓸 수 있는 MCP 도구, 코딩 규칙, 건드릴 수 있는 파일 범위(Scope), 자율 작업 루프 — 가 전부 들어 있습니다. 핵심은 이게 **그냥 Markdown**이라는 점이에요. 코드가 아닙니다. 누구나 열어서 한 줄 고치면 에이전트 행동이 바뀝니다.

대표적인 `backend_agent.md`의 골격을 보면:

```markdown
# Backend Agent 스킬 (v3)

## 역할

너는 Marblo v3의 백엔드 개발 에이전트다. ...

## 기술 스택

- TypeScript (strict mode) / Node.js / Firebase ...

## 코딩 규칙

- `strict: true` 준수 — any 타입 금지
- async/await 패턴 (콜백 금지)

## Scope 규칙

- `v3/electron/`, `v3/src/services/` 만 수정
- API 키·시크릿 하드코딩 금지

## 자율 작업 루프 (필수)

1. get_agent_skill("backend") → 스킬 숙지
2. claim → IN_PROGRESS → 구현 → submit_for_review → 다음 태스크
```

`"너는 ~다"`로 시작하는 역할 선언이 정체성을 부여하고, 기술 스택이 "Python으로 할까?" 같은 고민을 없애고, Scope 규칙이 에이전트 간 충돌을 막습니다.

**(실습) "테스트 없이 코드 작성 금지" 규칙 추가**

`backend_agent.md`의 코딩 규칙 아래에 한 블록을 추가해 봅시다.

```markdown
### 테스트 의무 규칙 (추가!)

- 모든 함수에 대해 단위 테스트를 먼저 작성한다 (TDD)
- 테스트 파일은 `__tests__/` 폴더에 둔다
- 테스트 프레임워크: vitest
- 테스트 없이 submit_for_review 하지 말 것
- add_activity 에 테스트 결과("3/3 통과")를 반드시 포함
```

이 규칙을 넣은 뒤 에이전트를 스폰하면:

- 에이전트가 `get_agent_skill("backend")`로 이 파일을 읽고
- 코드를 짜기 **전에** 테스트를 먼저 작성하고
- `add_activity`에 "테스트 통과: 3/3" 같은 기록을 남깁니다

한 블록을 추가했을 뿐인데 에이전트의 작업 순서가 바뀐 거예요.

**(실습) 다른 스택으로 갈아끼우기**

Django + Vue 프로젝트를 하고 싶다면, 기술 스택 섹션만 바꾸면 됩니다.

```markdown
## 기술 스택

- Python 3.11+ (Django 5.x) / Django REST Framework / PostgreSQL / pytest

## 코딩 규칙

### Django 패턴

- CBV(Class-Based View) 우선
- 비즈니스 로직은 Model에 (Fat Model, Thin View)
```

기술 스택만 바꿔도 에이전트가 그에 맞춰 코딩합니다. React 대신 Vue를 쓰고 싶으면 `frontend_agent.md`의 스택 섹션만 고치면 돼요.

> 💡 오케스트레이터 스킬(`orchestrator_agent.md`)도 같은 방식으로 길들일 수 있지만, 한 가지는 고정입니다 — 오케는 **물리적으로 분리된 에이전트**(독립 Claude Code / Codex / Antigravity 프로세스)만 스폰하고, 직접 코딩하지 않으며, 중요한 액션 전엔 PM 확인을 받습니다. 이 원칙은 건드리지 마세요. (자세한 구조는 [[부록A_MCP_아키텍처_상태머신]] 참고.)

### 2. 커스텀 칸반 상태 (4분)

> 화면: 보드 탭 — 컬럼 구성

기본 칸반 상태는 `TODO → IN_PROGRESS → REVIEW → DONE`(+ 필요 시 `BLOCKED · FAILED`)입니다. 하지만 팀 프로세스에 따라 단계를 더 넣을 수 있어요.

```
QA 팀이 있는 경우:
TODO → IN_PROGRESS → REVIEW → QA_TESTING → STAGING → DONE

디자인 검토가 끼는 경우:
DESIGN → TODO → IN_PROGRESS → DESIGN_REVIEW → CODE_REVIEW → DONE

법적 검토가 필요한 경우:
TODO → IN_PROGRESS → LEGAL_REVIEW → TECH_REVIEW → DONE
```

상태를 추가하면 오케스트레이터가 새 단계를 인식하고 태스크를 그에 맞게 이동시킵니다. 우리 팀의 실제 업무 흐름을 보드에 그대로 옮기는 거예요.

> ⚠️ 상태를 늘릴수록 게이트가 늘어 흐름이 느려집니다. 처음에는 기본 4단계로 시작하고, **반복해서 손이 가는 단계**가 보일 때만 추가하세요.

### 3. 하네스에서 MCP 추가 — 에이전트의 능력 확장 (4분)

> 화면: 하네스 탭(HarnessStore) — MCP 카테고리

스킬 파일이 "어떻게 행동할지"라면, MCP는 "어떤 도구를 쓸 수 있는지"입니다. 에이전트에게 새 능력을 주려면 **하네스 탭에서 MCP를 추가**하면 됩니다. 단축키는 **⌘⇧H (Cmd/Ctrl + Shift + H)**.

예전엔 `~/.claude.json`이나 `.mcp.json`을 손으로 편집해야 했죠. 이제는 하네스 스토어에서 **버튼 한 번**입니다. MCP 카테고리에서 원하는 서버를 골라 설치하면, 설치 상태 아이콘과 설치 방식(git/mcp/npm-global/shell)이 표시됩니다.

```
하네스 탭 → MCP 카테고리에서 예:
- GitHub MCP   → 에이전트가 이슈·PR을 직접 다룸
- Slack MCP    → 작업 완료 시 Slack 알림
- Notion MCP   → 문서 자동 생성
```

MCP를 하나 붙이면 그 도구가 에이전트의 손에 들어갑니다. 예를 들어 Slack MCP를 추가하면 에이전트가 태스크를 끝낼 때 자동으로 Slack에 알릴 수 있어요. (하네스 스토어의 카테고리·설치 흐름은 [[2-1_하네스스토어_원클릭설치]]에서 다뤘습니다.)

> 💡 세 가지를 묶으면: **스킬 파일**로 행동을, **커스텀 상태**로 흐름을, **하네스 MCP**로 능력을 바꿉니다. 셋 다 코드를 몰라도 손댈 수 있고, 셋 다 우리 팀에 맞게 마블로를 길들이는 손잡이입니다.

## 정리 (1분)

> 화면: 요약 슬라이드

| 손잡이         | 무엇을 바꾸나                       | 어디서                  |
| -------------- | ----------------------------------- | ----------------------- |
| 역할 스킬 파일 | 에이전트의 **행동**(스택·규칙·루프) | 코드 탭, Markdown 한 장 |
| 커스텀 상태    | 칸반의 **흐름**(단계)               | 보드                    |
| 하네스 MCP     | 에이전트의 **능력**(도구)           | 하네스 탭 ⌘⇧H           |

기억할 것:

1. 스킬 파일은 **Markdown**이다 — "테스트 의무" 한 줄을 넣으면 에이전트가 진짜 테스트부터 짠다.
2. 기술 스택 섹션만 바꾸면 에이전트가 **다른 언어/프레임워크**로 코딩한다.
3. 상태는 **필요할 때만** 늘린다 — 게이트가 많을수록 느려진다.
4. MCP는 손편집이 아니라 **하네스에서 버튼 한 번**(⌘⇧H).

다음은 이 강좌의 마지막 섹션입니다. **곧 정식이 될 베타 기능**(Flows·Missions·Deploy)을 미리 보고, 마블로의 확장 방향과 함께 전체 여정을 마무리합니다.
