# 일상 운영 패턴

> 모듈 8 · 섹션 8-1 · 약 20분

## 도입 (3분)

여러분, 여기까지 오신 걸 축하합니다. 모듈 1에서 설치하고, 모듈 3에서 날씨 대시보드 만들고, 모듈 4~5에서 SaaS를 멀티모델로 빌드하고, 모듈 6에서 GCP에 배포하고, 모듈 7에서 랜딩페이지까지 만들었죠.

화면: 슬라이드 — "빌드 완료. 이제부터가 진짜입니다."

근데 프로젝트는 만들고 끝이 아닙니다. **운영**해야 해요. 버그가 발견되고, 기능 요청이 들어오고, 코드를 리팩토링해야 하고, 성능을 개선해야 하고. 매일매일 해야 할 일이 있습니다.

이번 섹션에서는 **마블로를 활용한 일상 운영 패턴**을 다룹니다. 아침에 출근해서 퇴근할 때까지, 마블로와 AI 에이전트 군단을 어떻게 활용하면 생산성을 극대화할 수 있는지 구체적으로 보여드리겠습니다.

## 본문 1: 일일 워크플로우 타임라인 (7분)

화면: 타임라인 다이어그램

### 아침: 상황 파악 (5~10분)

하루를 시작할 때 가장 먼저 하는 일입니다.

```bash
# 1. 어제 중단된 작업 이어받기
/tf-resume

# 오케스트레이터가 중단된 태스크의 컨텍스트를 복원합니다
# "어제 TASK-023 (API 에러 핸들링)이 IN_PROGRESS 상태에서 중단됐습니다.
#  마지막 활동: error middleware 코드 작성 중..."
```

```bash
# 2. 전체 프로젝트 상태 확인
/tf-status

# 출력 예시:
# ╔═══════════════════════════════════════╗
# ║  youtube-insight 프로젝트 현황         ║
# ╠═══════════════════════════════════════╣
# ║  TODO:        3개                      ║
# ║  IN_PROGRESS: 1개 (TASK-023)          ║
# ║  REVIEW:      2개 (TASK-021, 022)     ║
# ║  DONE:        18개                     ║
# ║  Agents:      2 idle, 1 working       ║
# ╚═══════════════════════════════════════╝
```

화면: 마블로 칸반 보드 — 태스크 상태 한눈에 보기

이 두 명령만으로 "지금 프로젝트가 어디쯤 왔는지" 30초 만에 파악할 수 있습니다.

### 오전: 작업 계획 + 실행

상황 파악이 끝났으면, 오늘 할 일을 계획합니다.

```bash
# 간단한 작업 — 바로 실행
/tf-start 로그인 페이지에 비밀번호 찾기 기능 추가해줘
```

`/tf-start`는 **빠른 시작**입니다. 한 문장으로 요구사항을 주면, 오케스트레이터가 태스크를 만들고, 에이전트를 배정하고, 바로 작업을 시작합니다.

```bash
# 복잡한 작업 — 분석 먼저
/tf-analyze 결제 시스템을 Stripe로 연동해야 해.
웹훅 수신, 구독 관리, 인보이스 생성이 필요해.
기존 user 테이블과 연동해야 하고, 테스트도 필요해.
```

`/tf-analyze`는 **심층 분석**입니다. 오케스트레이터가 요구사항을 분해하고, 의존성 그래프(DAG)를 만들고, 예상 시간과 비용을 알려줍니다. 복잡한 작업은 이걸로 먼저 계획을 세우세요.

```bash
# 분석 결과 확인 후 실행
/tf-plan
# 오케스트레이터가 제안한 계획을 검토하고 승인

# 계획 승인 후 실행
/tf-start
```

### 오후: 리뷰 + 수정

에이전트가 작업을 완료하면 REVIEW 상태로 이동합니다.

```bash
# 리뷰 요청 확인
/tf-review

# 오케스트레이터가 완료된 태스크들을 보여줍니다:
# TASK-024: Stripe 웹훅 수신 엔드포인트 [REVIEW]
# TASK-025: 구독 관리 로직 [REVIEW]
#
# 각 태스크의 변경사항 diff를 보여주고,
# Approve / Reject / Request Changes 선택
```

화면: 마블로 리뷰 패널 — 코드 diff와 승인/거절 버튼

리뷰에서 문제가 발견되면:

```bash
# 문제 수정 요청
/tf-fix TASK-024 웹훅 서명 검증 로직이 빠져있어. Stripe의 constructEvent로 서명을 검증해야 해.
```

### 문제 발생 시: 동기화 + 수정

```bash
# 에이전트 간 코드 충돌이 발생한 경우
/tf-sync

# 마블로가 Git 상태를 확인하고 충돌을 해결합니다
```

### 퇴근 전: 마무리

```bash
# 완료된 태스크 정리
/tf-done

# 오늘의 작업 요약:
# - 완료: 5개 태스크
# - 진행 중: 1개 (내일 이어서)
# - 새로 생성: 2개 (백로그)
# - 에이전트 사용: Claude 3, Gemini 2, Codex 1
# - 예상 비용: $1.23
```

## 본문 2: 두 프로젝트 동시 운영 (5분)

화면: 마블로 앱 — 두 개의 프로젝트가 사이드바에 표시

마블로의 강력한 기능 중 하나는 **프로젝트 격리**입니다. 두 개 이상의 프로젝트를 동시에 운영할 수 있어요.

### 프로젝트 전환

```bash
# 현재 프로젝트 확인
/tf-status
# → youtube-insight 프로젝트

# 다른 프로젝트로 전환 (마블로 사이드바에서 클릭)
# → marblo-blog 프로젝트로 전환

/tf-status
# → marblo-blog 프로젝트
```

화면: 마블로 앱에서 프로젝트를 전환하는 모습

### 격리가 보장되는 것들

```
프로젝트 A: youtube-insight          프로젝트 B: marblo-blog
├── 칸반 보드 A                      ├── 칸반 보드 B
├── 에이전트 A-1, A-2, A-3          ├── 에이전트 B-1, B-2
├── Git 저장소 A                     ├── Git 저장소 B
├── 태스크 히스토리 A                 ├── 태스크 히스토리 B
└── MCP 서버 인스턴스 A              └── MCP 서버 인스턴스 B
```

각 프로젝트의 에이전트는 자기 프로젝트의 코드만 건드립니다. 프로젝트 A의 에이전트가 프로젝트 B의 파일을 수정하는 일은 없어요. 이게 마블로의 **프로젝트 격리** 원칙입니다.

### 동시 작업 팁

1. **한 프로젝트에서 에이전트가 작업하는 동안** 다른 프로젝트로 전환해서 리뷰 가능
2. **에이전트 수는 프로젝트별로 독립** — 프로젝트 A에 3마리, 프로젝트 B에 2마리
3. **알림은 통합** — 어떤 프로젝트의 태스크가 완료되든 알림을 받음

## 본문 3: 슬래시 스킬 레퍼런스 카드 (5분)

화면: 슬래시 스킬 총정리 슬라이드

지금까지 배운 모든 슬래시 스킬을 정리합니다. 이건 **레퍼런스 카드**로 프린트해서 모니터 옆에 붙여놓으세요.

### 계획 단계

| 스킬 | 설명 | 사용 시점 |
|------|------|----------|
| `/tf-plan` | 프로젝트 계획 수립 | 새 기능 개발 시작 전 |
| `/tf-analyze` | 요구사항 심층 분석 + DAG 생성 | 복잡한 작업 전 |

### 실행 단계

| 스킬 | 설명 | 사용 시점 |
|------|------|----------|
| `/tf-start` | 빠른 작업 시작 (한 줄 요구사항) | 간단한 작업 |
| `/tf-resume` | 중단된 작업 이어받기 | 세션 시작 시 |
| `/tf-ralph` | 반복 작업 배치 자동화 | 테스트/리팩토링 등 |

### 모니터링 단계

| 스킬 | 설명 | 사용 시점 |
|------|------|----------|
| `/tf-status` | 프로젝트 전체 상태 확인 | 수시로 |
| `/tf-agents` | 에이전트 상태 확인 | 에이전트 작업 중 |

### 리뷰 단계

| 스킬 | 설명 | 사용 시점 |
|------|------|----------|
| `/tf-review` | 완료된 태스크 리뷰 | 에이전트가 REVIEW로 이동 후 |
| `/tf-approve` | 리뷰 승인 | 코드 확인 후 |
| `/tf-reject` | 리뷰 거절 + 수정 요청 | 수정 필요 시 |

### 문제 해결

| 스킬 | 설명 | 사용 시점 |
|------|------|----------|
| `/tf-fix` | 특정 태스크 수정 지시 | 버그/문제 발견 시 |
| `/tf-sync` | 에이전트 간 코드 동기화 | 충돌 발생 시 |
| `/tf-retry` | 실패한 태스크 재시도 | 에러로 태스크 실패 시 |

### 완료 단계

| 스킬 | 설명 | 사용 시점 |
|------|------|----------|
| `/tf-done` | 오늘 작업 마무리 + 요약 | 퇴근 전 |

### 유틸리티

| 스킬 | 설명 | 사용 시점 |
|------|------|----------|
| `/tf-cost` | 에이전트 비용 확인 | 비용 모니터링 시 |
| `/tf-config` | 마블로 설정 변경 | 설정 조정 시 |
| `/tf-help` | 스킬 도움말 | 스킬 사용법 확인 시 |

### 워크플로우 요약

```
아침:  /tf-resume → /tf-status
작업:  /tf-plan → /tf-start  (간단)
       /tf-analyze → /tf-plan → /tf-start  (복잡)
리뷰:  /tf-review → /tf-approve 또는 /tf-reject
문제:  /tf-fix, /tf-sync, /tf-retry
퇴근:  /tf-done
```

이 패턴을 2~3일만 반복하면 몸에 익습니다. 그 이후부터는 거의 자동으로 하게 돼요.

## 정리 (2분)

화면: 요약 슬라이드

오늘 배운 핵심입니다:

1. **일일 워크플로우**: resume → status → plan/start → review → done — 이 사이클을 매일 반복
2. **간단한 작업은 `/tf-start`**, 복잡한 작업은 `/tf-analyze` → `/tf-plan` → `/tf-start`
3. **두 프로젝트 동시 운영** 가능 — 프로젝트 격리가 보장됨
4. **슬래시 스킬 18개**를 상황에 맞게 사용 — 레퍼런스 카드 활용

다음 섹션에서는 반복 작업을 자동화하는 **Ralph** 기능을 다룹니다. `/tf-start`가 프로젝트 빌드용이라면, `/tf-ralph`는 반복 작업 배치 처리용입니다.
