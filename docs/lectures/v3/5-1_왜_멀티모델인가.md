# 왜 멀티모델인가

> 모듈 5 · 섹션 5-1 · 약 15분
> 관련: [[4-7_프로젝트_마무리]] | [[5-2_멀티모델_설정]]

## 도입 (3분)

여러분, 모듈 4까지 Claude 에이전트 하나로 정말 많은 것을 해봤죠? 백엔드도 만들고, 프론트엔드도 만들고, 테스트도 작성하고요. 근데 여기서 한 가지 질문을 드릴게요.

**"왜 개발팀에는 백엔드 개발자, 프론트엔드 개발자, QA 엔지니어가 따로 있을까요?"**

맞습니다. 각자 잘하는 영역이 다르기 때문이죠. AI 모델도 마찬가지입니다.

화면: 슬라이드 — "One model does NOT fit all"

Claude가 아무리 뛰어나도, 모든 작업에 최적인 건 아닙니다. 어떤 작업은 Gemini가 더 빠르고, 어떤 작업은 Codex가 더 효율적이에요. 그런데 지금까지 멀티모델 에이전트를 **하나의 보드에서 통합 관리**할 수 있는 도구는 없었습니다.

**마블로 v3의 킬링 피쳐가 바로 이겁니다.** Claude, Gemini, Codex — 서로 다른 AI 모델 에이전트를 한 프로젝트 칸반 보드에서 동시에 돌리고, 각자의 강점에 맞는 역할을 배정하는 것.

이번 모듈에서는 이걸 처음부터 끝까지 다뤄보겠습니다.

## 본문 1: 모델별 강점 비교 (5분)

화면: 비교 테이블 슬라이드

자, 주요 AI 코딩 모델들의 특성을 먼저 정리해봅시다.

### Claude (Anthropic)

```
강점:
- 복잡한 로직 설계와 아키텍처 판단
- 코드 품질 — 안전하고 가독성 높은 코드
- 긴 대화 맥락에서도 일관된 작업 수행
- MCP 도구 사용 능력 탁월
- 안전성(Safety) — 위험한 작업에 대한 거부 판단

약점:
- 토큰 비용이 상대적으로 높음 (특히 Opus)
- 반복적/단순 작업에는 과도한 리소스
```

Claude는 "시니어 아키텍트"라고 생각하시면 됩니다. 핵심 로직, 설계 판단, 복잡한 비즈니스 로직 — 이런 걸 시킬 때 빛나죠.

### Gemini (Google)

```
강점:
- 긴 컨텍스트 — 최대 100만 토큰
- 빠른 속도 — 특히 Flash 모델
- 코드 검색과 리팩토링
- 가격 대비 성능 최고 (Flash: $0.10/1M 입력 토큰)
- 멀티모달 — 이미지, 비디오 이해

약점:
- 복잡한 멀티스텝 추론에서 가끔 빗나감
- MCP 통합이 아직 발전 중
```

Gemini는 "빠른 주니어 개발자"예요. 컨텍스트를 엄청나게 많이 먹을 수 있어서 대규모 코드베이스를 한 번에 분석할 때 좋고, 무엇보다 빠르고 저렴합니다.

### Codex / GPT (OpenAI)

```
강점:
- 풀스택 자동화 — 코드 생성 속도
- ChatGPT Pro에 포함 (별도 과금 없음)
- 코드 생성량이 많은 작업에 적합
- 테스트 코드 작성 능력 우수

약점:
- 자율성 제어가 덜 세밀
- 대규모 프로젝트에서 컨텍스트 관리 어려움
```

Codex는 "코드 생산 머신"이에요. 특히 ChatGPT Pro 구독에 포함되어 있어서, 반복적인 코드 생성이나 테스트 작성에 비용 부담 없이 쓸 수 있죠.

## 본문 2: 단일 모델의 한계 시나리오 (4분)

화면: 시나리오 다이어그램

실제 개발 상황을 생각해봅시다.

### 시나리오 1: SaaS 프로젝트 빌드

```
작업 목록:
1. 백엔드 API 설계 + 구현      → 복잡한 비즈니스 로직
2. 프론트엔드 UI 20개 컴포넌트  → 반복적이지만 양이 많음
3. E2E 테스트 30개 케이스       → 패턴이 비슷한 반복 작업
4. CI/CD 파이프라인 구성         → 인프라 자동화
```

이걸 전부 Claude Opus에 시키면 어떻게 될까요?

**비용 계산:**

- 백엔드 (50K 토큰) = 약 $4.5
- 프론트엔드 (200K 토큰) = 약 $18
- 테스트 (150K 토큰) = 약 $13.5
- CI/CD (30K 토큰) = 약 $2.7
- **총: ~$38.7**

이제 멀티모델 전략을 쓰면?

```
1. 백엔드 API    → Claude Sonnet    비용: ~$1.5  (품질 중요)
2. 프론트엔드 UI → Gemini Flash     비용: ~$0.08 (양이 많고 반복적)
3. E2E 테스트    → Codex            비용: $0 (Pro 포함)
4. CI/CD         → Claude Sonnet    비용: ~$0.5
총: ~$2.08
```

**비용이 약 95% 절감됩니다.** 그런데 품질은? 핵심 로직은 Claude가 하고, 반복 작업은 저렴한 모델이 하니까 오히려 효율적이에요.

### 시나리오 2: 대규모 코드 리뷰

10만 줄짜리 코드를 리뷰해야 한다고 합시다. Claude의 컨텍스트 윈도우로는 한 번에 못 읽습니다. 하지만 Gemini는 100만 토큰 컨텍스트니까 코드를 통째로 넣고 분석할 수 있죠.

```
Gemini → 코드 전체 분석 + 문제점 목록 추출
Claude → 핵심 문제점에 대한 수정안 작성
```

이게 바로 **팀워크**입니다.

## 본문 3: 마블로의 접근 — 한 보드에서 모든 모델을 (3분)

화면: 마블로 칸반 보드 — 여러 모델 아이콘이 각 에이전트 옆에 표시

자, 핵심입니다. 마블로에서는 이걸 어떻게 하느냐.

```
프로젝트 칸반 보드
├── Agent: Claude-Backend  (model: claude)  → TASK-001: API 설계
├── Agent: Gemini-Frontend (model: gemini)  → TASK-002: UI 컴포넌트
├── Agent: Codex-Test      (model: gpt)     → TASK-003: 테스트 작성
└── Orchestrator: Claude                    → 전체 관리
```

기존에는 이게 불가능했습니다. Claude Code는 Claude만 쓰고, Cursor는 자체 모델만 쓰고, 각각 별도의 프로젝트에서 따로 작업하니까 통합 관리가 안 됐어요.

마블로는 다릅니다:

1. **통합 에이전트 관리**: 모델이 뭐든 간에, 마블로 칸반 보드 위의 에이전트로 취급됩니다
2. **MCP로 연결**: 모든 에이전트가 마블로 MCP 서버와 통신해서 태스크를 주고받습니다
3. **오케스트레이터가 지휘**: Claude 오케스트레이터가 태스크를 분배하고 진행을 모니터링합니다
4. **각 모델의 터미널을 실시간 관찰**: Agents 탭에서 Claude, Gemini, Codex 각각의 작업 현황을 한눈에 봅니다

비유하자면, 축구팀에서 감독(오케스트레이터)이 공격수, 미드필더, 수비수에게 각각 역할을 주는 것과 같죠. 공격수가 수비까지 다 할 필요 없잖아요?

**"Claude가 팀리더, Gemini가 프론트엔드, Codex가 테스트 — 한 보드에서 관리."**

이게 마블로 v3의 킬링 피쳐입니다.

## 정리 (2분)

화면: 요약 슬라이드

오늘 배운 핵심 세 가지입니다:

1. **각 AI 모델에는 고유한 강점이 있다** — Claude는 품질, Gemini는 속도와 컨텍스트, Codex는 대량 생산
2. **단일 모델만 쓰면 비용과 효율성에서 손해** — 비용이 10배 이상 차이 날 수 있습니다
3. **마블로는 멀티모델을 한 보드에서 통합 관리하는 유일한 도구** — 이게 킬링 피쳐입니다

다음 섹션에서는 실제로 마블로에서 멀티모델 에이전트를 어떻게 설정하는지, `agent-config.ts` 코드를 보면서 하나하나 설명하겠습니다.
