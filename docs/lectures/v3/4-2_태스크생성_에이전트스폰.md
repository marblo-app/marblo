# 태스크 생성 + 에이전트 스폰

> 모듈 4 · 섹션 4-2 · 약 20분
> 관련: [[4-1_요구사항_분석]] | [[4-3_Sprint1_백엔드]]

---

## 도입 (3분)

지난 섹션에서 `/tf-analyze`로 PRD를 만들고, 18개 태스크를 분해했습니다. 의존성 맵도 검토했고요.

화면: 마블로 워크스페이스 — 빈 칸반 보드

이제 이 기획을 **실제 시스템에 등록**하고, **에이전트를 투입**하는 단계입니다. 모듈 3에서는 `/tf-start` 하나로 한꺼번에 했었죠? 이번에는 조금 더 세밀하게 — 태스크 생성과 에이전트 스폰을 **분리해서** 해보겠습니다.

왜냐하면, 큰 프로젝트에서는 태스크를 먼저 등록하고, 한번 더 확인한 뒤에 에이전트를 투입하는 게 더 안전하거든요. 18개 태스크를 에이전트에게 맡겼는데, 태스크 설계가 잘못되면 되돌리기 어려우니까요.

---

## 본문

### `/tf-create-tasks` — 태스크 일괄 생성 (7분)

**(실습)** 먼저 태스크를 시스템에 등록합니다:

```bash
/tf-create-tasks
```

이 명령은 `/tf-analyze`에서 만든 태스크 목록을 마블로 시스템에 일괄 등록합니다. 내부적으로 `create_tasks_bulk` MCP 도구가 호출돼요.

화면: 칸반 보드에 18개 카드가 한꺼번에 생성되는 모습

```
✅ 18 tasks created successfully!

Backend tasks (7):
  [TASK-001] DB 스키마 설계 + 마이그레이션          → TODO
  [TASK-002] 사용자 인증 API                        → TODO
  [TASK-003] YouTube 메타데이터 수집 API             → TODO
  [TASK-004] YouTube 자막 추출 API                   → TODO (blocked: 003)
  [TASK-005] Claude API 분석 엔드포인트              → TODO (blocked: 004)
  [TASK-006] 분석 결과 저장/조회 API                 → TODO (blocked: 001, 005)
  [TASK-007] 사용량 제한 미들웨어                    → TODO (blocked: 002)

Frontend tasks (7):
  [TASK-008] 로그인/회원가입 UI                      → TODO (blocked: 002)
  [TASK-009] URL 입력 폼 컴포넌트                    → TODO (blocked: 003)
  [TASK-010] 분석 진행 상태 UI (로딩)                → TODO (blocked: 005)
  [TASK-011] 인사이트 카드 컴포넌트                  → TODO (blocked: 005)
  [TASK-012] 분석 상세 페이지                        → TODO (blocked: 011)
  [TASK-013] 대시보드 (히스토리 목록)                → TODO (blocked: 006, 012)
  [TASK-014] 검색 기능                               → TODO (blocked: 013)

DevOps tasks (2):
  [TASK-015] Docker Compose 설정                     → TODO
  [TASK-016] 환경 변수 + 설정 관리                   → TODO (blocked: 015)

Test tasks (2):
  [TASK-017] E2E 통합 테스트                         → TODO (blocked: 013, 014)
  [TASK-018] API 유닛 테스트                         → TODO (blocked: 003, 004, 005)
```

칸반 보드를 보면 카드가 쭉 나열되어 있을 거예요. 대부분 TODO 상태이고, `blocked`로 표시된 것들이 많죠.

### 칸반 보드에서 태스크 확인 (3분)

화면: 칸반 보드 — 18개 카드, TODO 열에 밀집

칸반 보드에서 각 카드를 클릭하면 상세 정보가 나옵니다:

- **태스크 제목 + 설명**
- **의존성** — 어떤 태스크가 완료되어야 시작 가능한지
- **카테고리** — backend, frontend, devops, test
- **예상 난이도** — 에이전트 기준 easy/medium/hard

지금 이 시점에서 마지막으로 한번 확인하세요:

```
"이 태스크 목록이 맞나? 빠진 건 없나? 순서가 이상한 건 없나?"
```

태스크를 수정하고 싶으면 에이전트 스폰 전에 하는 게 좋습니다:

```bash
# 태스크 수정 예시
/tf-feedback TASK-009 "URL 입력 시 YouTube URL 유효성 검증도 포함해주세요"

# 태스크 추가 예시
/tf-add "에러 핸들링 공통 컴포넌트" --type frontend --depends-on 008
```

### `/tf-spawn-agents` — 에이전트 투입 (7분)

태스크 확인이 끝났으면, 이제 에이전트를 투입합니다!

**(실습)** 터미널에 입력:

```bash
/tf-spawn-agents
```

화면: 에이전트 스폰 로그 + 터미널 패널에 에이전트별 탭 생성

```
🤖 Spawning agents for AI YouTube 인사이트...

Agent Team:
  [Agent-Backend]    → 7 tasks assigned
  [Agent-Frontend]   → 7 tasks assigned (all blocked initially)
  [Agent-DevOps]     → 2 tasks assigned
  [Agent-Test]       → 2 tasks assigned (all blocked initially)

Starting work:
  Backend Agent    : Claiming TASK-001 (DB 스키마 설계)
  Backend Agent    : Claiming TASK-002 (사용자 인증 API) — parallel OK
  Backend Agent    : Claiming TASK-003 (YouTube 메타데이터) — parallel OK
  DevOps Agent     : Claiming TASK-015 (Docker Compose 설정)
  Frontend Agent   : IDLE (waiting for dependencies)
  Test Agent       : IDLE (waiting for dependencies)
```

여기서 재미있는 걸 볼 수 있어요:

**1. Backend Agent가 3개 태스크를 동시에 시작합니다.** TASK-001, 002, 003은 서로 의존성이 없어요. 그래서 병렬로 진행 가능합니다.

**2. DevOps Agent도 바로 시작합니다.** TASK-015(Docker Compose)는 의존성이 없으니까요.

**3. Frontend Agent와 Test Agent는 대기.** 아직 백엔드 API가 준비되지 않았으니 기다립니다.

화면: 터미널 패널 — 4개 에이전트 탭, Backend와 DevOps 탭에 로그 스트리밍

터미널 패널을 보면 에이전트별 탭이 생겨 있을 겁니다. 각 탭을 클릭하면 해당 에이전트가 뭘 하는지 실시간으로 볼 수 있어요.

### 마블로 워크스페이스 전체 구성 확인 (3분)

화면: 마블로 데스크탑 앱 — 전체 워크스페이스 뷰

이 시점에서 마블로 워크스페이스의 전체 구성을 다시 확인합시다:

**왼쪽 패널 — 칸반 보드:**
- 18개 카드가 TODO, IN_PROGRESS 열에 분포
- 에이전트 아바타가 작업 중인 카드에 표시
- 의존성 선이 카드 사이를 연결

**오른쪽 상단 — 에이전트 터미널:**
- Backend Agent 탭: 파일 생성, 코드 작성 로그
- DevOps Agent 탭: Docker 설정 로그
- Frontend Agent 탭: "Waiting for dependencies..."
- Test Agent 탭: "Waiting for dependencies..."

**오른쪽 하단 — 파일 트리:**
- 에이전트가 생성한 파일이 실시간으로 추가

이 한 화면에서 18개 태스크, 4개 에이전트의 전체 상황을 파악할 수 있습니다. 여러 툴을 왔다갔다 할 필요가 없죠.

자, 이제 에이전트들이 일을 시작했습니다. 다음 섹션부터 본격적인 Sprint가 시작돼요!

---

## 정리

이번 섹션에서 한 일:

1. **`/tf-create-tasks`** — 18개 태스크를 칸반 보드에 일괄 등록
2. **태스크 최종 확인** — 에이전트 투입 전에 한번 더 검토
3. **`/tf-spawn-agents`** — 4개 에이전트(Backend, Frontend, DevOps, Test) 자동 스폰
4. **병렬 실행 확인** — 의존성 없는 태스크는 동시 시작 (TASK-001, 002, 003, 015)
5. **워크스페이스 전체 구성** — 칸반 + 터미널 + 파일 트리 한 화면

핵심 포인트: **태스크 생성과 에이전트 스폰을 분리**하면 실수를 줄일 수 있다. 큰 프로젝트에서는 항상 이렇게 하세요.
