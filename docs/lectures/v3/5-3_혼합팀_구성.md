# 실습: 혼합 에이전트 팀 구성

> 모듈 5 · 섹션 5-3 · 약 40분
> 관련: [[5-2_멀티모델_설정]] | [[5-4_오케스트레이터]]

---

## 도입 (3분)

자, 이론은 충분합니다. 이번에는 진짜로 해봅시다! **(실습)**

화면: 마블로 앱 — 빈 프로젝트 보드

이번 실습의 시나리오는 이렇습니다. 간단한 할 일 관리(Todo) API를 만드는 프로젝트에 세 가지 모델의 에이전트를 동시에 투입합니다:

| 에이전트 | 모델 | 역할 | 담당 |
|---------|------|------|------|
| Claude-Backend | Claude | backend | API 핵심 로직 |
| Gemini-Frontend | Gemini | frontend | React UI 컴포넌트 |
| Codex-Test | Codex (GPT) | test | 테스트 코드 작성 |

세 모델이 **동시에** 작업하고, 마블로 칸반 보드에서 **한 화면에** 진행 상황을 관찰합니다. 준비되셨나요?

---

## 본문 1: 사전 준비 확인 (5분)

화면: 터미널

먼저 각 CLI 도구가 설치되어 있는지 확인합시다.

**(실습)** 터미널을 열고 하나씩 확인해주세요:

```bash
# Claude Code 확인
claude --version
# 예: claude-code 1.x.x

# Gemini CLI 확인
gemini --version
# 예: gemini-cli 0.x.x

# Codex CLI 확인
codex --version
# 예: codex 0.x.x
```

설치가 안 되어 있다면:

```bash
# Claude Code
npm install -g @anthropic-ai/claude-code

# Gemini CLI
npm install -g @anthropic-ai/claude-code  # Google의 공식 설치 방법 따를 것
# 또는 brew install gemini-cli

# Codex CLI
npm install -g @openai/codex
```

**API 키도 확인합시다:**

```bash
# Claude — Claude Code 자체 인증으로 동작하므로 별도 키 불필요
# (claude login 으로 인증했다면 OK)

# Gemini
echo $GEMINI_API_KEY
# 비어있다면: export GEMINI_API_KEY="your-key-here"

# Codex — ChatGPT Pro 구독이 필요합니다
# codex login 으로 인증
```

화면: 각 CLI 버전 확인 결과가 터미널에 표시

모두 확인되셨으면 다음으로 넘어갑시다.

## 본문 2: 프로젝트 생성 + 태스크 준비 (5분)

화면: 마블로 앱

**(실습)** 마블로에서 새 프로젝트를 만듭니다.

1. 마블로 앱 좌측 상단 "+" 버튼 클릭
2. 프로젝트 이름: `multi-model-todo`
3. 프로젝트 디렉토리: 원하는 위치 선택 (예: `~/projects/multi-model-todo`)

이제 태스크를 수동으로 만들어봅시다. (나중에 오케스트레이터로 자동 생성하는 것도 배우지만, 지금은 수동으로 해서 과정을 이해합시다.)

화면: 칸반 보드의 "Add Task" 버튼 클릭

**태스크 3개를 생성합니다:**

```
TASK-001: Express API 서버 셋업 + CRUD 엔드포인트
- Role: backend
- Priority: 5 (critical)
- Description: Express.js로 Todo CRUD API를 만든다.
  GET /todos, POST /todos, PUT /todos/:id, DELETE /todos/:id

TASK-002: React Todo UI 컴포넌트
- Role: frontend
- Priority: 3
- Description: React + TypeScript로 Todo 리스트 UI를 만든다.
  TodoList, TodoItem, AddTodo, FilterBar 컴포넌트.
- Depends on: TASK-001

TASK-003: API E2E 테스트 작성
- Role: test
- Priority: 3
- Description: 모든 CRUD 엔드포인트에 대한 E2E 테스트를 jest + supertest로 작성한다.
- Depends on: TASK-001
```

화면: 칸반 보드에 3개 태스크가 TODO 컬럼에 표시

TASK-002와 TASK-003은 TASK-001에 의존합니다. 백엔드 API가 먼저 만들어져야 프론트엔드와 테스트를 제대로 할 수 있으니까요. 하지만 TASK-002와 TASK-003은 서로 독립적이라서 **동시에** 실행할 수 있습니다.

이게 바로 DAG(Directed Acyclic Graph)입니다:

```
TASK-001 (Backend)
├──→ TASK-002 (Frontend)  ← 병렬
└──→ TASK-003 (Test)      ← 병렬
```

## 본문 3: 에이전트 생성 — Claude Backend (7분)

화면: 마블로 Agents 탭

이제 에이전트를 하나씩 만들어봅시다.

**(실습)** Agents 탭으로 이동합니다.

### Claude Backend 에이전트 추가

1. "Add Agent" 버튼 클릭
2. 설정 입력:

```
Name: Claude-Backend
Model: Claude        ← 드롭다운에서 선택
Role: backend
Command: claude      ← 자동 입력됨
```

화면: 에이전트 추가 모달

3. "Launch" 클릭

화면: 새 터미널 패널이 열리면서 Claude Code가 부팅

이 순간 내부에서 벌어지는 일을 설명드릴게요:

```
1. AgentConfigGenerator.generateMCPConfig() 호출
   → /tmp/marblo-agent-configs/claude-mcp-<agent-id>.json 생성

2. AgentConfigGenerator.generateSkillFile() 호출
   → v3/skills/backend_agent.md 경로 반환

3. buildCLICommand() 호출
   → claude --dangerously-skip-permissions --mcp-config /tmp/.../claude-mcp-xxx.json

4. PtyManager.create() 호출
   → 실제 터미널 프로세스 생성

5. 3초 후 initialPrompt를 stdin으로 전송
```

Claude Code가 부팅되면 터미널에 이런 메시지가 보일 겁니다:

```
╭────────────────────────────────────────╮
│ ✻ Welcome to Claude Code!              │
│                                        │
│ /help for commands, /status for info   │
╰────────────────────────────────────────╯

> Connected to MCP server: marblo
```

"Connected to MCP server: marblo" — 이 메시지가 보이면 MCP 연결이 성공한 겁니다!

## 본문 4: 에이전트 생성 — Gemini Frontend (5분)

화면: 에이전트 추가 모달

**(실습)** 두 번째 에이전트를 추가합니다.

### Gemini Frontend 에이전트 추가

1. "Add Agent" 버튼 클릭
2. 설정 입력:

```
Name: Gemini-Frontend
Model: Gemini        ← 드롭다운에서 선택
Role: frontend
Command: gemini      ← 자동 입력됨
```

3. "Launch" 클릭

화면: 두 번째 터미널 패널이 열리면서 Gemini CLI가 부팅

Gemini는 Claude와 약간 다르게 보입니다:

```
Gemini CLI v0.x.x
Model: gemini-2.0-flash
MCP servers: marblo (connected)
Ready.
```

여기서 주목할 점 — Gemini는 기본적으로 **Flash 모델**을 사용합니다. Flash는 빠르고 저렴해서 프론트엔드 UI 코드 생성 같은 작업에 최적이에요.

내부적으로는 이런 차이가 있습니다:

```
Claude:  claude --mcp-config /path/to/config.json
Gemini:  GEMINI_MCP_CONFIG=/path/to/config.json gemini
```

CLI 플래그 vs 환경변수 — 접근 방식은 다르지만 결과는 같습니다. 둘 다 마블로 MCP 서버에 연결되죠.

## 본문 5: 에이전트 생성 — Codex Test (5분)

화면: 에이전트 추가 모달

**(실습)** 세 번째 에이전트입니다.

### Codex Test 에이전트 추가

1. "Add Agent" 버튼 클릭
2. 설정 입력:

```
Name: Codex-Test
Model: Codex (GPT)   ← 드롭다운에서 선택
Role: test
Command: codex       ← 자동 입력됨
```

3. "Launch" 클릭

화면: 세 번째 터미널 패널이 열리면서 Codex CLI가 부팅

```
codex v0.x.x
Running in full-auto mode
Ready for instructions.
```

Codex의 `--full-auto` 모드는 사용자 확인 없이 자동으로 코드를 생성하고 파일을 작성합니다. 테스트 코드처럼 패턴이 반복적인 작업에 딱이죠.

## 본문 6: 세 에이전트 동시 관찰 (7분)

화면: Agents 탭 — 3개 에이전트 카드가 나란히 표시

자, 이제 세 에이전트가 모두 실행 중입니다! Agents 탭을 보면 이런 화면이 보일 겁니다:

```
┌─────────────────┐  ┌─────────────────┐  ┌─────────────────┐
│ Claude-Backend   │  │ Gemini-Frontend  │  │ Codex-Test       │
│ Model: claude    │  │ Model: gemini    │  │ Model: gpt       │
│ Role: backend    │  │ Role: frontend   │  │ Role: test        │
│ Status: idle     │  │ Status: idle     │  │ Status: idle      │
│ [Terminal ▶]     │  │ [Terminal ▶]     │  │ [Terminal ▶]      │
└─────────────────┘  └─────────────────┘  └─────────────────┘
```

**(실습)** 이제 태스크를 할당해봅시다.

1. 칸반 보드로 돌아갑니다
2. TASK-001을 Claude-Backend 에이전트에게 드래그 앤 드롭 (또는 태스크 클릭 → Assign → Claude-Backend 선택)

화면: Claude-Backend 터미널에 작업이 시작되는 모습

Claude가 작업을 시작합니다:

```
> I'll start building the Express.js Todo CRUD API.
> First, let me initialize the project...

$ npm init -y
$ npm install express cors
$ npm install -D typescript @types/express @types/node ts-node

> Creating the API server...
```

잠시 기다리면 TASK-001이 완료될 겁니다. 그러면 TASK-002와 TASK-003의 의존성이 해제됩니다.

**(실습)** TASK-001이 DONE으로 이동하면:
- TASK-002를 Gemini-Frontend에 할당
- TASK-003을 Codex-Test에 할당

화면: 칸반 보드에서 두 태스크가 동시에 IN_PROGRESS로 이동

이제 진짜 멋진 순간입니다. **세 개의 터미널을 동시에 관찰해보세요:**

```
[Claude-Backend]     → 작업 완료, idle 상태
[Gemini-Frontend]    → React 컴포넌트를 빠르게 생성 중
[Codex-Test]         → Jest 테스트 파일을 자동으로 작성 중
```

같은 프로젝트 디렉토리에서 세 모델이 각자의 영역을 담당하며 코드를 작성하고 있습니다.

## 본문 7: 코드 스타일 비교 (5분)

화면: VS Code에서 각 에이전트가 작성한 파일 비교

작업이 끝나면, 각 모델이 작성한 코드를 비교해봅시다. 이게 굉장히 흥미롭습니다.

### Claude가 작성한 백엔드 코드

```typescript
// src/routes/todos.ts (Claude)
import { Router, Request, Response } from 'express';

const router = Router();
const todos: Todo[] = [];

interface Todo {
  id: string;
  title: string;
  completed: boolean;
  createdAt: Date;
}

router.get('/', (_req: Request, res: Response) => {
  res.json({ data: todos, count: todos.length });
});

router.post('/', (req: Request, res: Response) => {
  const { title } = req.body;
  if (!title?.trim()) {
    return res.status(400).json({ error: 'Title is required' });
  }
  // ...
});
```

Claude의 특징: 타입이 명확하고, 에러 핸들링이 꼼꼼하고, 구조가 체계적입니다.

### Gemini가 작성한 프론트엔드 코드

```tsx
// src/components/TodoList.tsx (Gemini)
import React, { useState, useEffect } from 'react';

export const TodoList: React.FC = () => {
  const [todos, setTodos] = useState<Todo[]>([]);

  useEffect(() => {
    fetch('/api/todos')
      .then(res => res.json())
      .then(data => setTodos(data.data));
  }, []);

  return (
    <ul>
      {todos.map(todo => (
        <TodoItem key={todo.id} todo={todo} />
      ))}
    </ul>
  );
};
```

Gemini의 특징: 심플하고 빠르게 작동하는 코드. 핵심에 집중하고 불필요한 부분이 적습니다.

### Codex가 작성한 테스트 코드

```typescript
// tests/todos.test.ts (Codex)
import request from 'supertest';
import app from '../src/app';

describe('Todo CRUD', () => {
  it('should create a todo', async () => {
    const res = await request(app)
      .post('/api/todos')
      .send({ title: 'Test todo' });
    expect(res.status).toBe(201);
    expect(res.body.data.title).toBe('Test todo');
  });

  it('should list all todos', async () => {
    const res = await request(app).get('/api/todos');
    expect(res.status).toBe(200);
    expect(Array.isArray(res.body.data)).toBe(true);
  });
  // ... 더 많은 테스트 케이스
});
```

Codex의 특징: 테스트 케이스를 빠르고 많이 생성합니다. 패턴이 반복적인 작업에 강합니다.

각 모델의 개성이 확실히 드러나죠? 그리고 이 세 가지 코드가 **하나의 프로젝트에서 조화롭게** 동작합니다.

## 정리 (3분)

화면: 요약 슬라이드

오늘 직접 해본 실습을 정리합니다:

1. **세 가지 모델의 에이전트를 하나의 프로젝트에 동시 투입** — 불과 몇 분 만에
2. **DAG 기반 의존성 관리** — TASK-001 완료 후 TASK-002, TASK-003 동시 시작
3. **각 모델의 코드 스타일 차이 확인** — Claude(꼼꼼), Gemini(빠르고 간결), Codex(대량 생산)
4. **한 화면에서 모든 에이전트의 작업을 실시간 관찰**

핵심 교훈: **적재적소에 모델을 배치하면, 비용은 줄고 품질은 유지되거나 오히려 올라갑니다.**

더 자세한 실습 단계는 [[실습_멀티모델_팀구성]]을 참고해주세요.

다음 섹션에서는 이 과정을 **자연어 한 줄로 자동화**하는 오케스트레이터를 배워보겠습니다.
