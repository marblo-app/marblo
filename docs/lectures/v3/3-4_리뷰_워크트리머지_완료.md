# 리뷰 → 워크트리 머지 → 완료

> 모듈 3 · 섹션 3-4 · 약 30분
> 관련: [[3-3_레인에서_에이전트관찰]] | [[4-1_풀스택기획_역할설계]]

---

## 이 레슨의 4요소

- **학습목표:** REVIEW로 올라온 카드를 **코드 탭에서 diff로 검토**하고, **워크트리 탭에서 Rebase/Merge(squash)** 해 첫 결과물을 main에 반영한다. 브라우저로 동작을 확인하고, "머지 권한은 사람이 쥔다"는 칸반 거버넌스를 이해한다.
- **시연할 마블로 화면·기능:** **코드 탭(CodeTab)** diff → **워크트리 탭(WorktreeTab)** Rebase/Merge(squash) → DONE → 브라우저 동작 확인.
- **진행할 프로젝트 단계:** **P1 완성(첫 머지).**
- **핵심 메시지:** "**칸반 거버넌스** — 머지 권한은 끝까지 내가 쥔다."

---

## 도입 (3분)

에이전트가 TASK-1을 끝내고 카드를 **REVIEW** 컬럼으로 올렸습니다. 지금까지는 관찰만 했죠. 이제 **PM이 직접 손을 대는 첫 순간** 입니다.

마블로에는 안전장치가 하나 있어요. 에이전트가 일은 자기 **격리된 워크트리**에서 다 했지만([[2-4_프로젝트연결_워크트리체크]]), 그 결과를 **main에 합치는(merge) 권한은 에이전트에게 없습니다.** 그건 끝까지 **사람의 결정**이에요. 이게 마블로의 **칸반 거버넌스**입니다.

이번 레슨에서 그 첫 머지를 직접 해서 **P1을 완성**합니다.

화면: 보드 탭 — REVIEW 컬럼에 TASK-1 카드 도착

---

## 본문

### 1. 코드 탭에서 diff 검토 (8분)

화면: 워크트리/레인 행 → Open → 코드 탭(CodeTab) diff 뷰

REVIEW 카드를 검토하려면 **무엇이 바뀌었는지** 봐야겠죠. 워크트리 행(또는 레인 행)의 **Open** 버튼을 누르면 그 에이전트의 워크트리가 **코드 탭**에서 열리고, 변경 사항이 **diff(초록 추가 / 빨강 삭제)** 로 보입니다.

```
코드 탭 — agent/todo-task1 변경 사항
  + index.html   (new)   입력창 + 추가 버튼 + 목록
  + style.css    (new)   레이아웃 + 완료 취소선
  ~ (없음)
```

diff를 훑으며 PM으로서 확인할 것:

- 요청한 결과물이 실제로 들어있나? (입력창·추가 버튼·목록 골격)
- 이상한 코드나 빠진 부분은 없나?

> 💡 코드를 한 줄씩 다 읽을 필요는 없어요. **카드의 의도대로 만들어졌는지**를 확인하는 게 리뷰의 핵심입니다. 부족하면 다음 레슨(모듈 4)에서 배울 **반려(Reject)** 로 돌려보낼 수 있어요. P1은 작아서 보통 한 번에 통과합니다.

오케스트레이터에게 `/tf-review`로 검토를 요청할 수도 있습니다 — REVIEW 카드 목록과 변경 요약을 정리해서 Approve/Reject를 물어봐요. 입문 단계에선 **코드 탭 diff를 눈으로 보는 것**을 권합니다.

### 2. 워크트리 탭에서 머지 (10분)

화면: 워크트리 탭(WorktreeTab) — TASK-1 워크트리 행 + 상태 pill + 액션 버튼

diff가 만족스러우면 합칩니다. **워크트리 탭**으로 가요. TASK-1의 워크트리 행에 상태 **pill**이 붙어 있을 거예요([[2-4_프로젝트연결_워크트리체크]]에서 배운 신호등).

```
워크트리 탭
  agent/todo-task1   [TASK-1]   🟢 머지 가능   + 2 파일
     [ Rebase ]  [ Merge (squash) ]  [ Open ]  [ Delete ]
```

- **🟢 머지 가능(mergeable)** 이면 → 바로 **Merge (squash)** 를 누릅니다.
- 만약 **🟡 뒤처짐(behind)** 이면 → 먼저 **Rebase** 로 main 최신을 따라잡은 뒤 머지. (P1은 단일 레인·첫 작업이라 보통 바로 🟢입니다.)

**Merge (squash)** 를 누르면 에이전트가 워크트리에서 만든 커밋들이 **하나로 압축(squash)** 되어 main에 깔끔하게 들어갑니다. 그 순간:

```
✅ merged: agent/todo-task1 → main (squash)
  → TASK-1: REVIEW → DONE
  → TASK-2 잠금 해제 (의존성 해소)
```

카드가 **DONE** 으로 가고([[1-4_큰그림_파이프라인]] 상태 머신의 마지막 칸 — DONE은 되돌릴 수 없음), 동시에 TASK-1에 막혀 있던 **TASK-2의 잠금이 풀립니다.** 에이전트가 곧 TASK-2를 claim해서 다음 사이클을 시작해요.

화면: 보드 탭 — TASK-1 DONE, TASK-2 자동 claim → 레인에서 작업 시작

> 💡 **완료 이력에 남습니다.** 워크트리 탭의 📜 완료 이력에 "누가(🙂 사람) 언제 어느 브랜치를 어떤 SHA로 합쳤나"가 기록돼요. 팀 작업의 감사 추적입니다. 여러분이 직접 머지했으니 모드 배지는 🙂 **사람**.

**(실습) 나머지 카드도 같은 흐름으로**
TASK-2(추가·완료·삭제) → TASK-3(localStorage) → TASK-4(필터)도 똑같이 **레인에서 작업 관찰 → 코드 탭 diff → 워크트리 머지** 를 반복합니다. 단일 레인이라 하나씩 순서대로 DONE이 돼요. 보드가 **전부 DONE**이 되면 P1 완성입니다.

### 3. 브라우저로 동작 확인 (6분)

화면: 브라우저 — index.html 실행

코드가 main에 다 들어왔으니 **진짜 동작하는지** 봐야죠. P1은 빌드가 없는 순수 HTML/CSS/JS라 **`index.html`을 브라우저로 열기만 하면** 됩니다.

```
프로젝트 폴더의 index.html 더블클릭
  (또는 코드 탭에서 미리보기)
```

화면: 브라우저 — 할 일 추가 → 완료 토글 → 삭제 → 필터 → 새로고침 후에도 유지

직접 만져봅시다:

1. 입력창에 "강의 마무리" 입력 → 추가 → 목록에 뜬다.
2. 항목 클릭 → 완료(취소선) 토글.
3. 삭제 버튼 → 사라진다.
4. 필터 **전체·진행중·완료** 전환 → 해당 항목만 보인다.
5. **새로고침(F5)** → 목록이 그대로 유지된다. ← `localStorage`가 동작한다는 증거!

여러분이 코딩한 줄은 **0줄.** 자연어 한 줄로 시작해서, 관찰하고, 리뷰하고, 머지한 것만으로 **동작하는 웹앱**이 나왔습니다. **첫 풀사이클 완성.**

### 4. 칸반 거버넌스 — 머지는 사람이 쥔다 (2분)

화면: 슬라이드 — "에이전트: 격리 워크트리에서 작업 / 사람: 머지 결정"

방금 한 흐름의 핵심을 짚을게요. 에이전트는 **자기 워크트리 안에서** 마음껏 일했지만, 그 결과가 main에 들어가려면 **반드시 사람의 머지 승인**을 거쳤습니다.

- 에이전트가 잘못 만들어도 → **격리돼 있어** main은 안전.
- 합칠지 말지 → **PM이 diff를 보고 결정.**
- 누가 언제 합쳤나 → **완료 이력에 기록.**

이게 마블로가 자율 에이전트를 **신뢰하고 쓸 수 있는** 이유예요. 자율성은 워크트리 안에서, 통제는 머지 게이트에서. **머지 권한은 끝까지 사람이 쥡니다.**

---

## 정리 (1분)

화면: 정리 슬라이드 — P1 풀사이클 한 장

P1 첫 풀사이클을 완주했습니다:

1. **자연어 요청**(3-1) → **보드 카드**(3-2) → **레인 관찰**(3-3) → **리뷰·머지**(3-4).
2. REVIEW 카드는 **코드 탭 diff**로 검토, **워크트리 탭에서 Merge(squash)** → DONE.
3. 머지하면 **의존성이 풀려** 다음 카드가 자동으로 이어진다.
4. **칸반 거버넌스** — 에이전트는 격리 워크트리에서, **머지 권한은 사람이.**
5. 코딩 0줄로 **동작하는 할 일 웹앱** 완성(localStorage 영속화 확인).

**모듈 3 끝 — 첫 풀사이클 완성!** 지금까진 에이전트 **한 명**이었죠. 다음 모듈에서는 **두 모델(Claude + Codex)이 동시에** 풀스택을 짜는 멀티에이전트 협업으로 한 단계 올라갑니다.
