# 왜 '에이전트 한 명'이 아니라 '팀'인가

> 모듈 1 · 섹션 1-1 · 약 15분
> 관련: [[1-2_마블로_한바퀴_탭투어]] | [[HOME]]

## 이 강의에서 다루는 것

- **학습목표:** 단일 AI 페어코딩과 멀티에이전트 팀의 차이, 그리고 마블로가 푸는 문제를 이해한다.
- **시연할 마블로 화면·기능:** (슬라이드) 혼자 코딩 vs 보드 위에서 여러 에이전트가 동시에 카드를 처리하는 30초 타임랩스 미리보기.
- **진행할 프로젝트 단계:** — (이 레슨은 개념 도입, 실습 없음)
- **핵심 메시지:** "당신은 코더가 아니라 **PM/팀리더**가 된다."

> 이 모듈에서 슬라이드를 쓰는 건 이 레슨뿐입니다. 1-2부터는 실제 앱 화면을 돌며 "이 강의가 끝나면 당신이 하게 될 일"을 먼저 보여줍니다.

## 도입 — 혼자 코딩하는 AI의 한계 (3분)

안녕하세요, 마블로 v3 강의에 오신 걸 환영합니다.

시작하기 전에 질문 하나 드릴게요.
여러분, Claude Code나 Codex 같은 AI로 코딩해보신 적 있으시죠?

> 화면: 터미널에서 Claude Code 단독 사용하는 화면

"이거 만들어줘" 하면 코드를 쭉 만들어주고, "버그 고쳐줘" 하면 고쳐주고.
꽤 편리하죠. 근데 프로젝트가 좀 커지면 어떻게 되나요?

- "백엔드 API 만들어줘" — 만들어줍니다.
- "그럼 프론트엔드도 만들어줘" — 만들어주는데, 아까 백엔드 컨텍스트가 슬슬 밀려납니다.
- "테스트도 짜줘" — 짜주는데 프론트엔드에서 뭘 했는지 기억이 흐릿합니다.

이게 AI **혼자** 코딩하는 것의 한계입니다.
사람도 혼자서 백엔드, 프론트엔드, 테스트, 배포를 다 하면 힘들잖아요?
AI도 마찬가지입니다. 한 세션에 모든 역할을 욱여넣으면 컨텍스트가 유실되고, 작업이 서로 충돌하고, 산만해집니다.

## 본문

### 혼자 코딩하는 AI vs. 팀으로 협업하는 AI (4분)

> 화면: 슬라이드 — "Solo AI" vs "Agent Team" 비교

**Solo AI 방식** (기존)

```
사람 → AI 1대 → 전부 다 혼자
    "백엔드 만들어줘"
    "이제 프론트 만들어줘"
    "테스트도 짜줘"
    → 컨텍스트 유실, 충돌, 산만
```

**Agent Team 방식** (마블로)

```
사람(PM) → Team Leader(오케스트레이터)
              ├── Backend Agent   → API 개발
              ├── Frontend Agent  → UI 개발
              ├── Test Agent      → 테스트 작성
              └── DevOps Agent    → 배포 설정
```

차이가 보이시죠? 하나의 AI한테 모든 걸 시키는 게 아니라, **역할별로 전담 에이전트를 두는 겁니다.**

각 에이전트는 자기 역할에만 집중하고, 서로 칸반 보드를 통해 작업을 주고받습니다.
마치 실제 개발팀처럼요.

중요한 건 이 에이전트들이 "가상"이 아니라 **물리적으로 분리된 프로세스**라는 점입니다.
Backend Agent는 자기만의 Claude Code 터미널에서 돌아가고,
Frontend Agent는 또 다른 터미널에서 돌아갑니다.
서로 컨텍스트를 침범하지 않습니다.

그리고 이 에이전트들은 한 가지 모델에 묶여 있지 않습니다.
마블로의 기본 팀은 **Claude Code + Codex** 두 주역이고,
여기에 떠오르는 3번째로 **Antigravity**가 합류합니다.
(모델별 강점과 역할 배정은 모듈 6에서 자세히 다룹니다.)

### Agent Teams 개념 — 세 가지 기둥 (4분)

> 화면: 슬라이드 — Agent Teams 아키텍처

Agent Teams의 핵심은 세 가지입니다.

**첫째, Team Leader(오케스트레이터)가 있습니다.**
이 친구가 프로젝트를 태스크로 분해하고,
적절한 에이전트를 스폰(spawn)해서 작업을 배분합니다.
여러분은 오케스트레이터에게 자연어로 한 줄만 던지면 됩니다.

**둘째, MCP로 소통합니다.**
MCP — Model Context Protocol이라는 표준 프로토콜을 통해
에이전트가 칸반 보드에 태스크를 만들고, 상태를 바꾸고, 진행 상황을 기록합니다.
(MCP의 내부는 부록 A에서 더 깊이 다룹니다.)

**셋째, 칸반 보드가 중앙 허브입니다.**
모든 에이전트가 하나의 칸반 보드를 공유합니다.
`TODO → CLAIMED → IN_PROGRESS → REVIEW → DONE`.
PM인 여러분은 이 보드를 보면서 진행 상황을 파악하고, 리뷰하고, 피드백을 줍니다.

> 마블로는 사람을 위한 JIRA가 아니라, **AI 에이전트 팀을 운영하기 위한 전용 워크스페이스**입니다.
> (참고: 마블로는 원래 v1이 Docker 컨테이너 5개를 띄우는 CLI 도구였지만, v3는 **앱 더블클릭 한 번**으로 끝나는 데스크탑 앱으로 바뀌었습니다.)

### 보드 위에서 팀이 동시에 일하는 모습 (3분)

> 화면: 마블로 Board/Lanes — 여러 카드가 동시에 처리되는 30초 타임랩스 미리보기

말로만 들으면 와닿지 않으니, 미리 한 장면 보여드릴게요.

보드 위에 카드 여러 장이 떠 있고, 그게 동시에 오른쪽으로 밀려갑니다.
한 카드는 Claude Code가, 다른 카드는 Codex가 동시에 처리하고 있어요.
TODO에 있던 카드가 CLAIMED → IN_PROGRESS → REVIEW로 스스로 움직입니다.

여러분이 한 일은? 처음에 "이거 만들어줘" 한 줄 던진 것뿐입니다.
나머지는 팀이 알아서 굴러갑니다. **당신은 코더가 아니라 PM이 됩니다.**

## 정리 (1분)

오늘 기억할 핵심 3가지:

1. **Solo AI → Agent Team:** 혼자 시키지 말고, 역할별 팀으로 운영하자.
2. **세 가지 기둥:** 오케스트레이터(팀리더) · MCP(소통) · 칸반 보드(중앙 허브).
3. **당신의 역할:** 코더가 아니라 **PM/팀리더**. 한 줄 요청 → 팀이 굴러간다.

다음 섹션에서는 이 모든 게 한 화면에 어떻게 들어 있는지,
마블로 앱을 직접 열어 **탭을 한 바퀴 돌며** 보여드리겠습니다.
