## 본문

### 1. STDIN 자동 프롬프트 주입 — 마블로의 핵심 기술 (5분)

화면: 오케스트레이터 터미널 — Claude Code가 실행 중인 모습

마블로의 가장 핵심이 되는 기술부터 보겠습니다.
**STDIN 자동 프롬프트 주입**이라고 합니다.

보통 Claude Code를 어떻게 쓰시나요?
터미널 열고, `claude` 치고, 프롬프트를 직접 타이핑하시죠?
한 에이전트한테는 이거면 됩니다.

근데 에이전트 **3개**를 동시에 돌리려면요?
터미널 3개 열고, 각각 claude 치고, 프롬프트 3번 복붙해야 합니다.
에이전트 5개면? 10개면? 이건 사람이 할 일이 아닙니다.

마블로는 이걸 **프로그래밍적으로** 해결합니다.

화면: 코드 에디터 — pty-manager.ts의 write 메서드 하이라이트

Electron 앱의 `node-pty` 라이브러리가 Claude Code의 STDIN에 직접 프롬프트를 주입합니다.
코드로 보면 이렇게 간단합니다:

```typescript
// electron/pty-manager.ts
write(id: string, data: string): void {
  const session = this.sessions.get(id);
  if (session) {
    session.process.write(data);
  }
}
```

그리고 프론트엔드에서는:

```typescript
window.electronAPI.pty.write(sessionId, prompt + "\r");
```

**이 한 줄이 마블로의 핵심입니다.**

이게 왜 중요하냐면, 이걸로 에이전트를 "프로그래밍적으로 제어"할 수 있게 되거든요.

- 오케스트레이터 터미널에서 자연어를 입력하면
- Claude Code가 그걸 받아서 태스크를 자동으로 분해하고
- `spawn_agent` MCP 도구를 호출해서 새 에이전트를 스폰하고
- 각 에이전트한테 초기 프롬프트를 자동으로 주입합니다.

화면: agent-manager.ts의 launch 메서드 — initialPrompt 전송 부분

실제 에이전트가 스폰될 때 벌어지는 일을 보시죠:

```typescript
// electron/agent-manager.ts — launch()
if (!isResume && launchConfig.initialPrompt) {
  const prompt = launchConfig.initialPrompt;
  let sent = false;
  const sendPrompt = () => {
    if (sent) return;
    sent = true;
    this.ptyManager.write(ptySessionId, prompt + "\r");
  };
  // Claude Code가 부팅되는 데 2-3초 걸림
  setTimeout(sendPrompt, 3000);
}
```

PTY 세션을 만들고 → Claude Code CLI가 부팅되면 → 초기 프롬프트를 STDIN에 주입합니다.
이 3초 딜레이는 CLI가 준비될 때까지 기다리는 거예요.

기존 방식: 터미널 열고 → claude 치고 → 프롬프트 타이핑 → 복붙...
마블로 방식: 앱에서 바로 주입. **끝.**

### 2. 슬래시 메뉴 — / 하나로 모든 명령을 (4분)

화면: 오케스트레이터 터미널에서 `/` 입력 → 팝업 메뉴 나타나는 모습

이건 써보시면 바로 "아, 이거다" 하실 겁니다.

오케스트레이터 터미널에서 `/`를 치면요, 이렇게 명령어 팝업이 뜹니다.

**(실습) `/` 입력 시연**

| 슬래시 명령     | 설명                                        |
| --------------- | ------------------------------------------- |
| `/analyze`      | 요구사항 분석 — 컴포넌트, 역할, 의존성 파악 |
| `/create-tasks` | 분석 기반 태스크 일괄 생성                  |
| `/spawn-agents` | 에이전트 라인업 제안 → 스폰                 |
| `/status`       | 전체 태스크 현황 조회                       |
| `/create-flow`  | 파이프라인 플로우 설계                      |

각 슬래시 명령어가 하는 일은 뭐냐면요,
**미리 정의된 한국어 프롬프트를 STDIN에 주입**하는 겁니다.

예를 들어 `/analyze`를 선택하면,
"요구사항을 분석하고 컴포넌트, 역할, 의존성을 파악해줘"라는 프롬프트가
Claude Code의 STDIN에 자동으로 들어갑니다.

왜 이게 좋으냐면:

- MCP 도구 이름을 외울 필요가 없습니다
- `create_tasks_bulk`? `spawn_agent`? 이런 거 몰라도 됩니다
- 그냥 `/`만 치면 돼요

키보드 방향키로 선택하고, Enter로 실행. 이게 전부입니다.

화면: `/analyze`를 선택한 후, Claude Code가 분석을 시작하는 모습

### 3. 올인원 워크스페이스 — 4개 탭 (5분)

화면: 마블로 앱 상단 탭 바 — Board, Code, Agents, Flows

이제 마블로의 4개 탭을 하나씩 보겠습니다.

**Board 탭 — 칸반 보드**

화면: Board 탭 활성화 — 칸반 보드 전체

여기가 모든 것의 중심입니다.
TODO, CLAIMED, IN_PROGRESS, REVIEW, DONE — 5개 컬럼이 있고,
태스크 카드를 드래그앤드롭으로 이동할 수 있습니다.

근데 중요한 건, 이 카드들이 에이전트에 의해 **자동으로** 움직인다는 겁니다.
Backend Agent가 태스크를 claim하면 TODO에서 CLAIMED로 자동 이동.
작업을 시작하면 IN_PROGRESS로.
다 했으면 REVIEW로.

이게 실시간 Firestore 동기화로 동작하기 때문에,
에이전트가 상태를 바꾸면 0.5초 안에 보드에 반영됩니다.

**Code 탭 — Monaco Editor**

화면: Code 탭 — 파일 트리 + 에디터

VS Code와 같은 Monaco Editor가 내장되어 있습니다.
왼쪽에 파일 트리, 오른쪽에 코드 에디터.
에이전트가 만든 코드를 바로 여기서 확인하고 수정할 수 있습니다.
VS Code를 별도로 열 필요가 없어요.

**Agents 탭 — 에이전트 대시보드**

화면: Agents 탭 — 에이전트 카드들 + 상태 표시

여기서 현재 돌아가는 에이전트들의 상태를 볼 수 있습니다.
각 에이전트 카드에 모델(Claude/Gemini/GPT), 역할, 현재 상태가 표시됩니다.
에이전트를 클릭하면 해당 에이전트의 터미널로 바로 이동합니다.

**Flows 탭 — 비주얼 플로우 에디터**

화면: Flows 탭 — DAG 에디터

이건 모듈 2에서 자세히 다룰 건데, 미리 보여드리면:
노드를 배치하고, 연결하면 파이프라인이 만들어집니다.
Input → LLM 분석 → Branch → Agent → Output
이런 흐름을 시각적으로 설계할 수 있어요.

### 4. 통합 터미널 패널 (3분)

화면: Board 탭에서 칸반 보드 + 하단 터미널 패널

이게 제가 개인적으로 가장 좋아하는 기능인데요.

Board 탭을 보면, 위쪽 60%가 칸반 보드이고, 아래쪽 40%가 터미널입니다.
이 경계선을 드래그해서 크기를 조절할 수도 있습니다.

```
┌──────────────────────────────────────┐
│ [마블로]  Board  Code  Agents  Flows │
├──────────────────────────────────────┤
│                                      │
│         칸반 보드 (60%)               │
│   TODO → CLAIMED → IN_PROGRESS →     │
│                                      │
├══════════════════════════════════════┤ ← 드래그 리사이즈
│ ● Orchestrator Terminal         [✕]  │
│ $ claude /tf-start                   │
│ $ _                        (40%)     │
└──────────────────────────────────────┘
```

여기서 두 가지를 동시에 할 수 있습니다:

1. 칸반 보드에서 카드가 움직이는 걸 보면서
2. 터미널에서 에이전트가 코딩하는 걸 실시간으로 관찰

오케스트레이터 터미널이 기본으로 열리고,
에이전트가 스폰되면 그 에이전트의 터미널 탭이 자동으로 추가됩니다.
탭을 클릭해서 에이전트 간 전환하면 됩니다.

### 5. 멀티모델 에이전트 지원 (3분)

화면: 에이전트 추가 모달 — 모델 선택 드롭다운

이건 다른 어떤 플랫폼에도 없는, 마블로만의 킬링 포인트입니다.

에이전트를 추가할 때 모델을 선택할 수 있습니다:

- **Claude**: 복잡한 로직, 코드 품질
- **Gemini**: 긴 컨텍스트, 빠른 속도
- **GPT (Codex)**: 풀스택 자동화
- **Custom**: 여러분이 원하는 어떤 모델이든

화면: agent-config.ts 코드 하이라이트

내부적으로 각 모델에 맞는 CLI 명령어가 자동으로 구성됩니다:

```typescript
// electron/agent-config.ts
switch (model) {
  case "claude":
    return {
      command: "claude",
      args: ["--dangerously-skip-permissions", "--mcp-config", mcpConfigPath],
      env,
    };
  case "gemini":
    return {
      command: "gemini",
      args: [],
      env: { ...env, GEMINI_MCP_CONFIG: mcpConfigPath },
    };
  case "gpt":
    return {
      command: "codex",
      args: ["--full-auto"],
      env,
    };
  case "custom":
    return {
      command: baseCommand,
      args: [],
      env: { ...env, MCP_CONFIG_PATH: mcpConfigPath },
    };
}
```

Claude는 `--mcp-config`로, Gemini는 `GEMINI_MCP_CONFIG` 환경변수로,
GPT(Codex)는 `--full-auto`로 — 모델마다 MCP 설정 방식이 다른데,
마블로가 이걸 자동으로 처리해줍니다.

여러분은 드롭다운에서 모델만 선택하면 됩니다.
뒤에서 벌어지는 복잡한 설정은 신경 쓸 필요 없어요.

모듈 5에서 이 멀티모델을 실전에서 활용하는 법을 자세히 다룹니다.

### 6. MCP 브릿지 서버 (3분)

화면: 코드 에디터 — bridge-server.ts

마지막으로 MCP 브릿지 서버입니다.
이건 좀 기술적인 내용인데, 알아두면 시스템을 이해하는 데 큰 도움이 됩니다.

문제 상황을 먼저 설명할게요.
Claude Code 안에서 돌아가는 MCP 서버는 별도의 Node.js 프로세스입니다.
이 MCP 서버가 "에이전트를 스폰해줘"라고 하면, 그건 **Electron 메인 프로세스**가 해야 합니다.
근데 MCP 서버와 Electron 프로세스는 서로 직접 통신할 수 없어요.

그래서 HTTP 브릿지 서버가 중간에 다리 역할을 합니다.

```
MCP 서버 (spawn_agent 도구 호출)
    ↓ HTTP POST
Bridge Server (127.0.0.1:랜덤포트)
    ↓ 내부 호출
AgentManager (Electron 메인 프로세스)
    ↓ PTY 생성
새 에이전트 Claude Code 인스턴스
```

```typescript
// electron/bridge-server.ts
// POST /spawn-agent → AgentManager.launch()
// POST /notify-orchestrator → 오케스트레이터 PTY에 메시지 전달
// GET /health → 헬스체크
```

두 가지 핵심 엔드포인트:

1. `/spawn-agent`: MCP 도구에서 에이전트 스폰 요청 → Electron이 실제로 PTY 생성
2. `/notify-orchestrator`: 에이전트가 태스크 상태를 바꾸면 → 오케스트레이터한테 알림

이게 있어서 에이전트가 태스크 상태를 변경하면 칸반 보드에 **즉시** 반영되는 겁니다.

## 정리 (2분)

화면: 슬라이드 — 핵심 기능 6가지 요약

오늘 본 핵심 기능 정리합니다:

| #   | 기능                     | 핵심                                                                     |
| --- | ------------------------ | ------------------------------------------------------------------------ |
| 1   | STDIN 자동 프롬프트 주입 | `pty.write(sessionId, prompt + '\r')` — 에이전트를 프로그래밍적으로 제어 |
| 2   | 슬래시 메뉴              | `/` 입력 → 명령어 선택 → 프롬프트 자동 주입                              |
| 3   | 올인원 워크스페이스      | Board + Code + Agents + Flows — 4개 탭                                   |
| 4   | 통합 터미널              | 칸반 위 + 터미널 아래 = 한 화면 관찰                                     |
| 5   | 멀티모델                 | Claude + Gemini + GPT + Custom                                           |
| 6   | MCP 브릿지               | MCP → HTTP → Electron → 칸반 실시간 동기화                               |

이 6가지가 마블로가 "그냥 AI 도구"가 아니라
**에이전트 군단 워크스페이스**인 이유입니다.

다음 섹션에서는 이걸 직접 설치해보겠습니다.
v1 때는 Docker 5개 컨테이너를 띄워야 했는데,
v3는... 앱 더블클릭하면 끝입니다.
