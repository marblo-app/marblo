# 마블로 멀티모델 설정

> 모듈 5 · 섹션 5-2 · 약 20분

## 도입 (3분)

자, 이전 섹션에서 왜 멀티모델이 필요한지 알아봤죠? 이번에는 실제로 마블로 내부에서 멀티모델이 어떻게 동작하는지 코드를 보면서 이해해봅시다.

화면: VS Code에서 `v3/electron/agent-config.ts` 파일 열기

마블로에서 에이전트를 추가할 때, 모델을 선택하면 내부적으로 많은 일이 자동으로 벌어집니다. CLI 커맨드 생성, MCP 설정 파일 생성, 환경변수 주입 — 이 모든 게 `agent-config.ts` 한 파일에서 관리됩니다.

이 파일을 이해하면, 마블로가 어떻게 서로 다른 CLI 도구들을 통합하는지 완벽하게 알 수 있습니다.

---

## 본문 1: ModelType과 기본 구조 (4분)

화면: `agent-manager.ts`의 타입 정의

먼저 마블로가 지원하는 모델 타입부터 봅시다.

```typescript
// agent-manager.ts
export type ModelType = 'claude' | 'gemini' | 'gpt' | 'custom';
export type AgentStatus = 'idle' | 'working' | 'error' | 'stopped';
```

네 가지 모델 타입이 있습니다:
- `claude` — Claude Code CLI
- `gemini` — Gemini CLI
- `gpt` — OpenAI Codex CLI
- `custom` — 사용자 정의 커맨드

`custom`이 있다는 게 중요합니다. 나중에 새로운 AI CLI 도구가 나와도 마블로에서 바로 쓸 수 있다는 뜻이에요.

그리고 `LaunchConfig` 인터페이스를 봅시다:

```typescript
// agent-config.ts
export interface LaunchConfig {
  model: ModelType;
  command: string;      // 실행할 CLI 명령어
  args: string[];       // CLI 인자
  env: Record<string, string>;  // 환경변수
  mcpConfigPath: string;        // MCP 설정 파일 경로
  skillContent: string;         // 에이전트 스킬 파일 내용
  initialPrompt?: string;       // 첫 프롬프트
}
```

모든 모델이 같은 `LaunchConfig` 인터페이스를 공유합니다. 이게 핵심 설계예요. 모델이 뭐든 간에, 마블로 입장에서는 "커맨드 + 인자 + 환경변수 + MCP 설정"만 있으면 에이전트를 실행할 수 있거든요.

## 본문 2: 모델별 CLI 커맨드 빌드 (7분)

화면: `agent-config.ts`의 `buildCLICommand` 메서드

이제 핵심 메서드를 봅시다. 모델별로 어떤 CLI 커맨드가 생성되는지요.

```typescript
private buildCLICommand(
  model: ModelType,
  baseCommand: string,
  mcpConfigPath: string,
  projectDir: string,
): { command: string; args: string[]; env: Record<string, string> } {
  const env = getMCPServerEnv(projectDir);

  switch (model) {
    case 'claude':
      return {
        command: baseCommand || 'claude',
        args: ['--dangerously-skip-permissions', '--mcp-config', mcpConfigPath],
        env,
      };

    case 'gemini':
      return {
        command: baseCommand || 'gemini',
        args: [],
        env: { ...env, GEMINI_MCP_CONFIG: mcpConfigPath },
      };

    case 'gpt':
      return {
        command: baseCommand || 'codex',
        args: ['--full-auto'],
        env,
      };

    case 'custom':
      return {
        command: baseCommand,
        args: [],
        env: { ...env, MCP_CONFIG_PATH: mcpConfigPath },
      };

    default:
      return { command: baseCommand, args: [], env };
  }
}
```

하나씩 볼게요.

### Claude 모델

```bash
claude --dangerously-skip-permissions --mcp-config /tmp/marblo-agent-configs/claude-mcp-agent123.json
```

- `--dangerously-skip-permissions`: 파일 읽기/쓰기 등의 권한 확인을 건너뜁니다. 에이전트가 자율적으로 작업하려면 필수예요.
- `--mcp-config`: MCP 서버 설정 파일 경로를 직접 전달합니다. Claude Code는 이 플래그를 통해 마블로 MCP 서버에 연결됩니다.

### Gemini 모델

```bash
GEMINI_MCP_CONFIG=/tmp/marblo-agent-configs/gemini-mcp-agent456.json gemini
```

Gemini CLI는 MCP 설정을 CLI 플래그가 아니라 **환경변수**로 받습니다. `GEMINI_MCP_CONFIG` 환경변수에 설정 파일 경로를 넣어주면 됩니다. 접근 방식이 다르죠? 하지만 마블로는 이 차이를 추상화해줍니다.

### Codex (GPT) 모델

```bash
codex --full-auto
```

Codex CLI는 `--full-auto` 플래그로 자동 모드로 실행합니다. 참고로 Codex의 MCP 통합은 아직 발전 중이어서, 현재는 마블로가 STDIN 주입 방식으로 태스크를 전달합니다.

### Custom 모델

```bash
MCP_CONFIG_PATH=/tmp/marblo-agent-configs/custom-mcp-agent789.json <사용자_정의_커맨드>
```

Custom은 사용자가 직접 CLI 커맨드를 지정하고, `MCP_CONFIG_PATH` 환경변수로 MCP 설정을 전달합니다. 예를 들어 Aider 같은 도구를 연결할 때 쓸 수 있어요.

## 본문 3: MCP 설정 자동 생성 (4분)

화면: `generateMCPConfig` 메서드 + 생성된 JSON 파일

에이전트를 추가하면, 마블로가 자동으로 MCP 설정 파일을 생성합니다.

```typescript
generateMCPConfig(agentId: string, model: ModelType, projectDir: string): string {
  fs.mkdirSync(CONFIG_DIR, { recursive: true });
  const mcpEntry = buildMCPServerEntry(projectDir);

  switch (model) {
    case 'claude':
      return this.generateClaudeConfig(agentId, mcpEntry);
    case 'gemini':
      return this.generateGeminiConfig(agentId, mcpEntry);
    case 'gpt':
      return this.generateGPTConfig(agentId, mcpEntry);
    case 'custom':
      return this.generateCustomConfig(agentId, mcpEntry);
  }
}
```

생성되는 MCP 설정 파일은 이런 모습입니다:

```json
{
  "mcpServers": {
    "marblo": {
      "command": "node",
      "args": ["/path/to/v3/dist-mcp/index.js"],
      "env": {
        "PATH": "/opt/homebrew/bin:/usr/local/bin:...",
        "MARBLO_PROJECT": "my-project-id",
        "MARBLO_SKILLS_DIR": "/path/to/v3/skills",
        "MARBLO_BRIDGE_PORT": "3847"
      }
    }
  }
}
```

여기서 중요한 점:

1. **모든 모델이 같은 MCP 서버에 연결됩니다.** `marblo`라는 이름의 MCP 서버가 하나 돌고, Claude든 Gemini든 이 서버와 통신합니다.

2. **MCP 서버는 Node.js 프로세스입니다.** `dist-mcp/index.js`를 실행하면, 마블로의 MCP 도구들(`create_task`, `update_task_status`, `get_agent_skill` 등)이 에이전트에게 제공됩니다.

3. **`MARBLO_BRIDGE_PORT`**: 이 환경변수가 MCP 서버와 Electron 앱 사이의 다리 역할을 합니다. MCP 서버에서 `spawn_agent` 같은 도구를 호출하면, 이 포트를 통해 Electron 메인 프로세스에 전달됩니다.

설정 파일은 임시 디렉토리(`/tmp/marblo-agent-configs/`)에 생성되고, 에이전트가 종료되면 자동으로 정리됩니다:

```typescript
cleanup(agentId: string): void {
  const files = this.generatedFiles.get(agentId) || [];
  for (const filePath of files) {
    if (fs.existsSync(filePath)) {
      fs.unlinkSync(filePath);
    }
  }
  this.generatedFiles.delete(agentId);
}
```

## 본문 4: 에이전트 추가 모달 UI 흐름 (3분)

화면: 마블로 앱의 에이전트 추가 모달 스크린샷

실제로 사용자가 에이전트를 추가할 때의 흐름을 봅시다.

**1단계: 모델 선택**

에이전트 추가 모달을 열면, 네 가지 모델 옵션이 보입니다:
- Claude (추천)
- Gemini
- Codex (GPT)
- Custom

**2단계: 역할(Role) 입력**

backend, frontend, test, devops 중에 선택하거나 직접 입력합니다.

**3단계: CLI 커맨드 자동 생성**

모델을 선택하면 CLI 커맨드가 자동으로 생성됩니다. 사용자가 수정할 수도 있어요:

```
Claude  → claude
Gemini  → gemini
Codex   → codex
Custom  → (직접 입력)
```

**4단계: API 키 확인**

각 모델별로 필요한 API 키가 설정되어 있는지 확인합니다:
- Claude → `ANTHROPIC_API_KEY` (Claude Code 인증이 되어 있으면 별도 키 불필요)
- Gemini → `GEMINI_API_KEY`
- Codex → ChatGPT Pro 구독 필요
- Custom → 모델에 따라 다름

**5단계: 실행**

"Launch" 버튼을 누르면 `AgentManager.launch()`가 호출되고, 방금 본 모든 과정이 자동으로 진행됩니다.

## 본문 5: PATH 문제 해결 (2분)

화면: `getEnrichedPath` 함수

실무에서 자주 만나는 문제가 있어요. macOS에서 Electron 앱이 Finder에서 실행되면, 터미널의 PATH를 상속받지 못합니다. 그래서 `gemini` 명령을 못 찾는다거나 `codex`를 못 찾는 에러가 나죠.

마블로는 이걸 `getEnrichedPath()` 함수로 해결합니다:

```typescript
function getEnrichedPath(): string {
  const basePath = process.env.PATH || '';
  const extraPaths = [
    '/opt/homebrew/bin',     // Homebrew (Apple Silicon)
    '/opt/homebrew/sbin',
    '/usr/local/bin',        // Homebrew (Intel)
    '/usr/bin', '/bin',
    path.join(os.homedir(), '.nvm/versions/node', process.version, 'bin'),
    path.join(os.homedir(), '.npm/bin'),
    path.join(os.homedir(), '.local/bin'),
    path.join(os.homedir(), '.cargo/bin'),
  ];

  const pathSet = new Set(basePath.split(':'));
  for (const p of extraPaths) {
    pathSet.add(p);
  }
  return Array.from(pathSet).join(':');
}
```

Homebrew, nvm, npm, cargo 등 일반적인 패키지 관리자 경로를 전부 추가해줍니다. 이렇게 하면 어디서든 CLI 도구를 찾을 수 있어요.

이건 여러분이 직접 새 CLI 도구를 `custom` 타입으로 추가할 때도 알아두면 좋은 내용입니다.

## 정리 (2분)

화면: 요약 다이어그램

정리해볼게요.

마블로의 멀티모델 설정 핵심:

1. **`ModelType`**: `claude | gemini | gpt | custom` 네 가지를 지원
2. **`buildCLICommand`**: 모델별로 다른 CLI 커맨드와 인자를 자동 생성
   - Claude → `--mcp-config` 플래그
   - Gemini → `GEMINI_MCP_CONFIG` 환경변수
   - Codex → `--full-auto` 플래그
   - Custom → `MCP_CONFIG_PATH` 환경변수
3. **MCP 설정 자동 생성**: 에이전트마다 독립적인 MCP 설정 파일이 만들어지고, 종료 시 자동 정리
4. **PATH 자동 보강**: macOS에서 CLI 도구를 못 찾는 문제를 자동으로 해결

핵심 원리는 이겁니다 — **모든 모델의 차이를 `LaunchConfig` 하나의 인터페이스로 추상화.** 그래서 마블로 입장에서는 Claude든 Gemini든 그냥 "command + args + env"를 가진 에이전트일 뿐이에요.

다음 섹션에서는 실제로 Claude, Gemini, Codex 에이전트를 한 프로젝트에 같이 붙여서 혼합팀을 구성하는 실습을 해보겠습니다.
