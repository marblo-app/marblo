# 첫 풀사이클 체험

> 모듈 1 · 섹션 1-5 · 약 25분
> 관련: [[1-4_환경설정_MCP_Hook]] | [[실습_첫_풀사이클]]

---

## 도입 (2분)

자, 드디어 이 순간이 왔습니다.

마블로 설치하고, Claude Code 세팅하고, MCP 연결하고, 슬래시 스킬 설치했죠?
이제 이 모든 걸 사용해서 **처음부터 끝까지** 한 바퀴 돌아보겠습니다.

이번 섹션에서 하는 건:
1. `/tf-plan`으로 Hello World API 프로젝트를 기획하고
2. `/tf-start`로 태스크 생성 + 에이전트 스폰하고
3. 칸반 보드에서 카드가 자동으로 움직이는 걸 관찰하고
4. `/tf-review`로 리뷰해서 완료

**5분 만에** 전체 흐름을 체험합니다.
나머지 강의는 전부 이 흐름을 **잘 하는 법**을 배우는 겁니다.

화면: 마블로 앱 — Board 탭 + 하단 오케스트레이터 터미널 (빈 상태)

---

## 본문

### Step 1: `/tf-plan` — 프로젝트 기획 (7분)

화면: 오케스트레이터 터미널 활성화

**(실습) 오케스트레이터 터미널에서 입력:**

```
/tf-plan Hello World API
```

화면: Claude Code가 소크라틱 질문을 시작하는 모습

`/tf-plan`을 실행하면 Claude Code가 소크라틱 질문을 합니다.
"Hello World API를 어떤 기술 스택으로 만들까요?"
"어떤 엔드포인트가 필요한가요?"
"인증이 필요한가요?"

지금은 간단하게 답변합시다:

```
간단한 FastAPI Hello World API.
GET /hello → "Hello, World!" 반환.
GET /hello/{name} → "Hello, {name}!" 반환.
테스트도 포함.
```

화면: Claude Code가 PRD를 생성하는 모습

Claude Code가 답변을 바탕으로:
1. **PRD (Product Requirements Document)** 를 생성합니다
2. PRD를 기반으로 **태스크를 분해**합니다

분해된 태스크 예시:
```
[TASK-001] FastAPI 프로젝트 초기 설정 (backend, priority=5)
[TASK-002] /hello 엔드포인트 구현 (backend, depends_on: TASK-001)
[TASK-003] /hello/{name} 엔드포인트 구현 (backend, depends_on: TASK-001)
[TASK-004] API 테스트 작성 (test, depends_on: TASK-002, TASK-003)
```

보이시죠? 역할(role)과 의존성(depends_on)이 자동으로 설정됩니다.
TASK-004(테스트)는 TASK-002와 TASK-003이 완료된 후에야 시작될 수 있습니다.

Claude Code가 "이대로 태스크를 생성할까요?"라고 물어봅니다.
확인하고 진행합시다.

### Step 2: `/tf-start` — 태스크 생성 + 에이전트 스폰 (5분)

화면: 오케스트레이터 터미널

```
/tf-start
```

또는 `/tf-plan` 과정에서 이어서 "진행해줘"라고 하면 됩니다.

`/tf-start`가 하는 일:
1. `create_tasks_bulk` MCP 도구를 호출해서 태스크 4개를 일괄 생성
2. `spawn_agent` MCP 도구를 호출해서 에이전트를 스폰

화면: 칸반 보드에 카드 4개가 TODO 컬럼에 나타나는 모습

잠깐, 여기서 보세요. 칸반 보드 위쪽에 카드가 하나씩 나타나기 시작합니다.
전부 TODO 컬럼에 들어가 있죠.

그리고 터미널 쪽을 보면:

```
Agent spawned successfully!
  Name: backend-hello
  Model: claude
  Role: backend
  Agent ID: a1b2c3d4-...
  PTY Session: agent-a1b2c3d4-...
```

에이전트가 스폰됐습니다!
터미널 패널에 새 탭이 생기죠? "Agent: backend-hello" 탭을 클릭하면
그 에이전트가 코딩하는 모습을 실시간으로 볼 수 있습니다.

### Step 3: 칸반 보드에서 실시간 관찰 (7분)

화면: 마블로 앱 — 칸반 보드 + 터미널 (에이전트 작업 중)

자, 이제 가만히 지켜봅시다.

```
┌──────────────────────────────────────────────────────┐
│  TODO        CLAIMED      IN_PROGRESS    REVIEW  DONE│
│ ┌────────┐ ┌────────┐                                │
│ │TASK-004│ │TASK-001│                                │
│ │ 테스트  │ │ 초기설정│                                │
│ └────────┘ └────────┘                                │
│ ┌────────┐                                           │
│ │TASK-002│                                           │
│ │ /hello │                                           │
│ └────────┘                                           │
│ ┌────────┐                                           │
│ │TASK-003│                                           │
│ │/hello/n│                                           │
│ └────────┘                                           │
├══════════════════════════════════════════════════════┤
│ ● backend-hello                                [✕]  │
│ > claim_task("task-001-id", "backend-hello")         │
│ > Successfully claimed task: FastAPI 프로젝트 초기 설정│
│ > update_task_status("task-001-id", "IN_PROGRESS")   │
│ > 작업을 시작합니다...                                │
└──────────────────────────────────────────────────────┘
```

하나씩 보겠습니다:

**1단계: CLAIMED**
에이전트가 `claim_task`를 호출합니다.
→ TASK-001이 TODO에서 CLAIMED로 이동!
카드에 "backend-hello" 라벨이 붙습니다.

**2단계: IN_PROGRESS**
에이전트가 `update_task_status`로 IN_PROGRESS로 변경합니다.
→ TASK-001이 IN_PROGRESS 컬럼으로 이동!
에이전트가 실제로 코딩을 시작합니다.

화면: 에이전트 터미널에서 파일을 생성하는 모습

에이전트가 `main.py` 파일을 만들고, requirements.txt를 작성하고...
진행하면서 `add_activity`로 기록합니다.

**3단계: REVIEW**
코딩이 끝나면 에이전트가 `submit_for_review`를 호출합니다.
→ TASK-001이 REVIEW 컬럼으로 이동!

그리고 나서 에이전트는 자동으로 다음 태스크를 찾습니다.
`get_available_tasks("backend")`를 호출하면
TASK-002와 TASK-003이 나옵니다 (TASK-001 의존성이 해소되었으므로).

이 과정이 자동으로 반복됩니다.
여러분은 칸반 보드에서 카드가 오른쪽으로 쭉 밀려가는 걸 지켜보면 됩니다.

### Step 4: `/tf-review` — 리뷰 + 완료 (4분)

화면: REVIEW 컬럼에 카드가 쌓인 모습

에이전트가 작업을 끝내면 REVIEW 컬럼에 카드가 쌓입니다.
이제 PM인 여러분 차례입니다.

```
/tf-review
```

화면: Claude Code가 REVIEW 태스크 목록을 보여주는 모습

`/tf-review`를 실행하면:
1. REVIEW 상태의 태스크를 모두 가져옵니다
2. 각 태스크의 활동 로그를 보여줍니다
3. 코드 변경 사항을 요약합니다
4. Approve 또는 Reject를 선택합니다

```
[REVIEW] TASK-001: FastAPI 프로젝트 초기 설정
  - main.py 생성 (FastAPI app)
  - requirements.txt 생성
  → Approve? (y/n): y

[REVIEW] TASK-002: /hello 엔드포인트 구현
  - GET /hello → {"message": "Hello, World!"}
  → Approve? (y/n): y
```

Approve하면 → 카드가 REVIEW에서 **DONE**으로 이동합니다!

전부 Approve하고 나면:

```
프로젝트 진행 현황: 4/4 (100%)
모든 태스크가 완료되었습니다! 🎉
```

화면: 칸반 보드 — 모든 카드가 DONE 컬럼에

카드 4개가 전부 DONE에 있습니다.
이게 전체 풀사이클입니다.

### "이게 전체 흐름입니다" (2분)

화면: 슬라이드 — 전체 흐름 다이어그램

지금 한 일을 정리하면:

```
/tf-plan  →  소크라틱 질문 → PRD → 태스크 분해
    ↓
/tf-start →  create_tasks_bulk + spawn_agent
    ↓
관찰      →  칸반: TODO → CLAIMED → IN_PROGRESS → REVIEW
    ↓
/tf-review → Approve → DONE
```

슬래시 스킬 3개로 전체 프로젝트를 완성했습니다.

**"이게 전체 흐름입니다. 나머지는 이걸 잘 하는 법입니다."**

모듈 2에서는 방금 뒤에서 무슨 일이 벌어졌는지 뜯어봅니다 — MCP, 상태 머신, 스킬 파일.
모듈 3에서는 좀 더 복잡한 프로젝트(날씨 대시보드)로 프론트+백엔드 왕복을 체험합니다.
모듈 4에서는 진짜 실전 — AI SaaS를 처음부터 끝까지 빌드합니다.
모듈 5에서는 Claude + Gemini + GPT를 동시에 돌리는 멀티모델을 다룹니다.

전부 지금 한 이 흐름의 확장입니다.

## 정리 (1분)

첫 풀사이클 핵심 요약:

| 단계 | 슬래시 스킬 | 뒤에서 호출되는 MCP 도구 |
|------|-----------|----------------------|
| 기획 | `/tf-plan` | (대화 기반, 직접 도구 호출 없음) |
| 실행 | `/tf-start` | `create_tasks_bulk` + `spawn_agent` |
| 관찰 | — | 에이전트가 `claim_task`, `update_task_status`, `add_activity` 자동 호출 |
| 리뷰 | `/tf-review` | `get_all_tasks` + `update_task_status(DONE)` |

실습 시트는 [[실습_첫_풀사이클]]을 참고하세요.

모듈 1 끝입니다!
설치하고, 핵심 기능 이해하고, 첫 풀사이클을 돌려봤습니다.
