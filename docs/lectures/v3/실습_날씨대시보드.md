# 실습: 날씨 대시보드

> 모듈 3 · 실습 · 전체 시나리오
> 관련: [[3-1_날씨대시보드_기획]] | [[3-2_날씨대시보드_실행]] | [[3-3_날씨대시보드_PM역할]] | [[3-4_날씨대시보드_회고]]

---

## 실습 개요

**목표:** 마블로의 전체 워크플로우를 처음부터 끝까지 직접 실행해봅니다.

**결과물:** 도시 이름 → 현재 날씨 + 5일 예보 카드형 대시보드

**기술 스택:** FastAPI + Next.js + OpenWeatherMap API

**예상 소요 시간:** 약 40-60분 (에이전트 작업 시간 포함)

---

## 사전 준비

### 1. OpenWeatherMap API 키 발급

아직 API 키가 없다면:

1. [https://openweathermap.org](https://openweathermap.org) 회원가입
2. API Keys 메뉴에서 키 생성 (무료 플랜 OK)
3. `.env` 파일에 추가:

```bash
OPENWEATHER_API_KEY=your_api_key_here
```

### 2. 프로젝트 디렉토리 준비

```bash
mkdir weather-dashboard
cd weather-dashboard
```

### 3. 마블로 데스크탑 앱 실행 확인

- 마블로 앱이 실행 중인지 확인
- Claude Code 세션이 연결되어 있는지 확인
- MCP 서버 상태가 `Connected`인지 확인

---

## Step 1: 기획 — `/tf-plan` (5분)

### 1-1. 기획 명령 실행

마블로 터미널에서:

```bash
/tf-plan 날씨 대시보드. 도시 검색하면 현재 날씨 + 5일 예보. FastAPI + Next.js + OpenWeatherMap API. 카드형 UI.
```

### 1-2. Socratic Questions 응답

마블로가 질문을 하면 아래와 같이 답변하세요:

| 질문 | 추천 답변 |
|------|----------|
| UI 형태는? | 카드형 대시보드, 반응형 |
| 인증 필요? | 아니요, 공개 서비스 |
| 추가 기능? | 즐겨찾기 도시 저장 |
| 데이터베이스? | SQLite (간단하게) |
| 차트 라이브러리? | Recharts 또는 Chart.js |

### 1-3. 생성된 태스크 확인

마블로가 다음과 같은 6개 태스크를 제안할 것입니다:

```
[TASK-001] 날씨 API 프록시 엔드포인트      (backend)
[TASK-002] 즐겨찾기 도시 저장 API          (backend, depends_on: 001)
[TASK-003] 도시 검색 UI                    (frontend, depends_on: 001)
[TASK-004] 날씨 카드 컴포넌트              (frontend, depends_on: 001)
[TASK-005] 5일 예보 차트                   (frontend, depends_on: 004)
[TASK-006] API 연동 테스트                 (test, depends_on: 003, 005)
```

### 체크포인트

- [ ] PRD(Product Requirements Document)가 생성되었는가?
- [ ] 태스크가 6개 생성되었는가?
- [ ] 각 태스크에 의존성(`depends_on`)이 올바르게 설정되었는가?
- [ ] 태스크가 구체적인가? ("백엔드 만들어줘" 같은 모호한 태스크는 없는가?)

---

## Step 2: 실행 — `/tf-start` (5분)

### 2-1. 실행 명령

```bash
/tf-start
```

### 2-2. 관찰 포인트

실행 후 다음을 확인하세요:

1. **칸반 보드** — 6개 카드가 생성되었는가?
2. **에이전트 스폰** — Backend Agent, Frontend Agent가 표시되는가?
3. **작업 시작** — Backend Agent가 TASK-001을 클레임했는가?
4. **블로킹 상태** — 프론트엔드 태스크(003, 004, 005)가 blocked로 표시되는가?

### 체크포인트

- [ ] `create_tasks_bulk`로 6개 태스크가 일괄 생성되었는가?
- [ ] 에이전트가 자동 스폰되었는가?
- [ ] TASK-001이 IN_PROGRESS 상태인가?

---

## Step 3: 모니터링 — `/tf-status` (반복)

에이전트가 작업하는 동안 주기적으로 상태를 확인하세요:

```bash
/tf-status
```

### 예상 진행 순서

```
Phase 1: Backend Agent → TASK-001 (날씨 API)
Phase 2: Backend Agent → TASK-002 (즐겨찾기) + Frontend Agent → TASK-003, 004 (검색 UI, 날씨 카드)
Phase 3: Frontend Agent → TASK-005 (예보 차트)
Phase 4: Test → TASK-006 (연동 테스트)
```

### 관찰 포인트

- 에이전트 터미널 로그에서 어떤 파일을 생성하는지 확인
- 칸반 보드에서 카드가 어떤 열로 이동하는지 관찰
- 의존성이 해소되면서 blocked 태스크가 활성화되는 시점 포착

---

## Step 4: 리뷰 — `/tf-review` (핵심!)

### 4-1. 백엔드 리뷰

TASK-001이 REVIEW 상태가 되면:

```bash
/tf-review TASK-001
```

**확인 사항:**
- [ ] `GET /api/weather/{city}` 엔드포인트가 구현되었는가?
- [ ] `GET /api/weather/{city}/forecast` 엔드포인트가 구현되었는가?
- [ ] OpenWeatherMap API 연동 코드가 있는가?
- [ ] 에러 핸들링이 되어 있는가?

문제없으면: `Approve`
수정 필요하면: `Reject` + 피드백 메시지

### 4-2. 프론트엔드 리뷰

TASK-004(날씨 카드)가 REVIEW가 되면:

```bash
/tf-review TASK-004
```

**확인 사항:**
- [ ] 온도, 습도, 풍속 등 날씨 정보가 카드에 표시되는가?
- [ ] 카드 디자인이 깔끔한가?
- [ ] 반응형 레이아웃인가?

### 4-3. 차트 리뷰

TASK-005(5일 예보 차트)가 REVIEW가 되면:

```bash
/tf-review TASK-005
```

**확인 사항:**
- [ ] 5일 예보 데이터가 차트로 시각화되는가?
- [ ] 차트 라이브러리가 올바르게 적용되었는가?
- [ ] X축(날짜), Y축(온도) 레이블이 있는가?

---

## Step 5: 결과 확인 (5분)

### 5-1. 프로젝트 실행

모든 태스크가 DONE이 되면:

```bash
# 백엔드
cd weather-dashboard/backend
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8001

# 프론트엔드 (새 터미널)
cd weather-dashboard/frontend
npm install
npm run dev
```

### 5-2. 기능 테스트

브라우저에서 `http://localhost:3000` 접속:

| 테스트 항목 | 확인 |
|------------|------|
| 도시 검색 | "Seoul" 입력 → 결과 표시 |
| 현재 날씨 카드 | 온도, 습도, 풍속 표시 |
| 5일 예보 차트 | 날짜별 온도 차트 |
| 즐겨찾기 | 도시 저장/불러오기 |
| 에러 처리 | 잘못된 도시명 → 에러 메시지 |

### 5-3. 최종 체크포인트

- [ ] 전체 6개 태스크가 DONE 상태
- [ ] 에이전트가 생성한 코드로 앱이 정상 동작
- [ ] 직접 코딩한 부분이 없음 (PM 역할만 수행)

## 트러블슈팅

### 에이전트가 시작하지 않는 경우

```bash
# MCP 연결 확인
/tf-status

# 에이전트 수동 스폰
/tf-spawn-agents
```

### API 키 오류

```
HTTPException: 401 Unauthorized
```

→ `.env` 파일의 `OPENWEATHER_API_KEY` 값을 확인하세요.

### 의존성 교착 상태

태스크가 모두 blocked 상태라면:

```bash
# 태스크 의존성 확인
/tf-status --verbose

# 필요시 의존성 수동 해제
/tf-feedback TASK-XXX "의존성 해소, 작업 시작해주세요"
```
