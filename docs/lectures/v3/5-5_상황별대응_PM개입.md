# 상황별 대응 — PM이 개입하는 순간

> 모듈 5 · 섹션 5-5 · 약 25분
> 관련: [[5-4_Sprint2_프론트_병렬통합]] | [[5-6_통합리뷰_스프린트마무리]]

---

## 이 강의에서 다루는 것

- **학습목표:** 스프린트가 순조롭지 않을 때 — FAILED·BLOCKED·끼어드는 새 기능·세션 끊김·자원 정리 — PM이 쥐는 다섯 개의 손잡이를 익힌다.
- **시연할 마블로 화면·기능:** 보드 탭(FAILED/BLOCKED 컬럼) + 에이전트 탭(재시작·reuse·cleanup) + 오케 PTY.
- **진행할 프로젝트 단계:** P3 돌발 대응.
- **핵심 메시지:** "막힘은 정상이다. 마블로엔 상황마다 손잡이가 하나씩 있다."

---

## 도입 — 실전은 늘 어긋난다 (3분)

지금까지는 비교적 순조로운 흐름을 봤습니다. 하지만 실제 프로젝트는 **항상** 어딘가 어긋나요. 에이전트가 실패하고, 태스크가 막히고, 갑자기 새 기능이 필요해지죠.

> 화면: "상황별 대응" 타이틀 + 보드의 빨강(FAILED)·주황(BLOCKED) 카드 미리보기

이번 섹션에서는 PM이 만나는 **다섯 가지 상황**과 각각의 대응을 배웁니다.

1. **FAILED** — 에이전트 작업 실패 → 진단 후 재시작
2. **BLOCKED** — 에이전트가 결정을 요청 → PM이 답
3. **새 기능** — 스프린트 도중 기능 추가
4. **세션 끊김** — 끊겼다가 복구
5. **자원 정리** — 에이전트 재활용(reuse)·정리(cleanup)

---

## 본문

### 1. FAILED — 작업 실패와 재시작 (5분)

가장 흔한 상황입니다. 에이전트가 작업 중 에러로 실패하는 경우.

> 화면: 보드 탭 — TASK-005가 빨간색 FAILED 컬럼으로

예를 들어 서비스 LLM API 키가 잘못 설정됐거나 발송 API 할당량이 초과된 경우:

```
[backend-claude] TASK-005: FAILED
  Error: AuthenticationError: Invalid API key
  Attempts: 2/3
  Status: IN_PROGRESS → FAILED
```

보드에서 해당 카드가 빨갛게 바뀝니다.

**대응: `/tf-fix`**

```
/tf-fix TASK-005
```

> 화면: `/tf-fix` 진단 결과

```
🔍 Diagnosis: TASK-005 — 5톤 메일 생성 엔드포인트
  Root cause: LLM_API_KEY 환경 변수가 비었거나 잘못됨
  Suggested fix:
    1. .env의 LLM_API_KEY 확인
    2. 제공사 콘솔에서 키 재발급
    3. 백엔드 컨테이너 재시작
  [R]etry  [M]anual fix  [S]kip
```

마블로가 에러를 자동 진단하고 해결책을 제안합니다. 환경 변수를 고친 뒤:

```
R   # Retry — 에이전트가 TASK-005 재클레임 → FAILED → IN_PROGRESS
```

> **핵심:** FAILED가 떠도 당황하지 마세요. `/tf-fix`로 진단 → 원인 해결 → 재시작. 이 패턴 하나입니다.

### 2. BLOCKED — 에이전트가 결정을 요청 (4분)

의존성 문제가 아니라, **에이전트가 스스로 결정하지 못해** 막히는 경우입니다.

> 화면: 보드 탭 — TASK-017에 주황색 BLOCKED 표시

```
[frontend-codex] TASK-017: BLOCKED
  Reason: "A/B 대시보드 — 응답률 0건일 때 빈 화면 vs 안내 카드, PM 결정 필요"
  Status: IN_PROGRESS → BLOCKED
```

**대응: `/tf-feedback`** — PM이 의사결정을 내려줍니다.

```
/tf-feedback TASK-017 "안내 카드로. '아직 발송 데이터가 없어요. 첫 캠페인을 보내보세요' + CTA 버튼. 모바일에서는 1열로."
```

```
✅ Feedback delivered to TASK-017
[frontend-codex] received PM feedback, resuming
  Status: BLOCKED → IN_PROGRESS
```

> **핵심:** BLOCKED는 에이전트가 PM에게 결정을 요청하는 신호예요. 빨리 답할수록 프로젝트가 빨리 흐릅니다.

### 3. 새 기능 끼워넣기 — `/tf-add` (4분)

스프린트 도중 "이것도 있으면 좋겠다" 싶을 때.

> 화면: 오케 PTY — `/tf-add` 입력

```
/tf-add "발송 결과 CSV 내보내기" --role frontend --depends-on TASK-017 --priority medium
```

```
✅ New task created:
  [TASK-023] 발송 결과 CSV 내보내기
  Type: frontend · Depends on: TASK-017 · Priority: medium
[frontend-codex] new task detected: TASK-023 (queued)
```

보드에 새 카드가 추가되고, 의존성에 따라 적절한 시점에 에이전트가 잡습니다.

주의할 점:

- **스코프 크리프**를 경계하세요. 새 기능을 계속 더하면 졸업 작품이 끝나지 않습니다.
- 정말 필요한 것만 추가하고, 나머지는 **v2로** 미루세요.
- `--priority low`로 우선순위를 눌러두는 것도 방법입니다.

### 4. 세션 끊김 — 복구 (3분)

인터넷이 끊기거나 앱이 종료됐다 다시 켜진 경우. 마블로는 모든 상태를 서버에 저장하므로 진행이 사라지지 않습니다.

> 화면: 마블로 재시작 → 프로젝트 복구

```
/tf-resume
```

```
🔄 Resuming project: ReachWave
  ✅ 22 tasks loaded (18 DONE, 3 IN_PROGRESS, 1 TODO)
  ✅ 4 agents restored
  ✅ Activity log synced

  backend-claude  : resuming TASK-009 (was IN_PROGRESS)
  frontend-codex  : resuming TASK-016 (was IN_PROGRESS)
Ready to continue!
```

에이전트가 마지막 상태부터 다시 시작합니다.

> **핵심:** 세션이 끊겨도 보드·레인·활동 로그가 서버에 남아 있어요. `/tf-resume` 한 번이면 복구됩니다. (다만 너무 오래 방치하면 에이전트 컨텍스트가 희미해지니, 가능하면 같은 작업 흐름 안에서 재개하세요.)

### 5. 자원 정리 — reuse와 cleanup (4분)

스프린트가 끝나갈수록 유휴 에이전트가 생깁니다. 백엔드를 다 끝낸 에이전트가 손을 놓고 있는 식이죠. 이때 **에이전트 탭**에서 두 가지를 합니다.

> 화면: 에이전트 탭 — 각 에이전트 카드의 Reuse · Cleanup 액션

- **Reuse(재활용)** — 컨텍스트가 살아 있는 에이전트에게 같은 프로젝트의 **다음 태스크**를 맡깁니다. 새로 스폰하는 것보다 빠르고, 앞 작업의 맥락을 그대로 이어가요. (예: 백엔드를 끝낸 Claude를 응답률 집계 후속 보정에 재활용)
- **Cleanup(정리)** — 더는 필요 없는 에이전트를 정리해 자원을 회수합니다. 스프린트가 끝나면 깔끔하게 닫아두세요.

```
에이전트 탭
  backend-codex   [Reuse →] [Cleanup ✕]   idle 8m
  test-codex      [Reuse →] [Cleanup ✕]   done
```

> **핵심:** 에이전트는 일회용이 아니라 **재활용**하는 자원입니다. 유휴 에이전트를 다음 태스크에 붙이거나, 끝났으면 정리하세요. (멀티윈도우로 여러 프로젝트에 걸쳐 에이전트를 운용하는 심화는 모듈 6에서.)

## 정리 (1분)

| 상황      | 손잡이          | 어디서      |
| --------- | --------------- | ----------- |
| 작업 실패 | `/tf-fix`       | 보드 + 진단 |
| 결정 요청 | `/tf-feedback`  | 보드 카드   |
| 새 기능   | `/tf-add`       | 오케 PTY    |
| 세션 끊김 | `/tf-resume`    | 앱 재시작   |
| 자원 정리 | Reuse / Cleanup | 에이전트 탭 |

이 다섯 개만 알면 어떤 돌발 상황도 넘깁니다. 실전에서 가장 자주 쓰는 건 `/tf-fix`와 `/tf-feedback`이에요 — 에이전트는 완벽하지 않고, 방향은 PM이 잡으니까요.

다음 섹션에서는 보드를 비우고, 에이전트 통계를 확인하며 ReachWave **1차 스프린트를 마무리**합니다.
