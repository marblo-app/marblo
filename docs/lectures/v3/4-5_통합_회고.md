# 통합 + 회고 — 두 에이전트, 하나의 앱

> 모듈 4 · 섹션 4-5 · 약 30분
> 관련: [[4-4_리뷰거버넌스_반려재작업]] | [[5-1_요구사항분석_페르소나]]

---

## 이 강의에서 다루는 것

- **학습목표:** 두 모델이 각자 워크트리에서 만든 결과물을 **일괄 머지**해 하나의 동작하는 앱으로 통합하고, 보드로 의존성 흐름을 복기한다.
- **시연할 마블로 화면·기능:** 워크트리 탭(일괄 Rebase/Merge) + 브라우저(앱 실행 확인) + 보드 탭(의존성 흐름 복기).
- **진행할 프로젝트 단계:** **P2 완성** — 동작하는 날씨 대시보드.
- **핵심 메시지:** "**두 에이전트, 하나의 동작하는 앱.**"

---

## 도입 — 흩어진 작업을 하나로 (3분)

여기까지 왔습니다. Claude는 백엔드를, Codex는 프론트와 테스트를 각자의 워크트리에서 만들었고, 여러분은 그걸 리뷰해 승인했죠.

> 화면: 보드 탭 — 대부분의 카드가 DONE, 워크트리 탭에 🟢 머지 가능 행들

하지만 아직 코드는 **각자의 워크트리에 흩어져** 있습니다. 백엔드는 백엔드 브랜치에, 프론트는 프론트 브랜치에. 이걸 **하나의 main으로 합쳐야** 비로소 동작하는 앱이 됩니다.

이번 섹션에서 그 마지막 한 걸음 — **통합 머지**를 하고, 브라우저에서 실제로 동작하는 걸 확인한 뒤, 한 바퀴를 회고합니다.

---

## 본문

### 1. 워크트리 일괄 머지 (8분)

> 화면: 워크트리 탭 — 여러 🟢 머지 가능 행 + 일괄 머지

워크트리 탭으로 갑니다. 리뷰를 통과한 워크트리들이 🟢 **머지 가능** 상태로 줄 서 있을 거예요.

```
워크트리 탭
  agent/backend-task001     🟢 머지 가능   +68 −0
  agent/backend-task002     🟢 머지 가능   +45 −0
  agent/frontend-task003    🟢 머지 가능   +88 −2
  agent/frontend-task004    🟢 머지 가능   +94 −0
  agent/frontend-task005    🟢 머지 가능   +120 −5
  agent/test-task006        🟢 머지 가능   +60 −0
```

**(실습)** 각 워크트리에서 **Merge**(squash)를 누릅니다. 🟢인 것만 활성화돼 있어요.

```
✅ Merged agent/backend-task001 → main (squash, 1 commit)
✅ Merged agent/backend-task002 → main
✅ Merged agent/frontend-task003 → main
...
📜 완료 이력에 6건 기록 (모드: 🙂 사람)
```

> 💡 머지 순서는 의존성을 따릅니다 — **백엔드 먼저, 프론트 나중.** 만약 그새 main이 앞서가 🟡 뒤처짐이 된 워크트리가 있으면, 합치기 전에 **Rebase**로 따라잡으면 됩니다(4-3에서 배운 그대로).

머지가 끝나면 **완료 이력**에 누가 언제 무엇을 합쳤는지 전부 남습니다 — 프로젝트 / 태스크 ID / 브랜치 / 커밋 SHA / 시각 / 모드(🤖 자동 또는 🙂 사람). 팀 작업의 감사 추적이죠. 합치고 난 워크트리는 **일괄 cleanup**으로 정리합니다.

### 2. 앱 실행 확인 (7분)

> 화면: 브라우저 — 날씨 대시보드 "Seoul" 검색 → 카드 + 5일 예보 차트

이제 main에 모든 게 합쳐졌으니, 실제로 동작하는지 봅시다.

**(실습)** 백엔드와 프론트를 띄웁니다.

```bash
# 백엔드 (FastAPI)
cd backend && uvicorn app.main:app --reload --port 8001

# 프론트엔드 (Next.js) — 새 터미널
cd frontend && npm run dev
```

브라우저에서 앱을 열면:

1. 도시 검색창에 **"Seoul"** 입력
2. **현재 날씨 카드**가 뜬다 — 온도·습도·풍속
3. 아래에 **5일 예보 차트** (날짜 축 레이블 + 모바일 반응형, 4-4에서 반려해 고친 그 부분!)
4. 즐겨찾기 도시 저장도 동작

> 화면: 브라우저 — 모바일 폭으로 줄였을 때도 차트가 안 깨짐

**두 모델이 만든 백엔드와 프론트가 한 앱에서 맞물려 동작합니다.** Claude의 API 응답을 Codex의 컴포넌트가 그대로 받아 그리는 거죠. 여러분이 직접 짠 코드는 **한 줄도 없습니다.**

### 3. 의존성 흐름 복기 (7분)

> 화면: 보드 탭 — 모든 카드 DONE + 의존성 그래프

보드로 돌아가 한 바퀴를 복기해봅시다. 모든 카드가 DONE에 모여 있죠.

```
TASK-001 (백엔드 API) ── 🟣 Claude
   ├── TASK-002 (즐겨찾기 API) ── 🟣 Claude
   ├── TASK-003 (검색 UI) ──────── Codex
   └── TASK-004 (날씨 카드) ────── Codex
          └── TASK-005 (예보 차트) ── Codex   ← 반려 1회 후 통과
                 └── TASK-006 (연동 테스트) ── Codex
```

이번 P2에서 우리가 한 일을 정리하면:

- **6개 태스크 / 2개 모델**(Claude 백엔드 2 + Codex 프론트·테스트 4)
- **병렬 레인**으로 백엔드·프론트 동시 진행
- **워크트리 격리**로 충돌 없이, 끝나고 **일괄 머지**
- **리뷰 1회 반려**(예보 차트) 후 재작업 → 통과

모듈 3(P1, 단일 에이전트)과 비교하면 뭐가 달라졌나요? **워크플로우는 똑같습니다.** 오케 → 보드 → 레인 → 워크트리 → 리뷰 → 머지. 달라진 건 **에이전트가 둘이 됐고, 각자 역할이 다르며, 동시에 일한다**는 것뿐이에요.

> 💡 이게 핵심 깨달음입니다 — 에이전트를 두 명으로 늘려도 PM이 하는 일은 그대로입니다. 기획하고, 역할 나누고, 관찰하고, 리뷰하고, 합친다. **사람이 추가로 배운 명령어는 없습니다.** 그래서 에이전트가 5명, 10명이 돼도 같은 방식으로 굴릴 수 있어요. (그 큰 규모가 바로 다음 모듈 — 실전 SaaS입니다.)

### 4. 다음으로 — 규모를 키운다 (3분)

> 화면: P2(날씨) vs P3(실전 SaaS) 비교 슬라이드

이번 워밍업급 풀스택에서는:

- 6개 태스크 · 2개 모델 · 1~2시간

다음 모듈(M5)에서는 **진짜 실전 SaaS**를 합니다:

- 18~22개 태스크 · Claude + Codex(+ 선택 Antigravity) · 여러 스프린트
- 프로젝트: **ReachWave** — 콜드메일(영업 메일) 자동화 SaaS

규모가 확 커지지만, 방금 말했듯 **방식은 동일합니다.** P2에서 두 모델 협업의 감각을 잡았으니, 이제 그걸 큰 무대에서 펼칠 차례예요.

> **[설명보드: 4-5 통합 + 한 바퀴 회고]** — Excalidraw (후속 제작)
>
> - 왼쪽: 흩어진 워크트리 3~4개(🟢) → 가운데 깔때기 "일괄 머지(squash)" → 오른쪽 단일 main + 동작하는 앱 스크린샷.
> - 하단: 파이프라인 한 줄 `오케 → 보드 → 레인(병렬) → 워크트리(격리) → 리뷰 → 머지`, 시작·끝 두 지점만 사람 아이콘.
> - 인셋: P2(6태스크·2모델) → P3(18~22태스크·Claude+Codex) "규모는 커져도 방식은 동일" 비교.
> - 모델 칩: Claude Code · Codex (+ Antigravity). ※ Gemini 표기 금지.

---

## 정리 (1분)

1. **일괄 머지**로 흩어진 워크트리를 하나의 main으로 통합한다(의존성 순서대로, 🟡는 Rebase 먼저).
2. **완료 이력**에 누가 언제 무엇을 합쳤는지 감사 추적이 남는다.
3. 브라우저에서 **두 모델의 백엔드·프론트가 맞물려 동작**하는 걸 확인했다 — P2 완성.
4. **워크플로우는 P1과 동일.** 에이전트가 둘이 돼도 PM이 배울 새 명령어는 없다.
5. **다음은 규모를 키운다** — M5 실전 SaaS(ReachWave).

**모듈 4 끝 — 멀티에이전트 협업 첫 완주!** 두 모델이 한 보드 위에서 하나의 동작하는 앱을 만들었습니다. 다음 모듈에서 이 방식을 실전 SaaS로 확장합니다.
