# 에이전트별 워크트리 격리 — 동시에 일해도 안 엉킨다

> 모듈 4 · 섹션 4-3 · 약 25분
> 관련: [[4-2_의존성체인_병렬레인]] | [[4-4_리뷰거버넌스_반려재작업]]

---

## 이 강의에서 다루는 것

- **학습목표:** 두 모델이 병렬로 일해도 코드가 엉키지 않는 이유 — **에이전트별 격리 워크트리** — 를 이해하고, 워크트리 탭에서 상태를 읽고 Rebase/Resolve를 다룬다.
- **시연할 마블로 화면·기능:** 워크트리 탭(WorktreeTab) — 레인별 워크트리 행, 상태 pill(🟢/🟡/⚠️/🔴/⚪), 액션(Rebase/Merge/Resolve/Open/Delete), 충돌 시 리졸버 에이전트 스폰.
- **진행할 프로젝트 단계:** P2 통합 준비.
- **핵심 메시지:** "**병렬로 일해도 워크트리가 격리해 안전하다.**"

---

## 도입 — "같은 폴더를 동시에 고치면?" (3분)

지난 섹션에서 Claude와 Codex가 동시에 일하는 걸 봤습니다. 그런데 자연스러운 의문이 하나 생기죠.

> **"두 에이전트가 같은 프로젝트 폴더에서 동시에 파일을 고치면, 서로 덮어쓰고 충돌하지 않나?"**

좋은 질문입니다. 그리고 답은 — **안 엉킵니다.** 왜냐하면 마블로는 **에이전트마다 별도의 작업 사본**을 주거든요. 그게 바로 **워크트리(worktree)**입니다.

모듈 2에서 워크트리 탭을 한 번 봤지만, 그땐 비어 있었어요(아직 일을 안 했으니까). 이번 섹션에서 처음으로 **에이전트들이 실제로 채운 워크트리**를 보고, 그걸 정리해 통합을 준비합니다.

---

## 본문

### 1. 워크트리란 무엇인가 (5분)

> 화면: 슬라이드 — main 저장소에서 워크트리 3개가 가지치는 그림

Git 워크트리는 **같은 저장소의 격리된 작업 사본**입니다. 하나의 저장소에서 여러 개의 작업 폴더를 동시에 둘 수 있게 해주는 Git 기능이에요.

마블로는 이걸 이렇게 씁니다.

```
main 저장소
  ├── 워크트리 A (backend)  ← 🟣 Claude Code 전용 브랜치
  ├── 워크트리 B (frontend) ←    Codex 전용 브랜치
  └── 워크트리 C (test)     ←    Codex 전용 브랜치
```

**에이전트마다 자기만의 워크트리 + 전용 브랜치**를 받습니다. Claude는 A에서 백엔드를 짓고, Codex는 B에서 프론트를 짓죠. 각자 **자기 방에서** 일하는 겁니다.

- 같은 파일을 동시에 만져도 서로의 변경이 안 보입니다(격리).
- 일이 끝나면 각자의 브랜치를 main으로 **따로 합칩니다**(머지).

이게 모듈 4의 가장 중요한 안전장치예요. 병렬 작업의 공포 — "동시 수정 충돌" — 를 구조적으로 없앱니다.

### 2. 워크트리 탭 — 이제 채워졌다 (6분)

> 화면: 워크트리 탭(WorktreeTab) — 레인별 워크트리 행이 채워진 모습

상단 탭바에서 **워크트리 탭**을 엽니다. 모듈 2에선 비어 있었지만, 이제 에이전트들이 일을 시작했으니 행이 채워졌습니다.

각 행에는 이런 정보가 있어요.

- **태스크 ID / 에이전트 ID** — 누가 무슨 태스크의 워크트리인지.
- **브랜치명** — 파란 모노스페이스로 표시 (예: `agent/backend-task001`).
- **변경량** — 초록 `+N` / 빨강 `−N` (추가·삭제 라인).
- **앞섬/뒤처짐** — ▲ahead / ▼behind (main 대비).
- **상태 pill** — 색·이모지로 한눈에.

### 3. 상태 pill = 신호등 (5분)

> 화면: 워크트리 탭 — 상태 필터 드롭다운 + 행별 pill

각 워크트리에는 **상태 pill**이 붙습니다. 색이 곧 다음 행동이에요.

| Pill             | 뜻        | 무슨 뜻이냐면                            |
| ---------------- | --------- | ---------------------------------------- |
| 🟢 **머지 가능** | mergeable | base와 깨끗이 합쳐짐. 머지해도 됨.       |
| 🟡 **뒤처짐**    | behind    | main이 그새 앞서감. Rebase로 따라잡아야. |
| ⚠️ **stale**     | warning   | 오래 방치됨. 정리 후보.                  |
| 🔴 **충돌**      | danger    | 충돌 발생. 사람 또는 리졸버가 풀어야.    |
| ⚪ **작업중**    | idle      | 에이전트가 아직 작업 중.                 |

> 💡 이 신호등만 읽을 줄 알면 병렬 작업이 무섭지 않습니다. 🟢이면 합치고, 🟡이면 Rebase, 🔴이면 풀고, ⚠️이면 정리. 색이 곧 다음 행동입니다.

P2 진행 중에는 보통 이런 그림이 나옵니다.

```
워크트리 탭
  agent/backend-task001    🟢 머지 가능   +68 −0   ▲2
  agent/frontend-task004   🟡 뒤처짐      +120 −5  ▼3   (main이 앞서감)
  agent/frontend-task005   ⚪ 작업중      +40 −0
```

Claude의 백엔드 워크트리는 깨끗이 머지 가능(🟢)인데, Codex의 프론트 워크트리는 그새 main이 앞서가서 뒤처짐(🟡)이 됐네요. 다음 단계 — Rebase로 따라잡습니다.

### 4. Rebase — main 따라잡기 (4분)

> 화면: 워크트리 행 — Rebase 버튼 클릭 → 🟡 뒤처짐이 🟢 머지 가능으로

🟡 **뒤처짐** 워크트리는 그대로 합치면 위험합니다. main의 최신 변경을 모르거든요. 그래서 먼저 **Rebase**로 따라잡습니다.

**(실습)** 🟡 행에서 **Rebase** 버튼을 누릅니다.

```
🔄 Rebasing agent/frontend-task004 onto main...
   3 commits replayed. Conflicts: 0.
   Status: 🟡 behind → 🟢 mergeable
```

충돌이 없으면 깔끔하게 따라잡고 🟢 머지 가능으로 바뀝니다. 이제 안전하게 합칠 수 있어요. (실제 머지는 다음 섹션·4-5에서.)

### 5. 충돌이 나면 — Resolve로 리졸버 스폰 (5분)

> 화면: 워크트리 행 — 🔴 충돌 → Resolve 버튼 → 리졸버 에이전트 스폰

가끔 Rebase 중에 **충돌(🔴)**이 납니다. 두 워크트리가 정말로 같은 줄을 다르게 고친 경우죠. 이때 마블로엔 전용 손잡이가 있습니다 — **Resolve**.

**(실습)** 🔴 행에서 **Resolve** 버튼을 누릅니다.

```
🔴 Conflict in agent/frontend-task004 (2 files)
   → Spawning resolver agent...
   [Resolver] 충돌 파일 분석: src/components/WeatherCard.tsx
   [Resolver] 양쪽 변경 의도 파악 → 병합안 작성
   [Resolver] Status: 🔴 conflict → 🟢 mergeable
```

Resolve를 누르면 마블로가 **리졸버 에이전트**를 스폰합니다. 이 에이전트가 충돌 파일을 읽고, 양쪽 변경의 의도를 파악해 병합안을 만들어요. 사람이 직접 풀 수도 있지만, 대부분은 리졸버가 처리합니다.

> 💡 충돌은 **실패가 아니라 정상**입니다. 병렬로 일하면 가끔 생기는 일이에요. 중요한 건 마블로에 그걸 푸는 손잡이(Resolve)가 있다는 점. 그리고 최종 확인은 항상 PM인 여러분이 합니다.

> **[설명보드: 4-3 워크트리 격리 + 통합]** — Excalidraw (후속 제작)
>
> - 왼쪽: main 저장소 큰 원에서 가지 3개 → 워크트리 A/B/C 상자, 각 상자에 에이전트 아이콘 + 브랜치 라벨 + 상태 pill.
> - 가운데: 🟡 워크트리에 "Rebase" 화살표가 main 최신을 끌어오는 그림.
> - 오른쪽: 🔴 충돌 워크트리 → "Resolve" → 리졸버 에이전트 아이콘 → 🟢.
> - 하단 띠: 신호등 범례(🟢 머지가능 / 🟡 뒤처짐 / ⚠️ stale / 🔴 충돌 / ⚪ 작업중) = "색이 곧 다음 행동".
> - 캡션: "각자 자기 방에서 → 따라잡고 → 풀고 → 합친다. 동시에 일해도 안 엉킨다."

## 정리 (1분)

1. **워크트리 = 에이전트별 격리 작업 사본 + 전용 브랜치.** 동시 수정 충돌을 구조적으로 없앤다.
2. **상태 pill은 신호등.** 🟢 합치기 / 🟡 Rebase / 🔴 Resolve / ⚠️ 정리 / ⚪ 작업중.
3. **Rebase**로 main을 따라잡고, **Resolve**로 충돌을 푼다(리졸버 에이전트 스폰).
4. **충돌은 정상.** 마블로엔 각각의 손잡이가 있고, 최종 확인은 PM이 한다.

이제 워크트리는 합칠 준비가 됐습니다. 그런데 합치기 전에 한 가지가 더 있죠 — **코드가 정말 괜찮은가?** 다음 섹션에서 리뷰 거버넌스, 즉 반려와 재작업을 봅니다.
