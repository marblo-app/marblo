# 요구사항 분석

> 모듈 4 · 섹션 4-1 · 약 30분
> 관련: [[3-4_날씨대시보드_회고]] | [[4-2_태스크생성_에이전트스폰]]

---

## 도입 (5분)

여러분, 모듈 3에서 날씨 대시보드를 만들면서 마블로의 워크플로우를 한 바퀴 돌려봤죠? 6개 태스크, 에이전트 2개, 30분 정도면 끝나는 작은 프로젝트였습니다.

화면: 모듈 4 타이틀 — "AI SaaS 빌드: YouTube 인사이트 서비스"

이제 **진짜 프로젝트**를 합니다.

우리가 만들 건 **AI YouTube 인사이트 서비스**입니다. YouTube 영상 URL을 넣으면, AI가 자동으로 영상을 분석해서 요약과 핵심 인사이트를 추출해주는 서비스예요.

규모를 비교해볼까요?

| | 날씨 대시보드 | AI YouTube 인사이트 |
|---|---|---|
| 태스크 수 | 6개 | 15-20개 |
| 에이전트 수 | 2개 | 4-5개 |
| 외부 API | OpenWeatherMap | YouTube Data API + Claude API |
| DB | SQLite (간단) | PostgreSQL + 사용자 관리 |
| 소요 시간 | ~30분 | ~4시간 |

규모가 확 커졌지만, **워크플로우는 동일**합니다. `/tf-plan` → `/tf-start` → `/tf-status` → `/tf-review`. 차이는 태스크가 더 많고, 에이전트가 더 많고, 의존성이 더 복잡하다는 것뿐이에요.

이번 섹션에서는 모듈 3의 `/tf-plan`보다 한 단계 세밀한 기획 도구인 **`/tf-analyze`**를 사용합니다. 큰 프로젝트에서는 기획 단계를 더 정밀하게 가져가야 하거든요.

---

## 본문

### 프로젝트 요구사항 정의 (5분)

화면: AI YouTube 인사이트 서비스 완성 데모 화면

먼저 우리가 만들 서비스의 전체 그림을 그려봅시다:

**핵심 기능:**
1. YouTube URL 입력 → 영상 메타데이터 수집
2. 영상 자막(transcript) 추출
3. Claude API로 자막 분석 → 요약 + 핵심 인사이트 추출
4. 인사이트 카드 형태로 대시보드에 표시
5. 분석 히스토리 저장 + 검색

**기술 스택:**
- **백엔드**: FastAPI + PostgreSQL + SQLAlchemy
- **프론트엔드**: Next.js + TailwindCSS
- **AI**: Claude API (anthropic 파이썬 SDK)
- **외부 API**: YouTube Data API v3

**사용자 흐름:**
```
사용자가 URL 입력 → 백엔드에서 YouTube 메타데이터 + 자막 수집
→ Claude API로 분석 → 결과를 DB에 저장 → 프론트엔드에 표시
```

### `/tf-analyze`로 정밀 기획 시작 (10분)

자, 이제 마블로에서 기획을 시작합니다.

화면: 마블로 터미널 패널

**(실습)** 터미널에 입력:

```bash
/tf-analyze AI YouTube 인사이트 서비스. YouTube URL을 넣으면 AI가 영상을 분석해서 요약 + 핵심 인사이트를 추출. FastAPI + Next.js + Claude API + YouTube Data API. 사용자별 분석 히스토리 저장.
```

`/tf-plan`과 뭐가 다르냐고요? `/tf-analyze`는 더 깊은 분석을 합니다:

1. **Socratic Questions** — 더 세부적인 질문들
2. **PRD 생성** — 기능 명세, 비기능 요구사항, 제약 조건까지
3. **아키텍처 제안** — 시스템 구성도, API 설계 방향
4. **태스크 분해 + 의존성 맵** — 15-20개 태스크의 전체 의존성 그래프

화면: `/tf-analyze` Socratic Questions 출력

Socratic Questions가 나오면 이렇게 답해봅시다:

```
Q: 사용자 인증 방식은?
A: 간단한 이메일 로그인. OAuth는 나중에.

Q: YouTube 자막이 없는 영상은?
A: "자막 없음" 메시지 표시. Whisper 등 음성 인식은 스코프 밖.

Q: Claude API 사용량 제한은?
A: 사용자당 일 10회 분석 제한.

Q: 인사이트 카테고리는?
A: 핵심 요약, 주요 포인트 (5개), 관련 키워드, 추천 행동.

Q: 대시보드 구성은?
A: 최근 분석 목록 + 개별 분석 상세 페이지. 카드 형태.

Q: 배포 환경은?
A: Docker Compose로 로컬 개발, 나중에 GCP 배포.
```

### PRD 검토 (5분)

질문에 답하면 마블로가 PRD를 생성합니다.

화면: 생성된 PRD 문서

```markdown
# PRD: AI YouTube 인사이트 서비스

## 1. 개요
YouTube 영상 URL을 입력하면 AI가 자동 분석하여
요약 및 핵심 인사이트를 제공하는 SaaS 서비스.

## 2. 핵심 기능
- F1: YouTube URL 입력 + 메타데이터 표시
- F2: 자막(transcript) 자동 추출
- F3: Claude API 기반 분석 (요약, 포인트, 키워드)
- F4: 인사이트 카드 UI
- F5: 분석 히스토리 + 검색
- F6: 간단한 사용자 인증

## 3. 기술 스택
- Backend: FastAPI + PostgreSQL + SQLAlchemy
- Frontend: Next.js 14 + TailwindCSS
- AI: Claude API (claude-sonnet-4-20250514)
- External: YouTube Data API v3

## 4. 비기능 요구사항
- 분석 응답 시간: 30초 이내
- 동시 사용자: 10명
- 사용자당 일일 분석 제한: 10회
```

PRD를 읽어보고, 빠진 게 있거나 수정할 부분이 있으면 바로 피드백을 주세요. 예를 들어:

```bash
"F2에 자막 언어 자동 감지 기능 추가해주세요. 그리고 비기능 요구사항에 '모바일 반응형' 추가요."
```

### 태스크 분해 + 의존성 맵 검토 (5분)

PRD가 확정되면 마블로가 태스크를 분해합니다. 15-20개 수준으로요.

화면: 태스크 목록 + 의존성 그래프

```
[TASK-001] DB 스키마 설계 + 마이그레이션          (backend)
[TASK-002] 사용자 인증 API (회원가입/로그인)       (backend)
[TASK-003] YouTube 메타데이터 수집 API             (backend)
[TASK-004] YouTube 자막 추출 API                   (backend, depends_on: 003)
[TASK-005] Claude API 분석 엔드포인트              (backend, depends_on: 004)
[TASK-006] 분석 결과 저장/조회 API                 (backend, depends_on: 001, 005)
[TASK-007] 사용량 제한 미들웨어                    (backend, depends_on: 002)
[TASK-008] 로그인/회원가입 UI                      (frontend, depends_on: 002)
[TASK-009] URL 입력 폼 컴포넌트                    (frontend, depends_on: 003)
[TASK-010] 분석 진행 상태 UI (로딩)                (frontend, depends_on: 005)
[TASK-011] 인사이트 카드 컴포넌트                  (frontend, depends_on: 005)
[TASK-012] 분석 상세 페이지                        (frontend, depends_on: 011)
[TASK-013] 대시보드 (히스토리 목록)                (frontend, depends_on: 006, 012)
[TASK-014] 검색 기능                               (frontend, depends_on: 013)
[TASK-015] Docker Compose 설정                     (devops)
[TASK-016] 환경 변수 + 설정 관리                   (devops, depends_on: 015)
[TASK-017] E2E 통합 테스트                         (test, depends_on: 013, 014)
[TASK-018] API 유닛 테스트                         (test, depends_on: 003, 004, 005)
```

이 태스크 목록을 **반드시 검토**해야 합니다. PM의 핵심 역할이에요.

**체크할 것들:**

1. **빠진 태스크는 없는가?** — 예: "에러 페이지", "404 페이지" 같은 것
2. **의존성이 올바른가?** — TASK-011이 TASK-005에 의존하는 게 맞나?
3. **태스크 크기가 적절한가?** — 하나의 태스크가 너무 크지 않은가?
4. **우선순위는?** — 핵심 기능이 먼저 구현되는 구조인가?

수정이 필요하면:

```bash
"TASK-007은 TASK-006 다음으로 옮겨주세요. 그리고 TASK-015는 맨 처음에 시작되게 의존성 없이 설정해주세요."
```

화면: 수정된 의존성 그래프

의존성 맵을 시각적으로 보면 이런 구조입니다:

```
[001 DB스키마] ─────┬── [006 분석결과 API] ── [013 대시보드] ── [014 검색]
                    │                                              │
[002 인증API] ──────┼── [007 사용량제한] ── [008 로그인UI]         │
                    │                                              │
[003 YouTube메타] ──┼── [004 자막추출] ── [005 Claude분석]         │
                    │                       │                      │
                    │                       ├── [010 로딩UI]       │
                    │                       └── [011 인사이트카드]  │
                    │                             └── [012 상세페이지]
                    │
[015 Docker] ────── [016 환경변수]

[009 URL입력] ─────── (depends: 003)
[017 E2E테스트] ───── (depends: 013, 014)
[018 유닛테스트] ──── (depends: 003, 004, 005)
```

이 전체 그래프를 이해하고 승인하는 게 이번 섹션의 가장 중요한 결과물입니다.

## 정리

이번 섹션에서 한 일:

1. **프로젝트 요구사항 정의** — AI YouTube 인사이트 서비스의 전체 그림
2. **`/tf-analyze`로 정밀 기획** — Socratic Questions → PRD → 태스크 분해
3. **PRD 검토 + 수정** — 빠진 기능, 비기능 요구사항 확인
4. **태스크 의존성 맵 검토** — 15-20개 태스크의 전체 관계 파악
5. **PM의 역할** — 태스크를 검토하고 최종 승인하는 것

기획이 잘 되어야 실행이 매끄럽습니다. "기획에 1시간 투자하면 실행에서 3시간을 아낀다"는 말이 있죠. 태스크 분해가 정밀할수록 에이전트가 더 잘 일합니다.

다음 섹션에서는 이 태스크들을 실제로 생성하고 에이전트를 스폰합니다!
