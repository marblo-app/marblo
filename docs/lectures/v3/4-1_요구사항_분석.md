## 도입 (5분)

여러분, 모듈 3에서 워밍업 프로젝트를 통해 마블로 워크플로우를 한 바퀴 돌려봤죠. 6~8개 태스크, 에이전트 2-3개, 1시간 정도면 끝나는 작은 프로젝트였습니다.

화면: 모듈 4 타이틀 — "AI SaaS 빌드: 영업메일 자동화 'ReachWave'"

이제 **진짜 프로젝트**를 만듭니다.

우리가 만들 건 **ReachWave** — B2B 영업 담당자가 리드 CSV만 올리면 AI가 회사·직책을 분석해서 톤별 콜드 메일 5종을 자동 생성하고, 발송·예약·A/B 테스트까지 한 화면에서 끝내는 SaaS입니다.

왜 이 도메인일까요? 세 가지 이유입니다:

1. **시장이 명확합니다** — 콜드 메일은 B2B SaaS·HR·세일즈에이전시·인플루언서 마케팅 등 5조 원 규모의 시장. "구독 결제" 동기가 강함
2. **AI 가치가 즉시 보입니다** — 사람이 30분 걸려 쓰는 메일 1통을 AI가 5톤 × 50개 리드 = 250통을 5분에 작성
3. **마블로 기능을 자연스럽게 다 씁니다** — 백엔드(API)·프론트(차트)·결제(Stripe)·다국어·LLM 프롬프팅·이종에이전트 협업

규모 비교:

|             | 워밍업 (AI 일정 매니저) | ReachWave                                       |
| ----------- | ----------------------- | ----------------------------------------------- |
| 태스크 수   | 6-8개                   | 18-22개                                         |
| 에이전트 수 | 2-3개                   | 4-5개 (이종)                                    |
| 외부 API    | 1개                     | 4개 (OpenAI/Claude, SendGrid, Stripe, Clearbit) |
| DB          | SQLite                  | PostgreSQL + 마이그레이션                       |
| 결제        | 없음                    | Stripe Checkout + Customer Portal               |
| 소요 시간   | ~1시간                  | ~5시간                                          |

규모는 커졌지만 워크플로우의 뼈대는 같습니다. 차이는 **단계를 분리한다**는 것 — 모듈 3에서는 `/tf-start` 안에 plan+execute가 묶여 있었지만, 큰 프로젝트는 `/tf-plan`(PRD 작성)을 독립 단계로 빼서 검토 호흡을 한 번 더 끊고, 이어서 `/tf-create-tasks` → `/tf-spawn-agents`로 태스크 등록과 에이전트 투입을 따로 갑니다. (참고: 빠른 스케치만 필요할 땐 `/tf-analyze`를 쓰지만, ReachWave 규모에서는 PRD까지 정식으로 가는 `/tf-plan`이 맞습니다.)

## 본문

### 페르소나와 가치 가설 (5분)

화면: 슬라이드 — 페르소나 카드 3장

큰 프로젝트일수록 "누가 쓰는가"부터 잡습니다. ReachWave의 1차 페르소나:

**🎯 김지훈 (32세, B2B SaaS 영업 매니저)**

- 매주 50-200개 리드에 콜드 메일 발송
- 톤을 5개 정도 돌려쓰는데 매번 손으로 작성
- "직책별로 톤을 자동으로 맞춰주면 좋겠다"
- 월 19,900원이면 즉시 구독, 49,900원도 ROI 정당화

**🎯 박서연 (28세, 1인 SaaS 창업자)**

- 직접 영업 + 코드 + 마케팅 다 하느라 시간 없음
- 메일 작성에 평균 25분/통 소요
- "보내고 답 안 오는 게 일상" — A/B 테스트로 응답률 비교 절실

**🎯 이수민 (35세, 영업에이전시 대표)**

- 클라이언트 5-10개사 대신 메일 발송 대행
- 클라이언트별 톤·서명 분리 + 발송 결과 리포트 필요
- 월 99,000원까지 지불 의향 (팀 플랜)

**가치 가설 한 줄**:

> "콜드 메일 1통에 평균 25분 → ReachWave로 1분 (24분 절약). 월 200통 발송 시 80시간 절약 = 시급 3만원 환산 240만원."

이걸 PRD에 박아두면 나중에 기능 추가/제거 결정 때 "이게 위 가설을 강화하나"라는 질문 하나로 정리됩니다.

### 프로젝트 요구사항 정의 (5분)

화면: ReachWave 완성 데모 (4페이지 스크린샷)

**핵심 기능 (MVP):**

| ID  | 기능                                                  | 핵심 가치             |
| --- | ----------------------------------------------------- | --------------------- |
| F1  | 리드 CSV 임포트 (이메일·이름·회사·직책·노트)          | 1분에 500개 리드 등록 |
| F2  | 회사·직책 자동 분석 (Clearbit 또는 LLM-only fallback) | 메일 톤 자동 매칭     |
| F3  | 5톤 메일 자동 생성 (쿨/친근/딜강조/팔로업/리마인더)   | 30분/통 → 1분/통      |
| F4  | 발송·예약·일괄 전송 (SendGrid/Postmark)               | 시간대 분산 발송      |
| F5  | A/B 실험 + 응답률 대시보드                            | 데이터 기반 톤 선택   |
| F6  | 결제 (토스페이먼츠 테스트키 — 한국 시장 현실)         | 구독 매출             |
| F7  | 이메일·구글 OAuth 인증                                | 친화 가입             |

**스코프 밖 (의도적 컷):**

- 받은 메일 자동 응답 (스코프 외)
- 화상 미팅 예약 (Calendly 등 외부 연동)
- 멀티 채널 (LinkedIn DM 등) — v2

**기술 스택:**

- **백엔드**: FastAPI 0.110 + PostgreSQL 16 + SQLAlchemy 2.0 + Alembic 마이그레이션 + Redis (rate limit·큐)
- **프론트엔드**: Next.js 15 (App Router) + TailwindCSS + shadcn/ui + Recharts (차트) + react-hook-form
- **AI**: **Gemini 3.1 Flash Lite 단일 모델** (분석·5톤 생성·편집 모두) — 비용 최소·복잡도 0
- **외부 API**: SendGrid (발송) + **토스페이먼츠 테스트키** (결제)
- **인프라**: Docker Compose (개발) → Cloud Run + **Cloud SQL for PostgreSQL** (배포, 모듈 6에서)

> **💡 왜 BigQuery가 아니라 Cloud SQL인가**
> ReachWave는 사용자 가입·결제·리드 CRUD·구독 한도 같은 **OLTP** 워크로드입니다. BigQuery는 분석용(OLAP) 웨어하우스라 트랜잭션·외래키·UPDATE에 약하고, 자잘한 호출에서 쿼리당 과금으로 비용이 폭발합니다.
> **PostgreSQL은 그대로 유지**하되, GCP 배포 시 **Cloud SQL for PostgreSQL** (매니지드 Postgres)을 씁니다 — 강의 코드(SQLAlchemy/Alembic)는 1줄도 안 바뀌고, 수강자가 Supabase·Neon·RDS 등 다른 호스팅으로 이주하기도 쉽습니다. 응답률 대시보드(F5) 같은 가벼운 집계는 Postgres 인덱스로 충분 (월 200통 × 500사용자 ≈ 10만 행 규모).

> **💡 왜 LLM은 단일 모델인가**
> 강의에서 만드는 ReachWave 본체는 **하나의 LLM 모델**만 씁니다 (Gemini 3.1 Flash Lite).
> 이유: ① 가격이 가장 저렴해 강의 실습 비용 부담 최소화, ② 듀얼 LLM은 복잡도만 추가하고 학습 본질과 무관, ③ **나중에 GPT-4.1이나 Claude로 바꾸고 싶으면 클라이언트 1줄만 수정하면 됨**.
>
> 단, **마블로 자체의 코딩 에이전트**는 별개입니다 — 이건 모듈 5에서 보겠지만, 백엔드 태스크엔 Codex, 프론트엔드엔 Claude, 분석엔 Gemini를 자동으로 추천받아 씁니다. "내가 만드는 서비스의 LLM"과 "나를 도와주는 코딩 에이전트의 모델"을 구분하세요.

**사용자 흐름:**

```
회원가입 → 무료 5리드 체험
  → CSV 업로드 → 자동 분석 → 5톤 미리보기
  → 톤 1개 선택 → 일괄 발송 또는 A/B 실험
  → 24시간 후 응답률 대시보드
  → "한도 초과" → Stripe Checkout → Pro 구독
```

### `/tf-plan`으로 정식 기획 (10분)

화면: 마블로 오케스트레이터 터미널

**(실습)** 터미널에 입력:

```bash
/tf-plan ReachWave — AI 영업메일 자동화 SaaS.
B2B 영업 담당자가 리드 CSV를 업로드하면 회사·직책 분석 후
톤별 메일 5종을 자동 생성하고 발송·예약·A/B 테스트하는 SaaS.
FastAPI + Next.js + Postgres + Gemini 3.1 Flash Lite + SendGrid + 토스페이먼츠.
무료 5리드 체험 + Pro 월 19,900원 (200통/월) + Team 월 99,000원.
```

`/tf-plan`은 큰 프로젝트용 풀세트입니다 — `/tf-analyze`가 컴포넌트·역할·의존성을 빠르게 스케치만 하는 데 비해, `/tf-plan`은 PRD 문서까지 정식으로 만듭니다:

1. **Phase 1 — 브레인스토밍 (Socratic Questions)**: 페르소나·스코프·기술결정 세부 질문 10-15개
2. **Phase 2 — PRD 생성**: 기능 명세 + 비기능 요구사항 + 제약조건 (`docs/PRD.md` 저장)
3. **Phase 3 — 태스크 분해**: 18-22개 태스크 + 의존성 그래프 + 역할·모델 추천
4. **Phase 4 — 검토·확정**: 사용자 승인 받고 다음 단계(`/tf-create-tasks`)로 넘김

화면: `/tf-plan` 출력 — Socratic Questions

자동으로 나오는 질문에 다음과 같이 답합니다:

```
Q: 인증 방식은?
A: 이메일 + Google OAuth. Magic link는 v2.

Q: 메일 발송은 즉시 vs 큐?
A: 일괄은 항상 Redis 큐 + 시간대 분산 (스팸 필터 회피). 단일 발송만 즉시.

Q: A/B 실험의 단위는?
A: 톤 단위. 동일 리드 그룹에 2톤 50:50 분할 발송 후 응답률 비교.

Q: 응답률은 어떻게 측정?
A: SendGrid webhook (open/click/reply). 답장은 IMAP 폴링 v2.

Q: 무료 한도와 Pro 한도?
A: 무료 5리드 1회성. Pro 월 200통. Team 월 1000통.

Q: 결제 실패 시?
A: 토스페이먼츠 결제 실패 안내 + grace period 3일. (강의에서는 테스트키만 사용)

Q: 톤 5종 이름은?
A: cold (격식) / warm (친근) / deal-focused (혜택) / follow-up / reminder.

Q: LLM 모델은?
A: **Gemini 3.1 Flash Lite 단일**. 분석·생성·편집 모두 하나로. 모델 교체는 client 1줄 수정 시 가능하도록 추상화만.

Q: 마이그레이션 도구?
A: Alembic. 첫 배포부터 적용.

Q: 모니터링?
A: Sentry + 자체 응답률 대시보드. APM은 v2.
```

답이 끝나면 마블로 오케스트레이터가 답변을 PRD로 변환합니다.

### PRD 검토 (5분)

화면: 생성된 PRD 문서

```markdown
# PRD: ReachWave — AI 영업메일 자동화 SaaS

## 1. 개요

B2B 영업 담당자가 리드 CSV를 업로드하면 AI가 회사·직책을 분석하여
톤별 콜드 메일 5종을 자동 생성하고, 발송·예약·A/B 테스트까지 한 화면에서
수행할 수 있는 SaaS.

## 2. 페르소나

- 1차: B2B SaaS 영업 매니저 (200통/월, 톤 다양화 니즈)
- 2차: 1인 창업자 (응답률 최적화 니즈)
- 3차: 영업에이전시 (멀티 클라이언트 + 팀 플랜)

## 3. 핵심 기능 (F1-F7)

F1. CSV 임포트 + 검증 (1MB, 500행 제한)
F2. 회사·직책 분석 (LLM 단일 호출)
F3. 5톤 메일 자동 생성 (Gemini 3.1 Flash Lite 5회 병렬)
F4. 발송·예약·일괄 (SendGrid + Redis 큐, 시간대 분산)
F5. A/B 실험 + 응답률 대시보드 (Recharts)
F6. 토스페이먼츠 결제 (테스트키, 정기결제 + 빌링키)
F7. Email + Google OAuth 인증

## 4. 비기능 요구사항

- 메일 생성 응답: 5톤 병렬 8초 이내
- 일괄 발송 지연: 큐 등록 즉시, 실제 발송은 분산 스케줄
- 동시 사용자: 50명 (MVP), 500명 (3개월 후)
- 보안: 메일 본문은 발송 후 30일만 보관 후 자동 폐기
- 결제: 토스페이먼츠 위탁 — 자체 카드 저장 X (PCI 부담 회피)

## 5. 모델 전략 (단일·교체 가능)

- **단일 모델: Gemini 3.1 Flash Lite** (분석·생성·편집 통합)
- 추상화: `llm/client.py` 하나 두고 모델 이름만 const로 분리 → 향후 1줄 수정으로 GPT/Claude 교체
- 학습 메시지: "서비스 LLM은 하나로 단순히 시작, 본인 상황 따라 교체"

## 6. 제약

- MVP는 한국어 + 영어 메일 (i18n)
- LinkedIn / Twitter 발송 v2
- SendGrid 무료 한도 (월 100통) 내 초기 운영
- 결제 PG는 강의에서는 **토스페이먼츠 테스트키**까지만 (실 운영은 수강자 직접 키 발급)
```

PRD를 읽고, 빠진 게 있거나 수정할 부분이 있으면 바로 피드백을 줍니다. 예:

```bash
"F5에 '발송 시간대 히트맵' 추가요. 시간대별 응답률 보고 싶어요."
"비기능에 '메일 보관 30일'을 60일로 늘려주세요. 분쟁 대응용."
```

### 태스크 분해 + 이종에이전트 팀 디자인 (5분)

PRD가 확정되면 마블로가 태스크를 분해합니다. 18-22개 수준.

화면: 태스크 목록 + 의존성 그래프 + **모델 추천**

```
[TASK-001] Postgres 스키마 + Alembic 첫 마이그레이션          (backend / gpt)
[TASK-002] Email + Google OAuth (NextAuth + FastAPI 검증)     (backend / claude)
[TASK-003] CSV 임포트 + 검증 API                              (backend / gpt)
[TASK-004] 회사·직책 분석 LLM 호출 (Gemini Flash Lite)        (backend / claude)
[TASK-005] 5톤 메일 병렬 생성 엔드포인트 (Gemini Flash Lite)  (backend / claude)
[TASK-006] SendGrid 발송 + Redis 큐 + 시간대 스케줄러         (backend / gpt)
[TASK-007] A/B 실험 분할 로직                                 (backend / claude)
```

**여기서 마블로의 이종에이전트 추천이 빛납니다.**

화면: dispatch-scoring 추천 로직 다이어그램

오케스트레이터가 각 태스크에 적합한 모델을 자동 추천합니다:

| 태스크 종류                                                                                   | 추천 모델     | 근거 (dispatch-scoring 가중치)                                                                    |
| --------------------------------------------------------------------------------------------- | ------------- | ------------------------------------------------------------------------------------------------- |
| TASK-001/003/006/008/012/019/020/021 — simple-fix · github · test · boilerplate · fast-exec   | **GPT/Codex** | `gpt`가 `github(+25)` `simple-fix(+25)` `test(+15)` `boilerplate(+15)` `fast-execution(+20)` 우위 |
| TASK-002/004/005/007/010/011/013-018 — architecture · multi-file · coding · design · refactor | **Claude**    | `claude`가 `architecture(+25)` `multi-file(+25)` `coding(+25)` `design(+20)` `refactor(+20)` 우위 |
| TASK-009/022 — large-context · research · analysis · documentation                            | **Gemini**    | `gemini`가 `large-context(+30)` `research(+25)` `analysis(+20)` 우위                              |

**왜 자동 추천이 중요한가**:

- 모든 태스크에 Claude를 쓰면 시간 + 비용 모두 손해 (cost-eff 점수에서 Codex 10 > Claude 3)
- 강점이 없는 모델에 보내면 페널티가 적용됨 (Codex가 architecture에 -10, Gemini가 multi-file -10)
- 마블로는 dispatch-scoring 청구항 9 [식 1]: `매칭점수 = w1·역할매칭 + w2·부하균등 + w3·비용효율 + 보조` 가중합으로 자동 결정

수강자는 이 추천을 그대로 받아들이거나, `--model gpt` 같은 인자로 오버라이드할 수 있습니다. 강의 라이브 빌딩에서는 자동 추천을 그대로 따라가면서 "왜 이렇게 추천했는지" 한 문장씩 설명하는 흐름.

## 정리

이번 섹션에서 한 일:

1. **시장·페르소나·가치 가설** — ReachWave: B2B 영업 자동화 SaaS 한 줄 가설
2. **MVP 스코프** — F1-F7 명확화 + 의도적 컷 (LinkedIn, 화상미팅 등 v2)
3. **`/tf-plan` Socratic Questions** — 페르소나·기술·결제 결정 사항 답변 (Phase 1)
4. **PRD 생성·검토** — 기능·비기능·제약 + **단일 LLM(Gemini Flash Lite) + 토스페이먼츠**
5. **태스크 분해 + 의존성 + 모델 추천** — 22개 태스크, dispatch-scoring 자동 추천

**두 가지 "모델"을 구분하세요**:

- 🤖 **서비스 LLM** (ReachWave 본체) = **Gemini 3.1 Flash Lite 하나** — 단순·저렴, 1줄로 교체 가능
- 🛠️ **코딩 에이전트** (마블로) = **Claude + GPT + Gemini 이종** — dispatch-scoring이 태스크별 자동 추천

기획이 잘 되어야 5시간 라이브 빌딩이 매끄럽습니다. 특히 **모델 추천을 PRD 단계에서 잡아두면** Sprint 시작 후 "이 태스크엔 어떤 모델?" 망설임 없이 바로 진행할 수 있어요.

다음 섹션에서는 이 태스크들을 실제로 생성하고 이종에이전트 4-5명을 스폰합니다.
