## 도입 (2분)

마블로 앱도 설치했고, Claude Code도 준비됐죠?
이제 이 둘을 연결하고, 에이전트가 제대로 작동하도록 환경 설정을 해보겠습니다.

세 가지를 설정합니다:

1. **MCP 서버 연결** — 에이전트가 칸반 보드를 읽고 쓸 수 있게
2. **슬래시 스킬 설치** — 18개 슬래시 명령어 활성화
3. **Hook 설정** — 규칙 강제 (티켓 없이 코드 수정 금지)

## 본문

### 1. MCP 서버 연결 (6분)

화면: 마블로 앱 — 오케스트레이터 시작 화면

MCP(Model Context Protocol)는 AI가 외부 도구를 호출하는 표준입니다.
이건 모듈 2에서 자세히 다루고, 지금은 "연결하는 법"에만 집중합시다.

마블로 v3에서는 MCP 설정이 **자동**으로 생성됩니다.

화면: 마블로 앱에서 프로젝트 열기 → 오케스트레이터 시작

**(실습) MCP 연결 확인**

마블로 앱에서 프로젝트를 열고, 오케스트레이터를 시작하면:

1. Electron 메인 프로세스가 MCP 서버 Node.js 프로세스를 실행
2. 임시 폴더에 MCP 설정 파일(JSON)을 자동 생성
3. Claude Code CLI에 `--mcp-config <path>` 플래그로 전달
4. Claude Code가 마블로 MCP 도구를 사용할 수 있게 됨

생성되는 MCP 설정 파일 구조:

```json
{
  "mcpServers": {
    "marblo": {
      "command": "node",
      "args": ["/path/to/dist-mcp/index.js"],
      "env": {
        "FIREBASE_API_KEY": "...",
        "FIREBASE_PROJECT_ID": "...",
        "MARBLO_PROJECT": "my-project-id",
        "MARBLO_BRIDGE_PORT": "54321",
        "MARBLO_SKILLS_DIR": "/path/to/skills"
      }
    }
  }
}
```

이 파일은 Electron이 자동으로 만들어서 `/tmp/marblo-agent-configs/` 폴더에 저장합니다.
여러분이 직접 만들 필요가 없어요.

화면: 터미널 — Claude Code에서 MCP 도구 확인

연결이 잘 됐는지 확인하는 방법:

오케스트레이터 터미널에서 Claude Code가 실행된 후:

```
"get_all_tasks를 호출해줘"
```

이렇게 입력하면 현재 프로젝트의 태스크 목록이 나옵니다.
"No tasks found"가 나오면 정상 — 아직 태스크를 안 만들었으니까요.
에러가 나오면 Firebase 설정을 다시 확인하세요.

마블로의 MCP 도구 전체 목록:

| #   | 도구                    | 용도                      |
| --- | ----------------------- | ------------------------- |
| 1   | `get_all_tasks`         | 전체 태스크 조회          |
| 2   | `get_available_tasks`   | 역할별 사용 가능한 태스크 |
| 3   | `create_task`           | 단일 태스크 생성          |
| 4   | `create_tasks_bulk`     | 일괄 태스크 생성          |
| 5   | `claim_task`            | 태스크 선점               |
| 6   | `update_task_status`    | 상태 변경                 |
| 7   | `add_activity`          | 진행 상황 기록            |
| 8   | `submit_for_review`     | 리뷰 제출                 |
| 9   | `get_task_dependencies` | 의존성 확인               |
| 10  | `get_agent_skill`       | 스킬 파일 로드            |
| 11  | `get_task_activities`   | 활동 로그 조회            |
| 12  | `check_feedback`        | PM 피드백 확인            |
| 13  | `acknowledge_feedback`  | 피드백 읽음 처리          |
| 14  | `search_tasks`          | 태스크 검색               |
| 15  | `spawn_agent`           | 에이전트 스폰             |
| 16  | `get_task`              | 단일 태스크 상세 조회     |
| 17  | `get_agents`            | 에이전트 목록             |
| 18  | `create_flow`           | 플로우 생성               |
| 19  | `get_flows`             | 플로우 목록               |
| 20  | `update_flow`           | 플로우 수정               |

20개 도구가 있습니다. 이걸 다 외울 필요는 없어요. 슬래시 스킬이 대신해줍니다.

### 2. 슬래시 스킬 설치 (7분)

화면: 터미널 — scripts 폴더

슬래시 스킬은 Claude Code에 커스텀 명령어를 추가하는 기능입니다.
`.claude/commands/` 폴더에 Markdown 파일을 넣으면,
Claude Code에서 `/명령어이름`으로 호출할 수 있습니다.

**(실습) 슬래시 스킬 설치**

마블로 프로젝트 폴더에서:

```bash
# 프로젝트 커맨드 설치 (프로젝트 내 .claude/commands/)
# 마블로 앱이 자동으로 설정하지만, 수동 설치도 가능:

mkdir -p .claude/commands
# 마블로 제공 스킬 파일들을 복사
```

화면: .claude/commands/ 폴더 내용

18개 슬래시 스킬 분류:

| 분류       | 스킬               | 설명                                         |
| ---------- | ------------------ | -------------------------------------------- |
| **기획**   | `/tf-plan`         | 프로젝트 전체 기획 (소크라틱 → PRD → 태스크) |
|            | `/tf-analyze`      | 요구사항 분석                                |
| **실행**   | `/tf-start`        | 빠른 시작 (plan + create + spawn 한 번에)    |
|            | `/tf-create-tasks` | 태스크 일괄 생성                             |
|            | `/tf-spawn-agents` | 에이전트 스폰                                |
| **작업**   | `/tf-status`       | 전체 진행 현황                               |
|            | `/tf-feedback`     | 에이전트에 피드백 전달                       |
|            | `/tf-add`          | 새 태스크 추가                               |
| **리뷰**   | `/tf-review`       | REVIEW 태스크 리뷰                           |
|            | `/tf-fix`          | FAILED 태스크 진단 + 복구                    |
|            | `/tf-sync`         | 상태 동기화                                  |
| **자동화** | `/tf-ralph`        | 반복 작업 일괄 처리                          |
|            | `/tf-done`         | 프로젝트 마무리                              |
|            | `/tf-resume`       | 세션 복원                                    |
|            | `/tf-hold`         | 작업 일시정지                                |
|            | `/tf-create-flow`  | 플로우 생성                                  |

각 스킬이 하는 일은 간단합니다.
예를 들어 `/tf-plan`을 실행하면:

1. 사용자에게 소크라틱 질문을 합니다 ("어떤 프로젝트인가요? 타겟은?")
2. 답변을 받아서 PRD(Product Requirements Document)를 생성합니다
3. PRD를 태스크로 분해합니다
4. `create_tasks_bulk` MCP 도구로 칸반 보드에 태스크를 생성합니다

이 전체 과정이 슬래시 스킬 하나로 실행됩니다.

### 3. Hook 설정 (5분)

화면: 코드 에디터 — .claude/settings.json 또는 프로젝트 Hook 파일

Hook은 Claude Code의 **규칙 강제** 기능입니다.
모든 프롬프트에 자동으로 규칙이 적용됩니다.

마블로에서 가장 중요한 Hook은:
**"티켓 없이 코드 수정 금지"**

이게 왜 필요하냐면요, 에이전트가 자율적으로 코딩하면
가끔 칸반 보드에 없는 작업을 하려고 합니다.
Hook이 이걸 방지합니다.

**(실습) Hook 설정**

프로젝트의 CLAUDE.md 파일에 규칙을 추가합니다:

```markdown
# CLAUDE.md

## 필수 규칙

- 코드를 수정하기 전에 반드시 MCP 태스크 티켓을 확인할 것
- 태스크 ID 없이 코드 수정 금지
- 작업 시작 전 claim_task 호출 필수
- 작업 진행 중 add_activity로 기록 필수
- 작업 완료 시 submit_for_review 호출 필수
```

### Hook vs CLAUDE.md vs 슬래시 스킬 차이 (3분)

화면: 슬라이드 — 세 가지 비교

이 세 가지가 헷갈릴 수 있는데, 역할이 다릅니다:

|               | Hook                  | CLAUDE.md                    | 슬래시 스킬            |
| ------------- | --------------------- | ---------------------------- | ---------------------- |
| **언제 적용** | 매 프롬프트마다 자동  | 세션 시작 시 자동 로드       | `/명령어`로 수동 실행  |
| **목적**      | 규칙 강제             | 프로젝트 컨텍스트            | 워크플로우 자동화      |
| **예시**      | "티켓 없이 수정 금지" | "FastAPI + Next.js 프로젝트" | `/tf-plan` → PRD 생성  |
| **변경 빈도** | 거의 안 바꿈          | 프로젝트마다 다름            | 워크플로우에 따라 선택 |

쉽게 비유하면:

- **Hook** = 회사 규정 (모든 직원에게 항상 적용)
- **CLAUDE.md** = 팀 위키 (프로젝트 정보를 공유)
- **슬래시 스킬** = 업무 매뉴얼 (필요할 때 꺼내서 실행)

## 정리 (2분)

환경 설정 완료 체크리스트:

- [ ] MCP 서버 연결 확인 (`get_all_tasks` 호출 성공)
- [ ] 슬래시 스킬 설치 (`/tf-plan` 등 사용 가능)
- [ ] Hook/CLAUDE.md 규칙 설정 ("티켓 없이 코드 수정 금지")
- [ ] Hook, CLAUDE.md, 슬래시 스킬의 차이 이해

이 세 가지 핵심:

1. **MCP**: 에이전트가 칸반 보드와 소통하는 통로
2. **슬래시 스킬**: MCP 도구를 쉽게 호출하는 단축키
3. **Hook**: 에이전트가 규칙을 지키게 강제하는 장치
