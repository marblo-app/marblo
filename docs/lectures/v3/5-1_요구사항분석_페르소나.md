# 요구사항 분석 + 페르소나 — 졸업 작품 "ReachWave"

> 모듈 5 · 섹션 5-1 · 약 30분
> 관련: [[4-5_통합_회고]] | [[5-2_태스크일괄생성_이종배정]]

---

## 이 강의에서 다루는 것

- **학습목표:** 실전 규모의 SaaS(P3 ReachWave)를 페르소나·가치 가설에서 출발해 PRD로 정리하고, 18~22개 태스크로 분해하면서 **어떤 모델에 어떤 역할을 맡길지**까지 설계하는 "PM의 기획" 흐름을 익힌다.
- **시연할 마블로 화면·기능:** 하단 오케스트레이터 PTY(자연어 요구 → `/tf-analyze` → PRD·태스크 분해) + 보드 탭(역할 배지가 붙은 카드 윤곽). 슬라이드는 페르소나 카드만 최소로.
- **진행할 프로젝트 단계:** **P3 기획** — ReachWave(콜드메일 자동화 SaaS). CSV 리드 → 회사·직책 분석 → 톤별 콜드메일 생성 → 발송·예약·A/B 테스트.
- **핵심 메시지:** "코드 전에 문제와 사용자부터. 기획이 5시간 스프린트의 안정성을 좌우한다."

---

## 도입 — 워밍업에서 졸업 작품으로 (4분)

여기까지 오느라 고생했습니다. 모듈 3에서 첫 풀사이클(P1 할 일 웹앱)을, 모듈 4에서 두 모델 협업(P2 날씨 대시보드)을 돌려봤죠. 둘 다 한두 시간이면 끝나는 작은 프로젝트였습니다.

> 화면: 모듈 5 타이틀 — "칸반 거버넌스로 실전 SaaS 스프린트 · 졸업 작품 ReachWave"

이번 모듈은 **졸업 작품**입니다. 진짜 SaaS를 처음부터 끝까지 만들어요.

우리가 만들 건 **ReachWave** — B2B 영업 담당자가 리드 CSV만 올리면 AI가 회사·직책을 분석해서 **톤별 콜드메일 5종**을 자동 생성하고, 발송·예약·A/B 테스트까지 한 화면에서 끝내는 SaaS입니다.

왜 이 도메인일까요? 세 가지 이유입니다.

1. **시장이 명확합니다** — 콜드메일은 B2B SaaS·HR·세일즈에이전시 등에서 "구독 결제" 동기가 강한 영역입니다.
2. **AI 가치가 즉시 보입니다** — 사람이 25~30분 걸려 쓰는 메일 1통을, AI가 5톤 × 수십 개 리드를 몇 분에 작성합니다.
3. **마블로 기능을 자연스럽게 다 씁니다** — 백엔드(API·DB)·프론트(차트)·결제(웹훅)·인증·LLM 프롬프팅·**이종 에이전트 협업**까지 한 프로젝트에 다 들어갑니다.

규모를 비교해 볼까요.

|             | P2 (날씨 대시보드) | P3 (ReachWave)                         |
| ----------- | ------------------ | -------------------------------------- |
| 태스크 수   | 6개                | 18~22개                                |
| 에이전트 수 | 2명 (Claude·Codex) | 4명 (이종, +선택 Antigravity)          |
| 외부 API    | 1개 (OpenWeather)  | 3개 (서비스 LLM, 메일 발송, 결제)      |
| DB          | 없음/단순          | PostgreSQL + Alembic 마이그레이션      |
| 결제        | 없음               | 토스페이먼츠(테스트키) 정기결제 + 웹훅 |
| 소요 시간   | ~1시간             | ~3시간(스프린트 단위)                  |

규모는 커졌지만 **워크플로우의 뼈대는 똑같습니다.** 오케에 요구를 던지고 → 태스크로 쪼개고 → 레인에서 에이전트가 짓고 → 워크트리에서 머지하는 그 파이프라인이요. 차이는 **단계를 더 또렷이 분리**한다는 것뿐입니다. 큰 프로젝트는 기획(`/tf-analyze`) → 등록(`/tf-create-tasks`) → 투입(`/tf-spawn-agents`)을 따로 끊어, 그 사이사이 검토 호흡을 한 번씩 더 넣습니다.

이번 섹션은 그 첫 단계 — **기획**입니다. 코드는 한 줄도 안 짭니다.

## 본문

### 1. 페르소나와 가치 가설 (6분)

> 화면: 슬라이드 — 페르소나 카드 3장

큰 프로젝트일수록 "누가 쓰는가"부터 잡습니다. ReachWave의 페르소나는 이렇습니다.

**🎯 김지훈 (32세, B2B SaaS 영업 매니저)**

- 매주 50~200개 리드에 콜드메일 발송
- 톤을 몇 개 돌려쓰는데 매번 손으로 작성
- "직책별로 톤을 자동으로 맞춰주면 좋겠다"
- 월 1~2만 원대면 즉시 구독 의향

**🎯 박서연 (28세, 1인 SaaS 창업자)**

- 영업·코드·마케팅을 혼자 다 하느라 시간이 없음
- 메일 작성에 평균 25분/통 소요
- "보내도 답이 안 오는 게 일상" — A/B 테스트로 응답률 비교가 절실

**🎯 이수민 (35세, 영업에이전시 대표)**

- 클라이언트 5~10개사 대신 메일 발송 대행
- 클라이언트별 톤·서명 분리 + 발송 결과 리포트 필요
- 팀 플랜이라면 더 높은 가격도 지불 의향

**가치 가설 한 줄:**

> "콜드메일 1통에 평균 25분 → ReachWave로 1분(24분 절약). 월 200통이면 80시간 절약."

이 한 줄을 PRD에 박아두면 나중에 기능 추가/제거를 결정할 때 "이게 위 가설을 강화하나?"라는 질문 하나로 정리됩니다.

### 2. MVP 스코프 정의 (5분)

> 화면: ReachWave 완성 데모 미리보기 (CSV 업로드 → 5톤 미리보기 → 발송 → A/B 대시보드)

**핵심 기능 (MVP):**

| ID  | 기능                                                | 핵심 가치            |
| --- | --------------------------------------------------- | -------------------- |
| F1  | 리드 CSV 임포트 (이메일·이름·회사·직책·노트)        | 1분에 수백 리드 등록 |
| F2  | 회사·직책 자동 분석 (서비스 LLM 호출)               | 메일 톤 자동 매칭    |
| F3  | 5톤 메일 자동 생성 (쿨/친근/딜강조/팔로업/리마인더) | 30분/통 → 1분/통     |
| F4  | 발송·예약·일괄 전송 (메일 API + 큐, 시간대 분산)    | 스팸 필터 회피       |
| F5  | A/B 실험 + 응답률 대시보드                          | 데이터 기반 톤 선택  |
| F6  | 결제 (토스페이먼츠 테스트키 — 한국 시장 현실)       | 구독 매출            |
| F7  | 이메일 + 구글 OAuth 인증                            | 친화 가입            |

**스코프 밖 (의도적 컷):**

- 받은 메일 자동 응답 — v2
- 화상 미팅 예약(Calendly 등 외부 연동) — v2
- 멀티 채널(LinkedIn DM 등) — v2

"무엇을 안 만들지"를 먼저 못 박는 게 PM의 일입니다. 스코프 크리프는 졸업 작품을 끝나지 않게 만드는 1번 원인이에요.

**기술 스택:**

- **백엔드:** FastAPI + PostgreSQL + SQLAlchemy 2.0 + Alembic + Redis(rate limit·큐)
- **프론트엔드:** Next.js(App Router) + TailwindCSS + 차트 라이브러리(예: Recharts)
- **AI(서비스 LLM):** **저비용 모델 1개**로 추상화 — 분석·5톤 생성·편집 모두 하나로
- **외부 API:** 메일 발송(예: SendGrid/Postmark) + **토스페이먼츠 테스트키**(결제)
- **인프라:** 로컬은 Docker Compose, 배포는 모듈 7에서 Cloud Run + 매니지드 Postgres

> 💡 **두 종류의 "모델"을 처음부터 구분하세요**
>
> - 🤖 **서비스 LLM** (ReachWave 본체가 사용자에게 콜드메일을 써주는 모델) = **저비용 모델 하나**. 단순·저렴, 나중에 운영 단계에서 더 좋은 모델로 **`client.py` 한 줄만 바꾸면** 교체됩니다.
> - 🛠️ **코딩 에이전트** (나 대신 ReachWave를 _짜주는_ 모델) = **Claude Code + Codex (+선택 Antigravity)** 이종 팀.
>
> 이 둘은 완전히 다른 축입니다. 이 구분 자체를 독립 주제로 더 깊이 보는 건 모듈 6([[6-5_서비스LLM_vs_코딩에이전트모델]])에서 다룹니다. 지금은 "서비스 LLM은 하나로 단순하게 시작한다"만 기억하면 됩니다.

### 3. `/tf-analyze`로 PRD와 태스크 윤곽 만들기 (8분)

> 화면: 하단 오케스트레이터 PTY

모듈 2에서 프로젝트를 연결하면 하단에 오케스트레이터가 떠 있다고 했죠. 거기에 자연어로 한 줄 던지는 것부터입니다.

**(실습)** 오케 패널에 입력:

```
ReachWave — AI 콜드메일 자동화 SaaS를 만들 거야.
B2B 영업 담당자가 리드 CSV를 올리면 회사·직책을 분석해서
톤별 메일 5종을 자동 생성하고 발송·예약·A/B 테스트하는 SaaS.
FastAPI + Next.js + Postgres + 저비용 서비스 LLM + 메일 API + 토스페이먼츠.
무료 체험 + Pro 월 구독 + Team 플랜.

/tf-analyze
```

`/tf-analyze`는 곧바로 코드를 짜지 않습니다. 대신 **소크라테스식 질문**으로 요구를 다듬고, 컴포넌트·역할·의존성을 파악해 PRD와 태스크 윤곽까지 만들어요. (모듈 3·4에서 본 그 흐름의 풀버전입니다.)

> 화면: 오케 PTY — 소크라테스 질문 출력

자동으로 나오는 질문에 이렇게 답합니다.

```
Q: 인증 방식은?
A: 이메일 + Google OAuth. Magic link는 v2.

Q: 메일 발송은 즉시 vs 큐?
A: 일괄은 항상 큐 + 시간대 분산(스팸 필터 회피). 단일 발송만 즉시.

Q: A/B 실험의 단위는?
A: 톤 단위. 같은 리드 그룹에 2톤 50:50 분할 발송 후 응답률 비교.

Q: 무료/Pro 한도는?
A: 무료 5리드 1회성. Pro 월 200통. Team 월 1000통.

Q: 서비스 LLM 모델은?
A: 저비용 모델 1개로 통일. 분석·생성·편집 모두 하나로.
   교체는 client.py 한 줄로 가능하도록 추상화만 해둘 것.

Q: 마이그레이션 도구는?
A: Alembic. 첫 배포부터 적용.
```

답이 끝나면 오케스트레이터가 답변을 **PRD**로 변환합니다.

> 화면: 생성된 `docs/PRD.md`

```markdown
# PRD: ReachWave — AI 콜드메일 자동화 SaaS

## 1. 개요

B2B 영업 담당자가 리드 CSV를 업로드하면 AI가 회사·직책을 분석하여
톤별 콜드메일 5종을 자동 생성하고, 발송·예약·A/B 테스트까지 한 화면에서
수행하는 SaaS.

## 2. 페르소나

- 1차: B2B 영업 매니저(200통/월, 톤 다양화)
- 2차: 1인 창업자(응답률 최적화)
- 3차: 영업에이전시(멀티 클라이언트 + 팀 플랜)

## 3. 핵심 기능 (F1~F7)

F1 CSV 임포트 + 검증 / F2 회사·직책 분석(LLM 단일 호출)
F3 5톤 메일 생성(서비스 LLM 5회 병렬) / F4 발송·예약·일괄(큐 + 시간대 분산)
F5 A/B 실험 + 응답률 대시보드 / F6 토스페이먼츠 결제(테스트키)
F7 Email + Google OAuth

## 4. 비기능 요구사항

- 5톤 병렬 생성 8초 이내 / 메일 본문 30일 보관 후 자동 폐기
- 동시 사용자 50명(MVP) → 500명(3개월)
- 결제: 토스 위탁, 자체 카드 저장 X(PCI 부담 회피)

## 5. 모델 전략 (단일·교체 가능)

- 서비스 LLM = 저비용 모델 1개. llm/client.py에 모델명만 const로 분리.
- "서비스 LLM은 하나로 단순히 시작, 상황 따라 1줄 교체"

## 6. 제약

- MVP는 한국어 + 영어(i18n) / LinkedIn·Twitter 발송 v2
- 결제 PG는 강의에서 토스 테스트키까지만
```

PRD를 읽고 빠진 게 있으면 바로 피드백을 줍니다. 예:

```
F5에 '발송 시간대 히트맵' 추가요. 시간대별 응답률을 보고 싶어요.
비기능의 '메일 보관 30일'을 60일로 늘려주세요. 분쟁 대응용.
```

### 4. 태스크 분해 + 이종 팀 디자인 (5분)

PRD가 확정되면 오케스트레이터가 태스크를 분해합니다. 18~22개 수준이에요.

> 화면: 보드 탭 — TODO 윤곽 + 역할 배지 + 의존성

```
[TASK-001] Postgres 스키마 + Alembic 첫 마이그레이션        (backend)

[TASK-005] 5톤 메일 병렬 생성 엔드포인트                    (backend)
[TASK-006] 메일 발송 + Redis 큐 + 시간대 스케줄러           (backend)

[TASK-010] 토스페이먼츠 결제 위젯 + 빌링키 등록             (backend)
```

각 태스크에 **역할 배지**(backend / frontend / devops / test)가 붙죠. 이 배지가 다음 단계의 핵심입니다 — 바로 이걸 보고 **어떤 모델을 붙일지**를 정하거든요.

이번 P3의 이종 팀은 이렇게 갑니다. (모듈 4에서 잡은 감각 그대로, 규모만 키운 것)

## 정리 (2분)

1. **P3 = ReachWave** — 콜드메일 자동화 SaaS. 졸업 작품 규모(18~22 태스크, 4명 이종 팀, ~3시간).
2. **기획 순서는 페르소나 → 가치 가설 → MVP 스코프 → PRD → 태스크 분해.** 코드 전에 문제와 사용자부터.
3. **두 종류 모델을 구분한다** — 서비스 LLM(저비용 1개) vs 코딩 에이전트(Claude+Codex+선택 Antigravity). Gemini는 빠졌다.
4. **역할 배지가 모델 배정의 단서.** PM의 첫 의사결정은 코딩이 아니라 "누구에게 무엇을 맡길지".

다음 섹션에서는 이 18~22개 태스크를 보드에 **일괄 등록**하고, 이종 에이전트 팀을 **실제로 스폰**합니다.
