# 실습: 플로우 에디터로 파이프라인 만들기

> 모듈 2 · 실습 · 약 20분
> 관련: [[2-6_플로우에디터_기초]] | [[2-5_에이전트_스킬파일]]

---

## 실습 목표

마블로 플로우 에디터에서 노드를 배치하고 연결해서 간단한 파이프라인을 만듭니다.
두 가지 방법(UI 드래그, MCP 도구)으로 플로우를 생성해봅니다.

---

## 사전 준비

- [ ] 마블로 v3 앱 실행 중
- [ ] Flows 탭 접근 가능
- [ ] 오케스트레이터 터미널 활성화

---

## 실습 1: UI로 플로우 만들기 — "텍스트 분석기" (10분)

### 목표 플로우

```
[사용자 입력] ──→ [LLM: 키워드 추출] ──→ [분석 결과 출력]
```

3개 노드, 2개 엣지의 가장 간단한 플로우입니다.

### Step 1: 새 플로우 생성

화면: Flows 탭

1. Flows 탭에서 **"+ 새 플로우"** (또는 "New Flow") 버튼 클릭
2. 플로우 이름: `텍스트 분석기`
3. 설명: `사용자 텍스트를 분석하여 핵심 키워드를 추출합니다`

### Step 2: Input 노드 배치

1. 노드 팔레트에서 **Input** 노드를 캔버스로 드래그
2. 캔버스 왼쪽에 배치 (x: 100, y: 200 부근)
3. 노드를 더블클릭하여 설정:
   - Label: `사용자 텍스트 입력`
   - Config: 입력 타입을 text로 설정

### Step 3: LLM 노드 배치

1. **LLM** 노드를 캔버스 중앙에 드래그 (x: 400, y: 200 부근)
2. 더블클릭하여 설정:
   - Label: `키워드 추출`
   - Model: Claude Sonnet
   - Prompt Template:
     ```
     다음 텍스트에서 핵심 키워드 5개를 추출하고,
     각 키워드의 중요도를 1-10으로 평가해주세요.

     텍스트: {{input}}

     JSON 형식으로 출력:
     [{"keyword": "...", "importance": N}, ...]
     ```
   - Temperature: 0.2

### Step 4: Output 노드 배치

1. **Output** 노드를 캔버스 오른쪽에 드래그 (x: 700, y: 200 부근)
2. 더블클릭하여 설정:
   - Label: `분석 결과`

### Step 5: 노드 연결

1. Input 노드의 **출력 포트** (오른쪽 원)을 클릭 후 드래그
2. LLM 노드의 **입력 포트** (왼쪽 원)에 놓기 → 엣지 생성
3. LLM 노드의 출력 포트 → Output 노드의 입력 포트 연결

완성된 모습:
```
[사용자 텍스트 입력] ───→ [키워드 추출 (LLM)] ───→ [분석 결과]
```

### Step 6: 저장 + 확인

1. **저장** 버튼 클릭
2. 플로우 목록에 "텍스트 분석기"가 나타나는지 확인
3. 상태: `draft`

### 확인 포인트

- [ ] 3개 노드가 캔버스에 배치되었는가
- [ ] 2개 엣지로 순서대로 연결되었는가
- [ ] 저장 후 플로우 목록에 나타나는가

## 실습 2: MCP 도구로 플로우 만들기 (5분)

### 목표

같은 플로우를 이번엔 오케스트레이터 터미널에서 MCP 도구로 만들어봅니다.

### 방법 A: 슬래시 스킬 사용

오케스트레이터 터미널에서:

```
/tf-create-flow 코드 리뷰 파이프라인.
Input으로 코드를 받으면, LLM이 코드를 분석하고,
Branch에서 이슈 유무를 판단해서,
이슈가 있으면 Agent가 수정하고,
이슈가 없으면 바로 Output으로 결과를 보여줌.
```

오케스트레이터가 자연어를 해석해서 `create_flow` MCP 도구를 호출합니다.

### 방법 B: 직접 지시

```
다음 구조의 플로우를 create_flow로 만들어줘:

이름: 코드 리뷰 파이프라인
노드:
1. Input (코드 입력)
2. LLM (코드 분석 - 이슈 검출)
3. Branch (이슈 있음/없음 분기)
4. Agent (코드 수정 - 이슈 있을 때)
5. Output (최종 결과)

연결:
Input → LLM → Branch
Branch(이슈있음) → Agent → Output
Branch(이슈없음) → Output
```

### 생성 확인

1. Flows 탭으로 이동
2. "코드 리뷰 파이프라인" 플로우가 나타나는지 확인
3. 노드와 엣지가 올바르게 생성되었는지 확인

화면: Flows 탭 — 새로 생성된 플로우

## 실습 3: 분기가 있는 플로우 (5분)

### 목표 플로우

```
                              ┌──→ [Agent: 수정] ──→ [Output: 수정 결과]
[Input] ──→ [LLM: 분석] ──→ [Branch]
                              └──→ [Output: 통과]
```

### Branch 노드 설정

Branch 노드의 핵심은 **조건**입니다:

```json
{
  "label": "이슈 판단",
  "config": {
    "condition": "output.issues.length > 0",
    "trueLabel": "이슈 있음",
    "falseLabel": "이슈 없음"
  }
}
```

- `true` 출력 → Agent 노드로 연결
- `false` 출력 → Output 노드로 바로 연결

### UI로 만들기

1. Input 노드 배치 (왼쪽)
2. LLM 노드 배치 (중앙 왼쪽)
3. Branch 노드 배치 (중앙)
4. Agent 노드 배치 (위쪽 오른쪽)
5. Output 노드 2개 배치:
   - "수정 결과" (Agent 뒤)
   - "통과" (Branch 아래쪽)
6. 연결:
   - Input → LLM
   - LLM → Branch
   - Branch (true) → Agent
   - Agent → Output (수정 결과)
   - Branch (false) → Output (통과)

### 확인 포인트

- [ ] Branch 노드에 2개의 출력 포트가 있는가 (true/false)
- [ ] true 경로와 false 경로가 다른 노드로 연결되는가
- [ ] 전체 플로우가 DAG(방향성 비순환 그래프)인가 (순환 없음)

## 노드 타입별 설정 참고

| 노드 | 필수 설정 | 선택 설정 |
|------|----------|----------|
| **Input** | label | inputType (text/file/url) |
| **LLM** | label, prompt | model, temperature, maxTokens |
| **Agent** | label, role | model, skillFile, initialPrompt |
| **API** | label, url, method | headers, body, auth |
| **Human** | label | description, timeout |
| **Branch** | label, condition | trueLabel, falseLabel |
| **Output** | label | format (text/json/file) |

---

## 트러블슈팅

| 문제 | 해결 |
|------|------|
| 노드가 연결되지 않음 | 출력 포트에서 시작해서 입력 포트로 드래그 (방향 주의) |
| 플로우 저장 실패 | Firestore 연결 확인, 네트워크 확인 |
| MCP로 생성 시 노드 위치가 이상함 | UI에서 수동으로 노드 위치 조정 |
| Branch 조건이 동작하지 않음 | condition 표현식 문법 확인 |
| 순환 참조 에러 | DAG여야 함 — 노드가 자기 자신으로 돌아가는 연결 제거 |
