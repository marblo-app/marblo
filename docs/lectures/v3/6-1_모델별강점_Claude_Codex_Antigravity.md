# 모델별 강점 — Claude · Codex · Antigravity

> 모듈 6 · 섹션 6-1 · 약 20분
> 관련: [[5-6_통합리뷰_스프린트마무리]] | [[6-2_dispatch_스코어링_자동배정]]

---

## 이 강의에서 다루는 것

- **학습목표:** 마블로 기본 플릿을 이루는 세 모델 — **Claude Code · Codex · Antigravity** — 의 강·약점을 구분하고, "어떤 작업에 누구를 붙일지"를 스스로 판단하는 감각을 익힌다.
- **시연할 마블로 화면·기능:** 에이전트 탭(한 보드 위 여러 모델 카드) + 모델별 강점 비교 표.
- **진행할 프로젝트 단계:** **P3(콜드메일 SaaS) 회고 맥락** — 방금 끝낸 스프린트에서 누가 무엇을 잘했는지 복기.
- **핵심 메시지:** "Gemini는 빠졌다. **기본 2인 + 떠오르는 3번째.**"

---

## 도입 — 같은 보드, 다른 선수들 (3분)

모듈 5에서 우리는 P3 콜드메일 SaaS를 멀티에이전트로 완주했습니다. 백엔드는 한 모델이, 프론트는 다른 모델이, 동시에 일했죠. 그때 역할을 나누면서 "왜 이 태스크는 Claude고, 저 태스크는 Codex일까?"라는 질문이 마음에 남았을 겁니다.

> 화면: 에이전트 탭 — 카드마다 모델 배지(🟣 Claude · 🟢 Codex · 🟠 Antigravity)가 붙어 있는 보드

이번 모듈은 그 질문에 정면으로 답합니다. 모듈 4·5에서는 "역할로 나눈다"는 감각만 잡았다면, 6-1에서는 **그 근거** — 각 모델이 실제로 무엇을 잘하고 무엇에 약한지 — 를 짚습니다.

먼저 큰 그림 하나. 마블로의 기본 플릿은 이렇게 정리됐습니다.

- **Claude Code** — 설계·복잡 로직·코드 품질의 주역
- **Codex** (내부 모델 id는 `gpt`) — 풀스택 구현·테스트·빠른 반복의 주역
- **Antigravity** — 떠오르는 3번째, 자율 멀티스텝 흐름에 특화

> ⚠️ 예전 강의에는 **Gemini**가 있었습니다. Gemini는 EOL(2026-06-18)로 **플릿에서 빠졌습니다.** 지금의 기본은 **Claude + Codex 두 주역**, 거기에 합류 중인 **Antigravity**입니다. 사용량 탭에 과거 Gemini 기록이 남아 있을 수는 있지만, 새 팀을 짤 때 Gemini는 더 이상 고르지 않습니다.

## 본문

### 1. Claude Code — 시니어 아키텍트 (5분)

> 화면: 에이전트 탭 — Claude 에이전트 카드 + 작업 로그

```
강점
- 복잡한 로직 설계와 아키텍처 판단
- 코드 품질 — 안전하고 가독성 높은 코드
- 긴 대화 맥락에서도 일관된 작업
- MCP 도구 사용 능력이 탁월 (마블로와 가장 잘 맞물림)
- 안전성 — 위험한 작업에 대한 거부 판단

약점
- 토큰 비용이 상대적으로 높음 (특히 Opus 계열)
- 단순·반복 작업에는 과한 리소스
```

Claude는 **"시니어 아키텍트"**로 생각하면 됩니다. 핵심 비즈니스 로직, 데이터 모델 설계, 까다로운 API 분기 — 이런 걸 시킬 때 빛납니다. P3에서 콜드메일 분석 로직과 결제(토스) 연동의 설계를 Claude에 맡긴 이유가 이겁니다.

특히 마블로 안에서는 **MCP 활용력**이 결정적입니다. 오케스트레이터로서 태스크를 분해하고 보드를 갱신하고 다른 에이전트를 깨우는 일 — 전부 MCP 도구 호출인데, Claude가 여기서 가장 안정적입니다. 그래서 **오케스트레이터(팀리더)는 Claude가 맡는 게 기본**입니다.

### 2. Codex — 코드 생산 머신 (5분)

> 화면: 에이전트 탭 — Codex 에이전트 카드 (모델 id: gpt)

```
강점
- 풀스택 UI 구현 — 코드 생성 속도가 빠름
- 테스트 코드 작성에 강함 (패턴 반복 양산)
- 작은 수정·빠른 편집(simple-fix, quick-edit)에 효율적
- ChatGPT Pro 구독에 포함 — 추가 토큰 과금 부담이 적음

약점
- 복잡한 아키텍처 판단은 Claude만 못함
- 대규모 프로젝트에서 컨텍스트 관리가 덜 세밀
```

Codex는 **"빠른 풀스택 개발자"**입니다. 마블로 내부에서는 모델 id가 `gpt`로 표기돼요(에이전트 카드·사용량 탭에서 "Codex"로 보입니다). P3에서 프론트엔드 컴포넌트와 연동 테스트를 Codex에 몰아준 이유 — UI는 양이 많고 패턴이 비슷하고, 테스트는 반복적이라 **빠르게 양산**하는 쪽이 유리하기 때문입니다.

그리고 비용 구조가 다릅니다. Codex는 **구독(Pro plan)에 포함**돼서, 토큰 단위로 돈이 새는 느낌이 적어요. 대신 plan에는 **사용량 한도(rate limit)**가 있습니다 — 이건 6-4 사용량 탭에서 직접 봅니다.

### 3. Antigravity — 떠오르는 3번째 (4분)

> 화면: 에이전트 탭 — Antigravity 에이전트 카드 (배지: agy)

```
강점
- 자율 멀티스텝 흐름에 특화 (agentic / autonomous)
- 서브에이전트를 부려 스스로 단계를 밟는 작업에 강함
- 출시 초기 무료 구간 — 비용 효율이 좋음

특징
- Gemini 계열을 backing으로 하는 후신 성격 (research/문서에도 보조적 강점)
- 아직 합류 중 — 기본 2인을 보완하는 포지션
```

Antigravity는 **"자율 실행에 강한 신예"**입니다. 한 번 지시하면 스스로 여러 단계를 밟아가는 **agentic 워크플로**에 최적화돼 있어요. 그래서 "이 폴더를 통째로 리서치하고 정리해줘"처럼 **자기주도적으로 굴러가는 큰 덩어리** 작업에서 빛납니다.

포지션을 정확히 잡읍시다. Antigravity는 Claude·Codex를 **대체하는 게 아니라 보완**합니다. 기본 2인으로 충분한 작업은 그대로 두고, 자율 멀티스텝 성격이 강한 태스크에 3번째 카드로 합류시키는 식이에요.

> 💡 "Gemini의 자리를 Antigravity가 이어받았다"고 이해하면 매끄럽습니다. 다만 단순 치환이 아니라 **결이 다릅니다** — Gemini가 긴 컨텍스트·빠른 양산형이었다면, Antigravity는 **자율 실행형**입니다.

### 4. 한 보드 위에서 — 비교 한 장 (2분)

> 화면: 슬라이드 — 3모델 비교 표

세 모델을 한눈에 정리합니다.

| 모델            | 한 줄 정체성       | 잘하는 일                                   | 강점 태그(예)                        |
| --------------- | ------------------ | ------------------------------------------- | ------------------------------------ |
| **Claude Code** | 시니어 아키텍트    | 설계·복잡 로직·코드 품질·MCP·오케스트레이션 | `architecture` `multi-file` `mcp`    |
| **Codex**(gpt)  | 빠른 풀스택 개발자 | UI 구현·테스트·작은 수정·빠른 반복          | `simple-fix` `quick-edit` `test`     |
| **Antigravity** | 자율 실행형 신예   | 멀티스텝 자율 흐름·리서치 보조              | `agentic` `multi-agent` `autonomous` |

이 "강점 태그"는 슬라이드용 비유가 아닙니다. 마블로는 실제로 **태스크의 성격(태그)과 모델의 강점을 점수로 매칭**해서 누구에게 배정할지 추천합니다. 그 점수 계산이 바로 다음 섹션(6-2)의 주제예요.

그리고 결정적 사실 하나 — 이 모든 모델이 **한 칸반 보드 위의 에이전트**로 동작합니다. 기존 도구들은 Claude면 Claude만, Cursor면 자체 모델만 썼지만, 마블로는 모델이 뭐든 **같은 보드·같은 MCP·같은 오케스트레이터** 아래 둡니다. 이게 마블로의 핵심입니다.

> ⚠️ 고정 단가(토큰당 가격)는 여기서 다루지 않습니다. 가격은 자주 바뀌고, 무엇보다 **추정이 아니라 실측**으로 봐야 하니까요 — 6-4 사용량 탭에서 진짜 숫자로 확인합니다.

## 정리 (1분)

1. **기본 플릿은 2+1.** Claude(설계·품질) + Codex(구현·테스트) 두 주역, 거기에 자율 실행형 Antigravity가 3번째로 합류.
2. **Gemini는 빠졌다.** EOL(2026-06-18) 이후 새 팀에서 고르지 않는다. 그 빈자리의 결을 Antigravity가 — 단순 치환이 아니라 다른 성격으로 — 잇는다.
3. **오케스트레이터는 Claude가 기본.** MCP 활용력이 가장 안정적이라 팀을 지휘하는 역할에 맞다.
4. **강점은 태그로 환산된다.** "이 모델은 이런 태스크에 강하다"가 곧 마블로의 자동 배정 점수의 재료다 → 6-2.

다음 섹션에서는 마블로가 이 강점들을 **어떻게 점수로 환산해 태스크를 자동 배정**하는지, dispatch 스코어링을 들여다봅니다.
