# 모델별 비용/성능 비교 + 최적 전략

> 모듈 5 · 섹션 5-5 · 약 20분
> 관련: [[5-4_오케스트레이터]] | [[실습_멀티모델_팀구성]]

> 🗄️ **[구버전 · M6로 이동]** 이 문서는 구 모듈5(멀티모델 오케스트레이션) 자료입니다. 강의 재편(재작성 청사진 기준)으로 **모듈 5는 실전 SaaS 스프린트(P3 ReachWave)**로 바뀌었고, 비용·성능 추적 내용은 슬라이드 시뮬 대신 **실제 사용량 탭** 기준으로 신 **[[6-4_사용량탭_비용추적최적화]]** 에 재집필되었습니다.

---

## 도입 (2분)

AI 에이전트를 돌리면 당연히 비용이 발생합니다. 특히 멀티모델을 쓰면 여러 API를 동시에 호출하니까, 비용 관리가 더 중요해지죠.

화면: 슬라이드 — "똑같은 결과물, 비용은 10배 차이"

하지만 역설적으로, 멀티모델 전략을 잘 쓰면 **비용을 오히려 줄일 수 있습니다.** 비싼 모델은 꼭 필요한 곳에만 쓰고, 나머지는 저렴한 모델에 맡기면 되니까요.

이번 섹션에서는 각 모델의 실제 토큰 가격을 비교하고, 작업 유형별 최적 모델 배치 전략을 세워보겠습니다.

---

## 본문 1: 토큰 가격 비교표 (5분)

화면: 가격 비교 테이블

2025년 기준 주요 모델의 토큰 가격입니다. (가격은 변동될 수 있으니 최신 정보를 확인하세요.)

### Claude 모델 라인업

| 모델             | 입력 (1M 토큰) | 출력 (1M 토큰) | 특징                      |
| ---------------- | -------------- | -------------- | ------------------------- |
| Claude Opus 4    | $15.00         | $75.00         | 최고 품질, 복잡한 추론    |
| Claude Sonnet 4  | $3.00          | $15.00         | 최적 균형, 가장 많이 사용 |
| Claude Haiku 3.5 | $0.80          | $4.00          | 빠르고 저렴               |

### Gemini 모델 라인업

| 모델             | 입력 (1M 토큰) | 출력 (1M 토큰) | 특징                |
| ---------------- | -------------- | -------------- | ------------------- |
| Gemini 2.0 Flash | $0.10          | $0.40          | 초저렴, 빠른 속도   |
| Gemini 2.5 Pro   | $1.25          | $10.00         | 고성능, 긴 컨텍스트 |

### OpenAI 모델 라인업

| 모델                | 입력 (1M 토큰) | 출력 (1M 토큰) | 특징         |
| ------------------- | -------------- | -------------- | ------------ |
| GPT-4o              | $2.50          | $10.00         | 범용 고성능  |
| GPT-4o mini         | $0.15          | $0.60          | 저렴한 대안  |
| Codex (ChatGPT Pro) | Pro 구독 포함  | Pro 구독 포함  | 월 $200 고정 |

여기서 눈에 띄는 게 있죠?

- **가장 비싼 것**: Claude Opus 4 — 출력 토큰당 $75/1M
- **가장 저렴한 것**: Gemini 2.0 Flash — 출력 토큰당 $0.40/1M
- **고정 비용**: Codex (ChatGPT Pro 포함) — 월 $200

Claude Opus와 Gemini Flash의 출력 가격 차이가 **약 188배**입니다. 이 차이를 활용하는 게 핵심이에요.

## 본문 2: 실제 프로젝트 비용 시뮬레이션 (5분)

화면: 비용 시뮬레이션 스프레드시트

구체적인 예시를 봅시다. 중간 규모 SaaS 프로젝트를 기준으로 합니다.

### 시나리오: Todo SaaS 프로젝트

| 작업                      | 예상 토큰 (입력+출력) | 비중      |
| ------------------------- | --------------------- | --------- |
| 백엔드 API 설계+구현      | ~80K 토큰             | 핵심 로직 |
| 프론트엔드 UI (10 페이지) | ~250K 토큰            | 반복적    |
| 테스트 코드 (50 케이스)   | ~200K 토큰            | 패턴화    |
| CI/CD 파이프라인          | ~30K 토큰             | 인프라    |
| 총                        | ~560K 토큰            |           |

### 전략 A: Claude Sonnet 단일 모델

```
백엔드:    80K × $9/1M  = $0.72
프론트:   250K × $9/1M  = $2.25
테스트:   200K × $9/1M  = $1.80
CI/CD:    30K × $9/1M  = $0.27
───────────────────────────
총 비용: ~$5.04
```

($9/1M은 입출력 평균 단가 추정)

### 전략 B: 멀티모델 최적화

```
백엔드:    80K × Claude Sonnet ($9/1M)     = $0.72  ← 품질 중요
프론트:   250K × Gemini Flash ($0.25/1M)   = $0.06  ← 빠르고 저렴
테스트:   200K × Codex (Pro 포함)           = $0.00  ← 구독에 포함
CI/CD:    30K × Claude Haiku ($2.4/1M)     = $0.07  ← 간단한 작업
──────────────────────────────────────────
총 비용: ~$0.85
```

**전략 A 대비 약 83% 절감!** $5.04에서 $0.85로.

물론 ChatGPT Pro 구독비 $200/월이 있지만, 이건 다른 용도로도 쓰이니까 순수 이 프로젝트의 추가 비용은 거의 없는 셈이죠.

### 대규모 프로젝트에서는 차이가 더 큽니다

```
10배 규모 프로젝트:
전략 A: ~$50.40
전략 B: ~$8.50

100배 규모:
전략 A: ~$504
전략 B: ~$85
```

프로젝트가 클수록 멀티모델 전략의 효과가 커집니다.

## 본문 3: 작업 유형별 최적 모델 배치 (5분)

화면: 매트릭스 다이어그램

자, 이제 구체적으로 어떤 작업에 어떤 모델을 써야 하는지 정리해봅시다.

### 매트릭스: 작업 유형 x 최적 모델

```
                          품질 중요도
                     낮음 ──────── 높음
                     │              │
속    빠름 ─  Gemini Flash ──  Claude Sonnet
도              │                  │
필         GPT-4o mini ──── Claude Opus
요    느림 ─     │                  │
도              Codex ─────── (예산 초과)
```

### 구체적 가이드라인

| 작업 유형               | 추천 모델            | 이유                   |
| ----------------------- | -------------------- | ---------------------- |
| **아키텍처 설계**       | Claude Opus/Sonnet   | 복잡한 판단력 필요     |
| **핵심 비즈니스 로직**  | Claude Sonnet        | 품질 + 안전성          |
| **API 엔드포인트 구현** | Claude Sonnet        | 에러 핸들링이 꼼꼼     |
| **React UI 컴포넌트**   | Gemini Flash         | 빠르고 양이 많음       |
| **CSS/스타일링**        | Gemini Flash         | 반복적, 품질보다 속도  |
| **테스트 코드 작성**    | Codex / Gemini Flash | 패턴 반복, 양산        |
| **문서 생성**           | Gemini Flash         | 길고 반복적            |
| **코드 리뷰**           | Claude Sonnet        | 논리적 분석 필요       |
| **대규모 리팩토링**     | Gemini Pro           | 긴 컨텍스트 필요       |
| **CI/CD 스크립트**      | Claude Haiku         | 간단하지만 정확해야 함 |
| **Dockerfile 작성**     | 아무 모델            | 상대적으로 쉬운 작업   |

### 핵심 원칙 세 가지

**1. 비용 민감한 작업 → Gemini Flash**

```
단순 UI, 스타일링, 문서, 반복 작업
→ $0.10/1M 입력으로 해결
```

**2. 품질 핵심 작업 → Claude Sonnet**

```
비즈니스 로직, 보안 관련, 아키텍처
→ 비용을 더 들여서라도 품질 확보
```

**3. 대량 생산 작업 → Codex**

```
테스트 50개, CRUD 엔드포인트 20개
→ Pro 구독 내에서 무한 사용
```

## 본문 4: 예산 최적화 팁 (3분)

화면: 슬라이드 — "실전 절약 팁"

실무에서 쓸 수 있는 비용 절약 팁들을 알려드리겠습니다.

### 팁 1: 2단계 파이프라인

```
1단계: Gemini Flash로 초안 생성 (저렴)
2단계: Claude Sonnet으로 리뷰 + 수정 (품질)
```

초안은 싸게 만들고, 마무리만 비싼 모델로. 전체 비용의 60~70%를 절약할 수 있습니다.

### 팁 2: 캐싱 활용

같은 유형의 태스크가 반복되면, 이전 결과를 컨텍스트로 제공하세요:

```
"이전에 만든 UserController.ts와 같은 패턴으로
 ProductController.ts를 만들어줘"
```

컨텍스트가 있으면 LLM이 더 적은 토큰으로 더 정확한 결과를 냅니다.

### 팁 3: 모델별 토큰 한도 설정

마블로에서 에이전트별로 토큰 사용량을 모니터링하고, 임계값을 설정할 수 있습니다:

```
Claude-Backend:    max 500K tokens/day
Gemini-Frontend:   max 2M tokens/day (저렴하니까 넉넉하게)
Codex-Test:        unlimited (Pro에 포함)
```

### 팁 4: 월별 예산 시뮬레이션

```
개인 프로젝트 (파트타임):
- Claude API: ~$10-30/월
- Gemini API: ~$1-5/월
- ChatGPT Pro: $200/월 (이미 쓰고 있다면)
→ 총: $11-235/월

팀 프로젝트 (풀타임):
- Claude API: ~$50-200/월
- Gemini API: ~$5-20/월
- ChatGPT Pro: $200/월
→ 총: $55-420/월
```

이 비용으로 주니어 개발자 여러 명 분의 작업량을 처리할 수 있다고 생각하면, ROI는 엄청납니다.

## 정리 (2분)

화면: 요약 슬라이드

모델별 비용/성능 전략을 정리합니다:

1. **가격 차이를 활용하라** — Gemini Flash와 Claude Opus는 188배 차이. 적재적소에 배치하면 80%+ 절감 가능.

2. **세 가지 원칙**:

   - 비용 민감 → Gemini Flash
   - 품질 핵심 → Claude Sonnet
   - 대량 생산 → Codex (Pro)

3. **2단계 파이프라인**: 싼 모델로 초안, 비싼 모델로 리뷰. 가장 실용적인 전략.

4. **마블로가 이걸 쉽게 만들어준다**: 모델 선택은 드롭다운 하나, 나머지는 자동.

이것으로 모듈 5를 마무리합니다. 멀티모델 에이전트 오케스트레이션 — 마블로의 킬링 피쳐를 완전히 이해하셨을 겁니다.

모듈 6에서는 이렇게 만든 프로젝트를 GCP에 배포하고 자동화하는 법을 배우겠습니다.
