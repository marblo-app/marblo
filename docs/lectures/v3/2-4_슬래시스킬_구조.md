# 슬래시 스킬 구조 — "/ 뒤에서 무슨 일이"

> 모듈 2 · 섹션 2-4 · 약 15분
> 관련: [[2-3_상태머신]] | [[2-5_에이전트_스킬파일]]

---

## 도입 (2분)

모듈 1에서 `/tf-plan`, `/tf-start`, `/tf-review`를 써봤죠?
"와, `/`만 치면 다 해주네" — 이렇게 느끼셨을 겁니다.

이번 섹션에서는 그 `/` 뒤에서 무슨 일이 벌어지는지 뜯어봅니다.
슬래시 스킬이 정확히 뭐고, 어떤 구조이고, 어떻게 만들어져 있는지.

핵심을 미리 말하면:
**슬래시 스킬 = 프롬프트 템플릿 + MCP 도구 호출 레시피**

그냥 Markdown 파일 하나입니다. 코드가 아닙니다.

---

## 본문

### SKILL.md의 구조 (4분)

화면: VS Code — .claude/commands/ 폴더

Claude Code에서 슬래시 스킬은 `.claude/commands/` 폴더에 있는 Markdown 파일입니다.
파일 이름이 곧 명령어 이름이 됩니다.

```
.claude/commands/
├── tf-plan.md          → /tf-plan
├── tf-start.md         → /tf-start
├── tf-create-tasks.md  → /tf-create-tasks
├── tf-spawn-agents.md  → /tf-spawn-agents
├── tf-status.md        → /tf-status
├── tf-review.md        → /tf-review
├── tf-feedback.md      → /tf-feedback
├── tf-fix.md           → /tf-fix
├── tf-add.md           → /tf-add
├── tf-ralph.md         → /tf-ralph
├── tf-done.md          → /tf-done
├── tf-resume.md        → /tf-resume
├── tf-hold.md          → /tf-hold
├── tf-sync.md          → /tf-sync
├── tf-analyze.md       → /tf-analyze
├── tf-create-flow.md   → /tf-create-flow
└── ...
```

각 파일의 내용은 **프롬프트 템플릿**입니다.
"이 MCP 도구를 이 순서로 호출해라"라는 지시가 적혀 있어요.

### 스킬 파일 예시: `/tf-start` (4분)

화면: VS Code — tf-start.md 내용

`/tf-start` 스킬의 구조를 보겠습니다:

```markdown
# /tf-start

프로젝트를 빠르게 시작합니다.
사용자의 요구사항을 분석하고, 태스크를 생성하고, 에이전트를 스폰합니다.

## 실행 단계

### 1단계: 분석
사용자의 입력을 분석하여 다음을 파악합니다:
- 필요한 기능 목록
- 기술 스택
- 역할별 태스크 분배

### 2단계: 태스크 생성
`create_tasks_bulk` MCP 도구를 사용하여 태스크를 일괄 생성합니다.
각 태스크에 포함할 정보:
- title: 구체적인 작업 설명
- description: 상세 요구사항
- role: backend / frontend / test / devops
- priority: 1-5 (높을수록 급함)
- depends_on: 의존하는 태스크 ID (TASK-001 형식)

### 3단계: 에이전트 스폰
역할별로 에이전트를 스폰합니다.
`spawn_agent` MCP 도구를 사용하여:
- name: 역할-기능 (예: backend-auth)
- model: claude (기본)
- role: 태스크 역할과 일치
- initial_prompt: "get_agent_skill('{role}')로 스킬 파일 읽고 작업 시작"

### 4단계: 확인
전체 태스크와 에이전트 현황을 요약합니다.
```

보이시죠? 코드가 아니라 **자연어 지시**입니다.
Claude Code가 이 지시를 읽고, 알아서 MCP 도구를 호출합니다.

이게 강력한 이유:
- 프로그래밍 몰라도 스킬을 수정할 수 있습니다
- "priority는 1-3만 쓰자"로 바꾸면 바로 적용됩니다
- 팀마다, 프로젝트마다 커스터마이징이 쉽습니다

### 18개 스킬 분류 (3분)

화면: 슬라이드 — 스킬 분류표

18개 스킬을 워크플로우 단계별로 분류하면:

**기획 단계**
| 스킬 | 하는 일 | 주요 MCP 도구 |
|------|---------|-------------|
| `/tf-plan` | 소크라틱 → PRD → 태스크 분해 | (대화 기반) |
| `/tf-analyze` | 요구사항 분석만 (태스크 생성 없이) | (대화 기반) |

**실행 단계**
| 스킬 | 하는 일 | 주요 MCP 도구 |
|------|---------|-------------|
| `/tf-start` | plan + create + spawn 한 번에 | `create_tasks_bulk` + `spawn_agent` |
| `/tf-create-tasks` | 태스크만 생성 | `create_tasks_bulk` |
| `/tf-spawn-agents` | 에이전트만 스폰 | `spawn_agent` |

**작업 중**
| 스킬 | 하는 일 | 주요 MCP 도구 |
|------|---------|-------------|
| `/tf-status` | 진행 현황 조회 | `get_all_tasks` |
| `/tf-feedback` | 에이전트에 피드백 | `add_activity` |
| `/tf-add` | 태스크 추가 | `create_task` |

**리뷰 단계**
| 스킬 | 하는 일 | 주요 MCP 도구 |
|------|---------|-------------|
| `/tf-review` | REVIEW 태스크 검토 | `get_all_tasks` + `update_task_status` |
| `/tf-fix` | FAILED 진단 + 복구 | `get_task` + `update_task_status` |
| `/tf-sync` | 상태 동기화 | `get_all_tasks` |

**자동화/마무리**
| 스킬 | 하는 일 | 주요 MCP 도구 |
|------|---------|-------------|
| `/tf-ralph` | 반복 작업 일괄 처리 | `create_tasks_bulk` |
| `/tf-done` | 프로젝트 마무리 | `get_all_tasks` |
| `/tf-resume` | 세션 복원 | `get_all_tasks` |
| `/tf-hold` | 작업 일시정지 | `update_task_status` |
| `/tf-create-flow` | 플로우 생성 | `create_flow` |

### MCP 도구를 직접 호출해보기 vs. 슬래시 스킬 (2분)

화면: 터미널 — 직접 호출 vs 슬래시 스킬

**(실습)** 같은 일을 두 가지 방법으로 해봅시다.

**방법 1: 슬래시 스킬**
```
/tf-status
```
→ Claude Code가 자동으로 `get_all_tasks`를 호출하고, 예쁘게 정리해서 보여줌

**방법 2: 직접 지시**
```
get_all_tasks를 호출해서 전체 태스크를 보여줘.
상태별로 분류하고 진행률을 알려줘.
```
→ 같은 결과지만, 내가 직접 지시해야 함

슬래시 스킬은 결국 **자주 쓰는 지시를 미리 저장해둔 것**입니다.
필요하면 여러분만의 슬래시 스킬을 만들 수도 있어요.

`.claude/commands/my-custom.md` 파일을 만들면 `/my-custom`으로 호출 가능합니다.

## 정리 (1분)

슬래시 스킬 핵심:

1. **SKILL.md** = 프롬프트 템플릿 (코드가 아닌 자연어)
2. `.claude/commands/` 폴더에 Markdown 파일로 존재
3. 파일 이름 = 명령어 이름 (`tf-start.md` → `/tf-start`)
4. 내용 = "어떤 MCP 도구를 어떤 순서로 호출하라"는 지시
5. **커스터마이징 쉬움** — Markdown만 편집하면 됨

슬래시 스킬은 **도구(MCP)를 쉽게 쓰게 해주는 인터페이스**입니다.
다음 섹션에서는 에이전트가 "어떻게 행동할지"를 정의하는
에이전트 스킬 파일을 살펴보겠습니다.
슬래시 스킬과는 다른 겁니다 — 헷갈리지 마세요!
