에이전트 스킬 파일을 수정하고, 수정된 규칙에 따라 에이전트의 행동이 바뀌는 것을 직접 확인합니다.

## 실습 1: "테스트 의무" 규칙 추가 (10분)

### 수정 전: 기본 backend_agent.md

파일: `skills/backend_agent.md`

현재 코딩 규칙 섹션을 확인합니다:

```markdown
## 코딩 규칙
### TypeScript 패턴
- `strict: true` 준수 — any 타입 사용 금지
- 인터페이스와 타입을 명확히 정의
- async/await 패턴 사용 (콜백 금지)
- 에러 핸들링: try/catch + 의미 있는 에러 메시지
```

### 수정: 테스트 의무 규칙 추가

**(실습)**

코딩 규칙 섹션 아래에 다음을 추가하세요:

```markdown
### 테스트 의무 (TDD)
- **코드를 작성하기 전에** 테스트를 먼저 작성할 것
- 테스트 파일: 소스 파일과 같은 디렉토리에 `__tests__/` 폴더 생성
- 테스트 프레임워크: vitest
- 최소 커버리지: 모든 public 함수에 테스트 1개 이상
- add_activity 기록 시 반드시 테스트 결과 포함:
  - 예: "검증 완료: vitest 5/5 통과"
- **테스트 없이 submit_for_review 금지**
```

### 검증

1. 오케스트레이터 터미널에서 간단한 태스크를 생성합니다:
   ```
   "utils/calculator.ts에 add, subtract, multiply 함수를 만들어줘"
   같은 backend 태스크를 하나 만들고 에이전트를 스폰해줘.
   ```

2. 에이전트 터미널에서 관찰:
   - [ ] `get_agent_skill("backend")`를 호출하는지 확인
   - [ ] 테스트 파일을 **먼저** 작성하는지 확인
   - [ ] `add_activity`에 테스트 결과가 포함되는지 확인
   - [ ] 테스트 통과 후 `submit_for_review`를 호출하는지 확인

3. 칸반 보드에서 카드 이동 관찰:
   - TODO → CLAIMED → IN_PROGRESS → REVIEW

### 수정 전/후 비교

| | 수정 전 | 수정 후 |
|--|--------|--------|
| 테스트 작성 | 안 할 수도 있음 | **반드시 먼저 작성** |
| add_activity | 코드 구현 요약만 | **테스트 결과 포함** |
| submit_for_review 조건 | 코드만 완성되면 제출 | **테스트 통과해야 제출** |

## 실습 2: 다른 기술 스택으로 커스터마이징 (10분)

### 시나리오: Django + Vue.js 프로젝트

기존 backend_agent.md는 TypeScript + Electron 기반입니다.
Django 프로젝트를 위한 에이전트 스킬을 만들어봅시다.

**(실습)**

`skills/backend_agent.md`를 복사해서 수정합니다.
(원본을 보존하고 싶으면 복사본을 만드세요)

**기술 스택 수정:**

```markdown
## 기술 스택
- Python 3.11+
- Django 5.x + Django REST Framework
- PostgreSQL (또는 SQLite for dev)
- pytest + factory_boy (테스트)
- Poetry (패키지 관리)
```

**코딩 규칙 수정:**

```markdown
## 코딩 규칙

### Python 패턴
- Type hints 필수 (mypy strict 호환)
- f-string 사용 (format() 대신)
- pathlib 사용 (os.path 대신)
- dataclass 또는 Pydantic 모델 활용

### Django 패턴
- CBV(Class-Based View) 우선, 단순한 경우만 FBV
- Serializer에서 검증 로직 처리
- Fat Model, Thin View 원칙
- 모든 QuerySet은 select_related/prefetch_related 최적화
- Migration 파일은 반드시 생성하고 테스트

### API 패턴
- RESTful URL 설계 (/api/v1/resources/)
- Pagination 기본 적용 (PageNumberPagination)
- 에러 응답 표준화 ({"error": "message", "code": "ERROR_CODE"})
```

**Scope 규칙 수정:**

```markdown
## Scope 규칙
- `backend/` 디렉토리 내 파일만 수정
- `backend/apps/`, `backend/config/` 수정 가능
- 프론트엔드 폴더(`frontend/`)는 수정 금지
- settings.py에 시크릿 직접 작성 금지 (환경변수 사용)
- migration 파일 수동 편집 금지
```

### 검증

1. 간단한 Django 태스크를 만들어봅니다:
   ```
   "Django REST API로 Todo CRUD 엔드포인트를 만들어줘"
   ```

2. 에이전트가 생성하는 코드를 확인:
   - [ ] Python 코드인가? (TypeScript가 아닌지)
   - [ ] Django REST Framework를 사용하는가?
   - [ ] CBV(Class-Based View)를 사용하는가?
   - [ ] Type hints가 있는가?

## 실습 3: frontend_agent.md 수정 (선택)

frontend_agent.md도 같은 방식으로 수정할 수 있습니다:

**React → Vue.js 변경 예시:**

```markdown
## 기술 스택
- Vue.js 3 (Composition API)
- TypeScript (strict mode)
- Pinia (상태 관리)
- Vue Router
- Tailwind CSS

## 코딩 규칙
### Vue.js 패턴
- <script setup> 문법 사용
- composable 함수로 로직 분리 (use~ 접두사)
- Props는 defineProps로 타입 선언
- 이벤트는 defineEmits로 타입 선언
- 반응형 데이터는 ref/reactive 사용
```

---

## 핵심 배운 점

1. **스킬 파일 수정 = 에이전트 행동 변경** — 코드를 바꾸는 게 아니라 Markdown만 편집
2. **기술 스택은 스킬 파일로 결정됨** — Django든 FastAPI든 스킬 파일만 바꾸면 됨
3. **규칙 추가 효과가 즉시 반영됨** — 에이전트가 `get_agent_skill`로 최신 파일을 읽으므로
4. **Scope 규칙으로 충돌 방지** — 에이전트별 수정 가능 범위를 명확히
