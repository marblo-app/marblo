# 의존성 체인 + 병렬 레인 — 두 모델이 동시에

> 모듈 4 · 섹션 4-2 · 약 35분
> 관련: [[4-1_풀스택기획_역할설계]] | [[4-3_에이전트별_워크트리격리]]

---

## 이 강의에서 다루는 것

- **학습목표:** 레인 탭에서 Claude·Codex 두 에이전트가 **동시에** 일하는 모습을 읽고, 의존성이 어떻게 작업을 막고 풀어주는지(차단·해제) 이해한다.
- **시연할 마블로 화면·기능:** 레인 탭(LanesTab) — 병렬 레인 2~3개, 모델 아이콘·워크트리 pill·터미널 attach + 보드 탭의 의존성 해제.
- **진행할 프로젝트 단계:** P2 백엔드 + 프론트 병렬 진행.
- **핵심 메시지:** "**의존성은 막고, 독립 작업은 동시에.**"

---

## 도입 — 레인은 작업대다 (3분)

지난 섹션에서 태스크를 분해하고 두 모델에 역할을 나눠 배정했습니다. 이제 진짜 재미있는 부분 — **에이전트들이 실제로 일하는 모습**을 봅니다.

> 화면: 레인 탭(LanesTab) — 레인 2개가 나란히, 각 레인 헤더에 모델 아이콘

여기서 핵심 화면이 **레인 탭**입니다. 레인(Lane) 하나가 **한 에이전트의 작업대**예요. 모듈 3에서 한 명의 작업대를 봤다면, 이번엔 **여러 작업대가 나란히** 돌아갑니다.

- 한 레인에서는 **Claude Code**가 백엔드를 짓고,
- 바로 옆 레인에서는 **Codex**가 프론트를 짓습니다.

말 그대로 두 모델이 한 화면에서 동시에 코딩하는 거죠. 이게 멀티에이전트 협업의 실체입니다.

---

## 본문

### 1. 작업 시작 — 누가 먼저 움직이나 (6분)

> 화면: 보드 탭 — 6개 카드가 TODO, 일부는 blocked 표시

작업을 시작하면 보드의 카드들이 이렇게 보입니다.

```
✅ 6 tasks created:
  [TASK-001] 날씨 API 프록시 엔드포인트     → TODO
  [TASK-002] 즐겨찾기 도시 저장 API         → TODO  (blocked: TASK-001)
  [TASK-003] 도시 검색 UI                   → TODO  (blocked: TASK-001)
  [TASK-004] 날씨 카드 컴포넌트             → TODO  (blocked: TASK-001)
  [TASK-005] 5일 예보 차트                  → TODO  (blocked: TASK-004)
  [TASK-006] API 연동 테스트                → TODO  (blocked: TASK-003, 005)
```

`blocked`라고 표시된 카드들 보이시죠? **의존성이 있는 태스크는 아직 시작할 수 없습니다.** 백엔드 API(TASK-001)가 준비돼야 프론트(003·004)가 붙을 수 있으니까요.

그래서 지금 이 순간 **일할 수 있는 태스크는 TASK-001 하나뿐**입니다. 마블로는 무작정 모든 에이전트를 돌리지 않아요.

```
🤖 Lanes:
  [Lane 1] Claude Code  → claim TASK-001 (날씨 API 프록시)   WORKING
  [Lane 2] Codex        → standby (의존성 대기 중)            IDLE
```

Claude Code가 TASK-001을 claim하고 일을 시작합니다. Codex는 아직 대기예요 — 프론트 태스크가 전부 백엔드에 막혀 있으니까요. **비용도 아끼고, 충돌도 막는** 구조입니다.

### 2. 레인 행 읽는 법 (7분)

> 화면: 레인 탭 — 레인 1행 확대 (모델 아이콘 · 워크트리 pill · attach 버튼)

레인 한 줄에는 정보가 촘촘히 들어 있습니다. 하나씩 읽어봅시다.

- **모델 아이콘** — 이 레인을 누가 돌리는지. 🟣 = Claude Code, Codex 배지 = Codex.
- **현재 태스크** — 지금 claim한 카드 (예: TASK-001).
- **상태** — CLAIMED / IN_PROGRESS / REVIEW 등 (보드 카드와 동기화).
- **워크트리 pill** — 이 에이전트가 일하는 격리 워크트리의 상태(🟢/🟡/⚪…). 워크트리는 다음 섹션(4-3)에서 깊이 다룹니다.
- **터미널 attach** — 클릭하면 그 에이전트의 PTY가 열려, **실제로 코드를 짜는 과정**을 들여다볼 수 있습니다.

**(실습)** Claude Code 레인의 **attach**를 눌러 백엔드 작업을 들여다봅시다.

> 화면: PTY attach — Claude Code가 weather.py를 작성하는 로그 스트리밍

```
[Claude Code] Claiming TASK-001: 날씨 API 프록시 엔드포인트
[Claude Code] Status: TODO → IN_PROGRESS
[Claude Code] Creating backend/app/routers/weather.py
[Claude Code] Adding OpenWeather API integration...
[Claude Code] GET /api/weather/{city}, GET /api/weather/{city}/forecast
[Claude Code] Activity: "날씨 API 엔드포인트 구현 완료"
[Claude Code] Status: IN_PROGRESS → REVIEW
```

레인 = 작업대, attach = 그 작업대를 들여다보는 창. 보드가 "무엇이 어디까지"라면, 레인은 "**지금 손으로 뭘 하고 있나**"를 보여줍니다.

### 3. 의존성 해제 — 두 번째 레인이 깨어난다 (8분)

> 화면: 보드 탭 — TASK-001이 REVIEW로, TASK-003·004의 blocked 해제

Claude Code가 TASK-001을 끝내는 순간, 마법 같은 일이 벌어집니다.

```
[Lane 1] Claude Code  → TASK-001 REVIEW 제출
  └─ 의존성 해소: TASK-002, TASK-003, TASK-004 unblocked!

[Lane 2] Codex        → claim TASK-004 (날씨 카드 컴포넌트)   WORKING
```

백엔드 API가 완성되자마자 그에 막혀 있던 프론트 태스크들의 `blocked`가 풀립니다. 그러자 대기 중이던 **Codex 레인이 깨어나** 프론트 작업을 시작해요.

> 화면: 레인 탭 — 두 레인이 동시에 IN_PROGRESS (2배속 캡처)

이제 화면에 **두 레인이 동시에** 돌아갑니다.

```
[Lane 1] 🟣 Claude Code → TASK-002 (즐겨찾기 API)      IN_PROGRESS
[Lane 2]    Codex       → TASK-004 (날씨 카드)          IN_PROGRESS
```

Claude는 다음 백엔드 태스크(즐겨찾기 API)로 넘어가고, Codex는 프론트를 짓습니다. **서로 다른 모델이, 서로 다른 역할을, 동시에.** 이게 "독립 작업은 동시에"의 실체예요.

> 💡 의존성이 작업을 **막는 것**과 **푸는 것** 둘 다 자동입니다. 여러분이 "이제 프론트 시작해"라고 말할 필요가 없어요. 백엔드가 REVIEW로 가는 순간 마블로가 알아서 프론트 레인을 깨웁니다.

### 4. 의존성 그래프 — 전체 흐름 보기 (8분)

> 화면: 의존성 그래프 — 카드 간 화살표로 연결된 DAG

지금 일어나는 일을 그래프로 보면 한눈에 들어옵니다.

```
TASK-001 (백엔드 API) ── Claude
   ├── TASK-002 (즐겨찾기 API) ── Claude
   ├── TASK-003 (검색 UI) ────── Codex
   └── TASK-004 (날씨 카드) ──── Codex
          └── TASK-005 (예보 차트) ── Codex
                 └── TASK-006 (연동 테스트) ── Codex  ← TASK-003도 필요
```

이 그래프가 곧 **작업 순서**입니다.

- **세로(의존)** — 위가 끝나야 아래가 풀린다. 막는 축.
- **가로(병렬)** — 같은 레벨의 독립 태스크는 동시에. 푸는 축.

예를 들어 TASK-002(백엔드)와 TASK-004(프론트)는 둘 다 TASK-001에만 의존하므로, **TASK-001만 끝나면 동시에** 진행됩니다. 반면 TASK-006(테스트)은 TASK-003·005가 모두 끝나야 하니 맨 마지막이죠.

> 화면: 보드 탭 — 진행률 바, 여러 카드가 IN_PROGRESS / REVIEW에 분산

시간이 좀 지나면 보드는 이런 모습이 됩니다.

```
Progress: ████████████░░░░░ 4/6 (67%)
  ✅ TASK-001  날씨 API 프록시        DONE         🟣 Claude
  ✅ TASK-002  즐겨찾기 API           DONE         🟣 Claude
  🔨 TASK-003  도시 검색 UI           IN_PROGRESS     Codex
  ✅ TASK-004  날씨 카드              DONE            Codex
  🔨 TASK-005  5일 예보 차트          IN_PROGRESS     Codex
  ⏳ TASK-006  API 연동 테스트        TODO  (depends: 003, 005)
```

여기서 재미있는 점 — Claude는 백엔드를 다 끝내서 **할 일이 없어졌습니다.** 프론트 태스크를 억지로 맡길 순 없으니 대기 상태가 되죠. 실제 팀에서도 백엔드 개발자가 먼저 끝나면 기다리잖아요? 같은 원리입니다. (이 유휴 시간을 활용하는 법 — reuse·cleanup·새 작업 끼워넣기 — 은 모듈 5·6에서.)

> **[설명보드: 4-2 병렬 레인 + 의존성 체인]** — Excalidraw (후속 제작)
>
> - 위: 레인 2개가 나란히 — 왼쪽 🟣 Claude(백엔드), 오른쪽 Codex(프론트). 각 레인 안에 PTY 미니 화면.
> - 가운데: 두 레인을 잇는 의존성 화살표 — TASK-001(백엔드) → TASK-003·004(프론트)에 "unblock!" 라벨.
> - 아래: 의존성 그래프(DAG) — 세로축 "막는다(의존)", 가로축 "동시에(병렬)" 두 방향 강조.
> - 캡션: "막을 건 막고, 풀린 건 동시에. 사람은 한 줄도 안 짠다."
> - 모델 칩: Claude Code · Codex (+ Antigravity). ※ Gemini 표기 금지.

## 정리 (1분)

1. **레인 = 한 에이전트의 작업대.** 병렬 레인으로 Claude·Codex가 동시에 일한다.
2. **레인 행**에는 모델 아이콘·현재 태스크·상태·워크트리 pill·터미널 attach가 있다.
3. **의존성은 자동으로 막고 푼다.** 백엔드 REVIEW → 프론트 레인 자동 활성화.
4. **그래프의 세로는 의존(막는 축), 가로는 병렬(푸는 축).** 독립 작업은 동시에.

두 모델이 동시에 일하면 한 가지 걱정이 생깁니다 — "같은 코드를 동시에 고치면 안 엉키나?" 다음 섹션에서 그 답, **워크트리 격리**를 봅니다.
