> 화면: 슬라이드 — "여기서 끝이 아닙니다"

지금까지 마블로의 **정식 기능 9개 탭**을 전부 다뤘습니다 — 가이드·보드·레인·코드·에이전트·사용량·워크트리·하네스·설정. 이 정도면 실무에서 바로 쓸 수 있습니다.

## 본문

### 1. 베타 미리보기 — 곧 정식이 될 기능들 (8분)

> 화면: 슬라이드 — "정식 9탭 + 베타 3탭"

먼저 짚을 게 있습니다. 지금부터 보여드리는 **Flows · Missions · Deploy**는 기본 빌드에서는 **숨겨져 있습니다.** 개발 플래그(`VITE_DEV_FEATURES`)를 켠 별도 빌드에서만 보이는 **베타 기능**이에요. 아직 다듬는 중이라 정식 9탭과 같은 완성도를 기대하면 안 되지만, 마블로가 어디로 가는지 보여주는 미리보기입니다.

**① Flows — 비주얼 자동화 파이프라인**

> 화면: (플래그 빌드) Flows 탭 — 노드 캔버스

칸반이 **"누가 뭘 하고 있나"**(상태)를 본다면, Flows는 **"어떤 순서로 처리하나"**(파이프라인)를 봅니다. `@xyflow/react` 기반의 비주얼 DAG 에디터로, 노드를 배치하고 연결해서 자동화 흐름을 설계합니다.

```
[Input] → [LLM 분석] → [Branch] → [Agent 작업] → [Output]
                           ↓
                       [Human 검토]
```

노드 타입은 Input · LLM · Agent · API · Human · Branch · Output. 예를 들어 "리드 CSV 업로드 → LLM이 분류 → 점수 분기 → 에이전트가 콜드메일 생성 → 발송" 같은 파이프라인을 시각적으로 엮을 수 있어요. Flows의 Agent 노드는 칸반 태스크와 양방향으로 연동됩니다 — Agent 노드가 실행되면 보드에 카드가 생기고, 카드가 DONE이 되면 다음 노드가 돕니다.

> 💡 Flows는 **플랜 게이팅**(요금제에 따라 노출/한도)이 걸린 베타입니다. 지금은 "칸반 + 플로우를 함께 쓰면 자동화가 강력해진다"는 그림만 잡아두세요. 미가용 빌드라면 이 부분은 **"곧 정식" 컷**으로 짧게 넘어갑니다.

**② Missions — 가이드형 미션 (WIP)**

> 화면: (플래그 빌드) Missions 탭

Missions는 마블로를 **단계별로 따라 하며 배우는** 가이드형 기능입니다. "첫 풀사이클 돌려보기", "멀티에이전트로 빌드하기" 같은 미션을 따라가면 마블로 사용법이 손에 붙도록 설계되고 있어요. 아직 **작업 중(WIP)**이라 미리보기 수준으로만 봅니다.

**③ Deploy — 배포 탭**

> 화면: (플래그 빌드) Deploy 탭

모듈 7에서 GCP Cloud Run 배포는 **CLI 주도**로 했죠(`gcloud run deploy`). Deploy 탭은 이 배포 과정을 **버튼 흐름**으로 끌어오려는 베타입니다. 지금은 dev 플래그 뒤에 있고, 정식이 되면 배포도 클릭 몇 번으로 가게 됩니다 — 하지만 **지금 운영에서는 CLI 경로가 정답**이에요.

정리하면: **Flows·Missions·Deploy = 곧 정식이 될 미래.** 오늘은 미리보기로만, 실전은 정식 9탭으로.

### 2. 확장 방향 — 직접 키울 수 있는 것들 (6분)

> 화면: 슬라이드 — 확장 로드맵

베타 기능 말고도, 마블로는 **여러분이 직접** 확장할 수 있습니다.

**새 에이전트 역할.** 지금까지 backend·frontend·test를 썼지만, 역할은 스킬 파일 한 장으로 자유롭게 정의합니다(8-3에서 봤죠).

```
Data 에이전트    → ETL·분석 쿼리·시각화 (대용량 컨텍스트 모델이 유리)
Security 에이전트 → OWASP 취약점 스캔·패치 (안전성 판단에 강한 Claude)
Design 에이전트  → UI/UX 제안·디자인 시스템 (가용 시 디자인 MCP 결합)
DevOps 에이전트  → 인프라·모니터링·스케일링 (Terraform·CI/CD)
```

`skills/` 폴더에 `data_agent.md` 한 장을 추가하면 그 역할이 생깁니다.

**팀 · 엔터프라이즈.** 개인을 넘어 팀/회사로 가면 — 공유 칸반 보드, 역할별 권한, SSO, 온프레미스 배포 같은 방향이 열립니다. 한 보드를 여러 사람이 공유하면서 각자의 에이전트 팀은 독립적으로 굴리는 그림이에요.

**자율 협업으로.** 지금은 PM(여러분)이 요구를 주고, 리뷰하고, 승인하며 중간중간 개입합니다. 마블로가 향하는 방향은 **에이전트끼리 서로 리뷰하고 피드백**해서 PM 개입을 줄이는 쪽입니다 — 예를 들어 test 에이전트가 backend의 결과를 자동 검토해 "서명 검증이 빠졌다"고 되돌리는 식으로. 물론 중요한 결정은 끝까지 사람이 합니다. 방향은 분명해요: **사람은 방향을 정하고, 에이전트는 실행한다.**

> ⚠️ 이 확장 항목 일부(팀/엔터프라이즈, 자율 협업)는 **로드맵·방향**입니다. 지금 당장 쓸 수 있는 건 "새 에이전트 역할 정의"와 "커스텀 상태·MCP"(8-3)예요. 이 둘부터 시작하세요.

### 3. 전체 여정 회고 (5분)

> 화면: 모듈별 여정 타임라인

이 강좌에서 여러분이 실제로 만든 것들입니다.

| 모듈 | 주제                    | 핵심                                                   |
| ---- | ----------------------- | ------------------------------------------------------ |
| 1    | 왜 팀인가 + 한 바퀴     | 9탭 + 오케 PTY, "PM/팀리더가 된다"                     |
| 2    | 셋업 0→1                | 하네스 원클릭, Claude Code + Codex 인증, 연결·워크트리 |
| 3    | 첫 풀사이클 (P1)        | **할 일 웹앱** — 보드·레인·워크트리 머지               |
| 4    | 멀티에이전트 (P2)       | **날씨 대시보드** — Claude + Codex 병렬                |
| 5    | 실전 SaaS 스프린트 (P3) | **ReachWave 콜드메일** — 칸반 거버넌스                 |
| 6    | 플릿·오케 심화          | 모델별 강점, dispatch, 멀티윈도우, 사용량/비용         |
| 7    | 배포 + 런칭             | 워크트리 머지 → GCP Cloud Run → CI/CD → 랜딩           |
| 8    | 운영·확장·마무리        | 일상 운영, Ralph, 커스터마이즈, 베타·확장 (지금)       |

**여러분이 만든 포트폴리오 3개:**

1. **할 일 웹앱(P1)** — 마블로 기본 워크플로우, 첫 워크트리 머지
2. **날씨 대시보드(P2)** — Claude + Codex 멀티에이전트 풀스택
3. **ReachWave 콜드메일 SaaS(P3)** — 요구분석부터 GCP 배포·런칭까지 풀사이클

이 셋은 그냥 연습이 아니라 **포트폴리오**입니다. "AI 에이전트 오케스트레이션으로 SaaS를 구축하고 클라우드에 배포한 경험" — 지금 시장에서 희소한 역량이에요.

핵심 멀티모델 전략도 한 줄로 정리됩니다.

```
Claude Code → 복잡 로직·코드 품질·MCP·보안 (품질 중시)
Codex(gpt)  → 풀스택·테스트·반복 코드·속도
Antigravity → 떠오르는 3번째 (Gemini의 후신)
```

> 💡 Gemini는 플릿에서 빠졌습니다. **기본 2인(Claude Code + Codex) + 떠오르는 Antigravity** — 이게 현재의 팀 구성입니다. 비용은 머릿속이 아니라 **사용량 탭에서 측정**해 통제합니다(단가는 늘 변하니까요).

### 4. 마무리 메시지 (3분)

> 화면: 슬라이드 — "일하는 방식의 변화"

잠깐 큰 그림을 봅시다. 얼마 전까지 "AI가 코드를 짠다"는 건 신기한 데모 수준이었습니다. 지금은 다릅니다. AI 에이전트가 실제로 파일을 만들고, 커밋하고, 테스트를 돌리고, 배포까지 합니다. 그리고 마블로 같은 도구로 이 에이전트들을 **조직화**해 진짜 팀처럼 운영할 수 있어요.

이건 단순한 도구 사용법이 아니라 **일하는 방식의 변화**입니다. 여러분은 이제 자연어로 요구를 던지면 에이전트 팀이 코드를 만들고, 칸반으로 관리하고, 멀티모델로 비용을 최적화하고, 클라우드에 배포하고, 반복을 자동화할 수 있습니다.

**여러분은 이제 에이전트 팀을 지휘하는 PM입니다.**

막막하다면 이렇게 시작하세요.

```
1. 지금 하는 프로젝트에서 가장 귀찮은 반복 작업 하나를 골라 /tf-ralph 로 처리
2. 익숙해지면 /tf-start 로 새 기능을 빌드
3. 더 익숙해지면 /tf-analyze 로 큰 프로젝트를 계획
4. 자신의 아이디어가 있다면 — 요구분석 → 멀티모델 팀 → 배포 → 런칭까지 직접
```

> 💡 커뮤니티·쿠폰 안내는 강좌 수강 페이지에 함께 제공됩니다(현행 링크·혜택은 그곳 기준). 만든 프로젝트를 공유하고, 막히는 부분을 질문하며 계속 굴려보세요.

## 정리 (1분)

> 화면: 최종 정리 슬라이드

1. **베타 미리보기** — Flows(자동화 파이프라인)·Missions(가이드 미션)·Deploy(배포 탭)는 `VITE_DEV_FEATURES` 플래그 뒤의 **곧 정식**. 실전은 정식 9탭으로.
2. **확장은 직접** — 새 에이전트 역할·커스텀 상태·MCP는 지금 당장. 팀/엔터프라이즈·자율 협업은 로드맵.
3. **여정 회고** — P1 할 일 웹앱 · P2 날씨 대시보드 · P3 ReachWave SaaS. 셋은 여러분의 포트폴리오.
4. **여기서 끝이 아니라 출발점.** 이제 여러분은 에이전트 팀을 지휘합니다.

지금까지 "마블로 v3 마스터 클래스"를 끝까지 완주해 주셔서 감사합니다. 여러분의 첫 번째 에이전트 프로젝트를 응원합니다. 화이팅!
