# 태스크 분해 → 보드 카드

> 모듈 3 · 섹션 3-2 · 약 15분
> 관련: [[3-1_오케에게_자연어요청]] | [[3-3_레인에서_에이전트관찰]]

---

## 이 레슨의 4요소

- **학습목표:** 자연어 요청이 **태스크로 쪼개져 보드에 카드로 올라오는** 것을 읽는다. 역할 배지와 의존성 표시의 의미를 안다.
- **시연할 마블로 화면·기능:** **보드 탭(BoardTab)** — TODO 컬럼에 카드 등장, 역할 배지(frontend), 의존성(depends_on) 표시, 우선순위.
- **진행할 프로젝트 단계:** P1 태스크 3~4개.
- **핵심 메시지:** "추상적 요청이 **추적 가능한 카드**가 된다."

---

## 도입 (2분)

지난 레슨에서 오케스트레이터에게 "localStorage 할 일 웹앱 만들어줘"라고 말하고, 되묻는 질문에 답한 뒤 "진행해줘"까지 했습니다. 그 순간 오케가 한 일 — **요청을 여러 개의 작은 태스크로 쪼개서 보드에 올리는 것** — 을 이번 레슨에서 눈으로 확인합니다.

상단 탭바에서 **보드(Board)** 탭을 엽니다.

화면: 마블로 상단 탭바 → 보드 탭

---

## 본문

### 1. TODO 컬럼에 카드가 등장한다 (5분)

화면: 보드 탭 — TODO 컬럼에 카드 3~4개가 하나씩 나타남

오케스트레이터가 `create_tasks_bulk`로 태스크를 일괄 생성하면, 보드의 **TODO 컬럼**에 카드가 하나씩 나타납니다. 방금 말로 한 요청이 **실체가 있는 카드**가 되는 순간이에요.

P1(할 일 웹앱)은 작아서 카드 3~4장이면 충분합니다. 예를 들면 이렇게요:

```
TODO
┌─────────────────────────────────┐
│ [TASK-1] 기본 화면 + 스타일       │  🟦 frontend  ·  우선순위 ●●●
│  index.html / style.css 골격      │
├─────────────────────────────────┤
│ [TASK-2] 할 일 추가·완료·삭제     │  🟦 frontend  ·  depends: TASK-1
│  app.js — DOM 조작 + 이벤트       │
├─────────────────────────────────┤
│ [TASK-3] localStorage 영속화      │  🟦 frontend  ·  depends: TASK-2
│  새로고침해도 목록 유지            │
├─────────────────────────────────┤
│ [TASK-4] 필터(전체·진행·완료)     │  🟦 frontend  ·  depends: TASK-2
│  + 빈 상태(empty) UI             │
└─────────────────────────────────┘
```

전부 TODO에 모여 있죠. 아직 아무도 손대지 않은 상태입니다([[1-4_큰그림_파이프라인]]의 상태 머신에서 첫 칸 — TODO).

### 2. 카드에 담긴 세 가지를 읽는다 (5분)

화면: 보드 탭 — 카드 하나 확대 (배지·의존성·우선순위)

카드 한 장에는 작업을 추적하는 데 필요한 정보가 압축돼 있어요. 세 가지만 읽을 줄 알면 됩니다.

**① 역할 배지 (role)** — `frontend`, `backend`, `test`, `devops` 같은 라벨이에요. 이 배지를 보고 **어떤 성격의 에이전트가 이 카드를 맡을지**가 정해집니다. P1은 프론트 단독이라 전부 **🟦 frontend** 예요. (백엔드·테스트 역할이 섞이는 건 모듈 4의 P2부터입니다.)

**② 의존성 (depends_on)** — `depends: TASK-1` 표시를 보세요. **TASK-1이 끝나야 TASK-2가 시작**될 수 있다는 뜻입니다. 화면 골격(TASK-1)이 있어야 그 위에 추가·삭제 로직(TASK-2)을 붙일 수 있고, 그게 되어야 저장(TASK-3)과 필터(TASK-4)를 얹을 수 있죠. 이 순서를 **오케가 자동으로 파악**해서 카드에 박아 둡니다.

**③ 우선순위** — 어떤 카드부터 집을지를 정하는 가중치예요. 의존성이 없는 TASK-1이 가장 먼저 잡힐 카드입니다.

> 💡 의존성이 걸린 카드(TASK-2/3/4)는 선행 카드가 끝날 때까지 **자동으로 막혀(blocked)** 있습니다. 에이전트가 엉뚱한 순서로 일하지 않게 마블로가 막아주는 거예요.

### 3. 좋은 카드 = 결과물이 하나로 명확한 카드 (2분)

화면: 슬라이드 — 좋은 카드 vs 나쁜 카드

오케가 만든 카드를 보면 하나의 공통점이 있어요. **각 카드가 딱 하나의 명확한 결과물**을 가집니다.

- ✅ "할 일 추가·완료·삭제" — 에이전트가 뭘 만들면 되는지 분명함
- ❌ "프론트엔드 만들어줘" — 너무 크고 모호함. 어디까지가 끝인지 알 수 없음

오케스트레이터가 보통 이 정도 크기로 알아서 쪼개주지만, **카드를 검토하고 승인하는 건 PM인 여러분**입니다. 너무 크면 "TASK-2를 둘로 나눠줘", 불필요하면 "TASK-4는 빼줘"라고 **말로** 조정하면 됩니다.

> 💡 보드는 단순한 목록이 아니라 **프로젝트의 단일 진실원(single source of truth)** 입니다. 에이전트·오케·PM이 모두 이 카드 상태를 보고 움직여요.

---

## 정리 (1분)

화면: 정리 슬라이드

1. 자연어 요청 → 오케가 `create_tasks_bulk`로 **TODO 컬럼에 카드** 생성.
2. 카드에서 읽을 세 가지: **역할 배지 · 의존성 · 우선순위.**
3. 의존성 걸린 카드는 선행 카드가 끝날 때까지 **자동으로 막힌다(blocked).**
4. 좋은 카드 = **결과물이 하나로 명확.** 검토·조정은 PM의 몫(말로).

카드가 보드에 올라왔으니, 이제 에이전트가 첫 카드를 집어 **실제로 코드를 짜는** 걸 레인에서 들여다봅니다.
