# Marblo v3 강의 커리큘럼

> AI 에이전트 군단 워크스페이스 — 데스크탑 앱으로 완성하는 실전 프로젝트
> 최종 업데이트: 2026.04.28

---

## 1. 강의 포지셔닝

### 한 줄 요약
**"AI 에이전트 군단을 데스크탑 앱에서 직접 관리하며, 실전 프로젝트를 처음부터 배포까지 완성합니다."**

### v1(CLI 기반) → v3(데스크탑 앱) 주요 변화

| | v1 (CLI + Docker) | v3 (Electron Desktop) |
|--|-------------------|----------------------|
| 실행 방식 | Docker Compose + 5개 컨테이너 | 앱 더블클릭 (설치 끝) |
| 칸반 보드 | 브라우저 (localhost:3001) | 앱 내장 (드래그앤드롭) |
| 터미널 | 별도 사이드카 서버 | 앱 내장 (node-pty + xterm.js) |
| 코드 에디터 | 없음 (VS Code 별도) | Monaco Editor 내장 |
| 에이전트 모델 | Claude만 | **Claude + Gemini + GPT + Custom** |
| 오케스트레이터 | 없음 | 자연어 → 태스크 자동 분해 |
| 멀티윈도우 | 없음 | 여러 프로젝트 동시 작업 (Cmd+Shift+N) |
| 세션 복원 | 없음 | 잠자기/재시작 후 자동 복원 |
| 팀 협업 | 없음 | 프로젝트 멤버 + 실시간 동기화 |
| 결제 시스템 | 없음 | Paddle(해외) + TossPayments(국내) |
| MCP 서버 | Python (FastAPI 프록시) | Node.js (Firebase 직접 연결) |
| 인증 | 없음 | Firebase Auth (Google/GitHub/Email) |
| 배포 | 로컬만 | macOS/Windows/Linux 패키징 |

### 킬링 포인트 3가지
1. **멀티모델 오케스트레이션**: Claude가 팀리더, Gemini가 프론트, Codex가 테스트 — 한 보드에서 관리
2. **올인원 데스크탑**: 칸반 + 터미널 + 에디터 = Cursor 대체 + 에이전트 군단
3. **실전 SaaS 빌드**: 강의가 끝나면 배포 가능한 서비스가 나옴

## 2. 타겟 수강생

- Claude Code를 써본 적 있는 개인 개발자 (에이전트 활용을 체계화하고 싶은 사람)
- AI 에이전트로 팀처럼 프로젝트를 관리하고 싶은 프리랜서
- Claude Code 생태계(MCP, Hook, 슬래시 스킬)를 깊이 이해하고 싶은 중급 개발자
- 부업/SaaS 프로젝트를 AI와 함께 빠르게 만들고 싶은 사람

### 선수 지식
- 프로그래밍 기초 (어떤 언어든 OK)
- 터미널 사용 경험
- Claude Code 기본 사용법 (있으면 좋고, 없으면 모듈 1에서 커버)

### Part 1. 시작 — "10분 안에 에이전트 돌려보기"

---

#### 모듈 1. 마블로 소개 + 설치 + 첫 체험 (2시간)

**학습 목표:** 마블로가 뭔지 이해하고, 핵심 기능을 파악하고, 설치 후 첫 에이전트 팀을 돌려본다.

**1-1. 왜 AI 에이전트 '군단'인가 (15분)**
- 혼자 코딩하는 AI vs. 팀으로 협업하는 AI
- Agent Teams: Team Leader가 Sub-agent를 스폰하고 조율
- JIRA + MCP vs. Marblo 비교표
- v3 데모 미리보기 (30초): 칸반 + 터미널 + 에이전트가 한 화면에서 돌아가는 모습

**1-2. 마블로 핵심 기능 소개 — "이걸 왜 만들었는가" (25분)** ⭐

> 마블로 앱을 열어서 각 기능을 하나씩 시연하며 설명합니다.

- **STDIN 자동 프롬프트 주입 (Orchestrator Terminal)**
  - 마블로의 핵심 기술: Electron의 node-pty가 Claude Code의 STDIN에 직접 프롬프트를 주입
  - 오케스트레이터 터미널에서 자연어를 입력하면 → Claude Code가 자동으로 태스크 분해 + 에이전트 스폰
  - 기존 방식: 터미널 열고, claude 치고, 프롬프트 복붙... → 마블로: 앱에서 바로 주입
  - `window.electronAPI.pty.write(sessionId, prompt + '\r')` — 이 한 줄이 핵심
  - 왜 중요한가: 에이전트를 "프로그래밍적으로" 제어할 수 있게 해주는 인터페이스

- **슬래시 메뉴 (/ Slash Commands)**
  - 오케스트레이터 터미널에서 `/` 입력 → 명령어 팝업 자동 표시
  - `/analyze`, `/create-tasks`, `/spawn-agents`, `/status`, `/create-flow`
  - 각 슬래시 명령어가 미리 정의된 한국어 프롬프트를 STDIN에 주입
  - "MCP 도구 이름을 외울 필요 없이 `/`만 치면 됨"
  - 키보드 방향키로 선택 → Enter로 실행

- **올인원 워크스페이스 (3개 핵심 탭)**
  - **Board 탭**: 칸반 보드 — 드래그앤드롭으로 태스크 이동, PM 피드백 → 에이전트 실시간 주입
  - **Code 탭**: Monaco Editor — VS Code 수준의 코드 에디터 + 파일 트리
    - Prettier 자동 포맷 (`Cmd+S` 저장 시 코드 자동 정리, 프로젝트 설정 인식)
    - 미니맵, 괄호 색상, Sticky Scroll, Indent Guide 등 핵심 기능 내장
    - Diff View: 에이전트가 변경한 부분을 시각적으로 비교
    - 에이전트 작업 → FileTree 실시간 반영 → 에디터에서 즉시 확인/수정
  - **Agents 탭**: 에이전트 대시보드 — 상태 모니터링, 비용 추적, 모델 프리셋, 일괄 정리

- **멀티윈도우 + 세션 복원**
  - `Cmd+Shift+N`으로 새 창 → 다른 프로젝트 독립 작업
  - Mac 잠자기/재시작 후 폴더 + 에이전트 + 오케스트레이터 자동 복원
  - 각 윈도우가 독립적인 IPC 이벤트, 데이터 로깅

- **PM 피드백 → 에이전트 실시간 주입 (PTY Injection)**
  - 칸반 보드에서 리플 → 에이전트 PTY stdin에 `[PM Feedback]` 자동 주입
  - 태스크 재배정/취소/우선순위 변경 → 에이전트에 즉시 알림
  - 에이전트 오프라인 시 → 오케스트레이터에 자동 포워딩

- **통합 터미널 패널**
  - 칸반 보드 하단에 터미널 패널이 통합
  - 보드에서 카드 이동 + 터미널에서 에이전트 로그 = 한 화면에서 관찰
  - 오케스트레이터 터미널 + 에이전트별 터미널 분리

- **멀티모델 에이전트 지원**
  - Claude + Gemini + GPT(Codex) + Custom 모델
  - 각 모델별 MCP 설정 자동 생성
  - 에이전트 추가 모달에서 모델 선택 → CLI 명령어 자동 구성

- **MCP 브릿지 서버**
  - Electron 메인 프로세스에서 HTTP 브릿지 서버 실행
  - MCP 도구 호출 → 브릿지 → 오케스트레이터 알림
  - 에이전트가 태스크 상태 변경 → 칸반 보드에 즉시 반영

**1-3. 마블로 설치 + Claude Code 필수 사용법 (25분)**
- **마블로 설치**: DMG 다운로드 → 더블클릭 → 끝
  - v1과 비교: Docker 5개 컨테이너 vs. 앱 1개
  - Firebase 프로젝트 연결 (제공된 가이드 따라 5분)
- **Claude Code 필수 사용법**:
  - 설치: `curl -fsSL https://claude.ai/install.sh | bash`
  - 핵심 명령어: `/compact`, `/cost`, `/clear`, `/model`
  - 권한 모드: Normal / Auto-Accept / Plan
  - 비용 최적화 팁

**1-4. 환경 설정 — MCP + 슬래시 스킬 + Hook (20분)**
- MCP 서버 연결 (마블로 앱이 자동으로 MCP 설정 생성)
- 슬래시 스킬 18개 설치: `./scripts/setup-claude.sh`
- Hook 설정: 매 프롬프트마다 "티켓 없이 코드 수정 금지" 강제
- Hook vs CLAUDE.md vs 슬래시 스킬 차이

**1-5. 첫 풀사이클 체험 (25분)**
- `/tf-plan Hello World API` → 소크라틱 질문 → PRD 생성 → 태스크 분해
- `/tf-start` → 태스크 생성 + 에이전트 자동 스폰
- 마블로 앱에서 실시간 관찰:
  - 칸반 보드: 카드가 TODO → CLAIMED → IN_PROGRESS → REVIEW 이동
  - 터미널 패널: 에이전트 작업 로그
- `/tf-review` → Approve → DONE
- **"이게 전체 흐름입니다. 나머지는 이걸 잘 하는 법입니다."**

#### 모듈 2. 시스템 구조 + 에이전트 스킬 설계 (2시간)

**학습 목표:** MCP, 상태 머신, 슬래시 스킬의 동작 원리를 이해하고, 에이전트 스킬을 커스터마이징할 수 있다.

**2-1. MCP란 무엇인가 (15분)**
- MCP = Model Context Protocol. AI가 외부 도구를 호출하는 표준
- v3 MCP: Node.js stdio → Firebase Firestore 직접 연결
- Tool, Prompt, Resource 개념

**2-2. 마블로 아키텍처 — v3 코드 뜯어보기 (20분)**
- 전체 구조: Electron Main → Preload → React Renderer → Firebase
- `electron/mcp-server/tools.ts` 열어보기: MCP 도구 정의
- `electron/agent-manager.ts`: 에이전트 라이프사이클 (스폰/재활용/삭제)
- `electron/orchestrator-manager.ts`: 오케스트레이터 세션 관리
- `electron/bridge-server.ts`: MCP → Electron 브릿지 (inject-message, set-agent-status)
- `electron/dispatch-scoring.ts`: 모델 프리셋 + 태그 기반 스코어링
- 코드 편집 파이프라인: 에이전트가 파일 수정 → FileTree 실시간 반영 → Monaco Editor에서 디프 확인 → Prettier 자동 포맷 → PM이 수정/승인

**2-3. 상태 머신 — 왜 JIRA 칸반과 다른가 (15분)**
- 7개 상태, 유효 전환만 허용하는 State Machine
- `SELECT FOR UPDATE SKIP LOCKED` — 동시 claim 충돌 방지
- Firestore Security Rules로 강제

**2-4. 슬래시 스킬 구조 — "/ 뒤에서 무슨 일이" (15분)**
- SKILL.md = 프롬프트 템플릿 (MCP 도구 호출 레시피)
- 18개 스킬의 분류: 기획/실행/작업/리뷰/자동화
- MCP 도구를 직접 호출해보기 vs. 슬래시 스킬 사용

**2-5. 에이전트 스킬 파일 — 역할별 행동 규칙 (30분)**
- 5가지 역할: backend, frontend, test, devops, orchestrator
- `skills/backend_agent.md` 열어보기: 코딩 규칙, TDD 의무, activity 기록
- **실습**: 스킬 파일 수정 → 에이전트 행동 변화 관찰
  - "테스트 없이 코드 작성 금지" 규칙 추가 전/후 비교
  - Django/Vue.js 등 다른 스택으로 커스터마이징

**2-6. PM 피드백 + 에이전트 제어 — "칸반에서 에이전트를 조종하기" (25분)**
- PTY Injection 원리: 칸반 리플 → bridge-server → 에이전트 PTY stdin
- 6가지 자동 주입 태그: `[PM Feedback]`, `[Task Status Changed]`, `[Task Reassigned]`, `[Priority Changed]`, `[Task Updated]`, `[Task Cancelled]`
- 에이전트 오프라인 → 오케스트레이터 자동 포워딩
- 실습: 칸반에서 에이전트에게 방향 전환 지시 보내기

### Part 3. 실전 — "직접 만들어보기"

#### 모듈 3. 워밍업 프로젝트: 날씨 대시보드 (1.5시간)

**프로젝트:** 도시 이름 입력 → 현재 날씨 + 5일 예보 → 카드형 대시보드

> 태스크 6개, 에이전트 2~3개. 프론트+백엔드 왕복을 가볍게 체험.
> FastAPI + Next.js + OpenWeatherMap API
> 메인 프로젝트 전에 워크플로우를 몸에 익히는 것이 목적.

**3-1. `/tf-plan`으로 프로젝트 기획 (15분)**
- `/tf-plan 날씨 대시보드. 도시 검색하면 현재 날씨 + 5일 예보.`
- 소크라틱 질문 → PRD 생성 → 태스크 6개 분해:
  ```
  [TASK-001] 날씨 API 프록시 엔드포인트 (backend)
  [TASK-002] 즐겨찾기 도시 저장 API (backend, depends_on: 001)
  [TASK-003] 도시 검색 UI (frontend, depends_on: 001)
  [TASK-004] 날씨 카드 컴포넌트 (frontend, depends_on: 001)
  [TASK-005] 5일 예보 차트 (frontend, depends_on: 004)
  [TASK-006] API 연동 테스트 (test, depends_on: 003, 005)
  ```
- 좋은 태스크 vs 나쁜 태스크: ❌ "백엔드 만들어줘" → ✅ 구체적 엔드포인트 명시

**3-2. `/tf-start`로 실행 + 관찰 (25분)**
- `create_tasks_bulk` 한 번으로 6개 일괄 생성
- Agent Teams 자동 스폰
- 칸반 보드에서 카드 이동 관찰 + 터미널 패널에서 에이전트 로그

**3-3. PM 역할 — `/tf-status` + `/tf-review` (30분)**
- Backend Agent → 날씨 API 완성 → Frontend 태스크 자동 available
- Frontend Agent → 날씨 카드 + 차트
- `/tf-review`로 REVIEW 확인 → Approve → DONE

**3-4. 회고 (10분)**
- 전체 흐름 확인: `/tf-plan` → `/tf-start` → `/tf-status` → `/tf-review`
- 의존성 순서대로 처리 확인 (백엔드 → 프론트 → 테스트)
- **"프론트+백엔드 왕복이 잘 되죠? 이제 규모를 키워봅시다."**

#### 모듈 4. 메인 프로젝트: AI SaaS 빌드 (4시간)

**프로젝트:** AI 기반 콘텐츠 분석 SaaS (YouTube URL → AI 요약 + 인사이트 카드 + 대시보드)

> 태스크 15~20개, 에이전트 4~5개. 처음부터 끝까지 마블로로 빌드.
> FastAPI + Next.js + Claude API + YouTube Data API

**4-1. `/tf-analyze` — 요구사항 분석 (30분)**
- 단계별 워크플로우로 정밀 제어:
  ```
  /tf-analyze AI YouTube 인사이트 서비스. URL 넣으면 요약+인사이트.
  FastAPI + Next.js + Claude API.
  ```
- 소크라틱 질문 → PRD + 태스크 분해 계획
- 15~20개 태스크 의존성 맵 검토/수정

**4-2. `/tf-create-tasks` + `/tf-spawn-agents` — 실행 (20분)**
- 태스크 일괄 생성 → 칸반 보드에 카드 등장
- 에이전트 스폰 → 터미널 패널에서 작업 시작 확인

| 비교 대상 | 가격대 | 시간 | 시간당 가격 |
|----------|--------|------|-----------|
| 인프런 AI 강의 평균 | 5~15만원 | 8~15시간 | 6,250~10,000원 |
| 마블로 얼리버드 149K | 149,000원 | 15.5시간 | 9,613원 |
| 마블로 정가 199K | 199,000원 | 15.5시간 | 12,839원 |

**결론:**
- 얼리버드 149K: **적정~저렴** (쿠폰 포함하면 파격)
- 정가 199K: **적정** (SaaS 도구 포함이라 부가 가치 높음)
- 번들 249K: **적정** (1년 SaaS 228K 포함이라 실질 21K)
- 경쟁 강의 대비 **마블로 쿠폰이 차별점** — 단순 강의가 아니라 도구+교육 패키지
