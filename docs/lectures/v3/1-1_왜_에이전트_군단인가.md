## 도입 (3분)

안녕하세요, 마블로 v3 강의에 오신 걸 환영합니다.

이 강의를 시작하기 전에 하나 질문을 드리겠습니다.
여러분, Claude나 ChatGPT 같은 AI로 코딩해보신 적 있으시죠?

화면: 터미널에서 Claude Code 단독 사용하는 화면

"이거 만들어줘" 하면 코드를 쭉 만들어주고, 버그 고쳐달라 하면 고쳐주고.
꽤 편리하죠. 근데 프로젝트가 좀 커지면 어떻게 되나요?

"백엔드 API 만들어줘" — 만들어줍니다.
"그러면 프론트엔드도 만들어줘" — 만들어주는데 아까 백엔드 컨텍스트가 날아갔습니다.
"테스트도 짜줘" — 짜주는데 프론트엔드에서 뭘 했는지 기억이 없습니다.

이게 AI **혼자** 코딩하는 것의 한계입니다.
사람도 혼자서 백엔드, 프론트엔드, 테스트, DevOps 다 하면 힘들잖아요?
AI도 마찬가지입니다.

## 본문

### 혼자 코딩하는 AI vs. 팀으로 협업하는 AI (4분)

화면: 슬라이드 — "Solo AI" vs "Agent Team" 비교 다이어그램

**Solo AI 방식** (기존)

```
사람 → AI 1대 → 전부 다 혼자
    "백엔드 만들어줘"
    "이제 프론트 만들어줘"
    "테스트도 짜줘"
    → 컨텍스트 유실, 충돌, 산만
```

**Agent Team 방식** (마블로)

```
사람(PM) → Team Leader(오케스트레이터)
              ├── Backend Agent   → API 개발
              ├── Frontend Agent  → UI 개발
              ├── Test Agent      → 테스트 작성
              └── DevOps Agent    → 배포 설정
```

차이가 보이시죠? 하나의 AI한테 모든 걸 시키는 게 아니라, **역할별로 전담 에이전트를 두는 겁니다.**

각 에이전트는 자기 역할에만 집중하고, 서로 칸반 보드를 통해 작업을 주고받습니다.
마치 실제 개발팀처럼요.

중요한 건 이 에이전트들이 "가상"이 아니라 **물리적으로 분리된 프로세스**라는 겁니다.
Backend Agent는 자기만의 Claude Code 터미널에서 돌아가고,
Frontend Agent는 또 다른 터미널에서 돌아갑니다.
서로 간섭하지 않습니다.

### Agent Teams 개념 (3분)

화면: 슬라이드 — Agent Teams 아키텍처

Agent Teams의 핵심은 세 가지입니다.

**첫째, Team Leader가 존재합니다.**
오케스트레이터라고 부르는데, 이 친구가 프로젝트를 태스크로 분해하고,
적절한 에이전트를 스폰(spawn)해서 작업을 배분합니다.

**둘째, MCP로 소통합니다.**
MCP — Model Context Protocol이라는 표준 프로토콜을 통해서
에이전트가 칸반 보드에 태스크를 만들고, 상태를 바꾸고, 진행 상황을 기록합니다.
이건 모듈 2에서 자세히 다룰 거예요.

**셋째, 칸반 보드가 중앙 허브입니다.**
모든 에이전트가 하나의 칸반 보드를 공유합니다.
TODO → CLAIMED → IN_PROGRESS → REVIEW → DONE.
PM인 여러분은 이 보드를 보면서 진행 상황을 파악하고, 리뷰하고, 피드백을 줍니다.

### JIRA + MCP vs. Marblo 비교 (2분)

화면: 슬라이드 — 비교표

"그러면 JIRA 쓰면서 MCP 서버 연결하면 되는 거 아닌가요?"
좋은 질문입니다. 비교해보죠.

|               | JIRA + MCP (직접 구축)           | Marblo v3                                |
| ------------- | -------------------------------- | ---------------------------------------- |
| 세팅 시간     | 2-3일 (JIRA API + MCP 서버 개발) | 앱 다운로드 → 5분                        |
| 에이전트 스폰 | 직접 스크립트 작성               | `spawn_agent` MCP 도구 1줄               |
| 실시간 터미널 | 없음 (로그만)                    | 앱 내장 터미널 (에이전트별)              |
| 코드 에디터   | 별도 VS Code                     | Monaco Editor 내장                       |
| 플로우 에디터 | 없음                             | 비주얼 DAG 에디터                        |
| 멀티모델      | 직접 구현                        | Claude + Gemini + GPT + Custom 기본 지원 |
| 비용          | JIRA 유료 + 개발 시간            | 올인원 데스크탑 앱                       |

핵심은, 마블로는 **에이전트 팀을 운영하기 위한 전용 워크스페이스**라는 겁니다.
JIRA는 사람을 위한 프로젝트 관리 도구지만,
마블로는 AI 에이전트를 위한 프로젝트 관리 도구예요.

### v1 vs v3 비교 — 얼마나 달라졌나 (2분)

화면: 슬라이드 — v1 vs v3 비교표

사실 마블로는 이미 v1이 있었습니다. CLI 기반이었죠.
v3에서 얼마나 달라졌는지 보시죠.

|               | v1 (CLI + Docker)             | v3 (Electron Desktop)              |
| ------------- | ----------------------------- | ---------------------------------- |
| 실행 방식     | Docker Compose + 5개 컨테이너 | **앱 더블클릭** (설치 끝)          |
| 칸반 보드     | 브라우저 (localhost:3001)     | 앱 내장 (드래그앤드롭)             |
| 터미널        | 별도 사이드카 서버            | 앱 내장 (node-pty + xterm.js)      |
| 코드 에디터   | 없음 (VS Code 별도)           | Monaco Editor 내장                 |
| 에이전트 모델 | Claude만                      | **Claude + Gemini + GPT + Custom** |
| 플로우 에디터 | 없음                          | 비주얼 DAG 에디터                  |
| MCP 서버      | Python (FastAPI 프록시)       | Node.js (Firebase 직접 연결)       |

한 줄로 요약하면: **Docker 5개 컨테이너가 데스크탑 앱 1개로 줄었습니다.**

### v3 데모 미리보기 (1분)

화면: 마블로 v3 앱 — 칸반 + 터미널 + 플로우가 한 화면에서 돌아가는 모습 (30초 미리보기)

잠깐 마블로 v3를 열어서 보여드릴게요.

보이시죠? 이 한 화면 안에:

- 위쪽에 칸반 보드가 있고, 태스크 카드들이 실시간으로 움직이고,
- 아래쪽에 터미널이 있어서 에이전트가 코딩하는 모습이 보이고,
- Agents 탭에서는 에이전트 상태를 모니터링하고,
- Flows 탭에서는 파이프라인을 시각적으로 설계할 수 있습니다.

이걸 설치하고, 설정하고, 실제로 돌려보는 게 이번 모듈 1의 목표입니다.

## 정리 (1분)

오늘 기억할 핵심 3가지:

1. **Solo AI → Agent Team**: 혼자 시키지 말고, 팀으로 운영하자
2. **MCP 기반 협업**: 에이전트들이 칸반 보드를 통해 자율적으로 작업
3. **마블로 = AI 에이전트 전용 워크스페이스**: JIRA가 사람용이면, 마블로는 AI용

다음 섹션에서는 마블로의 핵심 기능을 하나하나 살펴보겠습니다.
