## 도입 (3분)

서비스를 배포했으니, 이번에는 **자동화**를 해봅시다.

화면: 슬라이드 — "사람이 안 해도 돌아가는 시스템"

예를 들어 이런 시나리오를 생각해보세요:

> "매일 아침 9시에 YouTube 인기 동영상 트렌드를 수집하고,
> AI로 분석해서, 요약 리포트를 이메일로 보내줘."

이걸 사람이 매일 수동으로 하면 귀찮잖아요? Cloud Scheduler를 쓰면 한번 설정해놓고 영원히 자동으로 돌릴 수 있습니다.

**Cloud Scheduler = GCP의 크론잡 서비스**

리눅스의 `crontab`과 같은 역할이지만, 서버 없이 동작합니다. 지정한 시간에 HTTP 요청을 보내거나 Cloud Functions를 트리거합니다.

## 본문 1: Cron 표현식 기초 (4분)

화면: Cron 표현식 설명 슬라이드

먼저 Cron 표현식을 알아야 합니다. 어렵지 않아요.

```
┌──── 분 (0-59)
│ ┌──── 시 (0-23)
│ │ ┌──── 일 (1-31)
│ │ │ ┌──── 월 (1-12)
│ │ │ │ ┌──── 요일 (0-6, 0=일요일)
│ │ │ │ │
* * * * *
```

자주 쓰는 예시:

```
"0 9 * * *"     → 매일 오전 9시
"0 9 * * 1-5"   → 평일 오전 9시
"*/30 * * * *"  → 30분마다
"0 0 1 * *"     → 매월 1일 자정
"0 */6 * * *"   → 6시간마다
"0 9,18 * * *"  → 매일 9시, 18시
```

**시간대 주의!** Cloud Scheduler에서 시간대를 설정할 수 있습니다. 한국 시간을 쓰려면 `Asia/Seoul`을 지정하세요.

헷갈리면 https://crontab.guru/ 에서 테스트해볼 수 있습니다.

## 본문 2: Cloud Run에 크론 엔드포인트 추가 (5분)

화면: VS Code — 서버 코드

Cloud Scheduler가 호출할 엔드포인트를 만들어봅시다.

**(실습)** 서버 코드에 크론 전용 라우트를 추가합니다:

```typescript
// src/routes/cron.ts
import { Router, Request, Response } from "express";

const router = Router();

/**
 * 크론잡 엔드포인트: YouTube 트렌드 수집 + AI 분석 + 이메일 발송
 * Cloud Scheduler에서 매일 09:00 KST에 호출
 */
router.post("/cron/daily-trend-report", async (req: Request, res: Response) => {
  try {
    // 1. YouTube API로 트렌드 수집
    const trends = await fetchYouTubeTrends();

    // 2. AI로 트렌드 분석
    const analysis = await analyzeWithAI(trends);

    // 3. 이메일 발송
    await sendEmailReport(analysis);

    res.json({
      success: true,
      message: `Report sent. Analyzed ${trends.length} trends.`,
      timestamp: new Date().toISOString(),
    });
  } catch (error) {
    console.error("Cron job failed:", error);
    res.status(500).json({
      success: false,
      error: (error as Error).message,
    });
  }
});

/**
 * 헬스체크 — 크론잡이 정상 동작하는지 확인
 */
router.get("/cron/health", (_req: Request, res: Response) => {
  res.json({ status: "ok", service: "cron" });
});

export default router;
```

서버에 라우터 등록:

```typescript
// src/server.ts
import cronRouter from "./routes/cron";
app.use("/api", cronRouter);
```

**크론 엔드포인트 보안:**

누군가 이 URL을 무단으로 호출하면 안 되겠죠? Cloud Scheduler가 보내는 요청을 검증합시다:

```typescript
// 미들웨어: Cloud Scheduler 인증 확인
function validateSchedulerRequest(req: Request, res: Response, next: Function) {
  const userAgent = req.headers["user-agent"] || "";
  const authHeader = req.headers["authorization"] || "";

  // Cloud Scheduler는 OIDC 토큰을 보냅니다
  if (!authHeader.startsWith("Bearer ")) {
    return res.status(403).json({ error: "Unauthorized" });
  }

  // 프로덕션에서는 OIDC 토큰을 검증해야 합니다
  // 여기서는 간략화
  next();
}

router.post(
  "/cron/daily-trend-report",
  validateSchedulerRequest,
  async (req, res) => {
    // ...
  }
);
```

변경사항을 배포합니다:

```bash
# 빌드 + 푸시 + 배포 (한 줄로)
docker build -t ${REGION}-docker.pkg.dev/${PROJECT_ID}/${REPO}/${IMAGE_NAME}:v1.1.0 . && \
docker push ${REGION}-docker.pkg.dev/${PROJECT_ID}/${REPO}/${IMAGE_NAME}:v1.1.0 && \
gcloud run deploy marblo-todo-app \
  --image=${REGION}-docker.pkg.dev/${PROJECT_ID}/${REPO}/${IMAGE_NAME}:v1.1.0 \
  --region=${REGION}
```

## 본문 3: Cloud Scheduler 설정 (5분)

화면: 터미널

이제 Cloud Scheduler에서 크론잡을 만듭시다.

**(실습)**

```bash
# 서비스 URL 가져오기
SERVICE_URL=$(gcloud run services describe marblo-todo-app \
  --region=asia-northeast3 --format='value(status.url)')

# 서비스 계정 생성 (Cloud Scheduler용)
gcloud iam service-accounts create scheduler-sa \
  --display-name="Cloud Scheduler Service Account"

# Cloud Run 호출 권한 부여
gcloud run services add-iam-policy-binding marblo-todo-app \
  --region=asia-northeast3 \
  --member="serviceAccount:scheduler-sa@${PROJECT_ID}.iam.gserviceaccount.com" \
  --role="roles/run.invoker"
```

이제 크론잡을 생성합니다:

```bash
gcloud scheduler jobs create http daily-trend-report \
  --location=asia-northeast3 \
  --schedule="0 9 * * *" \
  --time-zone="Asia/Seoul" \
  --uri="${SERVICE_URL}/api/cron/daily-trend-report" \
  --http-method=POST \
  --oidc-service-account-email="scheduler-sa@${PROJECT_ID}.iam.gserviceaccount.com" \
  --oidc-token-audience="${SERVICE_URL}" \
  --headers="Content-Type=application/json" \
  --message-body='{"source":"scheduler"}'
```

옵션 설명:

| 옵션                           | 값            | 설명             |
| ------------------------------ | ------------- | ---------------- |
| `--schedule`                   | `"0 9 * * *"` | 매일 오전 9시    |
| `--time-zone`                  | `Asia/Seoul`  | 한국 시간 기준   |
| `--http-method`                | `POST`        | POST 요청        |
| `--oidc-service-account-email` | 서비스 계정   | 인증된 요청 보장 |

확인:

```bash
gcloud scheduler jobs list --location=asia-northeast3
# NAME                  SCHEDULE     TIME_ZONE    STATE
# daily-trend-report    0 9 * * *    Asia/Seoul   ENABLED
```

### 수동 테스트

크론잡을 당장 실행해보고 싶으면:

```bash
gcloud scheduler jobs run daily-trend-report --location=asia-northeast3
```

이 명령은 스케줄과 관계없이 즉시 실행합니다. 테스트할 때 아주 유용해요.

로그 확인:

```bash
gcloud logging read \
  "resource.type=cloud_run_revision AND textPayload:trend" \
  --limit=10 --format='table(timestamp,textPayload)'
```

## 본문 4: 실전 활용 예시 (3분)

화면: 슬라이드 — 크론잡 활용 사례

크론잡으로 할 수 있는 것들을 더 소개할게요:

### 예시 1: 일일 데이터 수집 + 분석

```bash
# 매일 아침 8시: 뉴스 수집 → AI 요약 → Slack 알림
gcloud scheduler jobs create http daily-news \
  --schedule="0 8 * * *" \
  --time-zone="Asia/Seoul" \
  --uri="${SERVICE_URL}/api/cron/daily-news" \
  --http-method=POST
```

### 예시 2: 주간 리포트

```bash
# 매주 월요일 9시: 주간 사용 통계 리포트
gcloud scheduler jobs create http weekly-report \
  --schedule="0 9 * * 1" \
  --time-zone="Asia/Seoul" \
  --uri="${SERVICE_URL}/api/cron/weekly-report" \
  --http-method=POST
```

### 예시 3: 데이터베이스 정리

```bash
# 매일 새벽 3시: 30일 이상 된 임시 데이터 삭제
gcloud scheduler jobs create http cleanup \
  --schedule="0 3 * * *" \
  --time-zone="Asia/Seoul" \
  --uri="${SERVICE_URL}/api/cron/cleanup" \
  --http-method=POST
```

### 예시 4: AI 에이전트 자동 트리거

이건 마블로와 연계할 수 있는 고급 활용이에요:

```bash
# 매일 아침: 마블로 에이전트에게 코드 리뷰 요청
gcloud scheduler jobs create http daily-review \
  --schedule="0 10 * * 1-5" \
  --time-zone="Asia/Seoul" \
  --uri="${SERVICE_URL}/api/cron/trigger-agent-review" \
  --http-method=POST \
  --message-body='{"agent":"claude","task":"review latest PRs"}'
```

## 정리 (2분)

화면: 요약 슬라이드

크론잡 자동화 핵심:

1. **Cloud Scheduler**: GCP의 서버리스 크론잡. 서버 없이 시간 기반 자동화.
2. **Cron 표현식**: `분 시 일 월 요일` — `0 9 * * *`은 매일 9시.
3. **보안**: OIDC 서비스 계정으로 인증된 요청만 허용.
4. **테스트**: `gcloud scheduler jobs run`으로 즉시 실행 가능.

기억하세요 — **한번 설정하면 사람이 안 건드려도 매일 자동으로 돌아갑니다.** AI 에이전트가 코드를 만들고, 크론잡이 자동으로 실행하고, 결과를 이메일로 받고. 이게 진짜 자동화입니다.

다음 섹션에서는 코드를 푸시하면 자동으로 배포되는 CI/CD 파이프라인을 만들어보겠습니다.
