# 레인에서 에이전트 진행 관찰

> 모듈 3 · 섹션 3-3 · 약 25분
> 관련: [[3-2_태스크분해_보드카드]] | [[3-4_리뷰_워크트리머지_완료]]

---

## 이 레슨의 4요소

- **학습목표:** **레인 탭(LanesTab)** 으로 단일 에이전트의 실시간 작업을 관찰한다. 레인 행의 구성(모델 아이콘·워크트리 pill·터미널 attach)을 읽고, 카드가 자동으로 움직이는 자율 루프를 이해한다.
- **시연할 마블로 화면·기능:** **레인 탭** — 카드 자동 claim → 에이전트 스폰 → 레인 행(모델 아이콘 🟣 claude · 워크트리 pill · 터미널 attach) → PTY로 실제 코드 작성 관찰. 보드와 연동된 카드 이동.
- **진행할 프로젝트 단계:** P1 구현.
- **핵심 메시지:** "레인 = **한 에이전트의 작업대.** 터미널을 열어 안을 들여다본다."

---

## 도입 (3분)

보드에 카드 3~4장이 TODO에 올라왔습니다. 이제 진짜 재미있는 부분 — **에이전트가 일하는 걸 지켜보는 것** 입니다.

지켜보는 무대가 **레인(Lanes) 탭** 이에요. 레인은 **한 에이전트의 작업대 한 줄**입니다. 에이전트가 지금 어떤 카드를 들고 있는지, 어느 워크트리에서 일하는지, 그리고 — 터미널을 열면 — **실제로 무슨 코드를 짜고 있는지**까지 한 행에서 다 보여줍니다.

P1은 단일 Claude 에이전트, **레인 한 줄**짜리 프로젝트예요. 여러 줄이 동시에 도는 병렬 작업은 모듈 4(P2)에서 봅니다. 지금은 한 줄을 차근히 들여다보며 "에이전트가 혼자 어떻게 일하는가"를 익힙니다.

화면: 마블로 상단 탭바 → 레인 탭(LanesTab)

---

## 본문

### 1. 카드가 스스로 움직인다 — 자율 루프 (5분)

화면: 보드 탭 ↔ 레인 탭 — 카드가 TODO → CLAIMED → IN_PROGRESS로 이동

이전 레슨 끝에서 "진행해줘"라고 한 순간, 오케스트레이터가 에이전트를 **스폰(spawn)** 했습니다. 그 에이전트는 누가 시키지 않아도 **자기 자율 루프**를 돕니다:

```
1. get_available_tasks  — 내가 할 수 있는 카드 조회
2. claim_task           — "이 카드 내가 한다" 선언   → 카드: TODO → CLAIMED
3. update_task_status    — 작업 시작                 → 카드: CLAIMED → IN_PROGRESS
4. (코드 작성)           — add_activity 로 진행 기록
5. submit_for_review     — 완료 제출                 → 카드: IN_PROGRESS → REVIEW
6. 다음 카드로 (1번부터 반복)
```

보드를 보면 **TASK-1 카드가 TODO에서 CLAIMED로, 다시 IN_PROGRESS로** 스스로 옮겨 가는 게 보입니다. 여러분이 카드를 끌어다 놓은 게 아니에요 — **에이전트가 MCP 도구를 호출**해서 상태를 바꾼 겁니다([[1-4_큰그림_파이프라인]]의 상태 머신이 실제로 도는 장면).

> 💡 의존성이 걸린 TASK-2/3/4는 아직 막혀 있습니다. TASK-1이 REVIEW로 가고 머지돼야(다음 레슨) 다음 카드의 잠금이 풀려요. P1은 단일 레인이라 카드를 **하나씩 순서대로** 처리합니다.

### 2. 레인 행을 읽는다 (7분)

화면: 레인 탭 — 에이전트 한 행(모델 아이콘 · 카드 · 워크트리 pill · attach 버튼)

레인 탭에 에이전트 한 줄이 나타납니다. 이 **한 행**에 들어있는 정보를 읽어봅시다.

```
🟣 claude · todo-fe   [TASK-1 기본 화면 + 스타일]  IN_PROGRESS
   🌿 worktree: agent/todo-task1  ·  ⚪ 작업중  ·  + 새 파일 2
   [ 터미널 열기(attach) ]
```

- **🟣 모델 아이콘** — 이 에이전트가 어떤 모델인지. P1은 **claude(보라 🟣)** 단일입니다. (Codex·Antigravity는 모듈 4·6에서 색이 섞여요.)
- **현재 카드** — 지금 들고 있는 카드와 상태(IN_PROGRESS).
- **🌿 워크트리 pill** — 이 에이전트 전용 격리 워크트리와 브랜치명, 그리고 상태 pill(⚪ 작업중 / 🟢 머지 가능 …). [[2-4_프로젝트연결_워크트리체크]]에서 본 그 신호등이 레인 행에도 붙습니다.
- **터미널 열기(attach)** — 누르면 이 에이전트의 PTY에 **붙어서** 실시간 출력을 봅니다.

> 💡 레인은 보드와 다릅니다. **보드 = 카드(무엇을)** 의 관점, **레인 = 에이전트(누가·어떻게)** 의 관점이에요. 같은 작업을 두 각도에서 보는 거죠.

### 3. 터미널을 attach해 안을 들여다본다 (7분)

화면: 레인 행 → 터미널 열기(attach) → 에이전트 PTY 스트리밍

"터미널 열기"를 누르면 그 에이전트가 **실제로 코드를 짜는 과정**이 흘러나옵니다. 블랙박스가 아니라 **유리 상자**예요.

```
● agent: todo-fe (claude)
> claim_task("task-1", "todo-fe")
  ✅ claimed: 기본 화면 + 스타일
> update_task_status("task-1", "IN_PROGRESS")
> index.html 작성 중...
  - 입력창 + 추가 버튼
  - <ul id="list"> 할 일 목록
> style.css 작성 중...
  - 기본 레이아웃 + 완료 항목 취소선
> add_activity("기본 화면 골격 + 스타일 완료")
> submit_for_review("task-1")
  ✅ submitted → REVIEW
> get_available_tasks("frontend")
  → TASK-2 는 아직 잠김(이전 카드 머지 대기)
```

에이전트가 파일을 만들고, 진행을 `add_activity`로 기록하고, 끝나면 `submit_for_review`로 제출하는 — **자율 루프가 실제로 도는 모습**입니다.

> 💡 **막혀 보여도 당황하지 마세요.** 에이전트가 에러를 만나면 터미널에 그대로 보입니다. 대부분은 스스로 고쳐요. 정말 막히면 카드가 BLOCKED/FAILED로 가는데, 그 대응은 모듈 5에서 다룹니다. 지금은 **"안이 다 보인다"** 는 것만 체감하면 됩니다.

### 4. 관찰만 해도 되는 이유 (2분)

화면: 슬라이드 — "PM은 지켜본다. 손은 에이전트가."

이 레슨에서 여러분이 직접 친 코드는 **한 줄도 없습니다.** 카드를 옮기지도 않았어요. 한 일은 **레인을 보고, 터미널을 열어 들여다본 것**뿐입니다.

이게 마블로에서 PM의 일하는 방식이에요. 코딩은 에이전트가 하고, 여러분은 **진행을 관찰하다가 결정이 필요한 순간(리뷰·머지)에만 개입**합니다. 그 개입 지점이 바로 다음 레슨입니다.

## 정리 (1분)

화면: 정리 슬라이드

1. 에이전트는 **자율 루프**(claim → work → submit)를 돈다. 카드가 스스로 TODO→CLAIMED→IN_PROGRESS→REVIEW로 이동.
2. **레인 = 한 에이전트의 작업대 한 줄.** 모델 아이콘(🟣 claude) · 워크트리 pill · 터미널 attach.
3. **터미널 attach** 로 코드 작성 과정을 실시간으로 들여다본다(유리 상자).
4. PM은 **관찰하다가 결정 지점에서만 개입.**

TASK-1이 REVIEW로 올라왔습니다. 이제 PM 차례 — diff를 보고, 워크트리를 머지해 **첫 결과물**을 받습니다.
