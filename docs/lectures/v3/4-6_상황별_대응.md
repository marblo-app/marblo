## 도입 (3분)

지금까지 순조롭게 진행되는 과정을 봤습니다. 하지만 실제 프로젝트에서는 **항상 문제가 생기죠**. 에이전트가 실패할 수도 있고, 태스크가 막힐 수도 있고, 갑자기 새 기능이 필요할 수도 있습니다.

화면: "상황별 대응 가이드" 타이틀 슬라이드

이번 섹션에서는 **PM이 만날 수 있는 5가지 상황**과 각각의 대응 방법을 배웁니다:

1. **FAILED** — 에이전트 작업 실패
2. **BLOCKED** — 태스크가 막혀서 진행 불가
3. **새 기능** — 프로젝트 도중 기능 추가
4. **세션 끊김** — 연결이 끊겼다가 복구
5. **정리** — 진행 중인 태스크 일시 중단

---

## 본문

### 상황 1: FAILED — 에이전트 작업 실패 (4분)

화면: 칸반 보드 — TASK-005가 빨간색 FAILED 상태

가장 흔한 상황입니다. 에이전트가 작업 중에 에러가 나서 실패하는 경우.

예를 들어 Claude API 키가 잘못 설정되어 있거나, YouTube API 할당량이 초과된 경우:

```
[Backend Agent] TASK-005: FAILED
  Error: anthropic.AuthenticationError: Invalid API key
  Attempts: 2/3
  Status: IN_PROGRESS → FAILED
```

칸반 보드에서 해당 카드가 빨간색으로 바뀝니다.

**대응: `/tf-fix`**

```bash
/tf-fix TASK-005
```

화면: `/tf-fix` 진단 결과

```
🔍 Diagnosis: TASK-005 — Claude API 분석 엔드포인트

Error: anthropic.AuthenticationError: Invalid API key
Root cause: CLAUDE_API_KEY 환경 변수가 설정되지 않았거나 잘못됨

Suggested fix:
  1. .env 파일에서 CLAUDE_API_KEY 값을 확인하세요
  2. Anthropic Console에서 API 키를 재발급하세요
  3. Docker 컨테이너를 재시작하세요

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[R]etry  [M]anual fix  [S]kip  [?] Help
```

마블로가 자동으로 에러를 진단하고 해결 방법을 제안합니다.

환경 변수를 수정한 후:

```bash
R  # Retry
```

```
🔄 Retrying TASK-005...
[Backend Agent] Reclaiming TASK-005
[Backend Agent] Status: FAILED → IN_PROGRESS
```

에이전트가 태스크를 다시 시도합니다. 환경이 올바르게 설정되었다면 이번에는 성공할 거예요.

**핵심 포인트**: FAILED가 뜨면 당황하지 마세요. `/tf-fix`로 진단 → 원인 해결 → 재시도. 이 패턴입니다.

### 상황 2: BLOCKED — 태스크 진행 불가 (4분)

화면: 칸반 보드 — TASK-013에 주황색 BLOCKED 표시

의존성 때문이 아니라, **에이전트가 스스로 결정하지 못해서** 막히는 경우가 있습니다.

예를 들어:

- "분석 결과 페이지에서 '요약'과 '핵심 포인트'의 순서를 어떻게 할까요?"
- "사용량 제한 초과 시 에러 메시지를 어떻게 표시할까요?"

```
[Frontend Agent] TASK-013: BLOCKED
  Reason: "대시보드 레이아웃 — 그리드 2열 vs 3열, PM 결정 필요"
  Status: IN_PROGRESS → BLOCKED
```

**대응: `/tf-feedback`**

PM이 의사결정을 내려주면 됩니다:

```bash
/tf-feedback TASK-013 "3열 그리드로 해주세요. 카드가 많아질수록 3열이 보기 좋습니다. 모바일에서는 1열로 변경되게 반응형으로요."
```

```
✅ Feedback delivered to TASK-013
[Frontend Agent] Received PM feedback, resuming work
[Frontend Agent] Status: BLOCKED → IN_PROGRESS
```

에이전트가 PM의 피드백을 받고 다시 작업을 시작합니다.

**핵심 포인트**: BLOCKED는 에이전트가 PM에게 결정을 요청하는 거예요. 빨리 답해줄수록 프로젝트가 빨리 진행됩니다.

### 상황 3: 새 기능 추가 — `/tf-add` (4분)

화면: 프로젝트 도중 새 기능이 필요한 상황

프로젝트 도중에 "이 기능도 있으면 좋겠다"라는 생각이 들 때:

```bash
/tf-add "영상 분석 결과 PDF 내보내기" --type frontend --depends-on 012 --priority medium
```

```
✅ New task created:
  [TASK-019] 영상 분석 결과 PDF 내보내기
  Type: frontend
  Depends on: TASK-012 (분석 상세 페이지)
  Priority: medium
  Status: TODO → assignable after TASK-012

[Frontend Agent] New task detected: TASK-019 (queued)
```

칸반 보드에 새 카드가 추가되고, 의존성에 따라 적절한 시점에 에이전트가 작업을 시작합니다.

주의할 점:

- **스코프 크리프(scope creep)**에 조심하세요. 새 기능을 계속 추가하면 프로젝트가 끝나지 않습니다
- 정말 필요한 기능만 추가하고, 나머지는 **v2로 미루세요**
- `--priority low`를 활용해서 우선순위를 조절하세요

### 상황 4: 세션 끊김 — `/tf-resume` (3분)

화면: 마블로 연결 끊김 화면

인터넷이 끊기거나 앱이 종료됐다가 다시 실행되는 경우:

```bash
/tf-resume
```

```
🔄 Resuming project: AI YouTube 인사이트 서비스

Restoring context...
  ✅ 18 tasks loaded (15 DONE, 2 IN_PROGRESS, 1 TODO)
  ✅ 4 agents restored
  ✅ Activity log synced

Agent status:
  Backend Agent   : resuming TASK-006 (was IN_PROGRESS)
  Frontend Agent  : resuming TASK-012 (was IN_PROGRESS)

Ready to continue!
```

마블로가 프로젝트 상태를 복원합니다. 에이전트가 마지막 작업 상태부터 다시 시작하죠.

**핵심 포인트**: 마블로는 모든 상태를 서버에 저장합니다. 세션이 끊겨도 진행 상황이 사라지지 않아요. `/tf-resume` 한 번이면 복구됩니다.

### 상황 5: 일시 중단 — `/tf-hold` (2분)

화면: 프로젝트 일시 중단

오늘은 여기까지만 하고, 내일 이어서 하고 싶을 때:

```bash
/tf-hold
```

```
⏸️ Project paused: AI YouTube 인사이트 서비스

Current state saved:
  Tasks: 15/18 completed
  Active agents: 2 (will be suspended)
  IN_PROGRESS tasks: TASK-006, TASK-012 (saved as snapshots)

Resume with: /tf-resume
```

진행 중인 에이전트가 일시 중지되고, 현재 상태가 저장됩니다. 다음에 `/tf-resume`으로 이어서 하면 됩니다.

**주의**: `/tf-hold`는 에이전트를 일시 중지하는 거라, 비용이 발생하지 않습니다. 하지만 너무 오래 두면 컨텍스트가 희미해질 수 있으니, 가능하면 같은 날 안에 재개하는 게 좋아요.

## 정리

5가지 상황별 대응 명령어 요약:

| 상황          | 명령어         | 설명                           |
| ------------- | -------------- | ------------------------------ |
| 에이전트 실패 | `/tf-fix`      | 진단 + 원인 해결 + 재시도      |
| 태스크 막힘   | `/tf-feedback` | PM 의사결정 전달               |
| 새 기능 추가  | `/tf-add`      | 태스크 추가 + 자동 스케줄링    |
| 세션 끊김     | `/tf-resume`   | 프로젝트 상태 복원             |
| 일시 중단     | `/tf-hold`     | 에이전트 일시 중지 + 상태 저장 |

이 5개만 알면 어떤 상황이든 대응할 수 있습니다. 실제 프로젝트에서 가장 자주 쓰게 될 건 `/tf-fix`와 `/tf-feedback`이에요. 에이전트는 완벽하지 않거든요. PM이 방향을 잡아줘야 합니다.
