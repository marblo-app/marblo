## 도입 (3분)

이전 섹션에서는 태스크를 수동으로 만들고, 에이전트를 수동으로 할당했죠? 솔직히 좀 번거로웠을 겁니다.

이번에 배울 오케스트레이터는 이걸 전부 자동화합니다.

화면: 마블로 오케스트레이터 패널

여러분이 할 일은 딱 하나예요:

```
"Todo API를 만들어줘.
 백엔드는 Express.js, 프론트엔드는 React,
 테스트도 필요해."
```

이 한 줄을 입력하면, 오케스트레이터가:

1. 태스크를 자동으로 분해하고
2. 의존성 관계를 DAG로 만들고
3. 각 태스크에 적합한 에이전트를 자동 배정하고
4. 에이전트들을 실행합니다

이게 어떻게 가능한지, 내부 코드를 보면서 설명하겠습니다.

## 본문 1: 오케스트레이터 아키텍처 (5분)

화면: 아키텍처 다이어그램

오케스트레이터의 내부 파이프라인은 이렇습니다:

```
자연어 입력
    ↓
TaskDecomposer  ← LLM에게 태스크 분해 요청
    ↓
DAGGenerator    ← 의존성 그래프 생성
    ↓
AutoRouter      ← 에이전트 자동 배정
    ↓
Firestore       ← 태스크 저장
    ↓
FlowGenerator   ← React Flow 시각화
```

이 모든 컴포넌트가 `electron/orchestrator/` 디렉토리에 있습니다:

```
v3/electron/orchestrator/
├── index.ts            ← OrchestratorService (통합 진입점)
├── task-decomposer.ts  ← 자연어 → 태스크 분해
├── dag-generator.ts    ← DAG 그래프 생성 + 사이클 검출
├── auto-router.ts      ← 태스크 → 에이전트 매칭
├── dag-resolver.ts     ← DAG 실행 + 완료 감시
├── flow-generator.ts   ← React Flow 그래프 생성
├── llm-client.ts       ← LLM API 호출 추상화
└── prompt-templates.ts ← LLM 프롬프트 템플릿
```

각 파일이 하나의 책임을 갖고 있습니다. 이 구조를 이해하면 나중에 커스터마이즈도 할 수 있어요.

## 본문 2: TaskDecomposer — 자연어를 태스크로 (6분)

화면: `task-decomposer.ts` 코드

가장 핵심적인 부분입니다. 자연어를 구조화된 태스크로 변환하는 `TaskDecomposer`를 봅시다.

```typescript
export class TaskDecomposer {
  private llm: LLMClient;
  private dagGenerator: DAGGenerator;

  async decompose(
    naturalLanguage: string,
    context?: string
  ): Promise<DecompositionResult> {
    // 1. LLM에게 프롬프트 전송
    const messages = buildDecomposePrompt(naturalLanguage, context);
    const raw = await this.llm.chatJSON<DecomposeResponse>(messages);

    // 2. 응답을 검증하고 정규화
    const tasks = (raw.tasks ?? []).map((t, i) =>
      validateTask(t, i, raw.tasks.length)
    );

    // 3. DAG 생성 + 사이클 검출
    const dag = this.dagGenerator.buildDAG(tasks);
    const cycles = this.dagGenerator.detectCycles(dag);

    // 4. 사이클이 있으면 자동 수정
    if (cycles) {
      this.removeCyclicEdges(tasks, dag);
      const fixedDag = this.dagGenerator.buildDAG(tasks);
      return { projectName: raw.projectName, tasks, dag: fixedDag };
    }

    return { projectName: raw.projectName, tasks, dag };
  }
}
```

여기서 중요한 포인트들:

**1) LLM에게 보내는 프롬프트**

```typescript
const DECOMPOSE_SYSTEM = `You are a senior software architect who breaks down
project requirements into actionable development tasks.

Rules:
- Each task should be 1-2 hours of focused work
- Assign roles: backend, frontend, test, devops
- Use TASK-NNN format (1-based) for depends_on references
- Priority: 1 (low) to 5 (critical)
- scope: list specific file paths the task will modify
- estimatedHours: realistic estimate (0.5 to 4)
- Ensure no circular dependencies
...`;
```

"시니어 소프트웨어 아키텍트" 역할을 부여하고, 구체적인 규칙을 줍니다. 역할은 `backend`, `frontend`, `test`, `devops` 네 가지로 고정되어 있어요. 이게 에이전트 자동 배정의 기준이 됩니다.

**2) 태스크 검증**

LLM 응답은 항상 믿을 수 없으니까, 검증 로직이 있습니다:

```typescript
function validateTask(raw, index, totalCount): DecomposedTask {
  const role = VALID_ROLES.has(raw.role) ? raw.role : 'backend';
  const priority = Math.max(1, Math.min(5, Math.round(raw.priority ?? 3)));
  const estimatedHours = Math.max(0.5, Math.min(8, raw.estimatedHours ?? 1));

  // depends_on 참조가 유효한지 확인
  const validDeps = (raw.depends_on ?? []).filter(dep => {
    if (!TASK_REF_RE.test(dep)) return false;
    const refIndex = parseInt(dep.replace(/^TASK-/i, ''), 10);
    return refIndex >= 1 && refIndex <= totalCount && refIndex !== index + 1;
  });

  return { title: raw.title, description: raw.description, role, priority, depends_on: validDeps, ... };
}
```

- 역할이 유효하지 않으면 `backend`로 폴백
- 우선순위는 1~5 범위로 클램핑
- 작업 시간은 0.5~8시간으로 제한
- 존재하지 않는 태스크를 참조하거나 자기 자신을 참조하면 제거

**3) 사이클 자동 수정**

LLM이 가끔 순환 의존성을 만듭니다(A → B → C → A). 이걸 자동으로 감지하고 수정합니다:

```typescript
private removeCyclicEdges(tasks, dag): [string, string][] {
  const cycles = this.dagGenerator.detectCycles(dag);
  // 사이클의 마지막 간선(back-edge)을 제거
  for (const cycle of cycles) {
    const from = cycle[cycle.length - 2];
    const to = cycle[cycle.length - 1];
    // to의 depends_on에서 from을 제거
  }
}
```

사용자가 신경 쓸 필요 없이 자동으로 처리됩니다.

## 본문 3: DAG 시각화와 병렬 실행 (4분)

화면: 마블로 플로우 에디터에서 DAG 시각화

`DAGGenerator`는 태스크들의 의존성을 **위상 정렬(Topological Sort)**하여 병렬 실행 가능한 레이어를 만듭니다.

```typescript
topologicalSort(dag: DAG): string[][] {
  // Kahn's 알고리즘
  // 결과: 레이어별로 묶인 태스크 ID 배열
  // [['TASK-001'], ['TASK-002', 'TASK-003'], ['TASK-004']]
  //  ^Layer 1      ^Layer 2 (병렬)            ^Layer 3
}
```

이 결과가 React Flow 시각화로 변환됩니다:

```typescript
toReactFlowGraph(dag: DAG): { nodes: FlowNode[]; edges: FlowEdge[] } {
  const layers = this.topologicalSort(dag);

  for (let layerIdx = 0; layerIdx < layers.length; layerIdx++) {
    const layer = layers[layerIdx];
    for (let nodeIdx = 0; nodeIdx < layer.length; nodeIdx++) {
      flowNodes.push({
        id: nodeId,
        position: {
          x: layerIdx * 280,   // 레이어별 X 좌표
          y: startY + nodeIdx * 100,  // 같은 레이어 내 Y 좌표
        },
        data: { label: dag.labels[nodeId], role: '', status: 'TODO' },
      });
    }
  }
}
```

화면에서는 이렇게 보입니다:

```
[TASK-001: API 설계] ──→ [TASK-002: UI 컴포넌트]
                     └──→ [TASK-003: 테스트 작성] ──→ [TASK-004: 통합]
```

왼쪽에서 오른쪽으로, 같은 열에 있는 태스크는 동시 실행 가능한 병렬 그룹입니다.

## 본문 4: AutoRouter — 자동 에이전트 배정 (4분)

화면: `auto-router.ts` 코드

태스크가 만들어졌으면, 어떤 에이전트에게 배정할지 결정해야 합니다. `AutoRouter`가 이걸 처리합니다.

```typescript
calculateScore(task: DecomposedTask, agent: Agent): number {
  let score = 0;

  // 역할 매칭 (가장 중요)
  if (agent.role === task.role) {
    score += 100;  // backend 태스크 → backend 에이전트
  } else {
    return 0;  // 역할이 안 맞으면 배정 안 함
  }

  // 태그 매칭 (세부 기술)
  const taskTags = this.extractTags(task);
  const matchingTags = taskTags.filter(t => agent.tags.includes(t));
  score += matchingTags.length * 10;

  // 우선순위 높은 태스크 → idle 에이전트 선호
  if (task.priority >= 4 && agent.status === 'idle') {
    score += 30;
  }

  // 부하 페널티: 이미 바쁜 에이전트는 점수 감점
  score -= agent.currentTaskCount * 15;

  return Math.max(0, score);
}
```

점수 체계가 직관적이죠?

- **역할 일치**: 100점 (필수 조건)
- **태그 일치**: 태그당 10점 (typescript, python, docker 등)
- **유휴 상태 보너스**: 20점
- **고우선 + 유휴**: 추가 30점
- **부하 페널티**: 현재 태스크 수 x -15점

이렇게 하면 backend 태스크는 backend 에이전트에게, frontend 태스크는 frontend 에이전트에게 자동 배정됩니다. 같은 역할의 에이전트가 여러 개 있으면 부하가 적은 쪽으로 갑니다.

배치 라우팅도 가능합니다:

```typescript
routeBatch(tasks, agents): Map<DecomposedTask, RoutingResult | null> {
  // 우선순위 높은 태스크부터 배정
  const sorted = [...tasks].sort((a, b) => b.priority - a.priority);

  for (const task of sorted) {
    // 가상 부하를 추적하면서 순차 배정
    const agent = this.route(task, virtualAgents);
    if (agent) {
      loadTracker.set(agent.id, currentLoad + 1);
    }
  }
}
```

## 본문 5: 전체 파이프라인 통합 (3분)

화면: `index.ts`의 `orchestrate` 메서드

이 모든 것을 묶는 게 `OrchestratorService.orchestrate()` 메서드입니다:

```typescript
async orchestrate(requirement, projectId, agents?, context?): Promise<OrchestrateResult> {
  // Step 1: 자연어 → 태스크 분해
  const decomposition = await this.decomposer.decompose(requirement, context);

  // Step 2: Firestore에 태스크 저장
  const createdTaskIds = await this.createTasksInFirestore(decomposition, projectId);

  // Step 3: 에이전트 자동 배정
  if (agents && agents.length > 0) {
    const routingMap = this.router.routeBatch(decomposition.tasks, agents);

    for (const [task, result] of routingMap) {
      if (result) {
        // 태스크를 CLAIMED 상태로 변경 + 에이전트 할당
        await updateDoc(doc(this.db, 'tasks', taskId), {
          status: 'CLAIMED',
          claimedBy: result.agent.id,
          claimedAt: Timestamp.now(),
        });
      }
    }
  }

  return { decomposition, createdTaskIds, routing };
}
```

세 단계가 파이프라인으로 연결됩니다:

1. **Decompose**: 자연어 → 구조화된 태스크 + DAG
2. **Persist**: Firestore에 저장 → 칸반 보드에 반영
3. **Route**: 태스크를 에이전트에 매칭 → 자동 시작

**(실습)** 실제로 해봅시다!

오케스트레이터 패널에 이렇게 입력해보세요:

```
블로그 플랫폼을 만들어줘.
- 마크다운 에디터가 있는 글 작성 페이지
- 글 목록 + 검색 기능
- 사용자 인증 (회원가입/로그인)
- 백엔드는 Express, 프론트는 React
- 테스트도 포함
```

화면: 오케스트레이터가 태스크를 분해하고 칸반 보드에 자동 생성되는 모습

잠시 기다리면 칸반 보드에 태스크들이 자동으로 생성되고, 플로우 에디터에 DAG가 시각화되며, 에이전트들에게 자동 배정됩니다.

이게 마블로 오케스트레이터의 힘입니다.

## 정리 (2분)

화면: 파이프라인 요약 다이어그램

오케스트레이터 핵심 정리:

1. **TaskDecomposer**: 자연어를 LLM으로 구조화된 태스크로 분해. 검증 + 사이클 자동 수정 포함.
2. **DAGGenerator**: Kahn's 알고리즘으로 위상 정렬. 병렬 실행 레이어 계산. React Flow 시각화.
3. **AutoRouter**: 역할 기반 점수제로 에이전트 자동 배정. 부하 분산 내장.
4. **OrchestratorService**: 전체 파이프라인을 하나의 `orchestrate()` 호출로 통합.

"자연어 한 줄 → 태스크 분해 → DAG → 에이전트 배정 → 실행"

이 전체 흐름이 자동으로 돌아갑니다.

다음 섹션에서는 이 파이프라인의 비용 측면을 분석하고, 모델별 최적 전략을 세워보겠습니다.
