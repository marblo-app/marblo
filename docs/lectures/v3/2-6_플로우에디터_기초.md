# 플로우 에디터 기초

> 모듈 2 · 섹션 2-6 · 약 25분
> 관련: [[2-5_에이전트_스킬파일]] | [[실습_플로우에디터]]

---

## 도입 (3분)

지금까지 칸반 보드 중심으로 작업을 관리했습니다.
태스크를 만들고, 에이전트가 claim하고, 상태가 이동하고.

플로우 에디터는 다른 관점입니다.
칸반이 **"누가 뭘 하고 있는가"** 를 보여준다면,
플로우는 **"어떤 순서로 진행되는가"** 를 보여줍니다.

화면: 마블로 앱 — Flows 탭 클릭

마블로의 Flows 탭을 열어보겠습니다.
여기가 비주얼 플로우 에디터입니다.

@xyflow/react(구 React Flow) 라이브러리 기반으로 만들어져 있고,
노드를 배치하고 연결해서 DAG(Directed Acyclic Graph)를 만들 수 있습니다.

---

## 본문

### 플로우란 무엇인가 (3분)

화면: 슬라이드 — 칸반 vs 플로우 비교

칸반과 플로우의 차이를 먼저 봅시다.

**칸반 보드:**
```
TODO | CLAIMED | IN_PROGRESS | REVIEW | DONE
카드  카드       카드           카드      카드
```
→ 상태 기반. "지금 어디에 있는가"에 집중.

**플로우 에디터:**
```
[Input] → [LLM 분석] → [Branch] → [Agent 작업] → [Output]
                            ↓
                     [Human 검토]
```
→ 순서 기반. "어떤 순서로 처리하는가"에 집중.

둘 다 필요합니다.
칸반은 현재 상황을 실시간으로 보는 데 좋고,
플로우는 자동화 파이프라인을 설계하는 데 좋습니다.

### 7가지 노드 타입 (5분)

화면: Flows 탭 — 노드 추가 팔레트

마블로 플로우에는 7가지 노드 타입이 있습니다.

```typescript
// electron/flow-engine/types.ts
export type NodeType = 'input' | 'llm' | 'agent' | 'api' | 'human' | 'branch' | 'output';
```

하나씩 설명합니다:

**1. Input 노드**
```
[Input]
사용자 입력을 받는 시작점.
예: 텍스트 입력, 파일 업로드, URL
```

**2. LLM 노드**
```
[LLM]
AI 모델을 호출해서 텍스트를 처리.
예: 요약, 분류, 번역, 분석
설정: 모델, 프롬프트 템플릿, 온도
```

**3. Agent 노드**
```
[Agent]
마블로 에이전트에게 작업 위임.
예: "이 코드를 리팩토링해줘"
설정: 역할, 모델, 스킬 파일
```

**4. API 노드**
```
[API]
외부 API를 호출.
예: REST API, Webhook, 데이터베이스 쿼리
설정: URL, 메서드, 헤더, 바디
```

**5. Human 노드**
```
[Human]
사람의 확인/입력을 기다림.
예: 승인/거절, 수동 데이터 입력
플로우가 여기서 일시정지됨.
```

**6. Branch 노드**
```
[Branch]
조건에 따라 분기.
예: if 점수 > 80 → A 경로, else → B 경로
설정: 조건 표현식
```

**7. Output 노드**
```
[Output]
결과를 출력하는 종착점.
예: 파일 저장, 알림 전송, 화면 표시
```

화면: 슬라이드 — 노드 타입 아이콘 + 설명

### 플로우 데이터 구조 (4분)

화면: VS Code — flow-engine/types.ts

플로우가 내부적으로 어떻게 저장되는지 봅시다:

```typescript
// electron/flow-engine/types.ts

export interface FlowNode {
  id: string;
  type: NodeType;            // 'input', 'llm', 'agent', ...
  position: { x: number; y: number };  // 캔버스 위의 위치
  data: {
    label: string;           // 노드 이름
    config: Record<string, unknown>;  // 노드별 설정
  };
}

export interface FlowEdge {
  id: string;
  source: string;            // 출발 노드 ID
  target: string;            // 도착 노드 ID
  sourceHandle?: string;     // 출발 포트 (branch의 true/false 등)
  targetHandle?: string;     // 도착 포트
}

export interface Flow {
  id: string;
  projectId: string;
  name: string;
  description: string;
  nodes: FlowNode[];
  edges: FlowEdge[];
  status: FlowStatus;       // draft, ready, running, completed, failed
}
```

이 데이터가 Firestore에 저장됩니다.
MCP 도구로도 플로우를 생성할 수 있어요:

```typescript
// create_flow MCP 도구
server.tool('create_flow', 'Create a new flow (pipeline).', {
  name: z.string(),
  description: z.string().optional(),
  nodes: z.string().optional(),     // FlowNode[] JSON 문자열
  edges: z.string().optional(),     // FlowEdge[] JSON 문자열
}, async ({ name, description, nodes, edges }) => {
  // Firestore에 저장
  const ref = await addDoc(collection(db, 'flows'), data);
  return text(`Flow created: ${ref.id}`);
});
```

### 플로우 실행 엔진 (3분)

화면: VS Code — flow-engine/ 폴더 구조

```
electron/flow-engine/
├── types.ts          — 타입 정의
├── topo-sort.ts      — 위상 정렬 (실행 순서 결정)
├── node-executors.ts — 노드별 실행 로직
├── flow-runner.ts    — 플로우 실행 엔진
├── kanban-bridge.ts  — 플로우 ↔ 칸반 연동
└── index.ts          — 진입점
```

플로우 실행 순서:
1. **위상 정렬**: 노드 간 의존성을 분석해서 실행 순서를 결정
2. **노드 실행**: 순서대로 각 노드를 실행
   - Input → 데이터 수집
   - LLM → AI 모델 호출
   - Branch → 조건 평가, 다음 경로 결정
   - Human → 사람 입력 대기 (플로우 일시정지)
   - Agent → 에이전트에 작업 위임
   - Output → 결과 출력
3. **이벤트 발생**: 각 단계마다 이벤트를 발행

```typescript
export type FlowEvent =
  | { type: 'node:start'; nodeId: string }
  | { type: 'node:complete'; nodeId: string; result: NodeExecutionResult }
  | { type: 'node:error'; nodeId: string; error: string }
  | { type: 'flow:paused'; runId: string; pendingNodeId: string }
  | { type: 'flow:completed'; runId: string; state: FlowExecutionState }
  | { type: 'flow:failed'; runId: string; error: string };
```

이 이벤트가 UI에 전달되어서 플로우 에디터에서 실시간으로 실행 상태를 볼 수 있습니다.

### (실습) 간단한 플로우 만들기 (7분)

화면: Flows 탭 — 빈 캔버스

**(실습) "Input → LLM 분석 → Output" 플로우 생성**

Step 1: Flows 탭에서 "새 플로우" 클릭

Step 2: Input 노드 배치
- 노드 팔레트에서 "Input" 드래그
- 캔버스 왼쪽에 배치
- 설정: Label = "사용자 입력"

Step 3: LLM 노드 배치
- "LLM" 노드 드래그
- Input 오른쪽에 배치
- 설정:
  ```json
  {
    "label": "텍스트 분석",
    "config": {
      "model": "claude-sonnet",
      "prompt": "다음 텍스트를 분석하고 핵심 키워드를 추출해주세요: {{input}}",
      "temperature": 0.3
    }
  }
  ```

Step 4: Output 노드 배치
- "Output" 노드 드래그
- LLM 오른쪽에 배치
- 설정: Label = "분석 결과"

Step 5: 노드 연결
- Input의 출력 포트를 LLM의 입력 포트로 드래그
- LLM의 출력 포트를 Output의 입력 포트로 드래그

완성:
```
[사용자 입력] ──→ [텍스트 분석 (LLM)] ──→ [분석 결과]
```

화면: 완성된 3개 노드 플로우

Step 6: 저장
- 플로우 이름: "텍스트 분석기"
- 저장 클릭 → Firestore에 저장

또는 MCP로 같은 플로우를 만들 수 있습니다:
```
/tf-create-flow 텍스트 분석 파이프라인.
사용자가 텍스트를 입력하면 LLM이 분석하고 키워드를 추출해서 결과를 보여줌.
```

오케스트레이터가 `create_flow` MCP 도구를 호출해서 자동 생성합니다.

### 칸반 ↔ 플로우 연동 (2분)

화면: kanban-bridge.ts 코드

플로우와 칸반 보드는 양방향으로 연결될 수 있습니다.

- 플로우의 Agent 노드가 실행되면 → 칸반에 태스크가 생성됨
- 칸반에서 태스크가 DONE이 되면 → 플로우의 다음 노드가 실행됨

이 연동은 `kanban-bridge.ts`가 담당합니다.
모듈 4(메인 프로젝트)에서 이 연동을 실제로 활용해볼 겁니다.

## 정리 (2분)

플로우 에디터 핵심:

| 항목 | 내용 |
|------|------|
| 라이브러리 | @xyflow/react (비주얼 DAG 에디터) |
| 노드 타입 | Input, LLM, Agent, API, Human, Branch, Output (7개) |
| 저장 | Firestore (MCP `create_flow`로도 생성 가능) |
| 실행 | 위상 정렬 → 순서대로 실행 → 이벤트 발행 |
| 칸반 연동 | Agent 노드 ↔ 칸반 태스크 양방향 |

칸반 vs 플로우:
- **칸반**: 현재 상태 관리 (누가 뭘 하고 있나)
- **플로우**: 자동화 파이프라인 (어떤 순서로 처리하나)
- **함께 쓸 때** 가장 강력합니다
