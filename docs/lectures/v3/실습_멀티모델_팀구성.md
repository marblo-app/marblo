# 실습: 멀티모델 팀 구성 Complete Guide

> 모듈 5 · 실습 · [[5-3_혼합팀_구성]] 보충 자료
> 관련: [[5-1_왜_멀티모델인가]] | [[5-2_멀티모델_설정]] | [[5-5_모델별_비용성능]]

---

## 실습 목표

이 실습을 완료하면 다음을 할 수 있습니다:
- Claude, Gemini, Codex 세 가지 모델의 에이전트를 하나의 마블로 프로젝트에서 실행
- 오케스트레이터를 사용해 자연어로 태스크를 분해하고 에이전트에 자동 배정
- 각 모델의 코드 스타일과 작업 방식의 차이를 이해

## 사전 요구사항

- [ ] 마블로 v3 앱이 설치되어 있어야 합니다
- [ ] Claude Code CLI 인증 완료 (`claude login`)
- [ ] Gemini CLI 설치 + API 키 설정 (`GEMINI_API_KEY`)
- [ ] Codex CLI 설치 + ChatGPT Pro 인증 (`codex login`)

---

## Step 1: CLI 도구 확인 (2분)

터미널을 열고 모든 CLI 도구가 정상 작동하는지 확인합니다.

```bash
# Claude Code
claude --version

# Gemini CLI
gemini --version

# Codex CLI
codex --version
```

모두 버전이 출력되면 OK. 만약 "command not found" 오류가 나면:

```bash
# Claude Code 설치
npm install -g @anthropic-ai/claude-code

# Gemini CLI 설치 (방법은 Google 공식 문서 참조)
npm install -g @anthropic-ai/claude-code

# Codex CLI 설치
npm install -g @openai/codex
```

**환경변수 확인:**

```bash
# Gemini API 키가 설정되어 있는지
echo $GEMINI_API_KEY

# 비어 있으면 설정
export GEMINI_API_KEY="your-gemini-api-key-here"

# .zshrc 또는 .bashrc에 영구 저장하려면:
echo 'export GEMINI_API_KEY="your-key"' >> ~/.zshrc
source ~/.zshrc
```

---

## Step 2: 프로젝트 디렉토리 준비 (3분)

작업할 프로젝트 디렉토리를 만듭니다.

```bash
mkdir -p ~/projects/multi-model-demo
cd ~/projects/multi-model-demo

# Git 초기화
git init

# 기본 구조 생성
mkdir -p src/api src/components tests

# package.json 초기화
npm init -y
```

---

## Step 3: 마블로에서 프로젝트 생성 (2분)

1. 마블로 앱을 실행합니다
2. 좌측 사이드바 하단의 **"+"** 버튼 클릭
3. 프로젝트 설정:
   - **프로젝트명**: `multi-model-demo`
   - **프로젝트 경로**: `~/projects/multi-model-demo`
4. "Create" 클릭

화면: 빈 칸반 보드가 표시됩니다.

---

## Step 4: 오케스트레이터 실행 (3분)

오케스트레이터를 먼저 띄웁시다.

1. 좌측 상단의 **"Orchestrator"** 버튼 클릭
2. 오케스트레이터가 Claude Code로 부팅됩니다 (3~5초 소요)
3. 연결 확인: "Connected to MCP server: marblo" 메시지 확인

화면: 오케스트레이터 터미널 패널

---

## Step 5: 에이전트 3개 생성 (5분)

**Agents** 탭으로 이동합니다.

### 5-a: Claude Backend 에이전트

1. "Add Agent" 클릭
2. 입력:
   ```
   Name: Claude-Backend
   Model: Claude
   Role: backend
   ```
3. "Launch" 클릭
4. 터미널에서 "Connected to MCP server: marblo" 확인

### 5-b: Gemini Frontend 에이전트

1. "Add Agent" 클릭
2. 입력:
   ```
   Name: Gemini-Frontend
   Model: Gemini
   Role: frontend
   ```
3. "Launch" 클릭
4. Gemini CLI 부팅 확인

### 5-c: Codex Test 에이전트

1. "Add Agent" 클릭
2. 입력:
   ```
   Name: Codex-Test
   Model: Codex (GPT)
   Role: test
   ```
3. "Launch" 클릭
4. Codex CLI 부팅 확인

화면: Agents 탭에 3개 에이전트가 모두 "idle" 상태로 표시

---

## Step 6: 오케스트레이터로 태스크 자동 생성 (5분)

오케스트레이터 터미널에 다음을 입력합니다:

```
간단한 할 일 관리 앱을 만들어줘.

요구사항:
1. Express.js 백엔드 — Todo CRUD API (GET, POST, PUT, DELETE)
2. React 프론트엔드 — TodoList, TodoItem, AddTodo 컴포넌트
3. Jest + Supertest로 API E2E 테스트
4. TypeScript 사용
```

오케스트레이터가 다음을 자동으로 수행합니다:

1. **태스크 분해**: 자연어를 3~5개의 구조화된 태스크로 변환
2. **DAG 생성**: 태스크 간 의존성 그래프 작성
3. **칸반 보드 업데이트**: Firestore에 저장 → 보드에 반영
4. **에이전트 배정**: backend → Claude-Backend, frontend → Gemini-Frontend, test → Codex-Test

화면: 칸반 보드에 태스크가 자동 생성되고, 에이전트 이름이 할당됨

---

## Step 7: 에이전트 동시 작업 관찰 (10분)

이제 가장 흥미로운 부분입니다. 세 에이전트가 동시에 작업하는 것을 관찰합니다.

### 관찰 포인트 1: 터미널 모니터링

Agents 탭에서 각 에이전트의 터미널을 전환하며 관찰합니다:

- **Claude-Backend**: Express 서버 파일 생성, 라우팅 설정, 에러 핸들링
- **Gemini-Frontend**: React 컴포넌트 빠르게 생성, CSS 스타일링
- **Codex-Test**: Jest 테스트 파일 자동 생성, 테스트 케이스 대량 생산

### 관찰 포인트 2: 칸반 보드 상태 변화

보드에서 태스크들이 자동으로 이동하는 것을 관찰합니다:

```
TODO → IN_PROGRESS → REVIEW → DONE
```

### 관찰 포인트 3: 코드 스타일 비교

작업이 진행되면 VS Code에서 파일들을 열어봅니다:

```bash
# Claude가 작성한 파일
cat src/api/routes.ts

# Gemini가 작성한 파일
cat src/components/TodoList.tsx

# Codex가 작성한 파일
cat tests/todo.test.ts
```

각 모델의 코드 스타일 차이를 관찰해보세요.

---

## Step 8: 결과 검증 (5분)

모든 에이전트가 작업을 완료하면, 결과를 검증합니다.

```bash
cd ~/projects/multi-model-demo

# 의존성 설치
npm install

# 백엔드 서버 시작 (별도 터미널)
npx ts-node src/api/server.ts

# 테스트 실행
npm test

# 프론트엔드 실행 (별도 터미널)
npm run dev
```

**체크리스트:**

- [ ] API 서버가 정상 시작되는가?
- [ ] `curl http://localhost:3000/api/todos`가 응답하는가?
- [ ] 테스트가 모두 통과하는가?
- [ ] 프론트엔드 UI가 정상 렌더링되는가?

---

## Step 9: 수동 태스크 추가 + 에이전트 배정 (선택)

오케스트레이터 없이 수동으로도 해볼 수 있습니다.

1. 칸반 보드에서 "Add Task" 클릭
2. 태스크 작성:
   ```
   Title: Todo 완료 통계 API 추가
   Role: backend
   Priority: 3
   Description: GET /api/todos/stats 엔드포인트를 추가.
                완료율, 총 개수, 완료 개수를 반환.
   ```
3. 생성된 태스크를 Claude-Backend 에이전트에 드래그

## 트러블슈팅

### 문제: Gemini CLI가 "command not found"

```bash
# Gemini CLI의 설치 경로 확인
which gemini

# PATH에 포함되어 있는지 확인
echo $PATH

# 마블로가 자동으로 보강하는 PATH 목록:
# /opt/homebrew/bin, /usr/local/bin, ~/.local/bin 등
```

### 문제: Codex에서 "인증 필요" 오류

```bash
# Codex 재인증
codex login

# ChatGPT Pro 구독이 활성화되어 있는지 확인
```

### 문제: MCP 서버 연결 실패

```bash
# MCP 서버 빌드 확인
cd /path/to/marblo/v3
npm run build:mcp

# 생성된 설정 파일 확인
ls /tmp/marblo-agent-configs/

# 설정 파일 내용 확인
cat /tmp/marblo-agent-configs/claude-mcp-*.json
```

### 문제: 에이전트가 작업을 시작하지 않음

1. Agents 탭에서 에이전트 상태 확인 (idle/working/error/stopped)
2. 터미널 패널에서 에러 메시지 확인
3. 에이전트 재시작: Agent 카드의 "Restart" 버튼 클릭

```

- 댓글 기능
```
