## 도입 (3분)

여러분, 드디어 마지막 섹션입니다.

화면: 슬라이드 — "마블로 v3 마스터 클래스 — 마무리"

솔직히 말씀드리면, 이 강좌를 끝까지 완주한 것 자체가 대단합니다. AI 에이전트, MCP, 멀티모델, GCP 배포, 칸반 보드 자동화 — 쉽지 않은 내용이었어요. 중간에 포기하고 싶었을 수도 있지만, 여기까지 오셨다는 건 이 기술에 대한 열정이 있다는 뜻입니다.

이번 섹션에서는 전체 과정을 돌아보고, 여러분이 만든 것을 정리하고, 앞으로 어떻게 활용하면 되는지 이야기하겠습니다.

## 본문 1: 전체 과정 회고 (5분)

화면: 모듈별 여정 타임라인

### 모듈 1: 시작 — 설치 + 첫 체험

```
설치 → MCP 설정 → Hook 설정 → 첫 풀사이클 체험
"와, 자연어로 명령하면 에이전트가 코드를 만든다고?"
```

기억나시죠? 처음 Claude Code에서 `/tf-start`를 실행하고, 에이전트가 파일을 만들고, 칸반 보드에 태스크가 이동하는 걸 봤을 때의 그 느낌. "이게 된다고?" 하셨을 거예요.

### 모듈 2: 개념 이해 — 마블로 시스템

```
아키텍처 → MCP 프로토콜 → 에이전트 라이프사이클 → 칸반 보드
"아, 이런 원리로 동작하는 거구나"
```

MCP가 에이전트와 마블로를 연결하는 프로토콜이라는 것, 오케스트레이터가 전체를 지휘한다는 것, 칸반 보드가 소통의 허브라는 것을 이해했습니다.

### 모듈 3: 워밍업 — 날씨 대시보드

```
기획 → 에이전트 실행 → PM 역할 → 회고
"처음으로 완전한 프로젝트를 에이전트로 만들어봤다"
```

날씨 API 연동, 대시보드 UI, 테스트까지 — 작지만 완전한 프로젝트를 에이전트 군단으로 빌드한 첫 경험이었습니다.

### 모듈 4: 실전 — AI YouTube Insight SaaS

```
요구사항 분석 → 태스크 생성 → 스프린트 빌드 → PM 역할
"실제 서비스 수준의 프로젝트를 만들었다"
```

백엔드 API, 프론트엔드 UI, YouTube API 연동, AI 분석 엔진까지. 이건 실제로 서비스할 수 있는 수준의 SaaS입니다.

### 모듈 5: 멀티모델 — Claude + Gemini + Codex

```
모델별 강점 → 설정 → 혼합팀 구성 → 비용 최적화
"한 보드에서 서로 다른 AI 모델을 동시에 돌릴 수 있다니"
```

마블로의 킬링 피쳐를 체험했습니다. 비용은 95% 절감하면서 품질은 유지하는 전략을 배웠죠.

### 모듈 6: 배포 — GCP Cloud Run

```
GCP 셋업 → Cloud Run 배포 → 크론잡 → CI/CD
"내가 만든 서비스를 전 세계가 접속할 수 있다"
```

로컬에서만 돌리던 프로젝트를 실제 URL로 접속 가능하게 만들었습니다.

### 모듈 7: 런칭 — 랜딩페이지 + 체크리스트

```
Stitch MCP → 랜딩페이지 → 런칭 체크리스트
"제품으로서의 완성도를 갖추기 시작했다"
```

기술적으로 동작하는 것과 "제품"은 다릅니다. 랜딩페이지, SEO, 모니터링, 법적 페이지까지 갖추면 그때부터 진짜 제품이 됩니다.

### 모듈 8: 운영 — 일상 패턴 + Ralph + 확장

```
운영 패턴 → Ralph 자동화 → 확장 방향 → 마무리 (지금)
"매일 실무에서 어떻게 쓰면 되는지 알겠다"
```

## 본문 2: 핵심 워크플로우 최종 정리 (4분)

화면: 워크플로우 다이어그램

이 강좌에서 배운 가장 핵심적인 워크플로우를 한 장에 정리합니다.

### 프로젝트 빌드 워크플로우

```
/tf-plan      요구사항 입력, 계획 수립
    ↓
/tf-analyze   심층 분석, DAG 생성 (복잡한 작업)
    ↓
/tf-start     에이전트 배정, 작업 시작
    ↓
/tf-status    진행 상황 모니터링
    ↓
/tf-review    완료된 태스크 리뷰
    ↓
/tf-done      작업 완료, 요약 생성
```

### 일상 운영 워크플로우

```
아침:   /tf-resume → /tf-status
오전:   /tf-start (간단) 또는 /tf-analyze → /tf-plan → /tf-start (복잡)
오후:   /tf-review → /tf-approve 또는 /tf-fix
퇴근:   /tf-done
반복:   /tf-ralph (배치 작업)
```

### 멀티모델 전략

```
Claude    → 핵심 로직, 아키텍처, 보안 (품질 중시)
Gemini    → 프론트엔드, 리팩토링, 대규모 분석 (속도 + 저비용)
Codex     → 테스트, 반복 코드 (Pro 포함, 무료)
```

이 세 가지만 기억하세요. 나머지는 상황에 맞게 응용하면 됩니다.

## 본문 3: 여러분이 만든 것 (3분)

화면: 슬라이드 — 프로젝트 3개 스크린샷

이 강좌를 통해 여러분이 실제로 만든 것들입니다:

### 1. 날씨 대시보드 (모듈 3)

```
기능: 실시간 날씨 조회, 5일 예보, 차트 시각화
기술: Next.js + OpenWeatherMap API + Chart.js
배운 것: 마블로 기본 워크플로우, PM 역할
```

### 2. AI YouTube Insight SaaS (모듈 4~6)

```
기능: YouTube 영상 분석, AI 요약, 트렌드 리포트, 자동 크론잡
기술: FastAPI + Next.js + YouTube API + AI + GCP Cloud Run
배운 것: 실전 프로젝트 빌드, 멀티모델, 클라우드 배포
```

### 3. SaaS 랜딩페이지 (모듈 7)

```
기능: Hero, Features, Pricing, CTA, SEO
기술: Next.js + Tailwind + Framer Motion + Stitch MCP
배운 것: 디자인 → 코드 변환, 런칭 준비
```

화면: 세 프로젝트의 스크린샷을 나란히 보여주기

이 세 가지는 여러분의 **포트폴리오**입니다. GitHub에 올리고, 이력서에 적을 수 있어요. "AI 에이전트 오케스트레이션으로 SaaS를 구축하고 GCP에 배포한 경험"은 지금 시장에서 매우 희소한 역량입니다.

## 본문 5: 마무리 메시지 (4분)

화면: 슬라이드 — 마무리

여러분, 잠시 큰 그림을 봅시다.

1년 전만 해도 "AI가 코드를 짠다"는 건 신기한 데모 수준이었습니다. ChatGPT에 코드를 물어보면 대충 맞는 답이 나오는 정도였죠.

지금은 다릅니다. AI 에이전트가 실제로 파일을 만들고, Git 커밋을 하고, 테스트를 실행하고, 배포까지 합니다. 그리고 마블로 같은 도구로 이 에이전트들을 **조직화**해서 실제 팀처럼 운영할 수 있습니다.

이건 단순한 도구 사용법이 아닙니다. **일하는 방식의 변화**입니다.

여러분은 이제:

- 자연어로 요구사항을 전달하면 AI 에이전트 군단이 코드를 만들고
- 칸반 보드에서 프로젝트를 관리하고
- 멀티모델 전략으로 비용을 최적화하고
- 클라우드에 배포하고
- 반복 작업을 자동화할 수 있습니다

**여러분은 이제 AI 에이전트 군단을 지휘할 수 있습니다.**

화면: "AI 에이전트 군단을 지휘하는 PM" 일러스트

### 다음 단계: 실전 적용
