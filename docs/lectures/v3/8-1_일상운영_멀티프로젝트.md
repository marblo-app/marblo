# 일상 운영 패턴 + 멀티프로젝트

> 모듈 8 · 섹션 8-1 · 약 20분
> 관련: [[7-4_랜딩페이지_런칭체크리스트]] | [[8-2_Ralph_반복자동화]]

---

## 이 강의에서 다루는 것

- **학습목표:** 빌드가 끝난 뒤의 **일상 운영 리듬**(아침 → 작업 → 리뷰 → 마무리)을 슬래시 루틴으로 익히고, **멀티윈도우**로 두 프로젝트를 한 책상에서 굴리는 운영 습관을 잡는다.
- **시연할 마블로 화면·기능:** 보드 탭 + 하단 오케스트레이터 PTY(슬래시 메뉴) + 멀티윈도우.
- **진행할 프로젝트 단계:** **운영 모드** — P3(ReachWave 콜드메일 SaaS)를 매일 굴리며 새 일거리를 처리.
- **핵심 메시지:** "마블로는 한 번 쓰는 도구가 아니라 **매일 여는 작업대**다."

---

## 도입 (3분)

여기까지 오셨다면 — 모듈 3에서 할 일 웹앱(P1), 모듈 4에서 날씨 대시보드(P2), 모듈 5에서 ReachWave 콜드메일 SaaS(P3)를 멀티에이전트로 빌드하고, 모듈 7에서 배포·런칭까지 끝냈습니다. 축하합니다.

> 화면: 슬라이드 — "빌드는 끝. 이제부터가 운영이다."

그런데 제품은 **만들고 끝이 아닙니다.** 버그가 들어오고, 기능 요청이 쌓이고, 리팩토링할 코드가 생기고, 성능을 손봐야 합니다. 매일 할 일이 있어요.

이번 섹션은 화려한 신기능이 아니라 **반복되는 하루의 리듬**입니다. 아침에 앉아서 마지막에 닫을 때까지, 마블로와 에이전트 팀을 어떻게 굴리면 매끄럽게 흘러가는지 — 그리고 프로젝트가 둘 이상일 때 **멀티윈도우**로 어떻게 분리하는지 보겠습니다.

---

## 본문

### 1. 하루의 리듬 — 아침 · 작업 · 리뷰 · 마무리 (8분)

> 화면: 보드 탭 + 하단 오케 PTY

명령어를 외울 필요는 없습니다. 대부분 **오케에 말로** 시키면 되고, 자주 쓰는 건 `/`를 눌러 슬래시 메뉴에서 고르면 됩니다. 하루를 네 박자로 나눠 보겠습니다.

**① 아침 — 상황 파악 (5분)**

하루를 시작할 때 가장 먼저 하는 일은 "지금 어디까지 왔나"를 보는 겁니다. 보드 탭을 열면 `TODO · IN_PROGRESS · REVIEW · DONE` 컬럼에 카드가 어떻게 흩어져 있는지 한눈에 들어옵니다. 어제 중단된 작업이 있으면 오케에 그대로 이어가자고 말합니다.

```
오케 PTY:
어제 하던 거 이어가자. 지금 상태 정리해서 보여줘.
```

```
/tf-status      ← 보드 전체 현황을 텍스트로 요약
```

`/tf-status`는 TODO·IN_PROGRESS·REVIEW·DONE 개수와 에이전트 상태(working/idle)를 30초 안에 요약해 줍니다. 보드를 눈으로 훑는 것과 같은 정보를, 오케 패널에서 글로 받는 거예요.

**② 작업 — 간단한 건 바로, 복잡한 건 분석부터 (자유)**

오늘 할 일을 정했으면 두 갈래로 나뉩니다.

```
간단한 작업 — 바로 시작
/tf-start 로그인 화면에 비밀번호 찾기 기능 추가해줘
```

`/tf-start`는 **빠른 시작**입니다. 한 문장이면 오케가 태스크를 만들고, 에이전트를 배정하고, 바로 일을 시작합니다.

```
복잡한 작업 — 분석 먼저
/tf-analyze 결제를 Toss로 연동해야 해. 웹훅 수신, 구독 관리,
인보이스 생성이 필요하고 기존 user 테이블과 엮여야 해. 테스트도 필요해.
```

`/tf-analyze`는 **심층 분석**입니다. 오케가 요구를 분해하고 의존성 체인을 잡아, 어떤 순서로 가야 하는지 보여줍니다. 큰 작업은 이걸로 먼저 그림을 그린 뒤 시작하세요. (분석 → 일괄 생성 흐름은 [[5-2_태스크일괄생성_이종배정]]에서 다뤘습니다.)

**③ 리뷰 — REVIEW 카드를 게이트한다 (자유)**

에이전트가 일을 끝내면 카드가 **REVIEW**로 올라옵니다. 여기서 PM이 게이트를 잡습니다.

```
/tf-review      ← REVIEW 카드 목록과 변경 diff 검토
```

코드 탭에서 diff를 보고, 괜찮으면 승인해 DONE으로, 부족하면 피드백을 달아 IN\*PROGRESS로 되돌립니다. 반려·재작업 흐름은 [[4-4_리뷰거버넌스_반려재작업]]에서 자세히 봤죠. 문제가 보이면 콕 집어 고치게 합니다.

```
/tf-fix TASK-024 웹훅 서명 검증이 빠졌어. 서명을 검증한 뒤 처리하도록 고쳐줘.
```

**④ 마무리 — 닫기 전에 정리 (자유)**

하루를 닫기 전에 오늘 한 일을 정리합니다.

```
/tf-done        ← 오늘 작업 요약 + 미완 항목 백로그로
```

```
오늘 요약:
- 완료: 5개 태스크
- 진행 중: 1개 (내일 이어서)
- 새로 생성: 2개 (백로그)
- 에이전트 사용: Claude 3, Codex 2
- 추정 비용: 사용량 탭에서 실측 확인
```

> 💡 비용 수치는 머릿속으로 어림하지 말고 **사용량 탭(UsagePage)에서 실측**으로 봅니다. "비용은 측정되는 순간 통제된다" — [[6-4_사용량탭_비용추적최적화]]에서 다뤘죠.

이 네 박자 — **아침(status) → 작업(start/analyze) → 리뷰(review/fix) → 마무리(done)** — 를 2~3일만 반복하면 손에 붙습니다. 그다음부터는 거의 자동으로 흘러가요.

> ⚠️ 슬래시 명령의 **전체 목록과 정확한 이름**은 버전마다 갱신됩니다. 외워서 쓰기보다, 오케 패널에서 `/`를 눌러 **그때그때 뜨는 메뉴**에서 고르거나 가이드 탭에서 확인하세요. 핵심은 명령어 암기가 아니라 **이 리듬**입니다.

### 2. 멀티윈도우 — 프로젝트를 창으로 나눈다 (7분)

> 화면: 두 개의 마블로 창 — 왼쪽 운영 중인 ReachWave, 오른쪽 새 사이드 프로젝트

운영을 하다 보면 프로젝트가 하나가 아니게 됩니다. ReachWave를 운영하면서 새 사이드 프로젝트를 시작하거나, 끝낸 P2 날씨 대시보드를 유지보수하면서 P3를 이어가야 하죠. 한 창에서 프로젝트를 왔다 갔다 전환하면 방금 보던 맥락이 사라져 헷갈립니다.

마블로는 **멀티윈도우**로 이걸 깔끔하게 가릅니다.

```
File → New Window  (단축키: Cmd/Ctrl + Shift + N)
```

새 창을 열고 거기서 **다른 프로젝트를 선택**하면, 두 창이 **독립적으로** 굴러갑니다.

- **창 A** — ReachWave 운영: 보드·에이전트·터미널이 ReachWave 것만
- **창 B** — 새 프로젝트: 보드·에이전트·터미널이 그 프로젝트 것만

핵심은 **프로젝트 격리**입니다. 창 B에서 스폰한 에이전트의 상태 변화·로그는 **창 B에만** 뜨고, 창 A를 오염시키지 않습니다. 각 프로젝트의 에이전트는 자기 프로젝트의 코드만 건드려요 — 창 A의 에이전트가 창 B의 파일을 고치는 일은 없습니다.

```
창 A: ReachWave              창 B: 새 사이드 프로젝트
├── 칸반 보드 A              ├── 칸반 보드 B
├── 에이전트 A-1, A-2        ├── 에이전트 B-1, B-2
├── 워크트리 A               ├── 워크트리 B
└── 태스크 히스토리 A        └── 태스크 히스토리 B
```

> 💡 모니터 두 대를 쓰는 것과 같습니다. 탭을 휙휙 바꾸는 대신, 한 프로젝트는 왼쪽 창에 다른 하나는 오른쪽 창에 펼쳐두고 **동시에** 봅니다. (멀티윈도우의 동작 원리·실습은 [[6-3_에이전트_재활용_멀티윈도우]]에서 자세히 다뤘습니다.)

### 3. 동시 운영의 기본기 (2분)

> 화면: 슬라이드 — 멀티프로젝트 운영 루프

여러 프로젝트를 굴리는 PM이라면 리듬이 이렇게 묶입니다.

```
프로젝트별로 창을 연다 (multi-window)
   └ 각 창 안에서:
       아침: /tf-status 로 상황 파악
       작업: /tf-start (간단) · /tf-analyze (복잡)
       리뷰: /tf-review → 승인 또는 /tf-fix
       마무리: /tf-done
```

- **한 프로젝트에서 에이전트가 도는 동안** 다른 창으로 넘어가 리뷰를 처리할 수 있습니다.
- **에이전트 수는 프로젝트별로 독립** — 한쪽에 3마리, 다른 쪽에 2마리.
- **끝난 에이전트는 재활용·정리** — 노는 에이전트는 다시 쓰고(reuse), 스프린트가 끝나면 한 번에 치웁니다(cleanup).

## 정리 (1분)

> 화면: 요약 슬라이드

1. **하루는 네 박자다.** 아침 `/tf-status` → 작업 `/tf-start`·`/tf-analyze` → 리뷰 `/tf-review`·`/tf-fix` → 마무리 `/tf-done`. 2~3일이면 손에 붙는다.
2. **명령어는 외우지 않는다.** 오케에 말로 시키거나 `/` 메뉴에서 고른다. 목록은 버전마다 바뀌니 가이드 탭에서 현행 확인.
3. **비용은 실측으로.** 어림하지 말고 사용량 탭에서 본다.
4. **프로젝트는 창으로 나눈다.** File → New Window(Cmd/Ctrl+Shift+N)로 둘을 독립 창에 두고 동시 운영 — 이벤트는 프로젝트별로 격리된다.

다음 섹션에서는 이 일상 속에서 **지루한 반복 작업**을 한 번에 처리하는 법 — Ralph를 다룹니다. `/tf-start`가 빌드용이라면, `/tf-ralph`는 배치 처리용입니다.
