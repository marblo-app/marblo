# 에이전트 스킬 파일 — 역할별 행동 규칙

> 모듈 2 · 섹션 2-5 · 약 30분
> 관련: [[2-4_슬래시스킬_구조]] | [[2-6_플로우에디터_기초]]

---

## 도입 (3분)

이전 섹션에서 **슬래시 스킬**을 봤죠? `/tf-plan`, `/tf-start` 같은 것들.
이건 **PM(여러분)이 쓰는** 명령어입니다.

이번에 볼 건 **에이전트 스킬 파일**입니다.
이건 **에이전트가 읽는** 행동 규칙이에요.

차이를 명확히 하면:
- 슬래시 스킬: PM이 실행 → Claude Code가 MCP 도구 호출
- 에이전트 스킬: 에이전트가 스폰될 때 읽음 → 행동 방식을 결정

비유하면:
- 슬래시 스킬 = PM의 업무 매뉴얼
- 에이전트 스킬 = 개발자의 코딩 컨벤션 + 역할 설명서

화면: VS Code — skills/ 폴더

---

## 본문

### 5가지 역할 (3분)

화면: skills/ 폴더 내용

마블로 v3에는 5가지 에이전트 역할이 있습니다:

```
skills/
├── backend_agent.md       — 백엔드 개발
├── frontend_agent.md      — 프론트엔드 개발
├── test_agent.md          — 테스트 작성
├── devops_agent.md        — 인프라 / 배포
└── orchestrator_agent.md  — 오케스트레이터 (팀 리더)
```

각 파일은 해당 역할의 에이전트가 **어떻게 행동해야 하는지** 정의합니다.
기술 스택, 코딩 규칙, MCP 도구 사용법, 자율 작업 루프까지 전부 들어있어요.

에이전트가 스폰되면 가장 먼저 하는 일이:
```
get_agent_skill("backend")  → skills/backend_agent.md 내용을 읽음
```

이 내용을 숙지한 후에야 태스크를 claim하고 작업을 시작합니다.

### `backend_agent.md` 상세 분석 (10분)

화면: VS Code — backend_agent.md 전체 내용

가장 대표적인 백엔드 에이전트 스킬을 하나하나 뜯어봅시다.

**1. 역할 선언**

```markdown
# Backend Agent 스킬 (v3)

## 역할
너는 Marblo v3의 백엔드 개발 에이전트다.
Electron 앱 내 API, 서비스, 데이터 처리 로직을 담당한다.
```

첫 줄이 중요합니다. "너는 ~다"로 시작하죠.
AI에게 역할을 부여하는 겁니다. 이 선언이 없으면 에이전트가 뭘 해야 할지 모릅니다.

**2. 기술 스택**

```markdown
## 기술 스택
- TypeScript (strict mode)
- Node.js + Electron (메인 프로세스)
- Firebase / Firestore (데이터베이스)
- MCP Server (도구 기반 작업 관리)
```

어떤 기술을 써야 하는지 명시합니다.
"Python으로 만들어도 되지 않을까?"라고 에이전트가 고민하지 않게
미리 스택을 정해주는 겁니다.

**3. MCP 도구 사용법**

```markdown
## MCP 도구 사용법

### 태스크 관리 도구
| 도구 | 용도 |
|------|------|
| `get_available_tasks(role)` | 내 역할의 작업 가능한 태스크 조회 |
| `claim_task(task_id, agent_id)` | 태스크 선점 |
| `update_task_status(task_id, status, comment)` | 상태 전환 |
| `add_activity(task_id, message)` | 작업 진행 내역 기록 |
| `submit_for_review(task_id, pr_url?)` | 리뷰 제출 |
| `check_feedback(role)` | PM 피드백 확인 |
```

에이전트가 사용할 수 있는 MCP 도구를 테이블로 정리해뒀습니다.
"이 도구들만 써라"라는 뜻이기도 하고,
"이 도구가 있으니 활용해라"라는 뜻이기도 합니다.

**4. 코딩 규칙**

```markdown
## 코딩 규칙

### TypeScript 패턴
- `strict: true` 준수 — any 타입 사용 금지
- 인터페이스와 타입을 명확히 정의
- async/await 패턴 사용 (콜백 금지)
- 에러 핸들링: try/catch + 의미 있는 에러 메시지

### Firestore 패턴
- 컬렉션/문서 경로를 상수로 관리
- 트랜잭션 사용 시 race condition 방지

### Electron IPC 패턴
- `ipcMain.handle()` 사용 (invoke/handle 패턴)
- 렌더러에서 받는 데이터는 반드시 검증
```

이 부분이 에이전트 코드 품질에 직접적인 영향을 줍니다.
"`any` 타입 사용 금지"라고 적어두면 에이전트가 진짜 `any`를 안 씁니다.

**5. Scope 규칙**

```markdown
## Scope 규칙
- `v3/electron/` 디렉토리 내 파일만 수정
- `v3/src/services/`, `v3/src/types/` 수정 가능
- 프론트엔드 컴포넌트(`v3/src/components/`)는 수정 금지
- API 키, 시크릿 절대 하드코딩 금지
```

이건 안전 장치입니다.
백엔드 에이전트가 프론트엔드 컴포넌트를 수정하면 충돌이 생기거든요.
"여기만 건드려라"를 명확히 정해주면 에이전트 간 충돌을 방지할 수 있습니다.

**6. 자율 작업 루프 (가장 중요!)**

```markdown
## 자율 작업 루프 (필수)
1. get_agent_skill("backend") → 이 스킬 파일 숙지
2. 루프:
   a. get_available_tasks("backend") → 태스크 조회
   b. claim_task(task_id, agent_id) → 선점
   c. add_activity(task_id, "태스크 선점. 작업 시작.")
   d. check_feedback(role="backend") → PM 피드백 확인
   e. update_task_status(task_id, "IN_PROGRESS")
   f. 코드 작성 → add_activity(task_id, "구현 완료: [요약]")
   g. 테스트/검증 → add_activity(task_id, "검증 완료: [결과]")
   h. check_feedback(role="backend") → 재확인
   i. submit_for_review(task_id)
   j. 다음 태스크로
3. 태스크 없으면 → 팀리더에게 보고 후 종료
```

이게 에이전트의 **메인 루프**입니다.
이 순서대로 태스크를 처리하고, 끝나면 다음 태스크를 찾습니다.
"대기하지 말고 즉시 다음 태스크로" — 이 규칙 덕분에 에이전트가 쉬지 않고 일합니다.

### `orchestrator_agent.md` 핵심 차이 (3분)

화면: VS Code — orchestrator_agent.md

오케스트레이터 에이전트는 다른 에이전트와 근본적으로 다릅니다.

```markdown
## 핵심 규칙

### 1. 물리적 분할 에이전트만 사용
- **절대 Claude Code 내부 팀(TeamCreate, Task 도구) 사용 금지**
- 에이전트 스폰은 반드시 `spawn_agent` MCP 도구로 수행
- 각 에이전트는 독립적인 Claude/Gemini/Codex CLI 프로세스

### 2. 컨펌 우선 정책
모든 중요 액션 전에 사용자 확인을 받을 것:
- 태스크 생성 전 → 태스크 목록 보여주고 확인
- 에이전트 스폰 전 → 에이전트 구성 보여주고 확인

### 3. 제약 사항
- 코드를 직접 작성하지 않음 — 에이전트에 위임
- 한 번에 최대 5개 에이전트까지만 스폰
- 같은 role의 에이전트는 최대 2개까지
```

오케스트레이터의 핵심 원칙:
- **직접 코딩 안 함** — 코딩은 서브 에이전트가 함
- **컨펌 받고 행동** — PM 확인 없이 태스크 생성이나 스폰 안 함
- **물리적 분할** — Claude Code 내부 팀이 아니라 독립 프로세스로 에이전트 실행

### (실습) 스킬 파일 수정 → 행동 변화 관찰 (8분)

화면: VS Code — backend_agent.md 편집

**(실습) "테스트 없이 코드 작성 금지" 규칙 추가**

backend_agent.md에 규칙을 추가해봅시다:

**수정 전:**
```markdown
## 코딩 규칙
### TypeScript 패턴
- `strict: true` 준수 — any 타입 사용 금지
```

**수정 후:**
```markdown
## 코딩 규칙
### TypeScript 패턴
- `strict: true` 준수 — any 타입 사용 금지

### 테스트 의무 규칙 (추가!)
- 모든 함수에 대해 단위 테스트를 먼저 작성 (TDD)
- 테스트 파일: `__tests__/` 폴더에 생성
- 테스트 프레임워크: vitest
- 테스트 없이 코드를 submit_for_review하지 말 것
- add_activity에 테스트 결과를 반드시 포함
```

이 규칙을 추가한 후 에이전트를 스폰하면:
- 에이전트가 `get_agent_skill("backend")`로 이 파일을 읽고
- 코드를 작성하기 전에 테스트를 먼저 작성합니다
- `add_activity`에 "테스트 통과: 3/3"같은 기록이 남습니다

**(실습) 다른 스택으로 커스터마이징**

Django + Vue.js 프로젝트를 하고 싶다면?

```markdown
## 기술 스택
- Python 3.11+ (Django 5.x)
- Django REST Framework
- PostgreSQL
- pytest + factory_boy

## 코딩 규칙
### Django 패턴
- CBV(Class-Based View) 우선
```

기술 스택 섹션만 바꾸면 에이전트가 그에 맞게 코딩합니다.
React 대신 Vue를 쓰고 싶으면 frontend_agent.md의 기술 스택만 바꾸면 됩니다.

### 에이전트가 스킬을 로드하는 코드 (3분)

화면: VS Code — tools.ts의 get_agent_skill

실제로 스킬 파일이 어떻게 로드되는지 코드를 봅시다:

```typescript
// electron/mcp-server/tools.ts — get_agent_skill 도구

server.tool(
  'get_agent_skill',
  'Get skill/instruction file for a given agent role.',
  { role: z.string().describe('Agent role name') },
  async ({ role }) => {
    const safeRole = role.replace(/[^a-zA-Z0-9_]/g, '');
    const skillsDir = path.resolve(SKILLS_DIR);

    // backend_agent.md 또는 backend.md를 찾음
    for (const filename of [`${safeRole}_agent.md`, `${safeRole}.md`]) {
      const filePath = path.resolve(skillsDir, filename);
      if (!filePath.startsWith(skillsDir)) continue; // path traversal 방지
      if (fs.existsSync(filePath)) {
        return text(fs.readFileSync(filePath, 'utf-8'));
      }
    }

    return text(`Error: No skill file found for role '${role}'.`);
  },
);
```

간단하죠?
1. role 이름을 받아서 (`"backend"`)
2. `skills/backend_agent.md` 파일을 찾고
3. 없으면 `skills/backend.md`를 찾고
4. 파일 내용을 그대로 반환

에이전트가 이 내용을 받아서 자기 행동 규칙으로 삼습니다.

> **보안 참고**: `filePath.startsWith(skillsDir)` 체크가 있어서
> path traversal 공격(../../etc/passwd 같은)을 방지합니다.

## 정리 (2분)

에이전트 스킬 파일 핵심:

| 섹션 | 역할 | 왜 필요한가 |
|------|------|-----------|
| 역할 선언 | "너는 ~에이전트다" | AI에게 정체성 부여 |
| 기술 스택 | 사용할 언어/프레임워크 | 기술 선택 혼란 방지 |
| MCP 도구 | 사용 가능한 도구 목록 | 도구 활용 가이드 |
| 코딩 규칙 | 코드 컨벤션 | 코드 품질 보장 |
| Scope 규칙 | 수정 가능한 파일 범위 | 에이전트 간 충돌 방지 |
| 자율 작업 루프 | 작업 순서 | 자율 동작의 핵심 |

기억할 것:
- 스킬 파일은 **Markdown**입니다 — 누구나 수정할 수 있습니다
- "테스트 의무"같은 규칙을 한 줄 추가하면 에이전트 행동이 바뀝니다
- 기술 스택을 바꾸면 에이전트가 다른 언어/프레임워크로 코딩합니다
