# 통합 리뷰 + 스프린트 마무리

> 모듈 5 · 섹션 5-6 · 약 20분
> 관련: [[5-5_상황별대응_PM개입]] | [[6-1_모델별강점_Claude_Codex_Antigravity]]

---

## 이 강의에서 다루는 것

- **학습목표:** 보드의 전 카드를 DONE으로 정리하고, 에이전트 통계로 한 스프린트를 복기하며 졸업 작품 ReachWave의 1차 완성을 매듭짓는다.
- **시연할 마블로 화면·기능:** 보드 탭(전 카드 DONE + 완료 배너) + 에이전트/통계 뷰.
- **진행할 프로젝트 단계:** **P3 1차 완성(로컬 동작)**.
- **핵심 메시지:** "보드가 비면 한 스프린트가 끝난다. 다음은 배포다."

---

## 도입 — 보드를 비운다 (2분)

축하합니다. ReachWave 1차 스프린트가 끝났습니다.

> 화면: 보드 탭 — 22개 카드가 모두 DONE 컬럼, 완료 배너

모듈 5 전체를 돌아보면:

- **5-1** 페르소나·가치 가설·PRD·태스크 분해(`/tf-analyze`)
- **5-2** 22 태스크 일괄 등록 + 이종 팀 스폰
- **5-3** Sprint 1 — 백엔드 라이브 빌딩(DB·OAuth·LLM·5톤·결제)
- **5-4** Sprint 2 — 프론트 병렬 + 통합
- **5-5** 상황별 대응 — PM이 개입하는 순간

이 전체 과정에서 여러분이 직접 코딩한 부분은 **없습니다.** PM으로서 기획·관찰·리뷰·의사결정만 했죠. "보드가 비었다"는 건 한 스프린트가 끝났다는 뜻입니다.

## 본문

### 1. 기능 최종 점검 (4분)

> 화면: 브라우저 — ReachWave 각 기능 빠른 시연

```
docker compose up -d --build   # 아직 안 떠 있으면
```

최종 점검 체크리스트:

| 기능                | 상태 | 비고                          |
| ------------------- | ---- | ----------------------------- |
| 회원가입/로그인     | OK   | Email + Google OAuth          |
| CSV 임포트          | OK   | 검증 + 필수 컬럼 안내         |
| 회사·직책 분석      | OK   | 서비스 LLM 단일 호출          |
| 5톤 메일 생성       | OK   | `asyncio.gather` 병렬 ≈ 8초   |
| 발송·예약           | OK   | Redis 큐 + 시간대 분산        |
| A/B 응답률 대시보드 | OK   | 톤별 막대 차트                |
| 토스 결제           | OK   | 테스트키 + webhook idempotent |
| Docker 통합         | OK   | `docker compose up`           |
| E2E/유닛 테스트     | OK   | 전부 통과                     |

모든 기능이 로컬에서 정상 동작합니다.

### 2. 에이전트 통계 복기 (6분)

한 스프린트의 흐름을 숫자로 돌아봅니다.

> 화면: 에이전트/통계 뷰

```
/tf-stats
```

```
📊 Project Statistics: ReachWave  (예시 수치)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Summary
  Total tasks     : 22
  Completed       : 22 (100%)
  Rejected/Rework : 4 (피드백 후 수정)
  Failed/Retried  : 1 (API 키 오류)

Agent Performance
  backend-claude  : 7 tasks  (인증·LLM·결제 등 핵심 로직)
  backend-codex   : 6 tasks  (DB·CSV·큐·Docker)
  frontend-codex  : 6 tasks  (UI 6종)
  test-codex      : 3 tasks  (E2E·유닛·보안)

Timeline (예시)
  Active coding   : ~2h
  Review/Feedback : ~45m   ← 전체의 약 30%

Files generated (예시)
  Backend : ~24 files · Frontend : ~28 files · Tests : ~6 files
```

> ⚠️ 위 수치는 **예시**입니다 — 실제는 매번 다릅니다. 핵심은 절대 숫자가 아니라 **패턴**이에요.

여기서 두 가지를 짚습니다.

- **모델 분담이 그대로 통계에 찍힙니다.** Claude는 견고함이 필요한 7개(인증·LLM·결제·집계), Codex는 양 많은 보일러플레이트·UI·테스트 15개. 한 모델로 다 밀었다면 시간·비용 모두 손해였을 겁니다.
- **Review/Feedback이 전체의 약 30%.** PM의 리뷰 시간이 프로젝트의 상당 부분을 차지합니다. 코딩을 안 한다고 PM이 한가한 게 아니에요 — 게이트를 지키는 게 일입니다.

> 비용·토큰을 **수치로** 들여다보는 사용량 탭과 절감 전략은 모듈 6([[6-4_사용량탭_비용추적최적화]])에서 본격적으로 다룹니다. 여기서는 "분담이 통계로 보인다"는 감각만 잡으면 됩니다.

### 3. 결과물 요약 + 다음 (4분)

> 화면: 보드 탭 — DONE 22장 + "Sprint 1 Complete" 배너

지금 손에 쥔 것:

- **동작하는 SaaS** — 회원가입부터 결제까지 한 흐름이 로컬에서 도는 ReachWave.
- **이종 팀 운영 경험** — Claude + Codex(+선택 Antigravity)를 한 보드에서 역할로 나눠 굴려봤다.
- **PM 근육** — 기획(PRD) → 분해 → 병렬 빌딩 → 리뷰 게이트 → 돌발 대응까지의 한 사이클.

아직 안 한 것 — **배포**입니다. 지금 ReachWave는 내 노트북에서만 돕니다. 이걸 워크트리에서 main으로 통합하고, 클라우드(Cloud Run)에 올리고, 도메인·CI/CD·랜딩페이지까지 붙여 **진짜 출시**하는 건 모듈 7의 일이에요.

> **[설명보드: 5-6 한 스프린트의 닫힘]** — Excalidraw (후속 제작)
> 📊 보드 파일: [assets/5-6_한_스프린트의_닫힘.excalidraw](assets/5-6_한_스프린트의_닫힘.excalidraw) — Excalidraw 에디터/excalidraw.com 에서 열기
>
> - 왼쪽: 22장 TODO 카드 → 오른쪽: 22장 DONE + 완료 배너(보드가 비는 모션).
> - 아래 띠: 기획 → 분해 → 병렬 빌딩 → 리뷰 → 대응 → **(다음) 배포** 화살표, 마지막만 점선.
> - 캡션: "보드가 비면 한 스프린트 끝. 다음은 배포."

## 정리 (1분)

1. **22/22 DONE** — ReachWave 1차 완성(로컬 동작). 졸업 작품 완주.
2. **기능 최종 점검** — 회원가입~결제~A/B 대시보드까지 한 흐름이 돈다.
3. **통계 복기** — 모델 분담이 숫자로 보이고, 리뷰가 전체의 ~30%. 수치는 예시일 뿐 패턴이 핵심.
4. **다음은 배포** — 워크트리 통합 → Cloud Run → CI/CD → 런칭(모듈 7).

졸업 작품을 완주했습니다. 이제 여러분은 마블로로 **처음부터 끝까지** SaaS를 만들 수 있어요. 다음 모듈에서는 한 걸음 물러서서, 이 팀을 더 잘 굴리는 법 — 모델별 강점·자동 배정·사용량/비용 — 을 깊게 봅니다.
