# 랜딩페이지 + 런칭 체크리스트

> 모듈 7 · 섹션 7-4 · 약 40분
> 관련: [[7-3_크론잡_CICD_자동화]] | [[8-1_일상운영_멀티프로젝트]]

---

## 이 강의에서 다루는 것

- **학습목표:** ReachWave의 **앞문(랜딩페이지)**을 에이전트로 빌드하고(디자인→코드), 반응형·SEO를 점검한 뒤, **보드에 런칭 체크리스트를 병렬 카드**로 풀어 도메인·SSL·모니터링·법적 페이지까지 마무리한다. **P3 런칭 준비 완료.**
- **시연할 마블로 화면·기능:** **보드 탭**(런칭 체크리스트 병렬 카드) + **브라우저 미리보기**.
- **진행할 프로젝트 단계:** **P3 런칭 준비 완료** — 코드·배포·자동화에 이어 출시 채비까지.
- **핵심 메시지:** "**코드가 끝이 아니라 출시가 끝.**"

---

## 도입 — 코드 배포 ≠ 제품 런칭 (4분)

> 화면: 슬라이드 — "서버에 올렸다 ≠ 사용자가 쓴다"

여기까지 정말 멀리 왔습니다. ReachWave를 만들고([[5-6_통합리뷰_스프린트마무리|M5]]), main에 모으고([[7-1_워크트리통합_main머지]]), 클라우드에 배포하고([[7-2_GCP_CloudRun_배포]]), 자동화까지 걸었죠([[7-3_크론잡_CICD_자동화]]). 그럼 런칭 끝? **아닙니다.**

**코드 배포**와 **제품 런칭**은 다릅니다. 배포는 서버에 코드를 올리는 기술 행위, 런칭은 사용자가 처음 만나 "이게 뭔데? 왜 써야 해?"에 3초 안에 답을 얻고 가입까지 가는 **전체 경험**입니다. SaaS 랜딩페이지는 첫 화면에서 이탈이 갈려요 — 가치 전달에 실패하면 10명 중 7명이 떠납니다.

그래서 두 가지를 합니다 — **(1) 사용자가 들어올 앞문(랜딩페이지)**, **(2) 출시 전 빠뜨리면 안 되는 것들(런칭 체크리스트)**. 그리고 체크리스트는 마블로답게 **에이전트 여러 명이 병렬로** 처리합니다.

## 본문

### 1. 랜딩페이지 구조 설계 (6분)

> 화면: 슬라이드 — SaaS 랜딩페이지 레이아웃

코드를 짜기 전에 구조부터. SaaS 랜딩페이지에는 검증된 패턴이 있어요.

```
┌──────────────────────────────┐
│  Nav      로고 + 메뉴 + 로그인  │
├──────────────────────────────┤
│  Hero    "콜드메일, 5가지 톤으로  │ ← 3초 안에 핵심 가치
│           AI가 자동 작성"         │
│          [무료로 시작하기]        │
├──────────────────────────────┤
│  Features  리드 분석 · 5톤 생성   │ ← 주요 기능 3~4개
│            · A/B 자동 실험        │
├──────────────────────────────┤
│  How It Works  CSV 업로드 →      │ ← 3단계 사용법
│                AI 분석 → 발송     │
├──────────────────────────────┤
│  Pricing   Free / Pro / Team    │ ← 가격표
├──────────────────────────────┤
│  CTA       "지금 시작하세요"      │ ← 최종 행동 유도
├──────────────────────────────┤
│  Footer  링크 · 개인정보 · 약관   │ ← 법적 고지
└──────────────────────────────┘
```

| 섹션         | 목적                | 전환 기여                      |
| ------------ | ------------------- | ------------------------------ |
| Hero         | 3초 안에 가치 전달  | 가장 중요 — 여기서 이탈이 갈림 |
| Features     | "이게 뭘 해주는데?" | 관심 유지                      |
| How It Works | "어떻게 쓰는 거야?" | 사용 장벽 낮춤                 |
| Pricing      | "얼마야?"           | 구매 의사 결정                 |
| CTA          | "지금 하자!"        | 최종 전환                      |

ReachWave의 핵심 가치(리드 → AI 분석 → 5톤 콜드메일 → A/B)를 Hero·Features·How It Works에 그대로 녹입니다.

### 2. 디자인 → 코드: 에이전트로 빌드 (12분)

> 화면: 마블로 오케스트레이터 → 보드 → 코드 탭

랜딩페이지를 코드로 만드는 길은 두 가지입니다. 상황에 맞게 고르세요.

**경로 A — 디자인 도구(예: Stitch MCP)가 가용한 경우.**
Figma 등의 디자인을 코드로 변환하는 MCP가 하네스에 연결돼 있으면, 에이전트가 **디자인 토큰(색·타이포·간격)을 읽어 Next.js 컴포넌트로** 변환합니다. 디자이너의 시안이 있을 때 간극을 메워주는 길이에요.

**경로 B — 디자인 도구 없이 에이전트가 직접 구현(기본).**
시안이 없거나 MCP가 없어도 전혀 문제없습니다. **검증된 SaaS 랜딩 패턴**을 말로 주면 에이전트가 Tailwind로 바로 짭니다. 강의의 기본 경로는 B예요.

> 💡 예전 강의는 Stitch MCP를 **필수**로 깔고 갔지만, 지금은 **선택**입니다. 디자인 도구는 "있으면 좋은" 가속기일 뿐, 랜딩페이지의 본질은 **구조와 카피**예요. 도구에 막혀서 못 만드는 일은 없게, B를 기본으로 둡니다.

**(실습)** 오케스트레이터에 요청합니다(경로 B 기준).

```
ReachWave 랜딩페이지를 만들어줘. Next.js App Router + Tailwind, 반응형(모바일 우선).
섹션:
1. Hero — "콜드메일, 5가지 톤으로 AI가 자동 작성" + CTA 2개(무료 시작 / 데모 보기)
2. Features — 리드 분석 / 5톤 생성 / A/B 자동 실험
3. How It Works — CSV 업로드 → AI 분석 → 발송 (3단계)
4. Pricing — Free / Pro / Team (3단계)
5. CTA + Footer (개인정보·약관 링크 자리 포함)
6. SEO 메타태그(title·description·OpenGraph)
frontend 역할로 컴포넌트 단위 태스크로 쪼개서 진행해줘.
```

오케스트레이터가 보드에 태스크를 풉니다.

```
보드 — 랜딩페이지
  TASK  Hero 섹션          [frontend]
  TASK  Features 섹션      [frontend]
  TASK  How It Works       [frontend]
  TASK  Pricing 테이블     [frontend]
  TASK  CTA + Footer       [frontend]
  TASK  페이지 조합 + SEO   [frontend]
```

레인에서 작업을 관찰하고, REVIEW로 오면 코드 탭 diff로 검토합니다([[3-4_리뷰_워크트리머지_완료|익숙한 흐름]]). 가격표 같은 데이터는 에이전트가 만든 뒤 본인 정책에 맞게 한 번 다듬으면 돼요(예: Pro/Team 금액·기능 목록).

### 3. 반응형 + SEO 점검 (8분)

> 화면: 브라우저 미리보기 + DevTools 모바일 뷰

**(실습)** 브라우저에서 직접 확인합니다. 코드 탭/`npm run dev`로 띄운 뒤 DevTools(`F12` → 기기 툴바 `Ctrl/Cmd+Shift+M`)로 봅니다.

**반응형 체크포인트:**

- [ ] Hero 텍스트가 모바일에서 줄바꿈이 자연스러운가
- [ ] Features·Pricing 카드가 모바일에서 세로로 쌓이는가
- [ ] CTA 버튼 터치 영역이 충분한가(최소 44×44px)
- [ ] 이미지가 모바일에서 잘리지 않는가

문제가 보이면 에이전트에게 바로 고치게 합니다 — 예: "Pricing 카드가 768px 미만에서 겹쳐요. 세로 스택으로 바꿔줘."

**SEO 메타태그.** 검색·공유에서 ReachWave가 제대로 보이려면 메타데이터가 필요해요.

```tsx
// app/layout.tsx
import type { Metadata } from "next";

export const metadata: Metadata = {
  title: "ReachWave — 콜드메일을 5가지 톤으로, AI가 자동 작성",
  description:
    "리드 CSV 한 장이면 충분합니다. ReachWave가 회사·직책을 분석해 5가지 톤의 콜드메일을 만들고 A/B로 실험합니다.",
  openGraph: {
    title: "ReachWave",
    description: "콜드메일, 5가지 톤으로 AI가 자동 작성.",
    images: ["/og-image.png"], // 1200×630
    locale: "ko_KR",
    type: "website",
  },
};
```

**OG 이미지**(1200×630)는 링크를 공유했을 때 뜨는 썸네일입니다. 서비스명과 핵심 가치가 한눈에 보이게 만드세요.

### 4. 보드에 런칭 체크리스트 — 병렬 카드 (9분)

> 화면: 보드 탭 — 런칭 체크리스트 4카드가 동시에 IN_PROGRESS

랜딩페이지가 섰으니, 출시 전 빠뜨리면 안 되는 것들을 처리합니다. 이게 꽤 많아요 — 사람이 하나씩 하면 반나절입니다. **마블로답게 에이전트 여러 명에게 병렬로** 맡깁니다.

**(실습)** 오케스트레이터에 입력합니다.

```
ReachWave 런칭 준비를 병렬로 처리해줘. 카드 4개로 나눠 동시에:
1. 커스텀 도메인 + SSL — Cloud Run 도메인 매핑 절차 정리 + DNS 레코드 안내
2. 에러 모니터링 — Sentry(Next.js + FastAPI) 연동, 알림 설정
3. 분석(Analytics) — GA4 연동 + 핵심 이벤트(가입 클릭/가격 도달) 트래킹
4. 법적 페이지 — 개인정보 처리방침 + 이용약관(한국어, 한국법 기준) 페이지 + Footer 링크
```

보드에서 4개 카드가 **동시에** 도는 걸 봅니다. Agents 탭에서 각 에이전트 터미널을 전환하며 관찰할 수 있어요.

```
보드 — 런칭 체크리스트
  TASK  도메인 + SSL        → Agent (Claude)   IN_PROGRESS
  TASK  Sentry 모니터링     → Agent (Codex)    IN_PROGRESS
  TASK  GA4 연동            → Agent (Claude)   IN_PROGRESS
  TASK  법적 페이지         → Agent (Claude)   IN_PROGRESS
        ⋯ 약 10분 후 ⋯       → 전부 REVIEW → 머지 → DONE
```

각 카드의 핵심만 짚습니다.

**① 도메인 + SSL.** `reachwave-api-xxxx.run.app`보다 `reachwave.app` 같은 도메인이 신뢰를 줍니다. Cloud Run 도메인 매핑 + DNS의 CNAME 한 줄이면 끝이고, **SSL은 Google이 자동 발급**합니다(별도 설정 불필요 — Cloud Run의 장점).

**② 에러 모니터링(Sentry).** 프로덕션 에러를 모르고 있으면 사용자가 조용히 떠납니다. Next.js·FastAPI 양쪽에 SDK를 붙이고, 에러 발생 시 Slack/이메일 알림을 겁니다. 7-3에서 만든 CI/CD와 묶으면 "어느 배포(릴리스)에서 에러가 났나"까지 추적돼요.

**③ 분석(GA4).** 사용자가 랜딩에서 뭘 하는지 알아야 개선합니다. page_view, **가입 버튼 클릭**, 가격표 도달(스크롤 깊이) 같은 핵심 이벤트를 추적하세요. 시작은 GA4로 충분합니다.

**④ 법적 페이지.** 한국에서 서비스를 운영하면 **개인정보 처리방침**이 개인정보보호법상 의무입니다(없으면 과태료 대상). 이용약관도 같이. 에이전트가 초안을 잘 잡지만 — **법적 문서는 반드시 전문가 검토를 받으세요.** AI 초안을 그대로 쓰는 건 위험합니다.

> 💡 이 4개는 서로 의존이 없어서 병렬에 딱 맞아요. 사람이 30분 넘게 걸릴 일을 에이전트 4명이 10분에 끝냅니다 — **에이전트 군단의 힘**이 런칭 잡일에서도 그대로 발휘되죠. 끝나면 7-1에서 배운 흐름으로 리뷰·머지하면 됩니다.

## 정리 (1분)

1. **배포 ≠ 런칭.** 서버에 올린 것과 사용자가 쓰는 것은 다르다. 앞문(랜딩)과 안전장치(체크리스트)까지가 런칭.
2. **랜딩은 구조와 카피.** 검증된 섹션 패턴을 에이전트에게 주고 빌드. 디자인 도구(Stitch 등)는 **선택**, 없으면 에이전트가 직접 구현(기본).
3. **반응형·SEO 점검.** 모바일 뷰 4체크 + 메타태그·OG 이미지.
4. **런칭 체크리스트는 병렬 카드.** 도메인/SSL·모니터링·분석·법적 페이지를 에이전트 4명이 동시에. 법적 문서는 전문가 검토 필수.
5. **P3 런칭 준비 완료.** 코드·배포·자동화에 이어 출시 채비까지 끝.

**모듈 7 끝 — P3가 프로덕션이 됐습니다.** 자연어 한 줄로 시작한 SaaS가 통합·배포·자동화·런칭까지 왔어요. 다음 모듈에서는 이렇게 만든 것을 **매일 운영하고, 반복을 자동화하고(Ralph), 더 확장**하는 법을 다룹니다.
