# 프로젝트 연결 + 워크트리 체크

> 모듈 2 · 섹션 2-4 · 약 25분
> 관련: [[2-3_설정탭_BYOK_프라이버시]] | [[3-1_오케에게_자연어요청]]

---

## 이 레슨의 4요소

- **학습목표:** 작업할 폴더/리포를 마블로에 연결하고 오케스트레이터를 띄운다. 워크트리 탭을 읽고, "에이전트마다 격리된 워크트리"라는 핵심 안전장치를 이해한다.
- **시연할 마블로 화면·기능:** 폴더/리포 선택 → 오케스트레이터 자동 실행 → 워크트리 탭(WorktreeTab) — 상태 pill(🟢 머지 가능 / 🟡 뒤처짐 / ⚠️ stale / 🔴 충돌 / ⚪ 작업중), 액션(Rebase/Merge/Resolve/Open/Delete), 완료 이력.
- **진행할 프로젝트 단계:** P1 리포 준비.
- **핵심 메시지:** "에이전트마다 격리된 워크트리에서 일하므로 서로 충돌하지 않는다."

---

## 도입 (2분)

설치·인증·설정을 끝냈으니, 이제 **실제로 일할 프로젝트**를 마블로에 물립니다. 그리고 마블로가 여러 에이전트를 동시에 굴리면서도 코드가 안 엉키게 해주는 핵심 장치 — **워크트리** — 를 처음 만납니다.

이 레슨이 끝나면, 다음 모듈(P1: 할 일 웹앱)에서 바로 첫 풀사이클을 돌릴 준비가 됩니다.

---

## 본문

### 1. 폴더/리포 연결 (4분)

화면: 마블로 — 프로젝트 열기/연결

마블로에 작업 폴더를 연결합니다. 두 가지 경우가 있어요.

- **이미 있는 리포** — 기존 Git 저장소 폴더를 선택.
- **새 프로젝트** — 빈 폴더를 선택(나중에 에이전트가 `git init`부터 시작).

**(실습) 프로젝트 연결**

1. 프로젝트 열기에서 폴더 선택 버튼(📁)을 누른다.
2. P1 실습용 폴더를 고른다(예: `~/projects/todo-app`). 비어 있어도 됩니다.
3. 연결을 확정한다.

> 💡 P1(모듈 3)은 프론트 단독 **할 일(Todo) 웹앱**이라 빈 폴더로 시작해도 충분합니다. 깃 히스토리가 있는 리포면 마블로가 현재 브랜치를 기준(base)으로 잡아요.

### 2. 오케스트레이터 자동 실행 (3분)

화면: 마블로 하단 — 오케스트레이터 PTY 패널

프로젝트를 연결하면 마블로가 하단의 **오케스트레이터 PTY 패널**에 오케스트레이터(팀리더 역할의 Claude Code)를 자동으로 띄웁니다. 이게 당신이 자연어로 말을 거는 창구예요.

여기서 MCP 연결도 자동입니다 — Marblo MCP가 이 세션에 붙어서, 오케스트레이터가 보드 카드를 만들고 에이전트를 스폰할 수 있게 됩니다. 당신이 `~/.claude.json`을 만질 일은 없어요(2-1에서 본 그대로).

연결 확인은 간단합니다. 오케 패널에 이렇게 쳐보세요:

```
get_all_tasks 를 호출해줘
```

"태스크 없음"이 나오면 정상 — 아직 아무 작업도 안 만들었으니까요. 에러가 나면 프로젝트 연결을 다시 확인합니다.

### 3. 워크트리 탭 진입 (3분)

화면: 마블로 상단 탭바 → 워크트리 탭

상단 탭바에서 **워크트리(Worktree)** 탭을 엽니다. 지금은 비어 있거나 메인 워크트리만 보일 거예요. 본격적으로 채워지는 건 에이전트가 일을 시작하면서부터입니다.

**왜 워크트리인가?** 에이전트 세 명이 같은 폴더에서 동시에 파일을 고치면 서로 덮어쓰고 충돌합니다. 그래서 마블로는 **에이전트마다 별도의 Git 워크트리(= 같은 저장소의 격리된 작업 사본)와 전용 브랜치**를 줍니다. 각자 자기 방에서 일하고, 끝나면 따로 합치는 거예요.

[설명보드: "워크트리 격리" 개념도]
📊 보드 파일: [assets/2-4_워크트리_격리_개념도.excalidraw](assets/2-4_워크트리_격리_개념도.excalidraw) — Excalidraw 에디터/excalidraw.com 에서 열기

- 가운데 큰 원 "main 저장소".
- 거기서 가지 3개가 뻗어 각각 작은 상자 "워크트리 A(backend) / B(frontend) / C(test)" — 각 상자 안에 에이전트 아이콘.
- 각 가지에 브랜치 라벨, 상자 모서리에 상태 pill(🟢/🟡).
- 하단 카피: "각자 자기 방에서 → 끝나면 main으로 머지. 동시에 일해도 안 엉킨다."

### 4. 상태 pill 읽기 (5분)

화면: 워크트리 탭 — 상태 필터 드롭다운 + 행별 pill

각 워크트리 행에는 **상태 pill**이 붙습니다. 색·이모지로 한눈에 읽혀요. 상단 필터 드롭다운에도 같은 항목이 있습니다.

| Pill             | 뜻        | 무슨 뜻이냐면                            |
| ---------------- | --------- | ---------------------------------------- |
| 🟢 **머지 가능** | mergeable | base와 깨끗이 합쳐짐. 머지해도 됨.       |
| 🟡 **뒤처짐**    | behind    | main이 그새 앞서감. Rebase로 따라잡아야. |
| ⚠️ **stale**     | warning   | 오래 방치됨. 정리 후보.                  |
| 🔴 **충돌**      | danger    | 충돌 발생. 사람 또는 리졸버가 풀어야.    |
| ⚪ **작업중**    | idle      | 에이전트가 아직 작업 중.                 |

행에는 pill 말고도 정보가 더 있어요 — 태스크 ID(또는 `(ad-hoc)`), 에이전트 ID, 브랜치명(파란 모노스페이스), 추가/삭제 라인(초록 +N / 빨강 −N), 그리고 앞섬/뒤처짐(▲ahead ▼behind)·충돌 요약("N conflicts" / "rebase 필요" / "충돌없음").

> 💡 색이 곧 다음 행동입니다. 🟢이면 합치고, 🟡이면 Rebase, 🔴이면 풀고, ⚠️이면 정리. 이 신호등만 읽을 줄 알면 병렬 작업이 무섭지 않아요.

### 5. 워크트리 액션 (4분)

화면: 워크트리 행 — 액션 버튼들

각 워크트리에서 할 수 있는 동작은 다섯 가지입니다.

- **Rebase** — base(main)의 최신을 끌어와 따라잡기. 🟡 뒤처짐일 때.
- **Merge** — squash로 main에 합치기. 🟢 머지 가능일 때만 활성.
- **Resolve** — 리졸버 에이전트를 스폰해 충돌 해결. 🔴일 때.
- **Open** — 코드 탭에서 이 워크트리를 열어 diff 확인.
- **Delete** — 워크트리 + 브랜치 정리.

지금은 누를 게 없어요(에이전트가 아직 일을 안 했으니까). 실제 머지·충돌 해결은 모듈 3·4에서 직접 합니다. 여기서는 "어떤 버튼이 어떤 상태에서 켜지는지"만 눈에 익히면 됩니다.

화면: 워크트리 탭 — 완료 이력 / 일괄 cleanup

- **📜 완료 이력** — 지금까지 머지된 워크트리의 감사 추적(프로젝트 / 태스크 ID / 브랜치 / 커밋 SHA / 시각 / 모드). 모드 배지는 🤖 **자동** 또는 🙂 **사람**으로, 누가 합쳤는지 남습니다.
- **⚠️ 정리 가능 일괄 cleanup** — 머지됐거나 오래 방치된 워크트리를 한 번에 제거.

팀 작업의 "누가 언제 무엇을 합쳤나"가 전부 기록으로 남는다는 점 — 이게 마블로가 신뢰할 수 있는 이유 중 하나예요.

### 6. 실습 — P1 리포 준비 확인 (2분)

화면: 워크트리 탭 + 오케 패널

**(실습) 셋업 마무리 점검**

1. 프로젝트가 연결되고 오케 패널이 떠 있는지.
2. `get_all_tasks` → "태스크 없음"(정상).
3. 워크트리 탭이 열리고 메인 워크트리가 보이는지.
4. 상태 pill 5종의 의미를 말로 설명할 수 있는지.

여기까지면 **빈 맥북 0→1 셋업 완료**입니다. 다음 모듈에서 자연어 한 줄로 첫 카드를 만들고, 이 워크트리들이 실제로 채워지는 걸 봅니다.

## 정리 (2분)

화면: 체크리스트 슬라이드

연결·워크트리 체크리스트:

- [ ] 작업 폴더/리포 연결
- [ ] 오케스트레이터 자동 실행 + MCP 연결(`get_all_tasks` 성공)
- [ ] 워크트리 탭 진입
- [ ] 상태 pill 5종(🟢/🟡/⚠️/🔴/⚪) 의미 이해
- [ ] 액션 5종(Rebase/Merge/Resolve/Open/Delete) 위치 파악

오늘 기억할 것:

1. **프로젝트 연결 = 오케 자동 실행 + MCP 자동 연결.** 손으로 설정할 게 없다.
2. **에이전트마다 격리된 워크트리.** 동시에 일해도 서로 안 엉킨다.
3. **상태 pill은 신호등.** 색이 곧 다음 행동(합치기/Rebase/풀기/정리).

**모듈 2 끝 — 셋업 0→1 완료!** 앱·CLI·키·연결·워크트리까지 전부 준비됐습니다. 이제 모듈 3에서 자연어 한 줄로 첫 풀사이클을 돌립니다.
