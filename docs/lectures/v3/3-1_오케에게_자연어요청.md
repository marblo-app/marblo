# 오케스트레이터에게 자연어로 요청

> 모듈 3 · 섹션 3-1 · 약 20분
> 관련: [[2-4_프로젝트연결_워크트리체크]] | [[3-2_태스크분해_보드카드]]

---

## 이 레슨의 4요소

- **학습목표:** 하단 오케스트레이터 PTY에 **평어(자연어)로** 요청해 첫 작업을 시작한다. 명령어를 외우는 게 아니라 "말로 시키는" 방식을 몸에 익힌다.
- **시연할 마블로 화면·기능:** 하단 **오케스트레이터 PTY 패널** — 자연어 입력 → `/tf-start`(또는 `/tf-analyze`) 흐름 → 소크라테스식 질문 → PRD·태스크 윤곽.
- **진행할 프로젝트 단계:** **P1 시작** — 할 일(Todo) 웹앱(프론트 단독·localStorage).
- **핵심 메시지:** "명령어를 외울 필요 없다. **말로** 시킨다."

---

## 도입 (3분)

모듈 2까지 끝내고 나면, 빈 맥북이 **셋업 0→1 완료** 상태가 됩니다. 앱·CLI·키·프로젝트 연결·워크트리까지 전부 준비됐죠. 그리고 [[1-4_큰그림_파이프라인]]에서 머릿속에 그렸던 그 흐름 — **오케 → 보드 → 레인 → 워크트리 → 머지** — 이제 그걸 **직접 손으로** 한 바퀴 돌립니다.

가장 작은 프로젝트로 시작해요. **할 일(Todo) 웹앱**입니다. 프론트엔드 단독, 데이터는 브라우저 `localStorage`에 저장하는 미니 앱이에요. 백엔드도, 외부 API도 없습니다. 목적은 단 하나 — **"자연어 한 줄 → DONE → 머지"** 전체 루프를 처음부터 끝까지 한 번 체감하는 것.

그리고 이번 레슨에서 배울 건 더 단순합니다. **그냥 말을 거는 것.**

화면: 마블로 — 하단 오케스트레이터 PTY 패널(빈 상태, 커서 깜빡임)

---

## 본문

### 1. 오케스트레이터는 "말을 거는 창구"다 (4분)

화면: 마블로 하단 — 오케스트레이터 PTY 패널

프로젝트를 연결하면 마블로가 하단에 **오케스트레이터 PTY 패널**을 자동으로 띄웠던 거 기억하시죠([[2-4_프로젝트연결_워크트리체크]]). 여기 떠 있는 게 **오케스트레이터** — 팀리더 역할의 Claude Code입니다.

이 패널이 여러분의 **유일한 입력 창구**예요. 보드에서 카드를 직접 만들 필요도, 에이전트를 손으로 스폰할 필요도 없습니다. 그냥 **여기에 평소 말하듯 적으면** 됩니다.

> 💡 다른 코딩 도구는 "메뉴 → 새 작업 → 폼 입력 → 제출"을 거치죠. 마블로는 **말로 시킵니다.** 오케스트레이터가 알아서 보드 카드를 만들고, 에이전트를 띄우고, 워크트리를 준비해요.

### 2. 자연어 한 줄로 요청하기 (5분)

화면: 오케 패널 — 자연어 입력

**(실습) 오케스트레이터 패널에 그대로 입력해봅시다:**

```
localStorage로 동작하는 할 일 웹앱 만들어줘
```

이게 전부입니다. 슬래시도, 옵션도 없어요. 그냥 만들고 싶은 걸 **한 문장**으로 말하면 됩니다.

오케스트레이터는 이 한 줄을 받아서 "아, 새 프로젝트를 기획해서 태스크로 쪼개야겠구나"라고 판단하고, 내부적으로 **`/tf-start`(또는 `/tf-analyze`) 흐름**을 탑니다. 슬래시 스킬을 직접 칠 수도 있지만(아래 팁 참고), 외울 필요는 없어요 — 말로 하면 오케가 알아서 해당 스킬을 부릅니다.

> 💡 **슬래시로 직접 부르고 싶다면:** `/tf-start localStorage 할 일 웹앱` 처럼 칠 수도 있습니다. `/tf-start`는 기획(분석)→태스크 생성→에이전트 스폰까지 이어주는 진입 스킬이고, `/tf-analyze`는 "분석·태스크 분해"에 집중하는 스킬이에요. 입문 단계에선 **그냥 자연어**를 권합니다.

### 3. 소크라테스식 되묻기 — 오케가 빈칸을 채운다 (6분)

화면: 오케 패널 — 오케스트레이터가 되묻는 질문들

요청을 던지면 오케스트레이터가 바로 코드를 짜기 시작하지 않습니다. 먼저 **소크라테스식으로 되묻어요.** 모호한 부분을 채워서 더 좋은 결과를 내려는 거예요.

예를 들면 이런 질문들이 올라옵니다:

```
오케스트레이터:
  할 일 웹앱, 좋습니다. 몇 가지만 확인할게요.
  1. 핵심 기능은 무엇으로 할까요? (추가 / 완료 토글 / 삭제가 기본)
  2. 필터(전체·진행중·완료)나 정렬도 넣을까요?
  3. 스택은? — 프론트 단독이라 하셨으니 별도 빌드 없는
     순수 HTML/CSS/JS 한 세트를 제안합니다. 괜찮으세요?
```

여기서 여러분은 **PM**입니다. 짧게 답하면 돼요:

```
1. 추가/완료/삭제 기본으로. 2. 전체·진행중·완료 필터 넣어줘.
3. 순수 HTML/CSS/JS 좋아. localStorage에 저장되게.
```

이렇게 몇 마디 주고받으면 오케스트레이터가 머릿속 그림을 정리합니다. 그러고는 **PRD(요구사항 문서)** 를 만들고, 그걸 기준으로 **태스크를 분해**하기 시작해요.

화면: 오케 패널 — PRD 요약 + "이대로 태스크를 만들까요?" 확인 프롬프트

```
오케스트레이터:
  정리했습니다. 할 일 웹앱(프론트 단독, localStorage)
  - 추가/완료 토글/삭제
  - 필터: 전체 · 진행중 · 완료
  - 순수 HTML/CSS/JS (빌드 없음)

  태스크 3~4개로 분해해 보드에 올릴게요. 진행할까요?
```

"응, 진행해줘"라고 답하면 다음 레슨의 무대 — **보드** 가 열립니다.

> 💡 **답을 잘 모르겠으면?** "알아서 적당히 해줘"라고 해도 됩니다. 오케스트레이터가 합리적인 기본값으로 채워요. PM의 역할은 모든 답을 아는 게 아니라 **방향을 정해주는 것**입니다.

### 4. 왜 "말로" 시키는 게 핵심인가 (2분)

화면: 슬라이드 — "명령어 암기 ❌ / 의도 전달 ⭕"

지금 한 일을 보세요. 외운 명령어는 **없습니다.** 여러분이 한 건:

1. 만들고 싶은 걸 **한 문장**으로 말했고,
2. 오케가 되묻는 말에 **짧게 답**했을 뿐입니다.

이게 마블로의 핵심 사용법이에요. 복잡한 CLI 플래그도, 폼도 아니라 — **의도를 평어로 전달**하면 오케스트레이터가 그걸 실행 가능한 작업으로 번역합니다. 슬래시 스킬(`/tf-*`)은 그 번역을 빠르게 하는 단축키일 뿐, **외울 필요는 없어요.**

---

## 정리 (1분)

화면: 정리 슬라이드

1. **오케스트레이터 PTY 패널 = 유일한 입력 창구.** 보드·에이전트를 직접 만질 필요 없다.
2. **자연어 한 줄**로 시작한다: "localStorage로 동작하는 할 일 웹앱 만들어줘".
3. 오케가 **소크라테스식으로 되묻고** → PRD → 태스크 분해까지 이어준다. (`/tf-start`/`/tf-analyze`를 알아서 호출)
4. PM의 역할은 정답을 아는 게 아니라 **방향을 정해주는 것.**

요청을 던졌으니, 이제 그 한 줄이 **추적 가능한 카드**로 바뀌는 걸 봅니다.
