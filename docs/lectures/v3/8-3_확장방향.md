## 도입 (3분)

여러분, 지금까지 마블로 v3의 핵심 기능을 전부 다뤘습니다. 에이전트 스폰, 칸반 관리, 멀티모델, GCP 배포, 랜딩페이지, 운영 패턴, Ralph까지. 이 정도면 실무에서 바로 쓸 수 있는 수준이에요.

화면: 슬라이드 — "여기서 끝이 아닙니다"

하지만 마블로는 계속 발전하고 있고, 여러분이 직접 확장할 수 있는 영역도 많습니다. 이번 섹션에서는 **앞으로 어떤 방향으로 발전할 수 있는지** 큰 그림을 보여드리겠습니다.

## 본문 1: 새로운 에이전트 역할 (5분)

화면: 에이전트 역할 확장 다이어그램

지금까지 써본 에이전트 역할은 `backend`, `frontend`, `test` 정도였죠? 하지만 마블로는 역할을 자유롭게 정의할 수 있습니다.

### Data Agent

```
역할: data
작업: 데이터 파이프라인 구축, ETL, 분석 쿼리 작성
모델 추천: Gemini (대용량 데이터 컨텍스트에 강함)
```

```
사용 예시:
/tf-start 사용자 행동 데이터를 분석해서 주간 리텐션 리포트 생성해줘.
PostgreSQL에서 데이터 추출 → 판다스로 분석 → 차트 생성.
```

Data Agent는 SQL 쿼리 작성, 데이터 전처리, 시각화 코드 생성에 특화됩니다.

### Security Agent

```
역할: security
작업: 보안 취약점 스캔, 의존성 감사, 보안 패치 적용
모델 추천: Claude (안전성 판단에 강함)
```

```
사용 예시:
/tf-ralph 프로젝트의 보안 취약점을 스캔하고 수정해줘.
OWASP Top 10 기준으로 체크.
```

Security Agent는 코드의 보안 취약점(SQL Injection, XSS, CSRF 등)을 자동으로 탐지하고 수정합니다.

### Design Agent

```
역할: design
작업: UI/UX 개선 제안, 디자인 시스템 관리, Figma 연동
모델 추천: Claude (디자인 판단) + Stitch MCP
```

디자인 에이전트는 Stitch MCP와 결합해서 더욱 강력해집니다. Figma에서 디자인 변경이 감지되면 자동으로 코드를 업데이트하는 파이프라인을 만들 수 있어요.

### DevOps Agent

```
역할: devops
작업: 인프라 관리, 모니터링 설정, 스케일링 자동화
모델 추천: Claude Sonnet (인프라 코드에 적합한 균형)
```

Terraform, Docker Compose, CI/CD 파이프라인 관리를 전담하는 에이전트입니다.

## 본문 2: 마블로 커스터마이징 (5분)

화면: 마블로 설정 화면

### 커스텀 상태 추가

기본 칸반 상태는 `TODO → IN_PROGRESS → REVIEW → DONE`이지만, 프로젝트에 맞게 커스터마이징 가능합니다:

```
예시 1: QA 팀이 있는 경우
TODO → IN_PROGRESS → REVIEW → QA_TESTING → STAGING → DONE

예시 2: 디자인 프로세스 포함
DESIGN → TODO → IN_PROGRESS → DESIGN_REVIEW → CODE_REVIEW → DONE

예시 3: 법적 검토가 필요한 경우
TODO → IN_PROGRESS → LEGAL_REVIEW → TECH_REVIEW → DONE
```

마블로 설정에서 상태를 추가하면, 오케스트레이터가 새로운 상태를 인식하고 태스크를 적절히 이동시킵니다.

### 커스텀 플로우 노드

태스크 간의 워크플로우도 커스터마이징할 수 있습니다:

```
기본 플로우:
태스크 생성 → 에이전트 배정 → 작업 → 리뷰 → 완료

커스텀 플로우 예시:
태스크 생성 → 자동 우선순위 계산 → 에이전트 배정
→ 작업 → 자동 테스트 실행 → 리뷰
→ Slack 알림 → PM 승인 → 스테이징 배포 → 완료
```

화면: 플로우 에디터 — 노드를 드래그해서 연결하는 모습

이런 커스텀 플로우는 마블로 웹 앱의 프로젝트 설정에서 시각적으로 편집할 수 있습니다. 노드를 추가하고, 조건을 설정하고, 자동 트리거를 연결하는 방식이에요.

### 커스텀 MCP 도구 추가

마블로에 새로운 MCP 서버를 연결해서 에이전트의 능력을 확장할 수 있습니다:

```json
{
  "mcpServers": {
    "marblo": { "..." },
    "stitch": { "..." },
    "slack": {
      "command": "slack-mcp",
      "args": ["--token", "${SLACK_BOT_TOKEN}"]
    },
    "notion": {
      "command": "notion-mcp",
      "args": ["--api-key", "${NOTION_API_KEY}"]
    },
    "github": {
      "command": "github-mcp",
      "args": ["--token", "${GITHUB_TOKEN}"]
    }
  }
}
```

Slack MCP를 연결하면 에이전트가 작업 완료 시 자동으로 Slack 알림을 보낼 수 있고, Notion MCP를 연결하면 문서를 자동 생성할 수 있습니다.

## 본문 3: 엔터프라이즈 + 커뮤니티 (5분)

화면: 슬라이드 — 엔터프라이즈 기능

### 엔터프라이즈 플랜

개인이 아닌 팀/회사에서 마블로를 사용할 때:

```
개인 플랜:
- 프로젝트 3개
- 에이전트 5마리
- 개인용 칸반 보드

팀 플랜:
- 프로젝트 무제한
- 에이전트 20마리
- 팀 공유 칸반 보드
- 역할별 권한 관리

엔터프라이즈 플랜:
- 모든 팀 플랜 기능
- SSO (Single Sign-On)
- 온프레미스 배포 옵션
- 전담 기술 지원
- SLA 보장
- 커스텀 에이전트 역할 무제한
```

### 팀 협업 기능

```
시나리오: 3명의 개발자가 마블로로 협업

김개발 (프론트엔드):
- 자신의 에이전트 팀으로 UI 작업
- 칸반 보드에서 프론트엔드 태스크만 필터링

이개발 (백엔드):
- 자신의 에이전트 팀으로 API 작업
- 칸반 보드에서 백엔드 태스크만 필터링

박PM (프로젝트 매니저):
- 전체 보드 조회
- 태스크 우선순위 조정
- 리뷰 승인/거절
```

한 칸반 보드를 여러 사람이 공유하면서, 각자의 에이전트 팀은 독립적으로 운영됩니다.

### 커뮤니티 플러그인 생태계

화면: 플러그인 마켓플레이스 컨셉 화면

마블로 커뮤니티에서 만든 플러그인을 설치해서 기능을 확장할 수 있는 방향도 준비 중입니다:

```
인기 플러그인 예시:
- marblo-plugin-sentry     → Sentry 에러 자동 티켓 생성
- marblo-plugin-jira       → Jira 동기화
- marblo-plugin-figma      → Figma 변경 감지 → 자동 코드 업데이트
- marblo-plugin-slack      → 작업 완료 시 Slack 알림
- marblo-plugin-analytics  → 에이전트 성과 분석 대시보드
```

### 마블로 API

외부 시스템에서 마블로를 제어할 수 있는 REST API도 제공됩니다:

```bash
# 태스크 생성 API
curl -X POST https://api.marblo.ai/v1/tasks \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -d '{
    "project_id": "youtube-insight",
    "title": "새 기능 추가",
    "role": "backend",
    "priority": 2
  }'

# 프로젝트 상태 조회 API
curl https://api.marblo.ai/v1/projects/youtube-insight/status \
  -H "Authorization: Bearer YOUR_API_KEY"
```

이 API를 활용하면 CI/CD 파이프라인에서 자동으로 태스크를 생성하거나, 외부 대시보드에서 마블로 상태를 모니터링할 수 있습니다.

## 본문 4: 미래 — 자율 에이전트 협업 (4분)

화면: 슬라이드 — "PM 개입을 줄이는 방향"

### 현재: PM이 지휘

```
현재 워크플로우:
PM(사람) → 요구사항 입력 → 오케스트레이터 → 에이전트 → 리뷰 → PM 승인
```

PM(여러분)이 중간에 계속 개입합니다. 요구사항을 주고, 리뷰하고, 승인하고.

### 미래: 에이전트 간 자율 협업

```
미래 워크플로우:
PM(사람) → 큰 목표만 설정 → 오케스트레이터 → 에이전트들이 자율 협업
                                        ↑
                             에이전트가 서로 리뷰하고 피드백
                             문제 발생 시만 PM에게 에스컬레이션
```

예를 들어:
1. PM: "유료 결제 기능 추가해줘"
2. 오케스트레이터가 태스크 분해
3. Backend Agent가 Stripe 연동 코드 작성
4. **Test Agent가 자동으로 리뷰** → "웹훅 서명 검증이 빠져 있습니다"
5. Backend Agent가 수정
6. Test Agent가 재확인 → 승인
7. Frontend Agent가 결제 UI 작성
8. **Design Agent가 자동으로 UI 리뷰** → "버튼 대비가 WCAG AA를 충족하지 않습니다"
9. Frontend Agent가 수정
10. PM에게는 최종 결과만 보고

이게 **에이전트 간 자율 협업**입니다. PM의 개입을 최소화하면서도 품질은 유지되는 거죠. 물론 아직 초기 단계이고, 중요한 결정은 사람이 해야 합니다. 하지만 방향은 확실합니다 — **사람은 방향을 정하고, 에이전트는 실행한다.**

## 정리 (3분)

화면: 로드맵 슬라이드

정리하겠습니다. 마블로의 확장 방향은 네 가지입니다:

1. **새로운 에이전트 역할** — Data, Security, Design, DevOps 등 프로젝트에 필요한 역할을 자유롭게 추가
2. **커스터마이징** — 상태, 플로우, MCP 도구를 프로젝트에 맞게 설정
3. **엔터프라이즈 + 커뮤니티** — 팀 협업, SSO, 플러그인 생태계, API
4. **자율 에이전트 협업** — PM 개입을 줄이고 에이전트가 서로 리뷰하는 미래

여러분은 지금 당장 1번과 2번을 시작할 수 있습니다. 자신의 프로젝트에 맞는 에이전트 역할을 정의하고, 워크플로우를 커스터마이징해보세요.

다음은 이 강좌의 마지막 섹션입니다. 전체 과정을 돌아보고, 앞으로 어떻게 활용하면 되는지 정리하겠습니다.
