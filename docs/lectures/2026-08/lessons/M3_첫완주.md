# M3 · 첫 완주 — 샘플 티켓 하나를 머지까지

## 이번에 무엇을 만드는가

**머지된 티켓 한 장.** 이 레슨이 끝나면 여러분의 `main` 브랜치에 여러분이 한 줄도 직접 쓰지 않은 코드가 들어가 있고, 그 과정 전체가 완료 이력에 기록으로 남습니다.

재료는 M1에서 자동으로 만들어진 `Marblo Sample` 폴더입니다. 그 안의 `src/format.js` 에는 **일부러 테스트가 없습니다.** 파일 맨 위 주석이 그렇게 말합니다 — *"a good first task to hand an agent"*. 첫 티켓은 이 빈자리를 채우는 일입니다.

여러분이 하는 일은 말 한 줄과 확인 몇 번, 그리고 마지막 머지 버튼 하나입니다. 나머지 — 티켓으로 쪼개고, 에이전트를 붙이고, 격리된 브랜치에서 고치고, 되돌려주는 것 — 은 마블로가 합니다. 이번 한 바퀴가 **요청 → 분해 → 배정 → 격리 → 관찰 → 검증 → 머지** 전체입니다. 앞으로 만드는 모든 것이 이 한 바퀴의 반복입니다.

> M2의 승격을 끝낸 상태에서 시작합니다. 오른쪽 탭바에 **보드** 가 없으면 M2로 돌아가세요.

## 따라 하는 순서

### 요청 — 말 한 줄

1. **왼쪽 위 오케스트레이터 터미널을 클릭합니다.** 폴더가 열려 있으면 오케스트레이터는 자동으로 떠 있습니다.

2. **이렇게 칩니다.** 자연어면 충분합니다. 슬래시 명령을 외울 필요 없습니다.

   ```
   src/format.js 에 테스트가 없어. 테스트를 붙여 줘.
   ```

   더 짧게 *테스트가 없는 함수에 테스트를 붙여 줘* 라고만 해도 됩니다. 마블로가 프로젝트를 읽고 대상을 찾습니다.

3. **오케스트레이터가 무엇을 만들지 먼저 보여 주면 확인해 줍니다.** 마블로는 티켓을 만들기 전에 목록을 보여 주고 확인을 받게 되어 있습니다. 내용이 맞으면 그대로 진행하라고 답합니다.

> 슬래시 명령이 궁금하면 입력칸에 `/` 를 쳐 보세요. `/tf-plan`(요구사항 분석 + 태스크 계획), `/tf-start`(태스크 일괄 생성 + 에이전트 스폰), `/tf-status`(현황 대시보드) 같은 것들이 목록으로 뜹니다. 보여만 드립니다 — **슬래시를 외우는 것은 이 코스의 산출물이 아닙니다.** 자연어로 같은 일이 됩니다.

### 분해 — 보드에 카드가 선다

4. **보드 탭을 엽니다.** `TODO` 컬럼에 카드가 하나(또는 몇 개) 생깁니다. 카드를 누르면 요청 내용, 손대는 곳, 먼저 끝나야 하는 일, 진행 기록을 볼 수 있습니다.

### 배정 — 에이전트를 붙인다

5. **오케스트레이터가 에이전트 라인업을 제안하면 승인합니다.** 어떤 역할을 몇 명 붙일지 먼저 말하고 확인을 받습니다. 첫 티켓은 보통 한 명이면 충분합니다.

6. **왼쪽 아래 에이전트 터미널을 봅니다.** 붙은 에이전트마다 터미널 탭이 하나씩 생깁니다. **마블로봇** 탭에서도 지금 누가 무엇을 맡고 있는지 목록으로 볼 수 있습니다.

### 격리 — 워크트리가 생긴다

7. **워크트리 탭을 엽니다.** 조금 전까지 *워크트리가 없습니다* 였던 자리에 행이 하나 생깁니다. 이것이 이 티켓 전용 브랜치입니다. **에이전트는 여러분의 `main` 을 직접 건드리지 않습니다.** 잘못돼도 원래 코드는 그대로입니다 — 이것이 마블로가 여러 작업을 동시에 굴릴 수 있는 이유입니다.

### 관찰 — 지켜본다

8. **에이전트 터미널을 그냥 보고 있으면 됩니다.** 파일을 읽고, 테스트를 쓰고, 돌려 보는 과정이 그대로 흐릅니다. 보드 카드는 `TODO → CLAIMED → IN PROGRESS` 로 움직입니다.

9. **막힌 것 같으면 카드를 눌러 물어봅니다.** 카드 상세에 **진행 상황 물어보기 · 왜 막혔는지 물어보기** 버튼이 있습니다. 누르면 그 질문이 그대로 대화로 전달됩니다.

### 검증 — 내가 읽는다

10. **카드가 `REVIEW` 로 오면 코드 탭에서 변경점을 봅니다.** 워크트리 탭의 행에서 **Code 탭에서 이 worktree 열기** 를 눌러도 같은 자리로 갑니다. `test/format.test.js` 같은 새 파일이 생겼고, `src/format.js` 의 `formatTodoLine` · `formatList` · `formatSummary` 세 함수를 덮고 있는지 봅니다.

11. **직접 돌려 봅니다.** 터미널에서 샘플 폴더로 가서 한 줄이면 됩니다. 설치할 것은 없습니다.

    ```bash
    node --test
    ```

    통과 개수가 늘어나 있으면 에이전트가 실제로 도는 테스트를 쓴 것입니다.

### 머지 — 마지막 한 번

12. **워크트리 탭으로 돌아가 상태 표시를 봅니다.** 행마다 상태가 색으로 붙습니다.

    | 표시 | 뜻 | 다음 행동 |
    | --- | --- | --- |
    | 🟢 머지 가능 | 바로 합칠 수 있음 | **Merge** |
    | 🟡 뒤처짐 | base 가 그새 앞서감 | **Rebase** 먼저, 그다음 Merge |
    | 🔴 충돌 | 같은 곳을 서로 고침 | **Resolve** |
    | ⚠️ stale | 오래 방치됨 | 내용을 확인하고 정리 |
    | ⚪ 작업중 | 아직 진행 중 | 기다림 |

13. **🟢 이면 Merge 를 누릅니다.** 화면 위에 *squash-merge 완료* 배너가 뜹니다.

14. **완료 이력 탭을 엽니다.** 방금 머지된 티켓이 행으로 남아 있습니다. 문제 · 접근 · 변경 · 검증 네 항목의 완료 보고가 붙어 있고, `sha` 를 누르면 그때 실제로 머지된 diff 가 열립니다.

## 화면에서 무엇을 보게 되는가

- 보드 카드가 `TODO → CLAIMED → IN PROGRESS → REVIEW → DONE` 으로 색을 바꿔 가며 이동합니다.
- 왼쪽 아래에 에이전트 터미널 탭이 생기고, 그 안에서 파일 편집과 테스트 실행이 실시간으로 흐릅니다.
- 워크트리 탭에 이 티켓 전용 행이 하나 서고, 앞에 상태 색이 붙습니다.
- 코드 탭에 `+` 초록 줄이 붙은 새 테스트 파일이 뜹니다.
- 머지하면 *squash-merge 완료* 배너, 그리고 완료 이력 탭에 새 행 하나.
- 터미널에서 `node --test` 를 돌리면 통과 개수가 M1 때보다 늘어 있습니다.

## 막힐 때

### 1. 승격을 건너뛰고 이 레슨을 시작했습니다

비기너 모드에도 코드 · 마블로봇 · 워크트리 탭은 있습니다. 그래서 "그냥 되겠지" 하고 시작하게 됩니다. 그런데 **보드와 완료 이력이 없습니다.**

그러면 무엇이 안 되냐면, 티켓이 `REVIEW` 로 넘어온 순간을 볼 수가 없습니다. 비기너 모드의 *일감 흐름* 띠는 할 일 · 진행 중 · 완료 세 칸뿐이라 REVIEW·BLOCKED·FAILED 를 구분해 보여 주지 않습니다. 검증할 때가 됐는데 화면은 여전히 "진행 중"이라, 사람들이 여기서 에이전트가 멈춘 줄 알고 기다립니다. 머지한 뒤에 기록이 남는 자리도 없습니다.

**M2로 돌아가 상단바 `</>` 마블로 모드로 보기 를 누르고 오세요.** 진행 중인 작업은 그대로 이어집니다.

### 2. 요청을 보냈는데 티켓이 안 생깁니다

먼저 오케스트레이터 터미널에 **경고 배너가 떠 있는지** 봅니다. 여기서 갈립니다.

- *Marblo MCP 툴이 붙지 않습니다* — **로그인 문제가 아닙니다.** CLI가 신뢰하지 않는 폴더에서는 로컬 MCP 서버를 띄우지 않기 때문입니다. 해당 CLI로 프로젝트 폴더를 한 번 신뢰(trust)해 준 뒤 다시 시작하세요. MCP 없이 뜬 오케는 보드도 배정도 하나도 못 합니다.
- *이 CLI 의 로그인이 필요합니다* — 다른 CLI가 로그인돼 있어도, 오케로 고른 그 CLI는 따로 로그인해야 합니다. 배너의 로그인 버튼을 누르세요.
- *아래 터미널에 뜬 질문에 직접 답해 주세요* — CLI가 대화형 질문을 띄운 채 멈춘 것입니다. 방향키로 고르고 Enter 를 직접 눌러 주세요. 마블로가 대신 누르지 않는 이유는, 무슨 화면인지 확실하지 않은 상태에서 키를 보내면 엉뚱한 선택이 확정되기 때문입니다.

배너가 없는데 아무 반응이 없다면 요청이 전달되지 않은 것입니다. 같은 문장을 한 번 더 보내 보세요.

### 3. Merge 버튼이 눌리지 않습니다

상태 색을 먼저 보세요. 이유는 대개 셋 중 하나입니다.

- **🟡 뒤처짐** — 그사이 base 가 앞서갔습니다. 같은 행의 **Rebase** 를 먼저 누르고, *rebase 완료* 가 뜬 뒤 Merge 를 누릅니다.
- **🔴 충돌** — 같은 곳을 양쪽이 고쳤습니다. **Resolve** 를 누르면 충돌을 푸는 에이전트가 붙습니다. Resolve 는 충돌 상태에서만 눌립니다.
- **권한** — 여러 명이 쓰는 프로젝트라면 머지는 프로젝트 관리자(owner/admin)만 할 수 있습니다. 혼자 만든 프로젝트에서는 여러분이 관리자입니다.

첫 티켓은 브랜치가 하나뿐이라 보통 🟢 입니다. 🟡·🔴 은 여러 티켓을 동시에 굴리기 시작하는 3부에서 자주 만납니다.

### 4. 샘플이 아니라 내 빈 폴더로 시작했습니다

빈 폴더를 연결하면 화면은 정상적으로 열리지만 첫 지시가 **아무 결과도 못 냅니다.** 읽을 파일이 없으니 "테스트를 붙여 줘"라고 해도 붙일 곳이 없습니다. 이건 실패가 아니라 재료가 없는 것입니다.

두 가지 길이 있습니다. 하나, `Marblo Sample` 폴더로 바꿔서 이 레슨을 그대로 따라간 뒤 자기 프로젝트로 돌아옵니다. 둘, 이미 코드가 있는 자기 저장소를 연결하고 **한 파일짜리 동등 티켓**으로 바꿉니다 — "테스트가 없는 파일 하나를 골라 테스트를 붙여 줘" 면 충분합니다. 첫 완주의 목적은 큰 기능이 아니라 **한 바퀴를 닫아 보는 것**입니다.

### 5. 워크트리가 안 만들어집니다

워크트리는 git 저장소 위에서만 만들어지고, **커밋이 하나도 없는 저장소에서는 실패합니다.** 마블로는 샘플 폴더를 만들 때 `git init` 과 첫 커밋까지 함께 하지만, 이 단계가 실패해도 폴더 연결 자체는 그대로 진행됩니다. 그래서 대화는 되는데 워크트리만 안 생기는 상태가 될 수 있습니다.

터미널에서 샘플 폴더로 가 `git log --oneline` 을 쳐 보세요. 아무것도 안 나오면 커밋이 없는 것입니다.

```bash
git init -b main
git add -A
git commit -m "Initial commit"
```

이 세 줄이면 됩니다. 저장소를 새로 만들 때 이름·이메일 설정이 없어 커밋이 거부되면 `git config user.name` 과 `user.email` 을 먼저 설정하세요.

### 6. 원격(GitHub)에 올리려는데 버튼이 안 보입니다

**마블로 화면에는 git push 전용 버튼이 없습니다.** 하네스 탭의 **저장소 연결** 은 GitHub 계정을 잇는 것이지 푸시 버튼이 아닙니다. 워크트리 행의 **GitHub** 버튼도 브라우저로 PR이나 브랜치 비교를 열어 주는 것입니다.

원격 푸시는 두 길 중 하나로 합니다. 오케스트레이터에게 말로 시키거나(`이 브랜치를 원격에 푸시해 줘`), 터미널에서 직접 `git push` 를 칩니다. **그리고 1부에는 원격이 필요 없습니다.** 이번 레슨의 산출물은 로컬 `main` 에 들어간 머지 하나입니다.

## 끝났는지 어떻게 아는가

**워크트리 탭에 "squash-merge 완료" 배너가 떴고, 완료 이력 탭에 그 티켓 행이 남아 있으면 M3은 끝입니다.**

한 번 더 확인하고 싶으면 터미널에서 샘플 폴더의 `main` 브랜치에 서서 `node --test` 를 돌려 보세요. `src/format.js` 를 덮는 테스트가 함께 통과하면, 여러분이 한 줄도 안 쓴 코드가 여러분의 `main` 에 들어간 것입니다.

여기까지가 1부입니다. 손에 남은 것은 **머지된 티켓 한 장**, 그리고 그것을 만든 한 바퀴입니다.
