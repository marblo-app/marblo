## 3. 특허 등록

### 3-1. 특허 출원 — 직접 vs 변리사

#### 직접 출원 (비용: ~25만원/건)

**장점**:
- 비용이 1/5~1/8 수준
- 기술을 가장 잘 아는 본인이 작성

**단점 (중요)**:
- **청구항(Claims) 작성이 핵심** — 이게 법률 문서임
  - 청구항이 너무 좁으면: 약간 변형한 것은 침해 아님 → 특허 무력화
  - 청구항이 너무 넓으면: 심사관이 선행기술로 거절 → 등록 실패
- 선행기술 조사 경험 부족 → 기존 특허와 겹치는지 판단 어려움
- 거절 시 의견서/보정서 대응이 어려움

**현실적 판단**:
- 특허 2, 3 (PTY 피드백, 자동 라우팅)은 기술 범위가 명확해서 직접 가능
- **특허 1 (핵심 — 오케스트레이션)은 변리사 추천** → 보호 범위를 최대한 넓게 잡아야 함

#### 변리사 통한 출원 (비용: ~120-200만원/건)

**포함 서비스**:
- 선행기술 조사 (기존 특허 DB 검색)
- 청구항 최적화 (넓되 등록 가능한 범위)
- 명세서 + 도면 작성
- 심사 대응 (거절 시 의견서)
- 등록까지 전 과정 관리

**비용 절감 팁**:
- 초안(아래 명세서)을 내가 작성해서 전달하면 변리사 비용 30~50% 절감 가능
- "명세서 초안 있고 청구항 최적화만 해주세요" → 80~120만원 선

|----------|-------------|---------|

### 3-3. 통합 특허: PTY 기반 이종 AI 에이전트 오케스트레이션 시스템 ⭐⭐ (유일 특허)

> Marblo의 모든 핵심 아키텍처를 1건의 특허로 통합 보호.
> PTY 격리 + MCP 통신 + stdin 피드백 + 자동 라우팅 + 과금 분리를 하나로 커버.

```
[발명의 명칭]
가상 터미널 기반 이종 AI 에이전트의 통합 오케스트레이션,
실시간 양방향 피드백 및 자동 라우팅 시스템

[기술 분야]
인공지능 에이전트 관리, 멀티모델 오케스트레이션, 소프트웨어 개발 도구

[배경기술 — 기존 문제]

종래의 AI 에이전트 관리 시스템은 다음과 같은 한계를 가짐:

(1) 프로세스 격리 부재:
    - CrewAI, AutoGen, LangGraph 등은 동일 Python 프로세스 내에서 에이전트를
      실행하여, 하나의 에이전트 장애(메모리 누수, 무한 루프 등)가 전체 시스템에 영향.
    - Claude Managed Agents(Anthropic, 2026)는 클라우드 컨테이너 격리를 제공하나,
      로컬 환경에서의 즉시적 양방향 터미널 상호작용은 불가.

(2) 이종 모델 운용 및 자동 배정 불가:
    - 기존 프레임워크는 단일 벤더(Claude만, GPT만) 또는 어댑터 패턴으로
      이종 모델을 지원하며, 각 모델 에이전트의 독립적 구독/과금 분리가 불가.
    - 태스크를 AI에 할당할 때 사용자가 수동으로 모델을 선택하거나 단일 모델만
      사용 가능하여, 태스크 특성에 맞지 않는 모델 배정과 비용 비효율 발생.

(3) 실시간 피드백 부재:
    - 에이전트에 작업 지시를 수정하려면 (a) API로 새 프롬프트 전송(컨텍스트 단절),
      (b) 에이전트 중단 후 재시작(작업 손실), (c) 다음 폴링 주기까지 대기(지연) 중
      하나를 택해야 함.
    - Paperclip은 heartbeat 주기에 코멘트를 확인하는 방식으로, 실시간 반영이 불가.

(4) 중앙 오케스트레이터 부재:
    - 기존 프레임워크는 에이전트 간 통신에 의존(AutoGen: 대화, CrewAI: 순차 파이프라인)
      하거나, 사용자가 그래프를 직접 설계(LangGraph)해야 함.
    - 자연어 요구사항을 자동으로 태스크로 분해하고, 적절한 에이전트(물리적 또는
      논리적)에 할당하는 중앙 오케스트레이터가 없음.

[발명의 구성]

본 발명은 이종 AI CLI 에이전트를 OS 레벨 가상 터미널(PTY)로 격리 실행하고,
표준화된 MCP 프로토콜로 중앙 태스크 보드와 통신하며, PTY 표준 입력을 통해
작업 중단 없이 실시간 피드백을 주입하고, 태스크 특성에 따라 최적 에이전트를
자동 라우팅하는 통합 오케스트레이션 시스템으로서, 다음 단계를 포함한다:

[청구항 1] PTY 프로세스 격리 생성
   복수의 AI CLI 에이전트(Claude Code, Codex CLI, Gemini CLI 등 이종 벤더 포함)를
   각각 독립된 가상 터미널(PTY) 프로세스로 생성하되, 각 PTY는 독립된 환경변수,
   작업 디렉토리, API 인증 정보를 보유하여 에이전트 간 완전한 프로세스 격리를
   달성하는 단계;

[청구항 2] MCP 자동 구성 및 주입
   각 에이전트의 PTY 생성 시 MCP(Model Context Protocol) 설정 파일을 자동
   생성하여, 에이전트가 중앙 태스크 보드의 도구(태스크 조회, 상태 변경, 활동 기록 등)에
   접근할 수 있도록 구성하는 단계;
   — 이때 에이전트는 MCP 서버만을 유일한 통신 수단으로 사용하며,
     에이전트의 AI 모델 종류와 무관하게 동일한 인터페이스로 보드와 통신함;

[청구항 3] PTY stdin 실시간 피드백 주입
   프로젝트 관리자 또는 중앙 오케스트레이터가 작성한 피드백 메시지를 소정의 형식으로
   포매팅한 후, 에이전트가 실행 중인 PTY 세션의 표준 입력(stdin)에 직접 기록(write)
   하여, 에이전트의 실행을 중단하지 않고 기존 대화 컨텍스트를 유지한 채로
   실시간 지시를 전달하는 단계;
   — 에이전트는 상기 stdin 입력을 사용자 입력으로 해석하여 현재 작업에 즉시 반영함;

[청구항 4] 중앙 오케스트레이터에 의한 자동 태스크 설계 및 배분
   중앙 오케스트레이터가 자연어 요구사항을 수신하여 구조화된 태스크 목록으로
   자동 분해하고, 각 태스크의 역할 태그(backend, frontend, test 등)와 등록된
   에이전트의 모델 유형 및 역할 적합도를 매칭하여, 물리적 에이전트(실행 중인 PTY
   프로세스) 또는 논리적 에이전트(미실행 상태, 필요 시 자동 생성)에 태스크를
   자동 할당하는 단계;

[청구항 5] 태스크 특성 기반 이종 모델 자동 라우팅
   각 태스크에 부여된 역할 태그(backend, frontend, test, devops 등)와 등록된
   에이전트 목록에서 각 에이전트의 모델 유형(Claude, GPT, Gemini 등)을 대조하여
   역할 매칭 점수를 산출하고, 의존성 그래프에서 현재 실행 가능한 태스크를 식별한 후,
   최적 매칭 에이전트에 태스크를 자동 할당하는 단계;
   — 에이전트가 부족하거나 부재 시, 적합한 모델의 새 PTY를 자동 생성하여 배정함;

[청구항 6] 이종 모델 독립 과금 분리
   각 에이전트가 독립된 PTY 프로세스에서 자체 API 키 및 구독 계정으로 실행되므로,
   Claude(구독 기반), GPT(API 과금), Gemini(무료 티어) 등 이종 과금 모델이
   동일 프로젝트 내에서 혼합 운용되면서도 과금이 자연스럽게 분리되며,
   각 에이전트의 토큰 사용량 및 비용을 독립적으로 추적하는 단계.

[핵심 차별점 — 선행기술 대비]

(A) PTY 에뮬레이션을 에이전트 격리 및 양방향 통신 메커니즘으로 사용:
    - CrewAI/AutoGen/LangGraph: 인프로세스 (격리 없음)
    - Paperclip: 단순 subprocess spawn (터미널 에뮬레이션 없음, 일회성)
    - Claude Managed Agents: 클라우드 Docker 컨테이너 (로컬 실시간 상호작용 불가)
    → 본 발명만이 PTY를 통한 영구 실행 + 실시간 양방향 터미널 상호작용을 제공

(B) stdin 피드백 주입에 의한 비침습적 실시간 지시 변경:
    - 모든 경쟁 프레임워크는 에이전트 중단, API 재호출, 또는 다음 폴링 주기 대기 필요
    → 본 발명만이 실행 중 컨텍스트 유지 상태에서 즉시 피드백 반영 가능

(C) MCP를 에이전트-보드 간 유일한 통신 프로토콜로 사용:
    - 타 프레임워크: 자체 SDK, REST API, Python 함수 호출 등 독자 인터페이스
    → 본 발명은 표준 프로토콜(MCP)만으로 통신하므로 에이전트 교체/추가가 자유로움

(D) 중앙 오케스트레이터에 의한 물리적/논리적 에이전트 구분 및 자동 배분:
    - 타 프레임워크: 에이전트가 항상 실행 중이거나(CrewAI), 요청 시 생성(AutoGen)
    → 본 발명은 이미 실행 중인 PTY(물리적)와 필요 시 자동 생성하는 PTY(논리적)를
      오케스트레이터가 구분하여 최적 배분

(E) 이종 벤더 AI 모델의 역할 기반 자동 라우팅 + 단일 보드 통합:
    - Claude Managed Agents: Claude 전용, 수동 배정
    - OpenAI Codex: GPT 전용 (복잡도별 라우팅은 GPT 모델 내부)
    → 본 발명은 Claude, GPT, Gemini 등 벤더가 다른 모델을 역할 매칭 점수로
      자동 라우팅하고 동일 MCP 보드에서 통합 관리

(F) 에이전트별 독립 과금 추적:
    - 타 프레임워크: 단일 API 키 공유 또는 비용 집계 미지원
    → 본 발명은 각 PTY의 독립 API 키/구독으로 자연스러운 과금 분리 + 사용량 추적
```

### 3-6. 특허의 법적 활용 — 소송, 견제, 글로벌 대응

#### 특허 등록 후 할 수 있는 것

| 활용 방식 | 설명 | 예시 |
|----------|------|------|
| **침해 경고장** | 유사 기능 구현 업체에 서면 경고 | 경쟁사가 PTY+MCP 조합 사용 시 → 경고장 → 라이선스 협상 |
| **라이선스 수입** | 기술 사용 허가 대가로 로열티 수취 | "PTY 오케스트레이션 기술 라이선스 연 $X" |
| **소송/가처분** | 침해 중지 청구 + 손해배상 | 한국 특허법원 또는 미국 연방법원 |
| **방어 특허** | 대기업이 우리를 역소송할 때 교차 라이선스 협상 카드 | "우리도 특허 있으니 협상하자" |
| **기업 가치** | 투자유치/M&A 시 IP 자산으로 밸류에이션 증가 | 특허 포트폴리오 = 기술 장벽 증명 |
| **출원 중 견제** | 등록 전이라도 "특허 출원 중(Patent Pending)" 표시 가능 | 경쟁사의 모방 심리적 억제 |

#### 소송이 실제로 가능한가?

**가능하지만, 조건이 있음:**

1. **등록 완료 필수** — 출원만으로는 소송 불가. 등록 후에야 권리 행사 가능.
2. **청구항 범위가 핵심** — 경쟁사의 구현이 청구항 문언에 포함되어야 침해 인정.
   - "PTY로 에이전트를 격리 실행하고 stdin으로 피드백을 주입하는 시스템"이 청구항이면,
     Docker 컨테이너로 격리하는 Claude Managed Agents는 해당 안 됨 (PTY가 아니므로)
   - 만약 다른 회사가 PTY + MCP 조합을 쓰면 → 직접 침해
3. **증거 수집** — 공개된 코드, 문서, API 사양에서 침해 증거 확보 가능

#### 실전 시나리오 예시

**시나리오 1: 국내 스타트업이 유사 서비스 출시**
```
1. 발견: 경쟁사 B가 "AI 에이전트를 PTY로 실행하고 MCP로 태스크 관리" 서비스 출시
2. 경고장: 특허 등록번호 기재, 침해 중지 요청 (내용증명)
3. 협상: (a) 서비스 중단, (b) 라이선스 계약, (c) 기술 변경 중 선택 요구
4. 미응시: 특허법원에 침해금지 가처분 신청 → 서비스 중단 명령
```

**시나리오 2: 대기업이 유사 기능 탑재**
```
1. 발견: 대형 IDE 회사가 "PTY 기반 멀티에이전트" 기능 추가
2. 경고장 → 라이선스 협상 (대기업은 소송보다 라이선스 선호)
3. 결과: 연간 로열티 수입 또는 일시금 합의
→ 대기업 상대 소송은 비용 부담이 크지만, 한국 특허는 등록률이 높고
   특허법원의 판결 속도가 빠름 (미국보다 유리)
```

**시나리오 3: 방어적 활용**
```
1. 상황: 대기업이 우리 서비스에 특허 침해 주장
2. 대응: "우리도 PTY 오케스트레이션 특허 보유 → 교차 라이선스 협상"
3. 결과: 상호 불가침 합의 (이게 실무에서 가장 흔한 활용)
```

#### 글로벌 대응 전략

| 단계 | 대상국 | 방법 | 비용 | 시기 |
|------|--------|------|------|------|
| **1단계** | 한국 | 특허로(patent.go.kr) 직접 출원 | ~25만원 | **즉시** (선출원주의) |
| **2단계** | 국제 (PCT) | PCT 국제출원 → 30개월 내 개별국 진입 | ~200만원 | 한국 출원 후 **12개월 내** |
| **3단계** | 미국 | PCT 경유 또는 USPTO 직접 출원 | ~500만원 | PCT 출원 후 30개월 내 |
| **4단계** | 일본/EU | PCT 경유 개별국 진입 | 각 ~300만원 | 매출/시장 확인 후 |

**핵심: 한국 출원이 최우선**
- 한국 출원일이 **우선권 기준일**이 됨 (파리조약)
- 한국 출원 후 12개월 내 PCT 출원하면, 한국 출원일을 기준으로 전 세계에서 선행기술 판단
- 즉, **오늘 한국에 출원하면** → 1년 내 해외 출원 시 오늘 날짜가 기준
- 이 1년 사이에 경쟁사가 유사 특허를 출원해도, 우리가 선행

**PCT(국제특허협력조약) 경로 — 가성비 최적**
```
한국 출원 (2026.04) → PCT 출원 (2027.03까지) → 30개월 내 개별국 진입
                                                  ├ 미국 (USPTO)
                                                  ├ 일본 (JPO)
                                                  ├ 유럽 (EPO)
                                                  └ 중국 (CNIPA)
```

- PCT 출원 1건으로 150+개국에 우선권 확보
- 30개월의 시간 벌이 → 사업 성과 보고 진입국 결정
- 매출이 없는 국가는 진입 안 하면 됨 (비용 절약)

**미국 출원이 중요한 이유**:
- AI 에이전트 시장의 주요 플레이어(Anthropic, OpenAI, Google)가 미국 회사
- 미국 특허가 있으면 해당 회사들과 라이선스 협상력 확보
- 미국은 손해배상액이 한국보다 훨씬 큼 (침해 입증 시 수백만~수천만 달러)

#### 비용 시뮬레이션 (글로벌)

| 시나리오 | 한국 | PCT | 미국 | 일본 | 합계 |
|----------|------|-----|------|------|------|
| **최소 (한국만)** | 25만 | - | - | - | **~25만원** |
| **추천 (한국+PCT)** | 25만 | 200만 | - | - | **~225만원** |
| **풀 글로벌** | 25만 | 200만 | 500만 | 300만 | **~1,025만원** |

> 매출 전에는 한국+PCT까지만 진행하고, 해외 매출 확인 후 개별국 진입 결정 추천.

#### 해외 AI 에이전트 특허 현황 (2024~2026)

**해외 빅테크도 AI 특허를 활발히 출원하고 있음:**

| 회사 | AI 특허 건수 | 대표 특허 | 비고 |
|------|:-----------:|----------|------|
| **Google** | ~1,837건 | 텍스트-이미지 생성 등 | AI 특허 출원 세계 1위 (2025 기준) |
| **Microsoft** | ~701건 (미국) | 게임 AI 내러티브 등 | AutoGen은 오픈소스, 별도 특허는 제한적 |
| **OpenAI** | 다수 | 텍스트 생성/편집 (US11983488B1) | 에이전트 오케스트레이션 특허는 확인 안 됨 |
| **IBM** | 다수 | AI 특허 라이선스 사업 | 연간 $4억 이상 특허 라이선스 수입 |

**핵심 포인트:**
- 빅테크들은 주로 **모델 자체** (학습 방법, 아키텍처)에 특허 집중
- **멀티에이전트 오케스트레이션**에 대한 특허는 아직 소수 → 선점 기회
- CrewAI/AutoGen/LangGraph는 오픈소스이므로 특허 출원 없음 (선행기술로는 존재)
- 2024년 USPTO 가이던스: AI 도구로 만든 발명도 사람(발명자)이 있으면 특허 가능
- 2025년 USPTO 개정: AI를 "일반 도구"로 취급 → AI 보조 발명의 특허 장벽 낮아짐

**Marblo에 유리한 점:**
- PTY 기반 에이전트 오케스트레이션은 **아무도 특허 출원하지 않은 영역**
- 빅테크가 나중에 유사 아키텍처를 채택할 때 → 우리 특허가 방어/라이선스 카드
- 한국 선출원 → PCT로 글로벌 우선권 확보하면 시간적 우위

#### 권리 행사 정리 — 국내 vs 해외

```
[국내 — 한국 특허 등록 후]
  ├── 발견: 경쟁사가 PTY+MCP+stdin 조합 사용
  ├── 1단계: 경고장 (내용증명) → 침해 중지 + 라이선스 협의 요청
  ├── 2단계: 미응시 → 특허법원 침해금지 가처분 신청
  └── 3단계: 손해배상 청구 소송

[해외 — PCT/개별국 등록 후]
  ├── 매출 추이 확인 → 유의미한 시장에만 개별국 진입
  ├── 미국 등록 시: USPTO 기반 침해 소송 (손해배상액 높음)
  └── 미등록 국가: 권리 행사 불가 (but "Patent Pending" 심리적 견제)

[바이브코딩/강의 모방 대응]
  ├── 강의·튜토리얼에 "본 아키텍처는 특허 출원 중 (Patent Pending)" 디스클레이머 표시
  ├── 개인 학습·실험 → 관대하게 허용 (커뮤니티 호의)
  └── 상용 서비스화 시 → 라이선스 협의 요청
```

### 3-7. 출원 절차

```
1. 선행기술 조사

   - 위 초안을 기반으로 작성 (직접 시) 또는 변리사에 전달
   - 도면: 시스템 구성도, 흐름도 (draw.io 등으로 작성)

3. 출원
   - 특허로 (patent.go.kr) 전자출원
   - 출원료: ~4.6만원/건
   - 우선심사 신청 가능 (추가 ~20만원, 4~6개월 단축)

4. 심사 청구 (출원일로부터 3년 내)
   - 심사청구료: ~14만원 (청구항 수에 따라 변동)
   - 조기에 청구 추천 (경쟁사 견제)

5. 심사 (12~18개월, 우선심사 시 4~6개월)
   - 거절이유통지 → 의견서/보정서 제출 (2개월 내)
   - 등록결정 → 등록료 납부

6. 등록 유지
   - 연차료: 1~3년 매년 ~1.5만원, 이후 점진 인상
```

## 4. 출원 주체 전략 — 사업체별 IP 분리

### 4-1. 사업체 구조

| 사업체 | 형태 | 운영 브랜드 |
|--------|------|------------|
| **디앤서랩** | 개인사업자 | Marblo(마블로), 개미날다(ant-can-fly) |
| **하이프마크** | 법인 | HypeMarc.AI |

### 4-2. 출원 주체 원칙

> **핵심: IP는 실제 개발/운영 주체별로 분리 출원한다.**

**개인사업자(디앤서랩)의 특수성:**
- 개인사업자는 법인격이 없음 → "디앤서랩" 이름으로 출원 **불가**
- 반드시 **대표자 개인 이름**으로 출원해야 함
- 나중에 법인 전환 시 개인 → 법인으로 양도 가능 (건당 3~5만원)

### 4-3. 출원 주체 매핑

#### 상표

| 상표 | 출원인 | 비고 |
|------|--------|------|
| **마블로** / **Marblo** | 대표자 개인 (디앤서랩 대표) | 디앤서랩 운영 브랜드 |
| **개미날다** / **ant-can-fly** | 대표자 개인 (디앤서랩 대표) | 디앤서랩 운영 브랜드 |
| **하이프마크** / **HypeMarc** | 하이프마크 법인 | 법인 명의 출원 |
| **HypeMarc.AI** | 하이프마크 법인 | 법인 명의 출원 |

#### 특허

| 특허 | 출원인 | 비고 |
|------|--------|------|
| **통합 특허** (PTY 오케스트레이션 + 피드백 + 자동 라우팅) | 대표자 개인 (디앤서랩 대표) | Marblo 핵심 기술 전체를 1건으로 보호 |

### 4-4. 하이프마크에서 통으로 출원하면 안 되는 이유

자매회사라도 **IP 통합 출원은 비추천**:

| 리스크 | 설명 |
|--------|------|
| **사업 분리 불가** | 마블로/개미날다 IP가 하이프마크 법인 자산이 되어, 별도 매각·투자유치 시 분리 곤란 |
| **투자 리스크** | "이 제품의 IP 소유권이 다른 법인에 있음" → 투자자 경계 |
| **법인 리스크 전이** | 하이프마크에 법적 문제 발생 시 마블로 IP도 같이 위험 |
| **양도 비용** | 나중에 분리하려면 양도 절차 + 세금 이슈 발생 |

### 4-5. 추천 경로 — 현재 ~ 법인 전환

```
현재 (개인사업자 단계)
├── Marblo 상표 + 특허 → 대표자 개인 명의 출원
├── 개미날다 상표        → 대표자 개인 명의 출원
└── HypeMarc 상표       → 하이프마크 법인 명의 출원

하이프마크가 Marblo 기술 사용 시
└── 대표자(개인) ↔ 하이프마크(법인) 간 통상실시권 계약 (등록비 ~3만원)

미래 (디앤서랩 법인 전환 시)
├── 디앤서랩 법인 설립
├── 개인 명의 특허/상표 → 디앤서랩 법인으로 양도 (이전등록 건당 3~5만원)
└── 필요 시 하이프마크와 크로스라이선스 계약
```

### 4-6. 비용 요약 (출원 주체 관련)

| 항목 | 비용 | 시기 |
|------|------|------|
| 특허/상표 양도 (이전등록) | 건당 3~5만원 | 법인 전환 시 |
| 전용/통상실시권 등록 | 건당 ~3만원 | 하이프마크 사용 시 |
| 법인 전환 후 일괄 양도 (5건 가정) | ~15~25만원 | 법인 전환 시 |

> **결론**: 지금은 **대표자 개인 명의**로 출원하고, 법인 전환 시 저렴하게 양도하는 것이 가장 안전하고 유연한 전략.

## 8. 자주 묻는 질문

**Q: 개인 이름으로 출원해도 되나?**
A: 가능하며, 개인사업자(디앤서랩)의 경우 반드시 대표자 개인 이름으로 출원해야 함.
   법인 전환 후 이전등록으로 양도 가능 (건당 3~5만원). 자세한 내용은 §4 참조.

**Q: 디앤서랩과 하이프마크 IP를 하이프마크에서 통합 출원해도 되나?**
A: 가능은 하지만 비추천. 사업 분리/투자유치/매각 시 IP 분리가 복잡해짐.
   각 사업체별로 분리 출원 후 필요 시 실시권 계약으로 교차 사용 추천. 자세한 내용은 §4 참조.

**Q: 출원 전에 GitHub 공개해도 되나?**
A: 한국은 공지예외 적용 가능 (공개 후 12개월 내 출원).
   단, 미국/유럽은 공개 시점부터 1년 내 출원 필수. 가능하면 출원 후 공개 추천.

**Q: AI가 작성한 코드도 특허 대상인가?**
A: 특허는 아이디어(발명)를 보호. 코드 자체가 아니라 "시스템 구성과 방법"을 청구.
   AI 보조 여부와 무관하게 발명자(사람)가 있으면 출원 가능.

**Q: 경쟁사가 유사 기능 만들면?**
A: 특허 등록 후 → 경고장 발송 → 협상/소송 가능.
   특허 출원만 한 상태 → "특허 출원 중" 표시로 견제 효과.

**Q: Claude가 작성한 초안을 그대로 출원해도 되나?**
A: 형식은 맞지만, 직접 출원 시 주의점:
   - 청구항 범위를 KIPRIS 선행기술과 비교하여 조정 필요
   - 도면(시스템 구성도)을 직접 그려서 첨부해야 함
   - 변리사 없이 거절 시 대응이 어려울 수 있음
   → 핵심 특허 1은 초안을 변리사에게 전달하여 청구항만 다듬는 것을 추천

**Q: 바이브코딩 강의에서 유사 아키텍처를 따라 만드는 사람들은?**
A: 개인 학습/실험은 특허 침해 아님 (비영리 실시). 하지만 상용 서비스화하면 침해.
   강의 콘텐츠에 "Patent Pending" 디스클레이머를 넣어서 미리 견제하는 것이 효과적.
