# Marblo 핵심가치 & 마케팅 가이드

> 내부 전략 문서 — 홈페이지, 랜딩페이지, 강의, 투자자료에 활용

---

## 1. 한 줄 정의

**Marblo는 AI 에이전트 팀의 개발 환경이다.**

에이전트를 "돌리는" 도구가 아니라 "관리하는" 플랫폼.

---

## 2. 시장의 문제점 — 왜 Marblo가 필요한가

### 2-1. 현재 AI 에이전트 시장의 현실

```
2024: "AI 에이전트가 뭐야?"
2025: "에이전트 하나 써보자" (Cursor, Claude Code, Codex)
2026: "에이전트 여러 개 돌리자" ← 지금 여기
2027: "에이전트가 알아서 팀으로 일하게 하자" ← Marblo가 가는 곳
```

### 2-2. 5대 핵심 문제점

| # | 문제 | 현상 | 고객의 고통 |
|---|------|------|-----------|
| P1 | **가시성 없음** | 에이전트가 터미널에서 뭘 하는지 모름 | "30분째 돌아가는데 진행이 되고 있는 건지..." |
| P2 | **컨텍스트 유실** | 에이전트 중단하면 모든 작업 맥락 소실 | "피드백 주려면 에이전트를 멈춰야 하는데, 그러면 다 날아가요" |
| P3 | **거버넌스 부재** | 누가 뭘 했는지 추적 불가 | "에이전트 3개 돌렸는데 어떤 파일을 누가 수정한 건지 모름" |
| P4 | **비용 블랙홀** | 얼마 쓰는지 모르고 API 비용 폭탄 | "이번 달 API 비용이 왜 이렇게 나왔는지 분석이 안 됨" |
| P5 | **벤더 종속** | 하나의 AI 모델에만 의존 | "Claude가 좋은데 프론트는 Gemini가 낫고, 둘 다 못 씀" |

### 2-3. 경쟁 제품의 한계 (마케팅 비교용)

**"에이전트 50개 돌립니다!" 류의 마케팅에 대한 반론:**

> 에이전트를 50개 돌리는 건 누구나 할 수 있습니다.
> 50개가 지금 뭘 하고 있는지 아는 것, 그게 진짜 문제입니다.

| 접근 방식 | 대표 제품 | 한계 |
|----------|----------|------|
| 단일 에이전트 IDE | Cursor, Windsurf | 에이전트 1개, 팀 관리 불가 |
| CLI 에이전트 내부 Task | Claude Code /agent | 터미널 하나에 섞임, 로그 소실, PM 개입 불가 |
| 인프로세스 프레임워크 | CrewAI, AutoGen, LangGraph | 코드로만 관리, UI 없음, 실시간 피드백 불가 |
| 클라우드 에이전트 | Claude Managed Agents, Codex | 단일 벤더, 로컬 실행 불가, 비용 통제 어려움 |
| 에이전트 대시보드 | Paperclip 등 | 폴링 방식, 실시간 아님, 터미널 에뮬레이션 없음 |

## 3. Marblo의 해답 — 3가지 핵심 가치

### 핵심 가치 삼각형

```
        Governance
       (거버넌스)
        /       \
       /    M    \
      /  a  r  b  \
     /   l     o   \
    /               \
Observability ─── Context
 (가시성)       (컨텍스트 유지)
```

### 3-1. Observability — "에이전트가 지금 뭘 하고 있는지 안다"

- 에이전트별 독립 터미널 뷰 — 실시간 작업 과정 모니터링
- 칸반 보드 — 태스크 상태가 자동으로 이동 (Todo → In Progress → Review → Done)
- 활동 로그 — 에이전트가 기록하는 작업 히스토리
- 비용 대시보드 — 에이전트별, 모델별 실시간 비용 추적

### 3-2. Context Persistence — "멈추지 않고 방향을 바꾼다"

- PTY 기반 세션 — 에이전트가 양방향 대화형 터미널에서 실행
- stdin 실시간 피드백 — 에이전트를 멈추지 않고 지시 변경 가능
- 세션 자동 복구 — 앱 재시작 후에도 이전 작업 컨텍스트 유지
- 자동 재시작 — 비정상 종료 시 동일 구성으로 자동 복구

### 3-3. Governance — "누가 뭘 했는지 다 남는다"

- 감사 추적(Audit Trail) — MCP 도구 호출 자동 로깅
- 역할 기반 배정 — 태스크 특성에 맞는 에이전트 자동 매칭
- PM 개입 — 칸반 보드에서 태스크 재배정, 우선순위 변경, 즉시 피드백
- 비용 분리 — 에이전트별 독립 API 키, 과금 자동 분리

## 4. 포지셔닝 — Marblo는 어디에 위치하는가

### 4-1. 시장 포지션 맵

```
                    팀/PM용
                      ↑
                      |
         Marblo ●     |
    (멀티에이전트+     |
     칸반+터미널+      |
     파일시스템)       |
                      |
 복수 에이전트 ←──────┼──────→ 단일 에이전트
                      |
    CrewAI/AutoGen ●  |          ● Cursor/Windsurf
    (코드 기반,        |          (에디터+AI 1개)
     UI 없음)         |
                      |          ● Claude Code
                      |          (터미널+AI 1개)
                      ↓
                   개발자 개인용
```

### 4-2. 핵심 비교 — "Cursor vs Marblo"

| | Cursor | Marblo |
|---|--------|--------|
| 대상 | 개발자 개인 | 개발자 + PM/팀리드 |
| 에이전트 | AI 1개 | AI 여러 개 (이종 모델 혼합) |
| 인터페이스 | 에디터 | 에디터 + 터미널 + 칸반 보드 |
| 피드백 | 에디터 내 채팅 | 칸반 + 터미널 stdin 실시간 주입 |
| 태스크 관리 | 없음 | 칸반 보드 자동 동기화 |
| 비용 관리 | 월 $20 고정 | 에이전트별 사용량 분리 추적 |
| 벤더 | 독자 모델 | Claude, GPT, Gemini 등 벤더 무관 |

### 4-3. 한 줄 포지셔닝

> **Cursor가 개발자 개인의 AI 페어프로그래머라면,
> Marblo는 AI 에이전트 팀의 프로젝트 매니저다.**

### 5-2. 랜딩페이지 히어로 섹션

**헤드라인:**
> AI 에이전트 팀을 위한 개발 환경

**서브헤드:**
> Claude, GPT, Gemini — 어떤 에이전트든 하나의 보드에서 관리하세요.
> 실시간 모니터링, 칸반 태스크 관리, 비용 추적까지.

**CTA:** 베타 시작하기 →

### 5-3. 핵심 기능 섹션 (Feature Highlights)

**Feature 1: 실시간 에이전트 모니터링**
> 에이전트별 독립 터미널에서 작업 과정을 실시간으로 확인하세요.
> 더 이상 "뭐하고 있는지 모르겠다"는 없습니다.

**Feature 2: 멈추지 않는 피드백**
> 에이전트를 중단하지 않고 실시간으로 방향을 수정하세요.
> 작업 컨텍스트가 유지된 채로 즉시 반영됩니다.

**Feature 3: 칸반 보드 자동 동기화**
> 에이전트가 태스크를 수락하면 카드가 자동으로 이동합니다.
> PM은 보드만 보면 전체 프로젝트 상황을 파악할 수 있습니다.

**Feature 4: 이종 AI 모델 혼합 운용**
> Claude로 백엔드, Gemini로 프론트엔드, GPT로 테스트.
> 각 AI의 강점에 맞게 태스크를 자동 배정합니다.

**Feature 5: 비용 투명성**
> 에이전트별, 태스크별, 모델별 비용을 실시간 추적합니다.
> API 비용 폭탄? 마블로에서는 일어나지 않습니다.

### 5-4. 문제-해결 대비 문구 (Pain Point → Solution)

| 고객의 고통 | Marblo의 해결 |
|------------|--------------|
| "에이전트가 30분째 뭘 하는지 모르겠어요" | 에이전트별 독립 터미널 + 활동 로그로 실시간 확인 |
| "피드백 주려면 멈춰야 하는데 다 날아가요" | stdin 실시간 주입 — 멈추지 않고 방향 수정 |
| "어떤 에이전트가 어떤 파일을 바꿨는지 모름" | 감사 추적 + 에이전트별 작업 범위 격리 |
| "이번 달 API 비용이 왜 이렇게 나왔지?" | 에이전트별 비용 분리 + 실시간 대시보드 |
| "Claude만 쓰기엔 아깝고, GPT도 섞고 싶은데" | 벤더 무관 — 아무 CLI 에이전트나 플러그인 |
| "팀원들이 에이전트 상황을 공유 못 해요" | 칸반 보드 — 에이전트 상태가 카드로 실시간 동기화 |

### 5-5. 강의/콘텐츠용 후크 (Hook)

**유튜브 썸네일용:**
- "에이전트 50개? 관리가 진짜 문제입니다"
- "Cursor 다음은 이겁니다"
- "AI 에이전트 팀을 만들어봤습니다 (실제 개발)"
- "Claude + GPT + Gemini 동시에 돌려봤습니다"

**강의 도입부:**
> 여러분, AI 에이전트 하나 돌리는 건 이제 누구나 합니다.
> Cursor 쓰면 되죠. Claude Code 쓰면 되죠.
> 그런데 에이전트 3개, 5개, 10개를 동시에 돌리면?

> 방향을 바꾸고 싶으면 전부 멈춰야 하나요?
> 이 문제를 해결하는 게 마블로입니다.

## 6. 타겟 고객 정의

### 6-1. Primary: 테크 리드 / PM (팀 단위)

- 에이전트 여러 개를 팀 프로젝트에 활용하려는 사람
- 에이전트의 작업 가시성과 비용 통제가 중요한 사람
- "에이전트가 잘 되고 있나?" 확인하고 싶은 사람

### 6-2. Secondary: 1인 개발자 (파워 유저)

- 혼자서 에이전트 2~5개를 동시에 돌리는 사람
- Cursor로는 부족해서 Claude Code + Codex를 섞어 쓰는 사람
- 프로젝트 규모가 커서 태스크 관리가 필요한 사람

### 6-3. Tertiary: AI 에이전트 교육자 / 콘텐츠 크리에이터

- "멀티에이전트 개발" 강의를 만들려는 사람
- 시각적 데모가 필요한 사람 (칸반 + 터미널 = 영상 소재)
- 바이브코딩 콘텐츠 차별화가 필요한 사람

## 7. 경쟁 대응 메시지

### 7-1. "Claude Code 내부 에이전트면 충분하지 않나요?"

> Claude Code의 Task tool은 강력합니다. 하지만 하나의 터미널 안에서 일어나는 일이라,
> 에이전트가 뭘 하는지 보이지 않고, 비용이 합산되고, PM이 개입할 수 없습니다.
> Marblo는 각 에이전트를 독립 터미널로 분리해서 모니터링하고,
> 칸반 보드로 태스크를 관리하고, 실시간 피드백을 줄 수 있습니다.

### 7-2. "CrewAI/AutoGen으로 충분하지 않나요?"

> CrewAI, AutoGen은 Python 코드로 에이전트를 정의하는 프레임워크입니다.
> 코드를 짤 수 있는 개발자에게는 유용하지만, UI가 없고, 실시간 모니터링이 안 되고,
> 에이전트를 멈추지 않고 피드백을 주는 것이 불가능합니다.
> Marblo는 코드 없이도 에이전트 팀을 구성하고 관리할 수 있는 데스크탑 환경입니다.

### 7-3. "Cursor가 멀티에이전트 추가하면?"

> Cursor가 멀티에이전트를 추가하더라도, Cursor의 모델만 사용해야 합니다.
> Marblo는 Claude, GPT, Gemini, Codex 등 어떤 AI 모델이든 하나의 보드에서 관리합니다.
> 특정 벤더에 종속되지 않는 것이 Marblo의 핵심 가치입니다.

## 9. 투자자/사업 설명용 요약

### 엘리베이터 피치 (30초)

> Marblo는 AI 에이전트 팀의 개발 환경입니다.
> 개발자들이 Claude, GPT, Gemini 같은 AI 에이전트 여러 개를 동시에 돌리는 시대가 왔는데,
> 이 에이전트들이 뭘 하고 있는지 모니터링하고, 태스크를 배분하고, 비용을 추적하는 도구가 없습니다.
> Marblo가 그 문제를 해결합니다.
> Cursor가 개인 개발자의 AI 코딩 도구라면, Marblo는 팀의 AI 에이전트 관리 플랫폼입니다.

### 시장 기회

> 2026년 기준, AI 코딩 에이전트 시장이 폭발적으로 성장 중입니다.
> 하지만 에이전트를 "쓰는" 도구만 있고 "관리하는" 도구는 없습니다.
> 에이전트가 1개일 때는 관리가 필요 없지만,
> 3개, 10개, 50개로 늘어나면 관리 없이는 생산성이 오히려 떨어집니다.
> Marblo는 이 "AI 에이전트 관리" 카테고리를 개척합니다.

### 비유: "에이전트계의 Snowflake"

Snowflake가 멀티클라우드 시대에 데이터 통합 레이어로 $70B 기업이 된 것처럼,
Marblo는 멀티모델 시대에 에이전트 관리 레이어를 구축합니다.

```
Snowflake: 어떤 클라우드든(AWS, Azure, GCP) 데이터를 통합 관리
Marblo:    어떤 AI든(Claude, GPT, Gemini) 에이전트를 통합 관리
```

| | Snowflake | Marblo |
|---|-----------|--------|
| 핵심 가치 | 멀티클라우드 데이터 통합 | 멀티모델 에이전트 통합 |
| BigTech가 못하는 이유 | AWS가 Azure 데이터를 지원할 리 없음 | Anthropic이 GPT를 지원할 리 없음 |
| 고객 니즈 | "데이터가 여기저기 흩어져 있어" | "에이전트가 여기저기 흩어져 있어" |
| 해자(Moat) | 벤더 중립 + 데이터 lock-in | 벤더 중립 + 워크플로우 lock-in |
| 성장 동력 | 클라우드 많아질수록 가치 증가 | AI 모델 많아질수록 가치 증가 |

**구조적 해자 — BigTech가 카피할 수 없는 이유:**

```
Anthropic이 만들면? → Claude만 지원 (GPT/Gemini 절대 안 넣음)
OpenAI가 만들면?    → GPT만 지원 (Claude 절대 안 넣음)
Google이 만들면?    → Gemini만 지원
Microsoft가 만들면? → Azure/GPT 종속
```

벤더 중립 멀티에이전트 관리는 BigTech의 이해관계와 구조적으로 충돌합니다.
이것은 기술 문제가 아니라 사업 구조 문제이므로, 시간이 지나도 해소되지 않습니다.
AI 모델이 다양해질수록 Marblo의 가치는 오히려 증가합니다.

> Snowflake가 "데이터의 스위스"라면, Marblo는 "AI 에이전트의 스위스"입니다.
