# 지식위키 시스템 사양서 (프로젝트 무관 · 포터블)

> **이 문서의 용도**: 어떤 프로젝트에든 **문서가 흩어지기 시작한 시점**에 얹을 수 있는, 재사용 가능한 지식위키 시스템의 완전한 사양이다.
> 도메인(금융·의료·SaaS·리서치랩·게임 무관)에 의존하지 않는다. 도메인 의존적인 것은 **폴더 이름과 태그 값뿐**이며, 그 둘을 어떻게 정하는지도 §1·§2.6 에 규정돼 있다.

| 항목        | 값                                                                                                                                                                           |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 문서 성격   | **규범(normative)** — 이 문서가 시스템의 정의다                                                                                                                              |
| 적용 대상   | 마크다운 문서가 **30건 이상**으로 늘어난 모든 리포                                                                                                                           |
| 필요 런타임 | Python 3.9+ (린터 1개, 표준 라이브러리만) · 선택적으로 Marblo MCP 위키 도구                                                                                                  |
| 라이브 영향 | **없음.** 이 시스템은 `docs/` 아래에서만 동작하며 코드·config·런타임을 건드리지 않는다                                                                                       |
| 예시 구현   | 본 리포의 `docs/wiki/` (노트 65건 · 폴더 인덱스 15 · 원본 앵커 160+). 아래 모든 절의 `▶ 예시` 블록이 그것을 가리킨다. **예시는 예시일 뿐이고, 규범은 예시 바깥의 본문이다.** |

## 0. 이 시스템이 푸는 문제

문서가 30건을 넘으면 세 가지가 동시에 무너진다.

| 무너지는 것 | 증상                                                                  | 이 시스템의 대응                                                       |
| ----------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **탐색**    | "그거 어디 적혀 있더라" — 파일명 grep 말고는 길이 없다                | ③ 그래프 구축 — `[[슬러그]]` + Backlinks 대칭 + 허브                   |
| **신뢰**    | 같은 수치가 세 문서에 다르게 적혀 있다                                | ② 문서 구축 — 원본 무변경 참조 + 중복 최소 원칙 + "갈리면 원본이 옳다" |
| **정직성**  | 성공만 기록되고 **무엇이 죽었는지**가 사라진다 → 같은 삽질을 반복한다 | ② 정직성 규약 + 특수문서(기각 원장 · 후보 트래커)                      |

★핵심 설계 판단: **폴더는 저장 구조, 그래프는 탐색 구조**다. 둘을 하나로 합치려 하면(=폴더 계층으로 탐색까지 해결하려 하면) 반드시 실패한다. 한 노트는 물리적으로 한 폴더에만 있지만, 개념적으로는 여러 축에 걸치기 때문이다.

### 4개 축

| 축                | 무엇을 정하나                          | 본 문서 |
| ----------------- | -------------------------------------- | ------- |
| ① **폴더 구축**   | 노트가 **어디에 놓이나**               | §1      |
| ② **문서 구축**   | 노트 **한 장이 어떻게 생겼나**         | §2      |
| ③ **그래프 구축** | 노트끼리 **어떻게 이어지나**           | §3      |
| ④ **자동화**      | 사람이 안 해도 되는 것을 **누가 하나** | §4      |

## 1. ① 폴더 구축

### 1.1 루트 위치

위키는 **리포의 기존 문서 디렉터리 아래 별도 서브트리**로 만든다.

```
<repo>/docs/wiki/          ← 위키 루트. 이 아래만이 위키다
<repo>/docs/*.md           ← 기존 문서. 위키가 아니다. 삭제·이동·편집 금지
<repo>/docs/<evidence>/    ← 원시 산출물(감사·리포트·실험로그). 위키가 아니다
```

★**리포 루트를 위키 루트로 삼지 않는다.** 루트로 잡으면 기존 문서 전체가 위키로 빨려들어가 §2.3(원본 무변경)이 첫날에 깨진다. 위키 도구의 `root_path` 도 **항상 이 서브트리**로 고정한다.

### 1.2 번호-도메인 트리

폴더는 **`NN-도메인명`** 형식이다. `NN` 은 두 자리 정렬번호, 10 단위로 띄운다.

```
docs/wiki/
  README.md            ← 위키 홈. 사람이 쓰는 최상위 인덱스
  00-<기반>/           시스템·데이터·용어 — "이게 무엇으로 되어 있나"
  10-<주력>/           현재 살아 움직이는 것 — "지금 뭐가 돌고 있나"
  20-<제약>/           규칙·가드·한계 — "무엇이 막혀 있나"
  30-<탐구>/           시도와 판정의 이력 — "무엇을 해봤나"  ★하위폴더로 세분
  40-<방법론>/         어떻게 판단하는가 — "무엇을 근거로 믿나"
  50-<운영>/           실행·인시던트·배포 — "밖에서 무슨 일이 있었나"
  _meta/               규약·태그사전·링크맵·린트·특수원장
```

**번호 슬롯의 의미는 고정, 이름은 프로젝트가 정한다.**

| 슬롯    | 고정된 역할                          | 이름 짓기                                  |
| ------- | ------------------------------------ | ------------------------------------------ |
| `00`    | **기반** — 나머지 전부가 전제하는 것 | 아키텍처·데이터소스·도메인 용어            |
| `10`    | **주력** — 지금 운영/제공되는 실물   | 제품·서비스·전략·모듈                      |
| `20`    | **제약** — 주력을 제한하는 규칙      | 안전장치·정책·리스크·컴플라이언스          |
| `30`    | **탐구** — 판정이 남는 시도          | 실험·조사·PoC·A/B — ★대개 여기가 가장 크다 |
| `40`    | **방법론** — 판정을 만드는 규칙 자체 | 검증절차·품질기준·리뷰규약                 |
| `50`    | **운영** — 바깥세계와 부딪힌 기록    | 배포·장애·고객이슈·공지                    |
| `_meta` | **위키 자신**                        | 고정. 이름 바꾸지 않는다                   |

- 10 단위로 띄우는 이유: 나중에 `15-` 를 끼워넣어도 정렬이 안 깨진다.
- 슬롯이 비면 그냥 만들지 않는다. **빈 폴더를 미리 파두지 않는다.**
- 폴더 추가는 "노트가 3건 이상 모였을 때" — 그 전엔 인접 폴더에 둔다.

▶ **예시** — 본 리포는 `00-foundations` / `10-strategies` / `20-risk-gates` / `30-experiments` / `40-methodology` / `50-live-ops` / `_meta` 로 채웠다.

### 1.3 탐구 폴더(`30-`)의 도메인 세분

`30-` 은 **혼자만 하위폴더를 가진다.** 이유는 구조적이다 — 탐구는 계속 쌓이기만 하고 줄지 않는다. 나머지 폴더는 노트가 교체되지만(전략이 바뀌면 노트를 고침), 탐구는 **끝난 것도 지우지 않는다**(기각 이력이 자산이므로 §2.4).

```
30-<탐구>/
  README.md                  ← 탐구 전체 인덱스 + 도메인 표
  <도메인A>/README.md         ← 도메인 인덱스
  <도메인A>/<노트>.md
  <도메인B>/...
```

**세분 기준 — "무엇을 건드렸나"이지 "언제 했나"가 아니다.**

| 옳은 축                                | 틀린 축                   | 왜                                                                                                                     |
| -------------------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 건드린 **대상**(어떤 부품·어떤 가설축) | **시간**(2025/2026)       | 시간축은 이미 `date` 와 로그에 있다. 폴더로 또 만들면 "작년에 뭐 했더라"만 풀리고 "이 부품 건드린 적 있나"는 안 풀린다 |
| **결론이 서로 이어지는** 묶음          | 담당자·팀                 | 담당은 바뀐다. 결론은 안 바뀐다                                                                                        |
| —                                      | **판정값**(`no-go/adopt`) | ★판정별 폴더는 금물. 판정이 뒤집히면 파일이 이사해야 하고 그러면 링크가 전부 깨진다. 판정은 **태그**로 (§2.6)          |

세분 시점: **한 도메인에 노트 3건**이 모이면 폴더를 판다. 그 전엔 `30-` 바로 아래 평평하게 둔다.

▶ **예시** — 8개 도메인(`selection` `timing-entry` `risk-gates` `flow-crowding` `tenbagger` `portfolio` `crypto` `candidates`). 마지막 `candidates` 만 성격이 다르다 — **판정이 아니라 대기열**이며, 그래서 폴더 인덱스 한 줄이 "★판정이 아니라 대기열"이라고 못박는다. 성격이 다른 묶음은 이렇게 **인덱스 한 줄로 경고**한다.

### 1.4 파일명 규약

| 규칙                                  | 내용                                                                                                          |
| ------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| **ASCII kebab-case**                  | `entry-timing-absent.md`. 공백·대문자·비ASCII 금지                                                            |
| **비ASCII 파일명 금지**               | wikilink 해석·툴체인·OS 이식성 리스크. 사람이 읽는 제목은 frontmatter `title` 에 (거긴 어떤 언어든 허용)      |
| ★**슬러그 전역 유일**                 | 폴더가 달라도 같은 파일명 금지. wikilink 가 **경로 없이 슬러그만** 쓰기 때문 (§3.1)                           |
| **폴더마다 `README.md`**              | 그 도메인의 인덱스                                                                                            |
| ★**`README` 는 wikilink 대상이 아님** | 파일명이 전부 `README` 라 슬러그가 충돌한다. 폴더 README 는 **상대경로 마크다운 링크로만** 연결               |
| **`_meta/` 는 대문자 예외**           | `CONVENTION.md` `LINK-MAP.md` 등. 규범 문서임을 눈에 띄게 하려는 의도적 예외. 슬러그 매칭은 **대소문자 무시** |

### 1.5 폴더 = 저장, 그래프 = 탐색

이 시스템에서 **폴더가 하는 일은 딱 두 가지**다.

1. 파일이 물리적으로 놓일 자리를 하나 준다 (중복 저장 방지)
2. 정렬된 목차를 제공한다 (`00`→`50` 순으로 훑으면 전체가 한 번 지나간다)

**폴더가 하지 않는 일**:

- ❌ 주제 분류 — 한 노트가 여러 주제를 걸치는 게 정상이다 → **태그**(§2.6)
- ❌ 관련 노트 찾기 — 옆 폴더 노트가 더 가까울 수 있다 → **wikilink**(§3.1)
- ❌ 상태 표현 — 진행중/완료/폐기 → **`status` 필드**(§2.1)

★따라서 **"이 노트를 어느 폴더에 둘지" 로 30분 고민하면 이미 진 것이다.** 하나 골라 넣고, 나머지는 태그와 링크로 표현한다. 폴더는 틀려도 링크가 맞으면 찾을 수 있고, 폴더가 맞아도 링크가 없으면 못 찾는다.

## 2. ② 문서 구축

### 2.1 Frontmatter — 필수 5필드, 순서 고정

모든 노트는 정확히 이 5필드로 시작한다. **필드 추가 금지.**

```yaml
---
title: 사람이 읽는 한 줄 정체 (어떤 언어든)
tags: [domain/<대분류>, verdict/<판정>, topic/<주제>, method/<기법>]
status: verified
date: 2026-08-24
links: [[이웃슬러그1]], [[이웃슬러그2]]
---
```

| 필드     | 타입              | 규칙                                                                        |
| -------- | ----------------- | --------------------------------------------------------------------------- |
| `title`  | 문자열            | 노트의 한 줄 정체. 파일 슬러그와 1:1 대응                                   |
| `tags`   | 배열              | `네임스페이스/값` 형식만. 사전은 `_meta/TAXONOMY.md`. **자유태그 금지**     |
| `status` | enum              | `stub` \| `draft` \| `active` \| `verified` \| `superseded`                 |
| `date`   | `YYYY-MM-DD`      | ★**최종 갱신일**(생성일 아님)                                               |
| `links`  | `[[슬러그]]` 나열 | 이 노트가 **의도적으로 잇는** 이웃. 본문 인라인 링크와 별개인 "선언된 간선" |

**왜 5개로 고정하나** — 필드는 늘어나기만 한다. 필드가 늘면 ⓐ 과거 노트가 전부 미달이 되고 ⓑ 린터가 복잡해지고 ⓒ 아무도 안 채운다. 5개는 "빠뜨리면 바로 눈에 띄는" 상한이다. 프로젝트가 더 필요하면 **필드를 늘리지 말고 태그 네임스페이스를 늘린다**(§2.6).

`status` 의미:

| 값           | 의미                                    | 다음 상태                             |
| ------------ | --------------------------------------- | ------------------------------------- |
| `stub`       | 자리만 잡음, 내용 없음                  | → `draft`                             |
| `draft`      | 내용 있으나 미검토                      | → `active` / `verified`               |
| `active`     | 현재 참조되는 살아있는 문서 (계속 갱신) | 종착 가능                             |
| `verified`   | 판정 확정 (탐구 노트의 정상 종착)       | → `superseded`                        |
| `superseded` | 후속 노트가 대체함                      | ★반드시 `links` 에 후속 노트를 넣는다 |

### 2.2 ★자체완결 노트 템플릿

```markdown
# {title}

> **한 줄 판정**: (결론 한 문장 — ★핵심 수치를 이 줄 안에)

## 무엇을 물었나

## 무엇을 했나

## 결과 (수치)

## 한계 / 정직성

## <라이브/실제> 영향

## Evidence

- [원시 산출물](상대경로)
- 원장 조항 `§x-y` — [<원장파일>](상대경로)

## Backlinks

- [[a]] · [[b]]
```

`## Evidence` 와 `## Backlinks` 는 **모든 콘텐츠 노트에 필수**(린터가 검사한다).

★그러나 **섹션이 있는 것만으로는 부족하다.** 빈 `## 결과` 는 섹션 충족이지 자체완결 충족이 아니다. 아래 R1~R6 이 실제 기준이다.

#### 자체완결 기준 R1~R6

> **대원칙**: 노트는 **링크를 한 번도 안 따라가고** 읽어도 **판정·핵심수치·왜·한계**를 회수할 수 있어야 한다.
> 링크는 **더 깊이 파려는 사람을 위한 것**이지, **본문의 공백을 메우는 장치가 아니다.**

| #      | 기준                                                                                                               | 충족                                                                                            | ★불충족 (= 얇은 노트)              |
| ------ | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------- | ---------------------------------- |
| **R1** | **결론 한 줄** — 판정을 그 자리에서 말한다. ★판정이 수치로 갈렸으면 **그 수치를 같이 적는다**                      | "★순증분 **NO** — OFF 지표 **0.513** > ON **0.318**, 부호검정 **p=0.994**"                      | "검정했다. 결과는 아래 링크 참조"  |
| **R2** | **핵심수치 인라인** — 판정을 뒤집을 수 있는 수치가 **표로** 본문에 있다. 최소 **판정근거 지표 + 유의성 + 표본** 셋 | 지표 3~6개 · 유의성(p·보정·백분위) · 표본(n·창수·시드수)                                        | 지표만 있고 **유의성·표본이 없다** |
| **R3** | **왜 (1~2줄)** — 그 결과가 나온 **메커니즘**. 결과만으론 재사용이 안 된다                                          | "차단이 손실회피가 아니라 **승자누락**으로 작동했다 — 차단대상 이후 평균이 플러스"              | "통과하지 못했다" 로 끝            |
| **R4** | **한계** — 표본크기 · 편의(생존/사후선택/인샘플) · 프록시 여부를 **명시**                                          | "n=28 · 현행 목록 소급 = 사후선택편의 · 프록시 사용"                                            | "한계 있음" 같은 무내용 문장       |
| **R5** | **실제 영향** — 코드/설정/운영 **변경 여부를 단어로**. 무변경이면 "무변경"                                         | "무변경. 설정·운영 무변경"                                                                      | 절 자체가 없음                     |
| **R6** | ★**링크 의존 금지** — "상세는 원본에", "이 노트는 인덱스이며 재서술하지 않는다" 류 **deferral 문장 금지**          | "표는 **요지와 핵심 수치만** 인라인한 것이다. 전문은 원본에 있고 **수치가 갈리면 원본이 옳다**" | "상세는 각 원본 파일에 있다"       |

★판정이 본래 수치가 아닌 노트 — 규범 문서, 아키텍처 설명, **판정불가(`undecidable`)** — 는 R1 에서 수치 대신 **"무엇에 대한 어떤 주장인지"** 를 못박는다. 예: "★**나빠서가 아니라 검증이 불가능해서** 탈락 — 시계열이 시점보존형이 아니다".

#### ★중복 최소 원칙 (드리프트 방지)

R2 를 "원본을 통째로 옮겨라"로 읽으면 안 된다. **인라인하는 것은 판정을 좌우하는 줄뿐**이다.

- ✅ **인라인** — 판정 · 판정근거 지표 3~6개 · 유의성 · 표본 · 한계 · 실제영향 · "왜"
- ❌ **인라인 안 함** — 전체 결과표 · 파라미터 그리드 전수 · 로그 · 재현 명령 · 스키마 · 원시 JSON

★**같은 수치를 두 곳에 두면 반드시 갈린다.** 그래서 노트에는 **최소 집합**만 두고, ★**갈리면 원본이 옳다**를 한계 절에 적는다.

### 2.3 원본 무변경 참조 (P1/P2)

| #      | 원칙                         | 의미                                                                                                                                       |
| ------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **P1** | **복사 + 링크만**            | 기존 문서는 **삭제·이동·편집 금지**. 위키는 요약을 새로 쓰고 원본을 링크한다                                                               |
| **P2** | **원장은 소유자 전용**       | 프로젝트에 단일 원장(source-of-truth ledger)이 있으면 그것은 **읽기 전용**. 위키가 조항을 인용·요약할 뿐, 위키 때문에 원장을 고치지 않는다 |
| **P3** | **결론 먼저, 근거는 링크로** | 본문은 판정·수치·한계까지. 원시 산출물은 Evidence 링크                                                                                     |
| **P4** | **정직성 우선**              | §2.4                                                                                                                                       |
| **P5** | **한 노트 = 한 주장**        | 두 판정이면 노트를 쪼갠다                                                                                                                  |
| **P6** | **자체완결**                 | §2.2 R1~R6                                                                                                                                 |

★**P3 와 P6 는 충돌하지 않는다.** P3 는 "**원시 산출물**을 링크로", P6 는 "**결론과 그 근거수치**는 인라인"이다.

**왜 원본을 안 고치나** — 위키를 얹는 시점의 리포에는 이미 사람·스크립트·다른 문서가 기존 경로에 의존하고 있다. 위키 도입이 그 의존을 깨면 **위키가 도입 실패의 원인**이 된다. "아무것도 안 깨는 층"이어야 도입이 통과된다.

**외부 참조 표기** — 위키 밖 파일은 wikilink 가 **아니라** 상대경로 마크다운 링크:

```markdown
[docs/evidence/2026-08-20_xxx.md](../../evidence/2026-08-20_xxx.md)
원장 조항 `§2-63` — [LEDGER.md](../../LEDGER.md)
```

★wikilink 는 **위키 내부 그래프 전용**이다. 외부를 wikilink 로 걸면 린터가 깨진링크로 잡는다.

### 2.4 정직성 규약

> **이 위키는 성과 자랑이 아니라 무엇이 죽었는지의 기록이다.**

| 규칙                                   | 내용                                                                                                                                                             |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **기각을 지우지 않는다**               | 실패한 시도의 노트는 성공한 것과 **같은 격**으로 남는다. 폴더도 같고 인덱스에도 같이 오른다                                                                      |
| **한계·표본크기 필수**                 | R4. 수치만 옮기고 한계를 빼면 **위키가 원본보다 위험해진다**                                                                                                     |
| ★**"기각"과 "판정불가"를 섞지 않는다** | `no-go` = 봤는데 없다. `undecidable` = **볼 수가 없었다**. 후자는 데이터가 생기면 **재검 대상**이고, 전자는 아니다. 이 둘을 합치면 재검 자격 판단이 불가능해진다 |
| **판정 분포를 홈에 노출**              | 위키 홈에 `no-go/adopt/observe/undecidable` 건수 표를 둔다. ★기각이 채택보다 많은 게 정상이고, 그 비율이 보이는 것 자체가 규율이다                               |
| **뒤집힘을 지우지 않는다**             | 결론이 뒤집히면 옛 결론을 삭제하지 말고 **"그 뒤 무엇이 돌았나" 절을 추가**한다. 뒤집힘의 이력이 자산이다                                                        |
| **인용 규율**                          | 외부로 나가는 수치는 별도 노트(`citation-warnings` 류)에 **인용 금지 목록**을 두고 그 관문을 통과시킨다                                                          |

#### ★staleness — 노트는 낡는다

노트는 작성 시점 스냅샷이다. 뒤에 같은 주제가 다시 다뤄지면 **노트의 문장이 거짓이 된다**(예: "이건 단독 검정된 적이 없다" 가 단독 검정 후 거짓이 됨).

- 후속 작업이 끝나면 ★**관련 노트 본문을 같은 커밋에서 고치고 `date` 를 갱신**한다.
- 판정이 완전히 대체되면 `status: superseded` + `links` 에 후속 노트.
- ★**원본을 노트에 맞춰 고치지 않는다**(P1). 노트가 낡았으면 **노트를 고친다.**

### 2.5 특수문서 — 일반 노트 규약이 안 맞는 두 종류

일반 노트는 "**하나의 확정된 판정**"이다. 그 틀에 안 맞는 문서가 정확히 두 종류 있고, 둘 다 `_meta/` 나 탐구 하위폴더에 **의도적 예외**로 둔다.

#### (A) 기각 원장 — `do-not-retry` 형

> **용도**: 새 아이디어가 나오면 **가장 먼저 여기를 검색**한다. 여기 있으면 재시도하지 않는다.

| 속성     | 값                                                                 |
| -------- | ------------------------------------------------------------------ |
| 위치     | `_meta/do-not-retry.md`                                            |
| `status` | `active` (+ `status/living` 보조태그)                              |
| 형태     | **표 원장** — 항목 하나당 한 행                                    |
| 필수 열  | `#ID` · 무엇 · **왜 죽었나(수치 포함)** · 원본 참조 · **사유코드** |

★핵심 장치는 **사유코드**다. 사유코드는 단순 분류가 아니라 ★**"무엇이 바뀌어야 재검정할 자격이 생기는가"의 정의**다.

| 코드 | 사유(패턴)                   | 재시도 해금 조건                            |
| ---- | ---------------------------- | ------------------------------------------- |
| `C1` | 표본 선택 편의 산물          | 편의 없는 표본 복원 + 진단 클린             |
| `C2` | 이미 알려진 변수에 흡수됨    | 기존 변수 잔차화 후 독립 기여 실증          |
| `C3` | 현실 비용에서 사망           | 실측 비용 포함 모델에서 재검                |
| `C4` | 다중검정 아티팩트            | 사전등록 단일가설 + 다중보정 + OOS 동시통과 |
| `C5` | **데이터 부재 = 검정 불가**  | 해당 데이터 확보(대개 시간이 필요)          |
| `C6` | 낙관적 프록시 산물           | 실데이터로 프록시 대체                      |
| `C7` | 단순 기준선(baseline)에 열위 | 기준선을 이기는 증거                        |
| `C8` | 구조적 부적합                | 시스템 구조 자체가 바뀌어야 함              |
| `C9` | look-ahead 주입 시에만 생존  | 시점 정합 복원 후 재측정                    |
| `C0` | **외부 인용 금지 수치**      | (해금 없음 — 인용 자체가 금지)              |

★코드 표는 **프로젝트가 자기 실패 패턴으로 다시 채운다.** 위 10개는 "정량 검정을 하는 프로젝트"의 전형이며, 제품·엔지니어링 프로젝트라면 `C1`(관측 편의) `C3`(운영비용) `C7`(기존안 열위) `C8`(구조 부적합) 정도가 남고 나머지는 도메인 코드로 대체된다.

★원장 상단에 **메타 교훈 3~5개**를 두고 "아래 모든 항목에 선적용"이라고 못박는다. 개별 행을 다 읽지 않아도 **다음 아이디어가 어디서 죽을지**를 미리 알려주는 것이 원장의 진짜 값이다.

#### (B) 후보 트래커 — `candidate-panel` 형

> **용도**: **아직 판정이 안 난 것들의 대기열.** 판정 노트와 절대 섞지 않는다.

| 속성     | 값                                                                                 |
| -------- | ---------------------------------------------------------------------------------- |
| 위치     | `<탐구폴더>/candidates/`                                                           |
| `status` | `draft` 로 시작해 **끝까지 `draft`/`active`** — 트래커는 `verified` 가 되지 않는다 |
| 형태     | **§0 라이브 트래커 표 + 그 아래 후보 상세**                                        |

트래커 표의 필수 열: `후보` · `실험ID` · **`상태`(⬜대기 / 🔄진행 / ✅완료)** · **`판정`(완료된 것만)**.

```markdown
## 0. ★검정 진행 현황 (라이브 트래커 · 최종갱신 YYYY-MM-DD)

> 항목이 끝날 때마다 여기를 갱신한다. 상세 판정·수치는 원장/Evidence 에, 요지는 아래에.

| 후보      | 실험 |  상태   | 판정                            |
| --------- | ---- | :-----: | ------------------------------- |
| **A#6 …** | E1   | ✅ 완료 | ★순증분 NO(…) → 라이브 규칙 OFF |
| A#2 …     | —    | ⬜ 대기 | 낮은 EV(계열 실패)              |

**진행 요약**: 검정 **N/M 완료** — …
```

★세 가지가 트래커를 살린다.

1. **판정이 난 항목을 표에서 지우지 않는다** — ✅ 로 바꾸고 판정을 한 줄 적는다. 지우면 "왜 이건 안 했지?"가 반복된다.
2. **대기 항목에도 사유를 적는다** — "낮은 EV(계열 실패)" 처럼. 사유 없는 ⬜ 는 영원히 ⬜ 다.
3. **최종갱신일을 제목 줄에** — 트래커의 신뢰도는 곧 갱신일이다.

★상단 한 줄 판정에 **"이 노트는 라이브 트래커다"** 를 명시한다. 그래야 독자가 "확정 판정"으로 오독하지 않는다.

### 2.6 태그 사전 (`_meta/TAXONOMY.md`)

태그는 **`네임스페이스/값` 형식만** 허용하고, **사전에 없는 값은 못 쓴다**(린터가 에러). 새 태그는 **사전에 먼저 등록**하고 쓴다.

| 네임스페이스 | 용도                                                                     | 개수 규칙           |
| ------------ | ------------------------------------------------------------------------ | ------------------- |
| `domain/`    | 노트가 속한 대분류 = 폴더와 1:1                                          | **정확히 1개 필수** |
| `topic/`     | 주제축 — ★폴더가 표현 못 하는 교차축                                     | 0~N개               |
| `verdict/`   | 판정 — 탐구 노트에서만                                                   | 0~1개               |
| `method/`    | 사용한 기법·절차                                                         | 0~N개               |
| `status/`    | 문서 성격 보조 (`normative` `living` `frozen`)                           | 0~1개               |
| `meta/`      | `_meta` 전용 (`convention` `taxonomy` `linkmap` `lint` `index` `ledger`) | —                   |
| (도메인축)   | 프로젝트 고유 축 — 예: 대상 시장·플랫폼·자산군·고객군                    | 0~N개               |

**`verdict/` 4값은 이 시스템의 규범이다** (§2.4 정직성 규약의 실행 장치):

| 값                    | 의미                                                               |
| --------------------- | ------------------------------------------------------------------ |
| `verdict/adopt`       | 채택. 실제에 반영됨                                                |
| `verdict/no-go`       | 기각. 반영 근거 없음                                               |
| `verdict/observe`     | 방향성은 있으나 확정 불가 — 관찰·축적만                            |
| `verdict/undecidable` | ★**데이터·표본 부족으로 검정 자체가 불가.** `no-go` 와 섞지 않는다 |

★**자유태그를 허용하면 3개월 안에 사전이 죽는다.** `#todo` `#important` `#temp` 가 생기고, 아무도 안 지우고, 검색이 안 되기 시작한다. 사전 등록을 강제하는 비용(태그 하나 추가에 1분)이 그 결과보다 압도적으로 싸다.

## 3. ③ 그래프 구축

### 3.1 `[[슬러그]]` — 유일한 내부 링크 문법

```markdown
[[crash-gate]] ← 경로·확장자 없이 슬러그만
```

| 규칙                                          | 내용                                                                                                                                                                                                                              |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **경로 없음**                                 | 파일이 폴더를 옮겨도 링크가 안 깨진다. ★그 대가로 §1.4 의 **슬러그 전역 유일**이 필수가 된다                                                                                                                                      |
| **파이프 별칭 금지**                          | `[[slug\|표시명]]` 을 쓰지 않는다 — 도구별 해석 편차가 크다. 별칭이 필요하면 문맥 문장으로 설명                                                                                                                                   |
| **대소문자 무시**                             | 슬러그 매칭은 lowercase 비교                                                                                                                                                                                                      |
| **등록 별칭은 최소**                          | 실무상 `[[wiki-home]] = README.md` 하나면 충분하다. 별칭 표는 `_meta/LINK-MAP.md` 에 두고 **린터가 그 표를 읽어 해석**한다. ★별칭을 늘리지 않는다 — 늘리면 "같은 노트를 두 이름으로 부르는" 상태가 되고 Backlinks 대칭이 무너진다 |
| **외부는 wikilink 아님**                      | §2.3                                                                                                                                                                                                                              |
| ★**코드블록 안의 `[[...]]` 는 링크가 아니다** | 규약 문서가 문법을 **설명**할 때 링크로 잡히면 안 되므로. 그래서 문법 설명은 **반드시 백틱으로 감싼다**                                                                                                                           |

**메모리·에이전트 호환**: `[[name]]` 은 여러 에이전트 메모리 시스템(Marblo memory 포함)의 표기와 동일하다. 위키 노트에 적은 `[[슬러그]]` 를 그대로 에이전트 메모리에 적어도 같은 대상을 가리킨다. ★이 정합성은 우연이 아니라 **설계 제약**이다 — 그래서 파이프 별칭을 금지한다.

### 3.2 Backlinks 대칭

> 규칙: `A` 의 `links` 나 본문에 `[[B]]` 가 있으면, `B` 의 `## Backlinks` 에 `[[A]]` 가 있어야 한다.

- **수동 유지 + 린트 검증**이다. 자동생성은 §4.3 의 자동화 후보.
- 비대칭은 ★**경고(WARN)이지 에러가 아니다** — 의도적 단방향(원장→일반노트 같은)이 존재하기 때문. 단방향을 의도했으면 **노트에 사유를 적는다**.
- 인덱스(`README`)와 `_meta/` 는 대칭 검사에서 제외한다 — 인덱스는 정의상 나가는 링크만 많다.

**왜 대칭이 중요한가** — 단방향 그래프에서는 "이 노트를 누가 참조하나"를 알 수 없다. 그런데 노트를 **고칠 때 실제로 필요한 정보가 바로 그것**이다(§2.4 staleness). Backlinks 는 탐색 편의가 아니라 **갱신 안전장치**다.

### 3.3 링크 맵 (`_meta/LINK-MAP.md`) — 그래프의 단일 등록부

| 절                 | 내용                                      | 왜                                                                                                  |
| ------------------ | ----------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `## 별칭`          | `별칭 → 실제 파일` 표                     | ★**린터가 파싱하는 표**다. 형식(첫 열=별칭, 둘째 열=상대경로, 둘 다 백틱)을 바꾸면 린터가 못 읽는다 |
| `## 슬러그 등록부` | 슬러그 · 파일 · domain · status · verdict | 위키 전체 목록의 단일 소스                                                                          |
| `## 간선`          | from → to (frontmatter `links` 기준)      | 그래프 형태를 사람이 훑는 용도                                                                      |
| `## 허브`          | 인바운드 링크 수 상위                     | ★**허브가 곧 이 프로젝트의 핵심 개념**이다. 허브가 예상과 다르면 구조가 잘못된 것                   |
| `## 외부 앵커`     | 위키 → 기존 문서/코드 매핑 (양방향 표)    | 원본이 바뀌었을 때 **어느 노트를 고쳐야 하는지** 역인덱스                                           |

★**새 노트를 만들면 ⓐ 폴더 README ⓑ LINK-MAP 을 같은 커밋에서 갱신**한다. 이 둘이 밀리면 위키는 파일 더미로 되돌아간다.

▶ **예시** — 본 리포의 허브 상위는 `adversarial-validation`(인바운드 41) → `timing-alpha-absent`(25) → `do-not-retry`(19). ★최대 허브가 "**판정 규칙 문서**"라는 것이 이 랩의 정체를 드러낸다. 허브 표는 그런 식으로 읽는다.

### 3.4 린트 7종

```
python3 docs/wiki/_meta/lint_wiki.py [wiki_root]
```

- **읽기 전용.** 어떤 파일도 수정하지 않는다.
- 종료코드: 에러 있으면 `1`, 없으면 `0`. **경고는 `0`** (의도적 단방향 허용).
- 표준 라이브러리만 사용 — 설치 없이 어느 리포에나 복사해 쓴다.

| 코드  | 심각도    | 의미                                                             | 고치는 법                            |
| ----- | --------- | ---------------------------------------------------------------- | ------------------------------------ |
| `FM`  | **ERROR** | frontmatter 5필드가 순서대로 없음 / `status`·`date` 값이 규약 밖 | §2.1 형식대로                        |
| `TAG` | **ERROR** | 태그 사전에 없는 태그                                            | 사전에 먼저 등록                     |
| `BRK` | **ERROR** | 대상 슬러그가 없는 `[[wikilink]]`                                | 오타 수정 또는 대상 노트 생성        |
| `DUP` | **ERROR** | 폴더가 달라도 같은 슬러그                                        | 슬러그는 전역 유일 (§1.4)            |
| `ORP` | **ERROR** | 인바운드 wikilink 0 = 고아                                       | 홈이나 관련 노트에서 링크를 걸어준다 |
| `SEC` | **ERROR** | 콘텐츠 노트에 `## Evidence` 또는 `## Backlinks` 없음             | §2.2                                 |
| `BL`  | WARN      | `A→B` 인데 `B` 의 Backlinks 에 `[[A]]` 없음                      | 역방향 기재 또는 단방향 사유 명시    |

**린터가 일부러 무시하는 것**

- 코드블록/인라인코드 안의 `[[...]]` — 규약 문서의 **예시**가 링크로 잡히면 안 되므로
- `README.md` — wikilink 대상이 아님 (§1.4)
- 도구 소유 파일(`index.md` `log.md` `MEMORY.md`) — 사람이 안 쓰므로 규약 검사 제외. 단 **링크 대상으로는 인정**하고 **고아 판정에서도 제외**한다

#### ★린터가 검사하지 **못하는** 것 — 자체완결성

§2.2 의 **R1~R6** 은 기계 검사 대상이 아니다. `SEC` 는 절이 **있는지**만 보고, **비어 있어도 통과**한다.

★따라서 **린트 에러 0 은 "규약 위반이 없다"이지 "노트가 자체완결이다"가 아니다.** 자체완결성은 사람이 리뷰에서 본다. 빠르게 훑는 법:

```bash
# R6 deferral 문장 탐지 (프로젝트 언어에 맞게 패턴 교체)
grep -rnE '상세는|재서술하지 않|원본에 있|see the original' --include='*.md' docs/wiki | grep -v _meta

# R1 판정 줄에 수치가 있는지
grep -rh '한 줄 판정' --include='*.md' docs/wiki | grep -vE '[0-9]'
```

### 3.5 위키 도구 연동 (`wiki_ingest` → `wiki_query`)

Marblo MCP 위키 도구는 위키 그래프를 **질의 가능한 층**으로 올린다.

| 도구          | 용도                                                                        | 인자                 |
| ------------- | --------------------------------------------------------------------------- | -------------------- |
| `wiki_ingest` | 문서·링크 그래프 파싱 → `index.md`/`log.md` 생성·갱신, 에이전트 메모리 유지 | `root_path`          |
| `wiki_query`  | 자연어 질의 → 랭크된 마크다운 매치                                          | `root_path`, `query` |
| `wiki_lint`   | index/log 존재 · 해석된 그래프 · 고아 검사                                  | `root_path`          |

```
wiki_ingest(root_path="docs/wiki")
wiki_query(root_path="docs/wiki", query="…")
wiki_lint(root_path="docs/wiki")
```

★두 가지가 규범이다.

1. **`root_path` 는 항상 위키 서브트리로 고정.** 리포 루트로 ingest 하면 기존 문서 전체가 위키로 빨려들어가 P1(§2.3)을 위반한다.
2. **`index.md` · `log.md` · `MEMORY.md` 는 도구 소유 파일이다.** 사람이 손으로 고치지 않는다. 사람이 쓰는 인덱스는 `README.md`.

**두 린트의 관계** — `lint_wiki.py`(규약 층)와 `wiki_lint`(도구 층)는 보는 것이 다르다. 규약 린트는 **글쓰기 규칙**을, 도구 린트는 **도구가 실제로 해석한 그래프**를 본다. 커밋 전 순서: `lint_wiki.py` → `wiki_ingest` → `wiki_lint`.

## 4. ④ 자동화 3층

> ★**본 절은 아래 "P4 정합 주석"의 적용을 받는다.**
>
> **P4 정합 주석 (2026-08-24 갱신 — P4 구현 완료, 실물 정합 반영됨)** — L3 은 데답 P4 구현체와 맞춰졌다. ★실제 구현의 핵심 차이 2가지: **(a) 트래커 렌더는 노트 frontmatter 스캔이 아니라 `candidates_status.json`(후보 단일 소스)에서 렌더한다** — 상태·판정·§참조·audit경로를 그 JSON 한 곳에 두고 스크립트가 표를 생성. **(b) `build_tracker.py` 는 읽기전용 렌더러**(`--check` 대조 / `--ledger` 원장줄 / `--all`)이고 §0 반영은 사람이 적용한다(도구가 사람 문서를 직접 쓰지 않는 L3 안전장치). 스키마는 ★"완료 후보는 `do_not_retry` 블록 또는 `ledger_note` 필수"를 강제해 기각이 원장 연결 없이 종료되는 걸 막는다. 프로젝트가 이식할 때 이 두 설계(JSON 단일소스 · 읽기전용 렌더)를 권장한다.

자동화는 **아래에서 위로** 쌓는다. 상위 층은 하위 층이 통과한다고 전제한다.

| 층     | 이름            | 무엇을 하나                                                   |      쓰기 권한      | 실행 시점             |
| ------ | --------------- | ------------------------------------------------------------- | :-----------------: | --------------------- |
| **L1** | **규약 린트**   | 형식·그래프 무결성 검사                                       |       ❌ 없음       | 커밋 전 · CI          |
| **L2** | **도구 인덱싱** | 그래프 파싱 → 인덱스/로그/메모리 갱신, 자연어 질의            | ⚠️ 도구 소유 파일만 | 노트 추가 후 · 주기적 |
| **L3** | **생성·갱신**   | 원장 파싱 → 노트 스캐폴드, 트래커 자동 갱신, 인덱스 자동 편입 |   ⚠️ 지정 블록만    | 실험 접수/종료 시     |

### L1 — 규약 린트 (읽기 전용)

§3.4 의 `lint_wiki.py`. **아무것도 쓰지 않는다**는 것이 이 층의 정의다.

CI 훅:

```yaml
# 위키 변경이 포함된 PR 에서만 실행
- run: python3 docs/wiki/_meta/lint_wiki.py
```

★L1 을 CI 에 걸기 **전에** 반드시 기존 에러를 0 으로 만든다. 빨간 CI 를 켠 채 두면 사람은 그 신호를 무시하도록 학습한다.

### L2 — 도구 인덱싱 (도구 소유 파일만 씀)

§3.5. **쓰기 범위가 `index.md`/`log.md`/`MEMORY.md` 로 한정**되는 것이 이 층의 안전 근거다.

- 사람 문서(`README.md`, 노트)는 **절대 건드리지 않는다.**
- L1 이 통과한 상태에서만 돌린다 — 깨진 링크가 인덱스에 그대로 실리면 인덱스가 오염된다.

### L3 — 생성·갱신 자동화

> ★L3 만이 **사람 문서에 쓴다.** 그래서 세 가지 안전장치가 규범이다.

| 안전장치                   | 내용                                                                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| ★**마커 블록 안에만 쓴다** | `<!-- auto:start -->` … `<!-- auto:end -->` 사이만 교체. 블록 밖은 사람 영역이며 스크립트가 건드리지 않는다                        |
| ★**원본 파싱은 읽기 전용** | 원장·Evidence 를 **파싱만** 하고 절대 수정하지 않는다 (P1/P2, §2.3)                                                                |
| ★**생성물은 초안이다**     | 스캐폴드가 만든 노트는 `status: stub`. 사람이 R1~R6 을 채워야 `draft` 이상이 된다 — 자동생성 노트가 `verified` 로 태어나면 안 된다 |

#### L3-a. 실험 접수 → 노트 스캐폴드 (`EXPERIMENT-INTAKE`)

새 탐구가 **시작될 때** 접수 규약을 한 장 받아 노트 뼈대를 만든다.

| 단계 | 동작                                                                                                                         |
| ---- | ---------------------------------------------------------------------------------------------------------------------------- |
| 1    | 접수 폼(가설 · 대상 · 검정 설계 · 기각 조건 · 필요 데이터)을 받는다                                                          |
| 2    | ★**기각 원장(§2.5-A)을 먼저 조회** — 히트하면 사유코드의 **해금 조건**을 제시하고, 그게 충족됐다는 진술 없이는 접수를 막는다 |
| 3    | 슬러그 유일성 확인 → 폴더 결정 → `status: stub` 노트 생성(frontmatter 5필드 + 표준 섹션 골격)                                |
| 4    | 후보 트래커(§2.5-B) 표에 ⬜ 대기 행을 추가                                                                                   |
| 5    | 폴더 README · LINK-MAP 등록부에 행 추가                                                                                      |

★2단계가 이 자동화의 존재 이유다. 나머지는 편의지만, **기각 원장 선조회는 규율**이다 — 사람은 원장을 안 읽고, 스크립트는 읽는다.

#### L3-b. 트래커 자동 갱신 (`build_tracker.py`)

탐구가 **끝날 때** 후보 트래커의 `## 0` 표를 갱신한다.

| 단계 | 동작 (★데답 실물 기준)                                                                                                                                                                                           |
| ---- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | ★`candidates_status.json`(후보 단일 소스: `status` · `verdict` · `sections` · `audit` · `do_not_retry`)를 읽는다 — 노트 스캔 아님                                                                                |
| 2    | §0 표 행(⬜/🟢/✅)·판정 칸과 "**진행 요약**: N/M 완료·k건 진행중" 줄·**최종갱신일**을 렌더(집계·원장번호는 스크립트가 세고 배번, 수기 전사 0)                                                                    |
| 3    | ★**읽기전용**: `--check` 로 현 §0 과 대조(불일치 diff·exit 1) / `--ledger` 로 기각 원장 후보줄 렌더. §0 반영은 사람이 적용(도구가 사람 문서 직접 안 씀)                                                          |
| 4    | 스키마 검증: ★**완료 후보는 `do_not_retry` 블록 또는 `ledger_note` 필수**(없으면 FATAL) → 기각이 원장 연결 없이 종료되는 걸 차단. `no-go`/`undecidable` 은 원장 후보로 렌더(자동 병합은 안 함 — 사유코드는 사람) |

★4단계 스키마 강제 + 자동 병합 금지가 규범이다. 사유코드는 "무엇이 바뀌면 재검 가능한가"의 판단이고, 그건 기계가 못 한다.

#### L3-c. 인덱스·원장 파생 (보조)

| 후보                          | 내용                                                    | 상태 |
| ----------------------------- | ------------------------------------------------------- | ---- |
| Backlinks 자동생성            | 현재 수동 + `BL` 경고 (§3.2) → 마커 블록 안 자동생성    | 권장 |
| Evidence 디렉터리 날짜 인덱싱 | 파일명 날짜 → 운영 폴더의 로그 노트에 자동 편입         | 권장 |
| 원장 조항 파서                | 원장 `§x-y` → 노트 매핑 표 자동 생성 (★읽기 전용 파싱)  | 권장 |
| 허브·간선 표 재생성           | LINK-MAP `## 간선`/`## 허브` 를 frontmatter 에서 재계산 | 권장 |

### 자동화 도입 순서 (중요)

```
L1 (린트) → 에러 0 달성 → CI 훅
   ↓
L2 (ingest/query) → root_path 고정 확인
   ↓
L3-a (접수 스캐폴드) → L3-b (트래커) → L3-c (파생)
```

★**순서를 건너뛰지 않는다.** L1 없이 L3 를 넣으면 스크립트가 깨진 그래프 위에 더 쓰고, 되돌리기가 어려워진다.

## 5. 요약 — 이 시스템의 불변 규칙 5개

1. **복사 + 링크만** — 기존 문서·원장은 삭제·이동·편집하지 않는다 (§2.3)
2. **폴더는 저장, 그래프는 탐색** — 폴더 고민에 시간을 쓰지 않는다 (§1.5)
3. **노트는 자체완결** — 링크를 안 따라가도 판정·수치·왜·한계가 회수된다 (§2.2 R1~R6)
4. **정직성 우선** — 기각·한계·표본을 남긴다. 기각과 판정불가를 섞지 않는다 (§2.4)
5. **자동화는 아래에서 위로, 쓰기는 마커 안에서만** (§4)
