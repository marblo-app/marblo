# 지식위키 스킬 스캐폴드 4종

> [WIKI-SYSTEM.md](WIKI-SYSTEM.md) 의 시스템을 **실행 가능한 스킬**로 쪼갠 것이다.
> 각 스킬은 **목적 · 입력 · 단계 · 산출**로 규정되며, 그대로 `skills/<name>.md`(또는 `.claude/skills/<name>/SKILL.md`)로 옮기면 등록된다.
> ★본 문서는 **스캐폴드(사양)** 이다 — 실제 스킬 파일 생성은 [WIKI-ADOPTION-GUIDE.md](WIKI-ADOPTION-GUIDE.md) §3 의 절차를 따른다.

| 스킬                 | 언제 쓰나                                 | 시스템 사양서 대응               |
| -------------------- | ----------------------------------------- | -------------------------------- |
| `/wiki-init`         | 프로젝트에 위키가 **아직 없을 때**, 한 번 | §1 폴더 · §2.1 · §2.6 · §3.3~3.4 |
| `/wiki-note`         | 노트를 **한 장 쓸 때마다**                | §2.2 R1~R6 · §2.4 · §3.1~3.2     |
| `/wiki-ingest`       | 노트를 커밋하기 **직전마다**              | §3.4~3.5 · §4 L1~L2              |
| `/experiment-intake` | 새 탐구를 **시작할 때**                   | §2.5 · §4 L3-a                   |

### 4종의 관계

```
/wiki-init  ──(1회)──▶  위키 뼈대 존재
                            │
      ┌─────────────────────┴─────────────────────┐
      ▼                                           ▼
/experiment-intake  ──(탐구 시작)──▶  stub 노트 + 트래커 ⬜ 행
      │                                           │
      └───────────▶  /wiki-note  ◀────────────────┘
                    (내용 채우기 / 일반 노트 신규작성)
                          │
                          ▼
                    /wiki-ingest   ← 커밋 게이트. 여기를 통과 못 하면 커밋 안 한다
```

## 1. `/wiki-init` — 위키 뼈대 구축

```yaml
---
name: wiki-init
description: >
  프로젝트에 지식위키 뼈대를 1회 구축한다. 번호-도메인 폴더 트리, _meta 규범 4종
  (CONVENTION/TAXONOMY/LINK-MAP/LINT), 로컬 린터, 위키 홈 README 를 만든다.
  기존 문서는 절대 이동·편집하지 않는다(복사+링크만).
---
```

### 목적

`docs/wiki/` 서브트리를 **비어 있지만 규범이 완비된 상태**로 만든다. 이 스킬이 끝나면 `/wiki-note` 를 바로 쓸 수 있다.

★목적이 아닌 것: **기존 문서를 옮기는 것.** 이관은 별개 작업이며 `/wiki-note` 를 반복 적용해서 한다.

### 입력

| 항목                 | 필수 | 내용                                                                              |
| -------------------- | :--: | --------------------------------------------------------------------------------- |
| 위키 루트 경로       |  ✅  | 기본 `docs/wiki`. ★리포 루트 금지 (§1.1)                                          |
| 도메인 슬롯 이름 6개 |  ✅  | `00`~`50` 각 슬롯의 프로젝트별 이름. 사양서 §1.2 표의 "고정된 역할"에 맞춰 정한다 |
| 프로젝트 고유 태그축 |  ⬜  | `topic/` 값 목록 + 도메인 고유 네임스페이스(있으면)                               |
| 원장 파일 경로       |  ⬜  | 단일 source-of-truth 원장이 있으면 그 경로 (P2 대상)                              |
| Evidence 디렉터리    |  ⬜  | 원시 산출물이 쌓이는 경로 (`docs/audit/` 류)                                      |
| 판정 체계 사용 여부  |  ⬜  | 탐구 성격 프로젝트면 `verdict/` 4값 사용. 아니면 생략                             |

### 단계

| #   | 단계                                                                                                                            | 검증                                                                       |
| --- | ------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| 1   | **기존 문서 스캔** — 문서 수·디렉터리·원장 후보·Evidence 디렉터리를 파악해 보고                                                 | 리포를 **읽기만** 한다                                                     |
| 2   | **경로 안전 확인** — 위키 루트가 리포 루트가 아닌지, 이미 존재하지 않는지                                                       | 존재하면 **중단**하고 `/wiki-note` 를 안내                                 |
| 3   | **폴더 트리 생성** — `NN-도메인/` 6개 + `_meta/`, 각 폴더에 `README.md` 스텁                                                    | §1.2·§1.4                                                                  |
| 4   | **`_meta/CONVENTION.md`** — 사양서 §1~§3 을 이 프로젝트 이름으로 인스턴스화한 규범 문서                                         | P1~P6 · R1~R6 이 모두 들어갔는가                                           |
| 5   | **`_meta/TAXONOMY.md`** — `domain/` 6값(폴더와 1:1) + `topic/` + `verdict/` 4값 + `method/` + `status/` + `meta/`               | ★린터가 백틱 `` `ns/value` `` 패턴으로 파싱하므로 **모든 태그를 백틱으로** |
| 6   | **`_meta/LINK-MAP.md`** — `## 별칭`(`wiki-home` 1건) · `## 슬러그 등록부`(빈 표) · `## 간선` · `## 허브` · `## 외부 앵커`       | ★별칭 표 형식 고정 (§3.3)                                                  |
| 7   | **`_meta/LINT.md`** — 린트 7종 표 + 실행법 + ★"린트 0 ≠ 자체완결" 경고절                                                        | §3.4                                                                       |
| 8   | **`_meta/lint_wiki.py`** — 표준 라이브러리만, 읽기 전용, 종료코드 규약                                                          | §3.4                                                                       |
| 9   | **위키 홈 `README.md`** — 불변 규칙 3개 · "여기서 시작하세요" 질문표 · 트리 표 · (판정 체계 사용 시) 판정 분포 표 · 도구 사용법 | ★`[[wiki-home]]` 별칭 대상                                                 |
| 10  | **린트 실행** — `python3 <루트>/_meta/lint_wiki.py`                                                                             | ★**에러 0** 이어야 종료. 아니면 고치고 재실행                              |

### 산출

- `<루트>/README.md` — 위키 홈
- `<루트>/NN-*/README.md` ×6 — 폴더 인덱스 스텁
- `<루트>/_meta/{CONVENTION,TAXONOMY,LINK-MAP,LINT}.md` — 규범 4종
- `<루트>/_meta/lint_wiki.py` — 로컬 린터
- 콘솔: 린트 결과(에러 0) + 다음 액션 안내

★**산출에 없는 것**: 콘텐츠 노트. `/wiki-init` 은 노트를 만들지 않는다.

## 2. `/wiki-note` — 자체완결 노트 작성

```yaml
---
name: wiki-note
description: >
  위키 노트를 한 장 작성하거나 개정한다. frontmatter 5필드, 표준 섹션,
  자체완결 기준 R1~R6 을 강제하고, Backlinks 대칭·폴더 README·LINK-MAP 을
  같은 변경에서 갱신한다. 원본 문서는 참조만 하고 수정하지 않는다.
---
```

### 목적

**링크를 안 따라가도 판정·핵심수치·왜·한계가 회수되는** 노트 한 장을 만든다.

★이 스킬의 난이도는 형식이 아니라 **R1~R6 을 실제로 채우게 만드는 것**에 있다. 린터가 못 잡는 영역이라 스킬이 대신 잡는다.

### 입력

| 항목              | 필수 | 내용                                                |
| ----------------- | :--: | --------------------------------------------------- |
| 주제 / 한 줄 주장 |  ✅  | ★**한 노트 = 한 주장**(P5). 두 주장이면 두 번 실행  |
| 원본 소스         |  ✅  | 요약 대상 원본 파일·원장 조항·Evidence 경로         |
| 폴더(도메인)      |  ⬜  | 미지정 시 스킬이 §1.2 표로 제안                     |
| 판정              |  ⬜  | 탐구 노트면 `adopt`/`no-go`/`observe`/`undecidable` |
| 개정 대상 슬러그  |  ⬜  | 있으면 신규가 아니라 **개정 모드**                  |

### 단계

| #   | 단계                                                                                                | ★게이트                                                                                                     |
| --- | --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 1   | **원본 정독** — 지정된 원본과 Evidence 를 **읽는다**. 요약을 요약하지 않는다                        | 원본을 **수정하지 않는다**(P1/P2)                                                                           |
| 2   | **기각 원장 조회** — 원장이 있으면 이 주제가 이미 죽었는지 확인                                     | 히트하면 **사유코드와 해금 조건**을 사용자에게 제시                                                         |
| 3   | **슬러그 결정** — ASCII kebab-case, **전역 유일** 확인                                              | 중복이면 중단 (§1.4)                                                                                        |
| 4   | **frontmatter 작성** — 5필드 순서 고정, `date` = **오늘(최종 갱신일)**, 태그는 **사전에 있는 값만** | 없는 태그는 **TAXONOMY 에 먼저 등록**하고 진행                                                              |
| 5   | **본문 작성** — 표준 섹션 골격                                                                      | —                                                                                                           |
| 6   | ★**R1 게이트** — 한 줄 판정에 **결론 + 판정을 가른 수치**                                           | 수치 없으면 되돌아가 채운다. 수치가 본래 없는 노트(규범·판정불가)는 **"무엇에 대한 어떤 주장인지"** 로 대체 |
| 7   | ★**R2 게이트** — 결과 표에 **지표 + 유의성 + 표본** 셋                                              | 셋 중 하나라도 없으면 미달. ★단 **전체 결과표를 옮기지 않는다**(중복 최소 원칙)                             |
| 8   | ★**R3 게이트** — "왜 그 결과가 나왔나" 메커니즘 1~2줄                                               | "통과 못 했다" 로 끝나면 미달                                                                               |
| 9   | ★**R4 게이트** — 표본크기 · 편의 · 프록시 여부 + ★"수치가 갈리면 원본이 옳다"                       | "한계 있음" 같은 무내용 문장 금지                                                                           |
| 10  | ★**R5 게이트** — 코드/설정/운영 변경 여부를 **단어로**. 무변경이면 "무변경"                         | 절 누락 금지                                                                                                |
| 11  | ★**R6 게이트** — deferral 문장(`상세는 원본에` 등) **전수 검색 후 제거**                            | 발견 시 그 자리를 실제 내용으로 채운다                                                                      |
| 12  | **Evidence 절** — 원본을 **상대경로 마크다운 링크**로. 원장은 `§조항` 병기                          | ★wikilink 로 걸지 않는다 (§2.3)                                                                             |
| 13  | **링크 · Backlinks 대칭** — `links` 의 각 대상 노트 `## Backlinks` 에 이 슬러그 추가                | §3.2                                                                                                        |
| 14  | **인덱스 갱신** — ⓐ 폴더 `README.md` 표 ⓑ `_meta/LINK-MAP.md` 슬러그 등록부·간선                    | ★**같은 커밋**에서 (§3.3)                                                                                   |
| 15  | **staleness 점검** — 이 노트가 기존 노트의 문장을 거짓으로 만드는가                                 | 만들면 그 노트도 **같은 커밋에서 고치고 `date` 갱신** (§2.4)                                                |
| 16  | **`/wiki-ingest` 호출**                                                                             | 게이트 통과 없이 커밋하지 않는다                                                                            |

### 산출

- `<루트>/<폴더>/<슬러그>.md` — R1~R6 을 만족하는 노트
- 갱신된 폴더 `README.md` 1건
- 갱신된 `_meta/LINK-MAP.md`
- 갱신된 이웃 노트들의 `## Backlinks`
- (필요 시) 갱신된 `_meta/TAXONOMY.md` · staleness 로 고친 기존 노트
- 콘솔: R1~R6 체크리스트 결과

## 3. `/wiki-ingest` — 커밋 게이트 (린트 → 인덱싱 → 도구 린트)

```yaml
---
name: wiki-ingest
description: >
  위키 변경을 커밋하기 직전에 실행하는 게이트. 로컬 규약 린트(에러 0)를 먼저 통과시키고,
  wiki_ingest 로 인덱스/로그/메모리를 갱신한 뒤, wiki_lint 로 도구 층 그래프를 확인한다.
  root_path 는 항상 위키 서브트리로 고정한다.
---
```

### 목적

**깨진 그래프가 커밋되지 않게** 막고, 도구 층 인덱스를 최신으로 유지한다.

★순서가 규범이다: **규약 린트 → ingest → 도구 린트.** 깨진 링크 상태로 ingest 하면 오염된 인덱스가 만들어진다.

### 입력

| 항목               | 필수 | 내용                              |
| ------------------ | :--: | --------------------------------- |
| 위키 루트          |  ✅  | 기본 `docs/wiki`. ★리포 루트 금지 |
| 자체완결 스캔 여부 |  ⬜  | 기본 ON — R1/R6 휴리스틱 grep     |
| 엄격 모드          |  ⬜  | ON 이면 `BL` 경고도 실패로 취급   |

### 단계

| #   | 단계                                                                                            | 실패 시                                                                 |
| --- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| 1   | **범위 확인** — 변경된 위키 파일 목록, root_path 가 서브트리인지                                | 루트가 리포 루트면 **즉시 중단**                                        |
| 2   | **L1 규약 린트** — `python3 <루트>/_meta/lint_wiki.py`                                          | ★**에러 ≥1 이면 여기서 중단.** 코드별 조치(§3.4 표)를 안내하고 되돌린다 |
| 3   | **자체완결 휴리스틱** — deferral 문장 grep(R6) · 판정 줄 수치 없는 노트 grep(R1)                | 기계 검사 불가 영역이므로 ★**경고로 보고**하고 사람이 판단              |
| 4   | **L2 인덱싱** — `wiki_ingest(root_path=…)`                                                      | 도구 미가용이면 **건너뛰고 명시적으로 보고**(조용히 넘어가지 않는다)    |
| 5   | **L2 도구 린트** — `wiki_lint(root_path=…)`                                                     | 고아·index 누락 보고                                                    |
| 6   | **도구 소유 파일 확인** — `index.md`/`log.md`/`MEMORY.md` 외 파일이 도구에 의해 바뀌지 않았는지 | 바뀌었으면 ★**경고** — 도구가 사람 문서를 건드린 것                     |
| 7   | **요약 리포트** — 문서 수 · 슬러그 수 · 에러/경고 · 갱신된 도구 파일                            | —                                                                       |

### 산출

- 콘솔 리포트: `에러 N · 경고 M` + 코드별 조치 안내
- 갱신된 `index.md` · `log.md` · (있으면) `MEMORY.md` — ★**도구 소유 파일만**
- 종료 신호: 에러 0 이면 **커밋 가능**, 아니면 **커밋 금지**

★**이 스킬은 사람 문서를 쓰지 않는다.** 수정이 필요하면 `/wiki-note` 로 돌려보낸다.

## 4. `/experiment-intake` — 탐구 접수 → 스캐폴드

```yaml
---
name: experiment-intake
description: >
  새 탐구(실험/조사/PoC)를 접수한다. 기각 원장을 먼저 조회해 재시도 자격을 검사하고,
  통과하면 stub 노트를 스캐폴드하고 후보 트래커에 대기 행을 추가한다.
  기각 원장 히트 시 사유코드의 해금 조건 충족 진술 없이는 접수를 막는다.
---
```

> ★**P4 정합 주석** — 본 스킬은 P4 티켓(`0NhSeu2s`) 의 `EXPERIMENT-INTAKE` 설계 기준으로 기술한 스캐폴드다.
> **P4 구현이 확정된 뒤 오케스트레이터가 실제 `EXPERIMENT-INTAKE` / `build_tracker.py` 규약과 본 절을 맞춘다.**
> 그때까지 산출 파일명·필드명은 **설계 의도이지 확정 인터페이스가 아니다.**

### 목적

탐구가 **시작되는 순간**에 두 가지를 강제한다.

1. ★**기각 원장 선조회** — 이미 죽은 축을 다시 파지 않게. _사람은 원장을 안 읽고, 스크립트는 읽는다._
2. **사전등록** — 가설·기각 조건을 **결과를 보기 전에** 적게. 사후 자유도를 줄이는 유일한 장치다.

### 입력

| 항목                   | 필수 | 내용                                                               |
| ---------------------- | :--: | ------------------------------------------------------------------ |
| 탐구 이름 / 가설 한 줄 |  ✅  | "무엇이 참이라고 주장하려는가"                                     |
| 대상·범위              |  ✅  | 어디에 적용되는 주장인가                                           |
| 검정 설계              |  ✅  | 무엇을 어떻게 비교하나 (대조군 포함)                               |
| ★**기각 조건**         |  ✅  | ★**어떤 결과가 나오면 이 가설을 버리는가** — 이게 없으면 접수 거부 |
| 필요 데이터            |  ✅  | 있는가 / 없으면 무엇이 필요한가                                    |
| 원장 재시도 근거       |  ⬜  | 원장 히트 시 필수 — **무엇이 달라졌는가**                          |

### 단계

| #   | 단계                                                                                                                                      | ★게이트                                                                                                  |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 1   | **접수 폼 수집** — 위 입력 6항목                                                                                                          | 기각 조건 누락 시 **접수 거부**                                                                          |
| 2   | ★**기각 원장 조회** — `_meta/do-not-retry.md` 를 주제·키워드로 검색                                                                       | —                                                                                                        |
| 3   | ★**재시도 자격 판정** — 히트하면 해당 행의 **사유코드 → 해금 조건**을 제시                                                                | 해금 충족 진술이 없으면 **접수 중단**. 사용자가 "그래도 진행"을 명시하면 ★그 사실을 노트에 기록하고 진행 |
| 4   | **인접 노트 조회** — 같은 도메인 기존 노트·메타 교훈을 요약 제시                                                                          | "이 계열은 N회 실패했다" 를 시작 전에 보여준다                                                           |
| 5   | **슬러그·폴더 결정** — 전역 유일 확인, 탐구 폴더의 도메인 하위폴더 선택                                                                   | 도메인 노트 3건 미만이면 평평하게 (§1.3)                                                                 |
| 6   | **stub 노트 생성** — frontmatter 5필드(★`status: stub`) + 표준 섹션 골격 + **사전등록 절**(가설·기각 조건·설계)                           | ★자동생성 노트는 **절대 `verified` 로 태어나지 않는다**                                                  |
| 7   | **트래커 행 추가** — 후보 트래커 `## 0` 표에 `⬜ 대기` 행 + 사유                                                                          | ★마커 블록 안에만 (§4 L3)                                                                                |
| 8   | **인덱스 등록** — 폴더 README · LINK-MAP 등록부                                                                                           | —                                                                                                        |
| 9   | **`/wiki-ingest` 호출**                                                                                                                   | 에러 0 확인                                                                                              |
| 10  | **종료 안내** — 탐구가 끝나면 `/wiki-note` 개정 모드로 R1~R6 을 채우고, 판정이 `no-go`/`undecidable` 이면 **원장 추가를 검토**하라고 안내 | ★원장 추가는 **자동 금지** — 사유코드는 사람이 정한다                                                    |

### 산출

- `<루트>/<탐구폴더>/<도메인>/<슬러그>.md` — `status: stub` + 사전등록 절이 채워진 노트
- 갱신된 후보 트래커 (`⬜ 대기` 행 + 최종갱신일)
- 갱신된 폴더 README · LINK-MAP
- 콘솔: **원장 조회 결과**(히트 여부·사유코드·해금 조건) + 인접 실패 이력 요약

## 5. 스킬 4종 요지 (한 줄씩)

| 스킬                 | 한 줄                                                                                            |
| -------------------- | ------------------------------------------------------------------------------------------------ |
| `/wiki-init`         | 빈 위키를 **규범이 완비된 상태**로 1회 세운다 — 폴더·`_meta` 4종·린터·홈. **노트는 안 만든다**   |
| `/wiki-note`         | 노트 한 장을 **R1~R6 게이트**로 통과시키고 Backlinks·README·LINK-MAP 을 **같은 커밋에서** 맞춘다 |
| `/wiki-ingest`       | **커밋 게이트** — 규약린트(에러0) → ingest → 도구린트. 사람 문서는 안 쓴다                       |
| `/experiment-intake` | 탐구 시작 시 **기각 원장을 먼저 조회**하고 사전등록을 강제한 뒤 `stub` 노트 + 트래커 행을 만든다 |
