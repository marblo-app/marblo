## 1. 공통 사전 준비 (양쪽 다 필요)

### 1.1 서류 — 미리 발급해 두면 두 곳에 모두 쓴다

| 서류                                      | 국내 PortOne | 글로벌 Paddle      | 비고                                                 |
| ----------------------------------------- | ------------ | ------------------ | ---------------------------------------------------- |
| **사업자등록증 사본**                     | ✅ 필수      | ✅ 필수            | Paddle 은 "정부 발행 사업자 등록 서류"로 요구        |
| **정산받을 통장 사본**(법인이면 법인명의) | ✅ 필수      | —                  | Paddle 은 별도 계좌 정보 입력(§3.5)                  |
| **대표자 신분증 사본**                    | ✅ 필수      | ✅ 필수            | Paddle 은 Sumsub 업로드                              |
| **법인인감증명서 원본**(3개월 이내)       | ✅ 법인만    | —                  |                                                      |
| **법인등기부등본 원본**(3개월 이내)       | ✅ 법인만    | —                  |                                                      |
| **주주명부 등 실소유자 확인서류**         | ✅ 법인만    | ✅ 법인만          | Paddle: **25% 이상 보유자 전원**의 이름·지분율       |
| **대표자 주소 증빙**                      | —            | ✅ 필요할 수 있음  | Sumsub 요청 시                                       |
| **USD 외화통장**                          | —            | ✅ **사실상 필수** | Paddle 은 **원화(KRW) 정산을 지원하지 않는다**(§3.5) |

> ★ Paddle 이 **명시적으로 받지 않는 서류**(공식): 공과금 고지서, 회계 서류, 세금 식별번호 서류(미국 EIN 등). PDF 로 준비할 것.

### 1.2 웹사이트 정비 — ★이게 두 심사의 공통 병목이다

국내 PG 입점심사도, Paddle 도메인 리뷰도 **웹사이트를 보고 심사한다.** 아래가 없으면 양쪽 다 지연된다.

**Paddle 도메인 리뷰 요건(공식 원문 기준) — 국내 PG 심사에도 그대로 유효:**

- [ ] 제품/서비스에 대한 **명확한 설명**
- [ ] **가격 페이지** 또는 가격 정보 (아직 없으면 스크린샷도 허용)
- [ ] 구매에 포함되는 **핵심 기능/제공물** 명시
- [ ] **이용약관 · 환불정책 · 개인정보처리방침** — ★"**네비게이션에서 명확히 접근 가능**해야 함"(단순히 페이지가 존재하는 것으로는 부족)
- [ ] 이용약관에 **법인명** 기재(개인사업자는 대표자 실명 권장)
- [ ] 사이트가 **라이브 상태 + HTTPS(SSL)**
- [ ] Paddle 로 팔지 않는 무관한 상품을 같은 도메인에 두지 말 것(구매자 혼란 → 승인 불리)

> ★ **결제창을 띄울 도메인·서브도메인은 각각 별도 승인**이 필요하다. `marblo.app` 승인 ≠ `app.marblo.app` 승인. 쓸 예정인 것을 처음에 다 적어서 내는 게 좋다.

### 1.3 미리 정해 두어야 할 것 (신청서에 직접 적는 값)

| ------------------------ | ----------------------------------- | ----------------------------------------------------------------- |
| **예상 월 거래액**       | PortOne 신청서 필수 입력            | ★이 값이 **보증보험 금액과 정산 한도를 좌우**한다. 과대 기입 주의 |

## 2. 국내 — PortOne(포트원) 신청

> 배경: 토스페이먼츠 직접 계약이 지연되고 있어, **한 번의 신청서로 여러 PG 에 동시 접수**할 수 있는 포트원으로 우회한다. 상세 판단 근거는 `docs/payment/portone-eval.md` 참조.
>
> ★ **중요한 사실 하나**: 포트원을 쓴다고 **카드사 심사가 짧아지지는 않는다**(공식 문서: "보통 2주 정도 소요"). 포트원의 이점은 *병렬 접수*와 *PG 교체 자유도*다.

### 2.1 STEP 1 — 관리자콘솔 가입 (5분, 무료)

1. https://admin.portone.io 접속
2. 로그인 화면 하단 **[가입하기]** 클릭
3. 이메일로 계정 생성 → 로그인

> ★ **여기까지는 계약과 무관하다.** 가입만 해도 §2.6 의 테스트 채널을 만들어 개발팀이 연동을 미리 끝낼 수 있다.

### 2.2 STEP 2 — 전자결제 신청서 작성

포트원 공식 안내 원문: "PG계약의 첫 단계 '가입신청서 제출'은 **반드시 포트원 관리자콘솔에서** 신청해 주셔야 합니다."

로그인 후 **좌측 하단 [전자결제신청]** 클릭 → 아래 순서로 진행된다.

| 순서 | 화면                 | 입력할 것                                                                                                          |
| ---- | -------------------- | ------------------------------------------------------------------------------------------------------------------ |
| ①    | **비즈니스 인증**    | **사업자등록증 업로드**. (이전에 포트원으로 신청한 이력이 있으면 이 단계는 생략된다)                               |
| ②    | **사업자 정보 등록** | 대표자 **연락처**, **생년월일**. [임시저장] 가능                                                                   |
| ③    | **서비스정보 등록**  | **상세 판매 품목**(업종, 중복 선택 가능) / **서비스 형태**(웹·앱) / **월 거래액**(평균 또는 예상) / **서비스 URL** |
| ④    | **최종 확인**        | 사업자 정보 검토 → **[제출하기]** → "전자결제 신청하기" 팝업 → PG 계약을 바로 진행하려면 클릭                      |

> ★ ③의 **서비스 URL** 은 "PG사로부터 심사를 받을 수 있는 URL" 이어야 한다. 공식 안내: "**PG 계약을 위해 연동하시는 서비스(웹/앱)에 기본 구성 구현은 필수 사항**". 즉 결제 진입 화면이 있어야 한다.
> ★ 앱 서비스인데 앱스토어 미등록이면 "**아직 앱스토어 등록 전이에요 (URL이 없습니다)**" 체크박스가 있다.

### 2.3 STEP 3 — 결제대행사(PG)·결제수단 선택

장바구니처럼 **여러 PG 를 담아 동시 접수**할 수 있다. 두 가지 방식:

- **포트원 추천 패키지** — 결제수단을 고르면 포트원이 PG 를 추천
- **전자결제 직접 신청** — PG·결제수단을 직접 선택 (결제방식: 일반결제 / 간편결제 / 해외결제 / 본인인증)

**우리 상황에 맞는 선택 (참고 — 최종 결정은 사장님)**

우리가 필요한 것은 **구독(정기결제) + 간편결제 4종**(카드·네이버페이·카카오페이·토스페이)이다.

| PG 후보               | 가입비   | 정기결제(빌링) 수수료 | 정기결제 결제창 지원                             | 간편결제 커버           |
| --------------------- | -------- | --------------------- | ------------------------------------------------ | ----------------------- |
| **NHN KCP**           | **무료** | 3.20%                 | ✅ 결제창/API 둘 다                              | 8종(우리 4종 전부 포함) |
| **KG이니시스**        | 20만원   | 3.20%                 | ✅ 결제창/API 둘 다                              | 8종(우리 4종 전부 포함) |
| 한국결제네트웍스(KPN) | **무료** | **2.90%**             | ✅ 결제창/API 둘 다                              | 5종(우리 4종 전부 포함) |
| 토스페이먼츠          | 20만원   | 3.23%                 | ✅ 결제창/API 둘 다                              | 8종                     |
| 나이스정보통신        | 20만원   | 3.20%                 | ⚠️ **API 만**(결제창 정기결제는 카카오/네이버만) | 9종                     |

→ **가입비 무료 + 결제창 정기결제 지원**을 함께 보면 **NHN KCP** 또는 **KPN** 이 유력. **2곳 이상 동시 접수**를 권한다(한 곳이 막혀도 진행되는 것이 포트원을 쓰는 이유 그 자체).
→ 수수료 차이는 0.03~0.33%p 로 사실상 무시할 수준이니, **가입비와 정기결제 결제창 지원 여부**로 고르는 편이 낫다.

**추가 작성 항목**(선택한 PG 에 따라 더 묻는 것):

- 네이버페이: 개발 방식(자체개발/워드프레스) → **자체개발**
- 카카오페이: 배송 및 서비스 기간 → 비실물이므로 **서비스 이용 가능 기간**
- 나이스정보통신: **정산 계좌 정보**(접수 시점에 미리 입력)
- KG이니시스: 홈페이지 명(서비스명)

### 2.4 STEP 4 — PG사 계약 진행 (여기서부터는 PG사와 직접)

공식 안내: "계약은 PG사의 정책에 따라 진행되므로, 모두 **PG사로부터 필요한 심사 양식과 계약서를 안내**받으시어 진행해주시기 바랍니다."

**소요: 접수 후 약 3영업일 내 PG사 계약담당자가 컨택**(포트원 콘솔 가이드 기준 "약 3영업일 내", 나이스정보통신 상세절차 기준 "2~3영업일 내").

이후 3가지가 진행된다:

#### (1) 입점심사

PG사가 **업종·상품·사이트 구현 여부**를 보고 심사한다. §1.2 의 웹사이트 요건이 여기서 그대로 작동한다.
공식 안내: "심사 기준은 결제대행사별로 크게 다르진 않으나 모두 **내부 심사기준**에 따라 결정되므로 정확한 결과는 실제 심사를 받아보셔야 알 수 있습니다."

#### (2) ★보증보험 가입 (비용 발생 지점)

공식 원문 기준:

- **필수**. "결제대행사와 계약시에는 **반드시 보증보험 가입이 필요**하며, **여러 PG사를 이용하신다면 결제대행사별로 가입**해주셔야 합니다."
- 가입처: **SGI서울보증보험**. PG사마다 연계된 보험 대리점이 있고, PG사가 안내하는 지점으로 **직접 연락**해 가입
- 계약기간: **1년**, 만료 시 갱신 필요
- 납부액: (보증보험 금액) × (기준요율). **기준요율 기본 0.953%** (PG사별로 다를 수 있음)
- 보증보험 금액은 **PG사가 업종·예상 매출을 보고 정한다** → **`확인필요`**(우리에게 얼마가 요구될지는 접수 전엔 알 수 없음)

**보증보험 금액 ↔ 월 정산한도(공식 예시)**

| 정산 주기            | 배수 | 보증보험 500만원일 때 월 정산한도 |
| -------------------- | ---- | --------------------------------- |
| 일일정산(승인일+7일) | 2배  | 1,000만원                         |
| 월 4회 정산          | 3배  | 1,500만원                         |
| 월 2회 정산          | 4배  | 2,000만원                         |
| 월 1회 정산          | 5배  | 2,500만원                         |

→ ★ **자주 정산받을수록 같은 보증보험으로 커버되는 한도가 작아진다.** 현금흐름 vs 한도의 트레이드오프이므로 PG 담당자와 상의해 정할 것.
→ ★ **PG 를 2곳 계약하면 보증보험도 2건**이다. 실운영은 1곳으로 시작하고 다중화는 나중에 하는 것이 비용상 유리하다.

#### (3) 계약서 및 구비서류

접수 방법: **우편 발송** 또는 **전자계약(온라인 업로드)**.
필요 서류는 PG사가 담당자 이메일로 상세 안내한다. 업종에 따라 내부 심사(RM)를 거쳐 **추가 서류**를 요구할 수 있다.

**개인사업자 (공식 목록)**

- [ ] PG사 계약서 **2부**
- [ ] 사업자등록증 사본 1부
- [ ] 정산받을 **통장 계좌 사본 1부 (대표자 명의)**
- [ ] 대표자 신분증 사본 1부 — 내국인: 주민등록증 또는 운전면허증 / 외국인: 외국인등록증(없으면 여권사본)
- [ ] **인감증명서 원본 1부 (대표자 명의)** — 주민등록번호 뒤 7자리 **마스킹** 후 발송, **3개월 이내 발급분**
- [ ] (제출 필요시) 보증보험증권 — 보증보험사가 발송 대행
- [ ] 소유자 확인서류(고객거래확인서) 1부 — 대표자 외 대리인이 작성하면 각각 1부

**법인사업자 (공식 목록)**

- [ ] PG사 계약서 **2부**
- [ ] 사업자등록증 사본 1부
- [ ] 정산받을 **통장 계좌 사본 1부 (법인 명의)**
- [ ] 대표자 신분증 사본 1부
- [ ] **법인인감증명서 원본 1부** — 공동대표는 모두 필요, **3개월 이내 발급분**
- [ ] **법인등기부등본 원본 1부** — **3개월 이내 발급분**
- [ ] **실제 소유자 확인 가능 서류 1부** — 주주명부(정관), 출자자명부, 이사회명부, 사원명부, 지분 보유현황 자료 등
- [ ] (비영리법인) 정관/규약, 비영리법인 설립허가서 등 1부

### 2.5 STEP 5 — 카드사 심사 (★약 2주)

공식 원문: "카드사 심사는 PG사에서 전 카드사로 심사를 요청합니다. 각 카드사별로 개별적으로 심사를 진행하기 때문에 소요 일시는 카드사별로 차이가 있을 수 있으나, **보통 2주 정도 소요**됩니다."

**미리 준비할 것(공식)**

- 심사 받을 사이트(앱) 내 **결제 연동된 화면**을 준비
- 결제창 방식이면: PG 결제창이 정상적으로 뜨는지, 결제창 안에 **카드사 목록이 모두 노출**되는지
- ★ **"카드사 심사 전에는 테스트 환경으로 미리 연동 개발작업을 진행할 수 있습니다"** — §2.6 이 이것

> ★ 안심해도 되는 부분(공식): "아직 카드사 심사가 완료되지 않았기 때문에 **운영 환경의 경우 결제가 실패되는 것이 당연**하며, 카드사 심사 시 정상 결제 여부나 이후 로직까지는 확인하지 않습니다."

> ⚠️ **주의(공식)**: "PG사를 통해 심사를 마치셨을지라도 **기존과 다른 서비스를 운영하시거나 결제방식이 달라진다면 카드사 재심사가 필요**합니다." → 심사 통과 후 결제 방식을 바꾸면 다시 2주다.

**심사 진행현황 조회** — PG사별 조회 페이지가 있다(KG이니시스 / NHN KCP / 나이스정보통신 / 다날 / KICC / 헥토파이낸셜 / 키움페이). 링크는 [포트원 카드사 심사 안내](https://help.portone.io/category/procedure/pg-application/screening) 하단 참조. 실시간 반영은 아니며, 지연된다고 판단되면 포트원에 문의하면 확인해 준다.

### 2.6 ★계약 전에도 개발팀이 미리 할 수 있는 것 (테스트 채널)

**사장님이 §2.1 관리자콘솔 가입만 해 주시면**, 계약·심사와 무관하게 개발팀이 연동을 완성해 둘 수 있다. 심사가 끝나는 순간 바로 켤 수 있다는 뜻이다.

콘솔 실측 기준 경로: **[결제 연동] → [연동 관리] → 채널 관리**

1. **연동 모드를 [테스트] 로 변경**
2. 사용할 결제대행사 선택
3. 결제방식/결제수단에 맞는 결제 모듈 선택
4. 채널 이름 입력 (예: "KCP 정기결제용") — 공용 테스트 채널이 제공되는 PG 는 MID 선택 시 자동 표시

같은 화면에서 **상점 아이디(Store ID)**, **V2 API Secret**, **웹훅 URL**(테스트/실연동 각각 별도 설정 가능)을 관리한다.

> 🔒 **보안 주의**: API Secret 은 **발급 직후 한 번만 값을 볼 수 있다**(페이지를 벗어나면 다시 볼 수 없고 재발급해야 한다). 이 값은 결제 거래를 통제할 수 있는 민감정보이므로 **서버에서만** 쓰고 브라우저·문서·메신저에 붙여넣지 말 것. 개발팀에 전달할 때는 안전한 경로로 전달하고, **이 문서를 포함한 어떤 문서에도 값을 적지 말 것.**

## 3. 글로벌 — Paddle 신청

> 배경: 해외 고객용. **Paddle 은 MoR(Merchant of Record)** 이라 각국 VAT/GST 를 Paddle 이 징수·신고·납부한다. 상세 근거는 `docs/payment/paddle-eval.md`.
>
> ★ 참고: **Stripe 는 선택지가 아니다.** 실측 결과 Stripe 계정 개설 국가 목록에 대한민국이 없다(해외 법인이 있어야 가능). Lemon Squeezy 는 Stripe 에 인수되어 정리 수순이다. **한국 사업자에게 열려 있는 실질적 글로벌 MoR 이 Paddle 이다.**

### 3.1 STEP 1 — 샌드박스 계정 먼저 (5분, 무료, 심사 불필요)

1. https://sandbox-vendors.paddle.com/signup 접속 → 가입 → 이메일 인증
2. 끝. **도메인 승인도 계정 심사도 필요 없다.**

→ 개발팀이 여기서 연동을 미리 만든다(PortOne 테스트 채널과 같은 역할).

### 3.2 STEP 2 — 라이브 계정 가입 (10분, 무료)

1. https://vendors.paddle.com/signup 접속 (→ `login.paddle.com/signup` 으로 이동)
2. **1단계 — 무엇을 파는가**
   - "**Digital products or SaaS**" 체크
   - "I have read and understood Paddle's Acceptable use policy, Terms of use & Privacy policy" 체크 → **Continue**
   - (참고: Paddle 은 SaaS·디지털 제품만 지원한다. 인적 서비스·클라우드 호스팅·금융·실물·도박·마켓플레이스는 "제약이 더 많은 카테고리"로 분류된다)
3. **2단계 — 계정 정보**: First name / Last name / Email / Password (최소 8자, 대문자·소문자·숫자 또는 기호 포함) → **Continue**
4. 이후 사업자 정보 입력 → 이메일 인증
5. 팀원 초대: **Business account > Team members** (샌드박스·라이브 각각 따로)

> ★ Paddle 자신의 권고(공식 원문): "It can sometimes take a few days to complete verification, so we recommend **starting the process in live before you start integrating with sandbox**."
> → **심사를 먼저 걸어놓고, 대기하는 동안 샌드박스로 개발**하는 것이 공식 권장 순서다.

### 3.3 STEP 3 — 계정 심사 3단계 (★소요는 전부 공식 "추정치")

Paddle 이 MoR 로 활동하기 전에 반드시 통과해야 한다.

#### ① Domain Review (도메인 심사)

- **어디서**: 대시보드 좌측 **Checkout > 웹사이트 승인(Request domain approval)**, 또는 'Get started' 페이지의 안내를 따라간다
- **무엇을**: §1.2 의 웹사이트 요건. 결제창을 띄울 **모든 도메인·서브도메인**을 제출(승인은 1개만 있어도 다음 단계로 진행 가능)
- **소요**: "대부분 자동 승인". 수동 심사로 넘어가면 **estimated 5–7 business days**
- **반려 사유(공식)**: 이용 정책(AUP) 위반 상품 / 고위험 도메인 / 우리가 추가 정보 요청에 회신하지 않음
- 제품 유형에 따라 추가 서류를 요구할 수 있음: 제품 소유권 증빙, 리셀러 계약서, 로그인 필요한 화면의 **테스트 계정** 등

#### ② Business Identification (사업자 확인)

- **어디서**: 별도 화면 없음. 가입 시 낸 정보로 **자동 대조**되며, 부족하면 Paddle 심사팀이 **이메일**로 요청한다 → **메일함을 지켜볼 것**
- **요구될 수 있는 서류**: 정부 발행 사업자 등록 서류 / **25% 이상 지분 보유자 전원**의 이름·지분율이 나오는 주주·지분 구조 서류
- **형식**: **PDF 권장**. 공개 등기부라면 로그인 없이 열리는 링크도 가능
- **받지 않는 서류**: 공과금 고지서, 회계 서류, 세금 식별번호 서류(EIN 등)
- **소요**: "often instant". 수동 심사 시 **estimated 2–4 business days**
- ★ **개인/개인사업자(sole trader)는 이 단계 불필요**

#### ③ Identity Verification (신원 확인)

- **누가**: 법인이면 **지분 25% 초과 보유자 등 핵심 이해관계자 최소 1명**. 개인/개인사업자면 본인
- **어떻게**: 대시보드 안에서 또는 Paddle 이 보내는 **이메일 링크**로 진행. 파트너사 **Sumsub** 를 통해 **정부 발행 신분증 + 주소 증빙** 업로드, 경우에 따라 **라이브니스 체크**(짧은 셀피 영상)
- **소요**: "typically instant". 수동 심사 시 **estimated 1–3 business days**
- 촬영 팁(공식): 안경 벗고, 머리카락 얼굴에서 치우고, 모자·목도리 제거, 배경 단순한 밝은 곳에서. 신분증은 **원본**을 촬영

> ⚠️ **소요 시간에 대한 공식 단서**: "Please note that this timeframe is an **estimate, not a guarantee**. Timelines can be affected by our current review backlog or if additional information is required from you."
> → **넉넉히 2주**로 보고 계획할 것.

### 3.4 STEP 4 — 계정 기본 설정

대시보드에서 설정할 항목(라이브 계정):

| 설정                 | 경로                                                | 우리 값                                                                 |
| -------------------- | --------------------------------------------------- | ----------------------------------------------------------------------- |
| 기본 결제 링크       | Checkout > Checkout settings > Default payment link | ★ **localhost 불가**, **도메인 승인을 통과한 실제 웹사이트**여야 함     |
| 결제수단             | Checkout > Checkout settings > Payment methods      | 카드는 항상 켜짐. 나머지는 클릭 몇 번으로 활성화(별도 가맹 계약 불필요) |
| 세금 포함/별도 가격  | Checkout > Sales tax settings                       | 포함(inclusive) / 별도(exclusive) / **고객 위치 기반 자동** 중 선택     |
| **잔액 통화**        | Business account > Currencies                       | ★ 공식 권고: "**은행 계좌와 일치하는 통화**" → 우리는 **USD**           |
| 실패결제 재시도·독촉 | Retain                                              | dunning 설정                                                            |
| 과세 카테고리        | Catalog > Taxable categories                        | **Standard Digital Goods** 는 기본 제공. 다른 카테고리는 승인 요청 필요 |

### 3.5 STEP 5 — ★정산 설정 (한국 사업자가 가장 주의할 부분)

**경로**: Business account > Payouts > Payout settings

#### (1) 원화(KRW)로는 받을 수 없다

Paddle 이 지원하는 정산 통화 **13종**(공식): AUD, GBP, CAD, CNY, CZK, DKK, EUR, HUF, PLN, ZAR, SEK, CHF, **USD**
→ **KRW 없음.** 공식 안내: 지원되지 않는 현지 통화면 "가장 경쟁력 있는 기본 통화로 보내고 **고객님의 은행이 현지 통화로 환전**합니다."

**→ 실무 결론: USD 외화통장을 미리 개설해 두어야 한다.** 이게 없으면 정산 자체가 막힌다.

#### (2) 발생하는 비용

| 항목                    | 값                                                                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------- |
| Paddle 추가 정산 수수료 | **없음** — "Paddle will not add any fees beyond the Paddle fee on payouts made to you"                   |
| **SWIFT 수수료**        | 통화와 은행 소재국이 불일치하면 **$/€/£15**. 한국은 무수수료 로컬망(미국 ACH·유로존 SEPA 등) 대상이 아님 |
| **환전 마진**           | 잔액 통화와 다른 통화로 받으면 Paddle 이 **최대 1.5%**. USD 잔액 → USD 수령이면 회피 가능                |
| 중개은행 수수료         | 경유 시 각 은행 수수료 발생, 우리 부담                                                                   |
| 국내 은행 환전          | USD → KRW 환전 스프레드는 우리 부담                                                                      |

#### (3) 정산 일정

- 매월 **1일**: 잔액이 임계값(**최소 $100**, 최대 $100,000 까지 조정 가능) 이상이면 payout 대기열로 전환
- **15일까지** Paddle 이 송금
- 송금 후 **최대 3영업일** 내 입금
- 임계값 미달분은 **다음 달로 이월**
- ★ **온디맨드 출금 불가** (공식: "Sellers cannot withdraw their balance on demand")

> ★ **임계값 조정 팁**: SWIFT $15 는 송금 1회당 발생한다. 월 정산액이 작을 때 $100 임계값으로 매달 받으면 수수료 비중이 커진다. 초기에는 **$500~1,000 정도로 올려** 송금 횟수를 줄이는 편이 유리하다(대신 입금이 늦어진다). 사장님 판단.

#### (4) 계좌 정보 입력 규칙 (공식 — 어기면 정산 지연)

- BIC/SWIFT, 계좌번호, IBAN, BSB, Routing/ABA, Sort code, Bank code, Branch code: **영숫자만, 공백 없이**
- 계좌명·은행명·사업장 주소·은행 주소: **영숫자만**
- ★ 특수문자(`-` `'` `@` `*` `#` `!` `%` `^` `&` `(` `)`)나 강세 문자 **사용 금지**

#### (5) 수령 방식

- 공식 헬프센터: **전신환(wire transfer) 또는 Payoneer**
- Go-live 체크리스트에는 "bank transfer, **PayPal**, or Payoneer" 로 기재 — **`확인필요`**(두 공식 문서 표기 불일치). 계정 개설 후 실제 화면에서 확인 필요
- Payoneer 사용 시 Payoneer 자체 수수료가 별도 발생

### 3.6 세금·회계 — 우리가 할 일이 거의 없다

| 질문                                | 공식 답변                                                                                                                                   |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 해외 VAT 를 우리가 신고하나?        | **아니오.** Paddle 이 100+ 관할에 등록되어 징수·신고·납부하고 규정에 맞는 인보이스를 발행한다. "all the tax-related risk rests with Paddle" |
| Paddle 에 VAT 를 청구하나?          | **아니오.** 우리 → Paddle 은 국경 간 B2B 이므로 **reverse charge** 대상                                                                     |
| 우리가 Paddle 에 계산서를 발행하나? | **아니오.** Paddle 이 정산할 때마다 **'Reverse Invoice'(자기청구 인보이스)** 를 자동 생성해 계정의 모든 Admin 에게 이메일로 보낸다          |

→ 회계 실무상 **월 1회 Reverse Invoice 1장 = 소프트웨어 수출 매출 1건**.

> ⚠️ **`확인필요`(세무사 판단)**
>
> 1. 이 Reverse Invoice 를 국내 신고에서 어떻게 처리할지(영세율 수출 등)
> 2. **국내 고객 매출을 Paddle 로 흘려도 되는지** — Paddle 은 한국 소비자에게 10% VAT 를 징수하도록 등록돼 있지만, 한국 사업자가 한국 소비자에게 팔면서 외국 MoR 을 끼우는 구조는 국내 부가세·현금영수증 실무와 어긋날 소지가 있다.
>    **→ 이 가이드의 전제: 국내 고객 = PortOne, 해외 고객 = Paddle 로 분리.**

## 5. 예상 타임라인

```
D+0     서류 준비 완료 + 웹사이트 정비 완료 + USD 외화통장 개설
        │
        ├─[국내] PortOne 콘솔 가입 → 전자결제 신청서 제출 (PG 2곳)
        │        └─ 개발팀: 테스트 채널로 연동 개발 착수 (계약 무관, 병행)
        │
        └─[글로벌] Paddle 라이브 가입 → 도메인 심사 제출 + 샌드박스 가입
                 └─ 개발팀: 샌드박스로 연동 PoC (심사 무관, 병행)

D+3     [국내] PG사 계약담당자 컨택 (공식: 약 3영업일 내)
D+5~7   [글로벌] 도메인 심사 결과 (공식: 수동 심사 시 5~7영업일)
D+7~10  [글로벌] 사업자·신원 확인 완료 → ★Paddle 판매 가능
D+?     [국내] 입점심사 + 보증보험 가입 + 계약서·구비서류  ← 소요 미명시 `확인필요`
D+?+14  [국내] 카드사 심사 완료 (공식: 약 2주) → ★국내 결제 가능
```

> ★ **글로벌이 국내보다 먼저 열릴 가능성이 높다.** Paddle 은 카드사 심사·보증보험이 없기 때문이다. 다만 우리 수요는 현재 국내가 압도적이므로(외부 실사용≈0, 파운더 대부분 국내), **국내 PortOne 이 우선순위**이고 글로벌은 "무료라서 미리 열어두는" 성격이다.
>
> `확인필요`: 국내 입점심사~계약 완료까지의 소요는 포트원 공식 문서에 명시값이 없다. PG사 정책에 따르며, 실제로는 서류 준비 속도에 좌우된다.
