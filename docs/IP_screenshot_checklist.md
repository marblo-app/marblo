# 특허 출원용 스크린샷 체크리스트 (v3 마블로)

> **목적**: 청구항 1-12 (원안) 및 신규 청구항 13-18 (보정안) 의 실시예 도면 확보.
> **원칙**: 한 장의 스크린샷이 한 개 이상의 청구항을 시각적으로 입증해야 함.
> **포맷**: PNG, 1920×1200 권장. 개인 식별 정보(이메일·실명·API 키) 가림.
> **저장 위치 권장**: `docs/IP_screenshots/01_board_kanban.png` 처럼 번호 + 영문 슬러그.
> **사전 준비**: 데모용 더미 프로젝트에 미션 1개 실행 → 태스크 5-10개를 다양한 상태로
> 분포 (TODO/CLAIMED/IN_PROGRESS/REVIEW/DONE/FAILED/BLOCKED 1개씩 있으면 이상적).

## A. 핵심 도면 (필수, 1순위)

### A1. 칸반보드 전체 — Board 탭 ★★★

- **청구항 매핑**: 1, 10, 14
- **캡처 조건**: 현재 제품의 5개 컬럼 모두 보이게 + 각 컬럼에 1개 이상 카드
  - TODO / CLAIMED / IN_PROGRESS / REVIEW / DONE
- **반드시 보여야 할 요소**:
  - 컬럼 헤더 (한글 라벨 + 카드 수 카운트)
  - 카드별 제목·역할 라벨·담당자·우선순위
  - "Board" 탭이 활성화된 상단 TabBar
- **메모**: 청구항 10 은 7개 (TODO/CLAIMED/IN_PROGRESS/REVIEW/BLOCKED/FAILED/DONE)
  "**중 1 이상을 포함**" 이라고 정의 → 위 5개는 그 subset 이므로 청구항 부합. 명세서 본문에
  BLOCKED/FAILED 도 "포함 가능한 상태" 로 언급되어 있는지만 변리사와 확인.

### A2. 태스크 카드 상세 (DONE 아님) — 호버 또는 클릭 ★★★

- **청구항 매핑**: 7, 10, **14 (신규)**, presence 인디케이터
- **캡처 조건**: CLAIMED 또는 IN_PROGRESS 상태 카드 1개의 확대된 모습
- **반드시 보여야 할 요소**:
  - 카드 제목 + 설명
  - 담당자 (예: `👤 backend-claude-001`) + presence 도트 (녹색/노랑/회색)
  - 우선순위 / 의존성 / 마지막 활동 시각
  - 활동 로그 일부 (claim/in_progress/activity 트레이스)
- **변형 추가 1장**: 오프라인 담당자 + "담당자 오프라인 — 큐 적재" 배너 + **회수 버튼**
  (방금 추가한 기능, 청구항 14 의 양방향 동기화 무흐름 시 안전장치)

### A3. 에이전트 PTY 터미널 — Agents 탭 또는 Harness 탭 ★★★

- **청구항 매핑**: 1, 5, 6, **14 (신규)**
- **캡처 조건**: 실행 중인 에이전트의 PTY stdout 이 실시간으로 흐르는 모습
- **반드시 보여야 할 요소**:
  - 검정 배경의 터미널 출력 (xterm.js)
  - 명령 프롬프트 / 스트리밍되는 텍스트
  - 우측·하단에 "메시지 입력" 입력란 (신규지시 input 영역) — 청구항 5 의 stdin 입력 경로
  - 에이전트 ID / 모델 라벨 (예: claude-sonnet-4 / gpt-4o / gemini)
- **변형 추가 1장**: 신규지시 입력 직후, 에이전트 실행 중단 없이 이어서 응답하는 순간
  (청구항 5 의 "중단하지 않고 컨텍스트 유지" 시연)

### A4. 시각적 UI ↔ PTY 양방향 동기화 합성 도면 ★★★★ (가장 중요)

- **청구항 매핑**: **14, 15 (신규 독립항)**
- **캡처 조건**: 한 화면 안에 칸반보드 + 에이전트 터미널 + 활동 로그가 동시에 보이는 분할 레이아웃
  (Layout.tsx 의 좌측 탭 / 중앙 콘텐츠 / 우측 사이드패널 구조 활용)
- **반드시 보여야 할 요소**:
  - 좌측: 칸반보드 또는 미션 트리
  - 중앙: 에이전트 PTY 출력 (stdout)
  - 우측 (또는 하단): 그 카드의 활동 로그 (stdout 의 구조화 결과가 카드에 반영된 모습)
- **메모**: 가능하면 같은 순간에 stdout 의 텍스트와 카드 상태가 일치하는 모습 (예: "REVIEW
  로 전환" 출력 + 카드가 REVIEW 컬럼으로 이동). **양방향 흐름 입증의 핵심 도면**.

## B. Mission · 태스크 분해 (2순위)

### B1. Missions 탭 — 미션 생성 폼

- **청구항 매핑**: 2 (태스크구조화), 11 (방법항)
- **캡처 조건**: 자연어 작업 요청을 입력하는 입력창 + 생성 버튼
- **반드시 보여야 할 요소**:
  - "작업 요청" 입력 textarea + placeholder
  - "Mission 생성" 또는 유사 CTA
  - (가능하면) 미션 옵션 (모델 프리셋, enabledModels)

### B2. Missions 탭 — 분해 결과 미션 트리

- **청구항 매핑**: 2 (태스크 분할), 4 (선후관계 + 의존성 그래프)
- **캡처 조건**: 미션이 분해된 직후 = 5-15 개 태스크가 의존성 DAG 로 표시된 모습
- **반드시 보여야 할 요소**:
  - 태스크 노드 + 역할 라벨 (backend/frontend/test/devops)
  - 의존성 화살표 또는 들여쓰기/Layer 표시
  - 각 노드에 매칭된 에이전트 ID 또는 모델

### B3. 매칭점수 / 신규 에이전트 생성 화면

- **청구항 매핑**: 2 (매칭점수산출), 3 (신규에이전트할당), 9 (3-지표 매칭)
- **캡처 조건**: dispatch 직전 매칭 후보 리스트 또는 신규 에이전트 spawn 다이얼로그
- **반드시 보여야 할 요소**:
  - 후보 에이전트별 점수 (역할매칭 / 부하균등 / 비용효율 3-지표 합산이면 베스트)
  - "기준 미달 → 신규 spawn" 분기 — 신규 에이전트 생성 모달 또는 로그

## C. 에이전트·터미널 운영 (3순위)

### C1. Agents 탭 — 활성 에이전트 리스트

- **청구항 매핑**: 1 (이종 에이전트), 6 (가상터미널 파라미터), **13 (신규: 이종 사업자)**
- **캡처 조건**: 동시에 떠 있는 여러 에이전트 (이상적으로 **서로 다른 모델/사업자**)
- **반드시 보여야 할 요소**:
  - claude-sonnet / gpt-4o / gemini 같은 **이종 사업자 모델 라벨** 동시 표기
  - 각 에이전트의 PTY ID, 작업 디렉토리, 상태 (running/idle/stopped)
  - 환경변수 / API 키 슬롯이 보이면 청구항 6 입증 가산점

### C2. 에이전트 spawn / 재사용 다이얼로그

- **청구항 매핑**: 3 (신규에이전트할당), 6 (파라미터)
- **캡처 조건**: 신규 에이전트 spawn 시 입력 받는 파라미터 폼
- **반드시 보여야 할 요소**:
  - 역할 선택 / 모델 선택 / 작업 디렉토리 / API 키 환경변수 / 터미널 유형

### C3. 통합 비용 위젯 / Settings — Cost

- **청구항 매핑**: 8 (이종 모델 통합 과금)
- **캡처 조건**: 모델별 누적 토큰·비용 + 합산 통합과금량
- **반드시 보여야 할 요소**:
  - 모델별 행 (claude / gpt / gemini 등) + 각 input/output 토큰 + 단가 + 비용
  - **합계 (전체 통합 비용)** — 청구항 8 의 "통합과금량 합산" 명확화

## F. 사용 시나리오 시퀀스 (스토리보드용)

특허 명세서에 "동작 흐름" 도면이 필요한 경우, 다음 4-5 컷을 **시간 순서대로** 캡처:

1. **컷 1** — Missions 탭, 사용자가 자연어 요청 입력
2. **컷 2** — 분해된 미션 트리 (DAG)
3. **컷 3** — Board 탭, 태스크가 TODO 컬럼에 배치 + 매칭된 에이전트
4. **컷 4** — Board + 터미널 분할, 카드가 IN_PROGRESS 로 이동 + 에이전트 stdout 흐름
5. **컷 5** — 사용자가 신규지시 입력 (PTY stdin), 카드 활동 로그에 즉시 반영
6. **컷 6** — REVIEW / DONE 으로 전환된 카드 + 합산 비용 위젯

이 6컷이 청구항 1·2·5·10·14 의 전체 흐름을 한 스토리로 보여줍니다.

## I. 주의사항

1. **API 키·인증토큰**: 화면 노출 시 반드시 마스킹. Settings 탭은 키가 점(•)으로 표시되는 상태에서 캡처.
2. **개인 이메일·실명**: 사용자 프로필 모달은 더미 계정 또는 모자이크 처리.
3. **Firestore 프로젝트 ID·URL**: 좌하단 dev 도구나 콘솔에 노출 안 되게 dev tool 닫고 캡처.
4. **타임스탬프**: "1분 전" 같은 표시는 OK. 절대 시각 표시는 가능한 가림.
5. **다국어**: 청구항이 한국어이므로 UI 도 가능하면 한국어 로케일로 (i18n 지원되면 ko 강제).
