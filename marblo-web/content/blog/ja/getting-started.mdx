Marblo は、あなた自身の Claude・Codex サブスクリプションを接続してエージェントを動かすプラットフォームです。そのため **Claude Code を使ったことがない方**にとっては、Marblo をはじめて開くとき、オーケストレーターとの最初の接続というひと手間が少し不慣れに感じられるかもしれません。この最初の接続さえ済ませればあとはスムーズに進みますので、アプリを最初に起動したときに表示される初回スタートのポップアップ（接続ウィザード）を、ぜひ最後まで進めてください。このガイドは、その接続ウィザードが案内する流れを、ダウンロードから最初のエージェントがチケットを最後まで完了する瞬間まで一つずつ解説します。

開発者を第一の読者としつつ、Node.js のインストール手順まで含めているので、**AI ツールがはじめての方でも一人で最後まで**進めます。

## ★ はじめる前に — 二つの準備物（自分のアカウントを接続）

Marblo は**あなた自身の AI アカウントを接続して**エージェントを動かします。そのため始めるには**二つの準備物**が必要で、どちらもそろえば最初の接続と初回スポーンがスムーズに進みます。

### 準備物 1 — 自分の有料 Claude サブスクリプション（または API キー）

Marblo がスポーンするエージェントは Claude Code CLI で動きます。そして **Claude Code は有料プラン（Claude Pro 以上）または Anthropic API キーがないと**実際には動作しません。無料アカウントで `claude login` をするとログイン自体は通りますが、**最初の作業で静かに失敗**します。

![Claude の料金比較表。「Claude Code」の行を見ると Free プランには無く、Pro・Max など有料プランでのみ提供される。](/images/guide/first-run/claude-pricing.png)

- **最もスムーズな道**：すでに Claude Pro（または Max）を使っているなら、そのまま `claude login` すれば OK です。
- **API キーでも可**：`ANTHROPIC_API_KEY` を発行して使えば、サブスクリプション無しでも動きます。使った分だけ課金されます。
- Codex を使うなら OpenAI 側も同じです — 有料 ChatGPT サブスクリプションまたは `OPENAI_API_KEY`。

> 要点：Marblo アプリ自体は無料で使えますが、エージェントは **あなたが接続した自分のサブスクリプション・API キー（モデル）で** 動きます。そのため実際の実行にかかるモデル使用量は、接続したご自身のアカウント基準で処理されます。始める前にこの接続だけ済ませておけば、初回スポーンがスムーズに進みます。

### 準備物 2 — Node.js / npm

エージェント CLI（Claude Code · Codex）は npm パッケージとしてインストールされます。そのため PC に **Node.js と npm** が必要です。開発者ならすでに入っている可能性が高いですが、無ければ下の **Step 2** で 5 分でインストールします。

今あるか確認するには、ターミナルで次を打ちます：

```bash
node -v && npm -v
```

バージョン番号（例：`v20.11.0` / `10.2.4`）が出れば準備完了です。`command not found` が出たら Step 2 へ。

## Step 0 — ファウンダー承認 & アプリのダウンロード

現在 Marblo はデスクトップアプリを **ファウンダー（選ばれたベータユーザー）にのみ**配布しています。そのためダウンロードページに直接行くと、アプリの代わりに**ログイン／申請の案内**が表示されます。

![Marblo のダウンロードページ。未ログインの新規訪問者には「Sign in to download — Marblo Desktop は選ばれたファウンダーに提供されます」という案内と Log in・Sign up ボタンが表示される。](/images/guide/first-run/en/01-download-login-gate.png)

順序はこうです。

1. [ファウンダー申請](/ja/founders)でメール一行で申請します（先着ではなく審査のうえ選定）。
2. 選ばれるとアクセス案内がメールで届きます。
3. ログインした状態で[ダウンロードページ](/ja/download)を開くと、そこで初めて macOS（Apple Silicon · Intel）・Windows 用ビルドを入手できます。

## Step 1 — インストールと初回起動

ダウンロードしたファイルを実行します。

- **macOS**：`.dmg` を開き、Marblo を**アプリケーション**フォルダにドラッグします。
- **Windows**：インストーラーをそのまま進めます。

![Marblo アプリの初回起動画面。](/images/guide/install-run.svg)

初回起動時に macOS の **Gatekeeper** または Windows の **SmartScreen** 警告が出ることがあります。正式に署名・公証されたビルドなので、次のように進めます。

- **macOS**：`システム設定 > プライバシーとセキュリティ` で **「このまま開く」**。
- **Windows**：`詳細情報 > 実行`。

## Step 2 — Node.js / npm をインストール

`node -v` が `command not found` だったら、ここで解決します。**すでにある場合はこの手順を飛ばしてください。**

1. [nodejs.org](https://nodejs.org/en) にアクセスします。
2. 緑色の **「Get Node.js®」** ボタン（LTS バージョン、例：v24.x）を押してインストーラーを入手します。
3. インストーラーをそのまま進めます。npm は Node.js に同梱されています。

![nodejs.org のトップ画面。緑色の「Get Node.js®」ダウンロードボタンと、下部の最新 LTS バージョン表示。](/images/guide/first-run/en/wall1-nodejs.png)

**Mac でターミナルに慣れているなら — Homebrew で一行インストール。** すでに [Homebrew](https://brew.sh) が入っていれば、インストーラーをダウンロードする代わりに、ターミナルで次の一行だけで Node.js と npm がまとめて入ります：

```bash
brew install node
```

Homebrew が無ければ、上の nodejs.org のインストーラー方式のほうが簡単です。どちらか一つだけ行えば OK です。

インストールが終わったら **ターミナルを開き直して**もう一度確認します：

```bash
node -v && npm -v
```

両方のバージョン番号が出れば、Node.js の準備は完了です。

> **なぜ必要？** Marblo はエージェント CLI を `npm install -g` で自動インストールします。npm が無いとその自動インストールが失敗し、アプリは「npm が見つかりません。Node.js / npm をインストールしてから再試行してください」と知らせます。Node.js を先に入れておけば、この回り道をまるごと省けます。

## Step 3 — CLI の自動インストール確認 & 認証

ここが **新規ユーザーが最もつまずく場所**です。落ち着いて二つだけ行います：(a) CLI が入ったか確認、(b) **自分の有料アカウントで認証**。

### 3-1. 必須 CLI は自動インストールされます

初回起動時に Marblo が Claude Code · Codex · Marblo MCP を**バックグラウンドで自動インストール**します。ハーネスタブから手動で入れる必要はありません。（Step 2 で Node.js を先に入れていれば、この自動インストールは静かに成功します。）

![Marblo 初回起動時に必須 CLI と MCP が自動インストールされる進行画面。](/images/guide/install-autocli.svg)

### 3-2. ★ 認証 — ここで有料アカウントが必要です

オーケストレーターを開こうとすると、Marblo が **CLI 認証ゲート**を表示します。「認証を実行」を押すとターミナルタブが開き、ログインコマンドが自動で入力されます。自分で打つ場合は：

```bash
claude login
```

ブラウザが開いたら、**自分の Anthropic アカウント**でログインします。Codex も使うなら：

```bash
codex login
```

> ⚠️ **ここでは一つだけ覚えておいてください。** ゲートの文言は「ログイン」としか言わないため、無料ログインで足りるように見えます。しかし：
>
> - **ログインだけでは足りません** — ログインしたアカウントに **サブスクリプションまたは API クレジット（Claude Pro/Max など）が** 接続されていないと実際には動きません。
> - 無料アカウントでログインするとゲートは「準備完了」で通しますが、**初回スポーンでエージェントがすぐに止まります。** そのときは慌てず、冒頭 **「はじめる前に — 二つの準備物」の準備物 1（サブスクリプション／API キー）を** 確認してください。

認証が終わると各 CLI が「認証済み」状態に変わります。状態が更新されなければアプリを再起動してください。

## Step 4 — フォルダ接続 → オーケストレーターが自動で開く

認証まで終われば、あとは楽な道です。作業する **プロジェクトフォルダを一つ選ぶ**だけで、Marblo がそのフォルダを自動登録し（クリック 0 回）、**オーケストレーターを自動で開きます。**

![Marblo でプロジェクトフォルダを追加する画面。](/images/guide/project-add.svg)

オーケストレーターはあなたの司令塔です。フォルダが接続されると、あいさつとともに「どんなチケットを作りますか／どのエージェントを付けますか」を提案します。

![フォルダを接続するとオーケストレーターが自動で開く画面。](/images/guide/project-orchestrator.svg)

## Step 5 — 最初のエージェントをスポーン

オーケストレーターにやりたいことを自然言語で伝えるだけです。例えば：

> 「README にインストール方法のセクションを追加するチケットを作って、エージェントを付けて。」

オーケストレーターがチケットを作り、**物理エージェント（独立した CLI プロセス）をスポーン**します。スポーンされたエージェントは自分のターミナルタブで実際にコードを読み書きします。

この瞬間、先ほど済ませた認証とサブスク接続が再び試されます。認証とサブスクリプション（または API クレジット）がそろっていれば、エージェントは生きて作業を始めます。もしすぐに「error」カードになって死ぬなら → Step 3 のサブスク接続をもう一度確認してください。

## Step 6 — 初回作業の完了（価値の瞬間）

エージェントが作業を終えると、チケットを **REVIEW** に移します。あなたは結果（差分、変更サマリー）を確認して承認します。チケットが **DONE** に移るこの瞬間が、Marblo の **核心的な価値の瞬間**です — 自分でタイプする人から、仕事を任せてレビューする人へと役割が変わる地点です。

![オーケストレーターでミッション（作業）を作る画面。](/images/guide/mission-create.svg)

ここまで来たらおめでとうございます。最初の接続の三つのステップをすべて終え、**エージェントがチケットを最後まで完了するのを自分の目で**見たのです。

## つまずいたら？ — 最初の接続トラブルシューティング

- **アプリが「npm が見つかりません」と言うとき** — Step 2 で Node.js をインストールし、ターミナルを開き直して再試行してください。
- **認証ゲートが消えない／「ログインが必要」を繰り返すとき** — `claude login` を最後まで完了し、ブラウザでログイン後にアプリを再起動してください。
- **ログインは済んだのにエージェントがすぐ死ぬとき（error カード）** — ログインしたアカウントに Claude Pro/Max または API クレジットが接続されているか確認してください。無料アカウントはここで止まります。
- **初回起動でアプリが開かないとき（警告ダイアログ）** — Gatekeeper/SmartScreen を Step 1 の通りに越えてください。
- **それでもつまずくとき** — [バグ報告](/ja/bugs)で教えてください。どこでつまずいたかが次のバージョンを作ります。

## 次のステップ

初回完了まで来たら、次は **複数のエージェントを同時に**動かすことです。バックエンド・フロントエンド・テストのエージェントに役割を分けて配置し、依存関係のあるチケットを DAG でつなげば、Marblo が順序を守りながら並列で動かします。

- [Marblo とは](/ja/blog/what-is-marblo) — オーケストレーター中心の全体像
- [一人の開発者、複数のエージェント](/ja/blog/one-dev-many-agents) — 一人でチーム規模の仕事をする方法
- [衝突しない並列エージェント](/ja/blog/parallel-agents-that-dont-collide) — ワークツリー分離で複数エージェントを同時に動かす

二つの準備物（有料 Claude アカウント + Node.js）さえそろえれば、残りはほとんど Marblo が自動で処理します。あとは最初の一度の接続を済ませるだけです。
