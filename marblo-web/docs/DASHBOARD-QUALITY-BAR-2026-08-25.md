## 1. 무엇이 그 급을 만드나 — 분해

좋은 분석 대시보드와 "차트가 그려진 화면" 의 차이는 미학이 아닙니다. 대개
**질문을 이어서 할 수 있느냐**입니다. 사람은 대시보드를 볼 때 한 번에 하나씩
묻지 않습니다:

```
"이번 주 이탈이 늘었나?"          → 추세
"언제부터?"                      → 그 시점
"그날 신규는 어땠나?"             → ★같은 시점의 다른 계열
"그날 무슨 일이 있었나?"          → ★드릴다운
"지난주엔 이 정도였나?"           → ★비교
"팀A 만 보면?"                   → 필터
"이 화면 링크로 보내도 되나?"      → ★URL 상태
```

★**화살표가 붙은 넷이 이 앱에 없던 것들이고, 그게 "그냥 그래프" 와 갈리는
지점입니다.** 나머지(추세·시점·필터)는 이미 있었습니다.

여기에 **읽히는가**(밀도)와 **기다릴 때 성의 있는가**(빈 상태·로딩)를 더하면
여섯 항목이 됩니다. 아래가 그 여섯을 판정 가능한 문장으로 바꾼 것입니다.

### 1. 밀도 — 절제가 밀도를 만든다

밀도는 "많이 넣기" 가 아니라 **"덜 그리기"** 입니다. 잉크가 줄어야 값이 보입니다.

- 격자는 **가로만**, `--viz-grid`(바탕 바로 위 한 단계). 세로 격자 없음.
- x축 라벨은 밟히지 않을 만큼만. 단일 계열 차트는 **처음·가운데·끝 셋**으로
  못박고, 다계열 차트는 최소 간격(28px)을 줘 폭에 맞춰 솎습니다. 라벨끼리 밟으면
  안 붙이느니만 못합니다.
- y축은 단일 계열 차트에서는 **아예 숨깁니다**(`hide`) — 값 라벨이 직접 붙으므로
  축 눈금이 중복입니다. 다계열에서만 축을 냅니다.
- 값 라벨은 **전부가 아니라 고른 것만**(`pickValueLabelIndices`: 점이 12개
  이하면 전부, 많으면 최대·최소·끝점). ★모든 점에 숫자를 붙이는 것은 밀도가
  아니라 소음입니다.
- 축·잉크·격자는 전부 **뒤로 물러난 색**(`--viz-ink-muted` / `--viz-grid`),
  계열색은 마크에만.

**판정:** 차트 하나에서 눈에 처음 들어오는 것이 **선의 모양**이어야 합니다.
격자나 축 숫자가 먼저 보이면 밀도가 아니라 잡음입니다.

### 2. 단면 호버 — 이게 제일 큰 차이다

사람은 "이 선의 그날 값" 을 묻지 않고 **"그날 무슨 일이 있었나"** 를 묻습니다.

- 툴팁은 **보이는 전 계열**을 한 카드에 냅니다.
- ★그날 값이 없는 계열도 **줄이 남습니다**(`—`). 줄을 빼면 "그날 그 계열이
  없었다" 가 아니라 "그런 계열이 없다" 로 읽힙니다. 둘은 다른 말입니다.
- ★값이 없는 계열을 `0` 으로 쓰지 않습니다. 툴팁은 그림보다 더 자주 인용되는
  자리라 여기서 0 을 지어내면 차트보다 크게 거짓말이 됩니다.
- 크로스헤어(점선)가 시점을 가리키고, 활성 점이 커집니다.
- 범례에 마우스를 올리면 그 계열만 진해지고 나머지가 흐려집니다.

**판정:** 툴팁 한 장을 캡처했을 때 **그날의 상태를 다 말할 수 있으면** 됐습니다.

### 3. 드릴다운 — 같은 화면 안에서

- 클릭 → `openDrill(...)` → **기존 상세 패널**이 같은 화면에서 열립니다. 페이지
  이동이 아닙니다(이 앱에 이미 있던 장치를 그대로 씁니다).
- 클릭 가능한 차트만 커서가 바뀌고 푸터에 안내가 붙습니다. **안 되는데 되는 척
  하지 않습니다.**
- ★**권한 경계** — 계열에 `drillScopeKey` 가 안 붙어 오면 클릭 자체가 안
  붙습니다. 조직 대시보드는 `visibleScopes` 를 반드시 넘깁니다.
  자세한 것은 `CHART-LIBRARY-DECISION-2026-08-24.md` §12.

**판정:** 차트에서 눈에 띈 이상한 날을 **한 번의 클릭으로** 파고들 수 있으면
됐습니다. 두 번 이상 클릭해야 하거나 페이지가 바뀌면 안 된 것입니다.

### 4. 즉각 전환 + URL 상태 — ⚠ 반만 됐다

- 기간 버튼은 이미 즉시 반응합니다(`days` 상태). 기간을 바꾸면 `animationKey`
  가 바뀌어 **진입 애니메이션이 다시 탑니다** — 값이 바뀌었다는 신호입니다.
- ★**URL 에 안 남습니다.** 지금 상태로는 "이 화면 좀 보세요" 하고 링크를 보낼 수
  없습니다. 앰플리튜드 급의 실무적 핵심 중 하나가 이건데, **이 PR 에서는 안
  합니다** — `AnalyticsPanel.tsx` 를 병행 티켓 둘이 동시에 만지고 있어 충돌합니다.
  → §3-D

**판정:** 기간을 바꾸고 주소창을 복사해 새 탭에 붙였을 때 **같은 화면**이 나오면
됐습니다. 지금은 안 됩니다.

### 5. 비교 — ⚠ 컴포넌트는 됐고 데이터가 없다

- `MultiSeriesChart` 가 계열마다 `compare`(이전 구간)를 받아 **같은 축 위에 점선
  고스트**로 겹칩니다. 툴팁에 증감률이 함께 나옵니다.
- ★비교선은 **날짜가 아니라 인덱스로** 겹칩니다(8/1 자리에 7/25). 날짜가 다르므로
  x축은 지금 구간을 쓰고, 이전 구간 날짜는 툴팁에서만 씁니다.
- ★이전 값이 `0` 이면 증감률을 만들지 않습니다(`—`). 0 나누기는 이야기가 아닙니다.
- ★**어드민에 배선은 안 했습니다** — 이전 구간 계열을 주는 백엔드 필드가 없습니다.
  없는 데이터를 프론트에서 지어내지 않습니다. → §3-C

**판정:** 숫자 옆에 **"지난 기간엔?"** 의 답이 같이 있으면 됐습니다.

### 6. 빈 상태·로딩 — 성의가 드러나는 자리

이 앱에는 이미 좋은 장치가 있습니다(`적재 전` / `값 없음` / `표본 n건`). 차트는
그걸 **무너뜨리지 않는 것**이 먼저고, 그 위에 로딩을 얹습니다.

- **안 그리는 상태 셋** — `pending`(적재 전) · `empty`(구간에 값 없음) ·
  `insufficient`(표본 부족). 앞의 둘은 **축도 0 선도 안 그립니다.** 상태는
  차트가 추론하지 않고 **부르는 쪽이 줍니다.**
- **스켈레톤** — recharts 는 서버 HTML 에 마크를 0개 보내므로, 하이드레이션
  전까지 **차트와 같은 높이**의 뼈대가 섭니다. 격자·영역 실루엣·축 눈금 자리까지
  실제 차트 모양입니다.
- ★스켈레톤은 **중립 회색만** 씁니다. 계열색을 쓰면 그건 스켈레톤이 아니라
  **가짜 데이터**입니다. 잠깐이라도 값처럼 보이는 것을 그리면, 이 차트 시스템이
  지키려는 규율을 스켈레톤이 뒤에서 깨는 셈입니다.
- 값은 서버에서 이미 왔으므로 **표 보기는 스켈레톤일 때도 나옵니다.**
- `prefers-reduced-motion` 이면 숨쉬기도 진입 애니메이션도 끕니다.

**판정:** 느린 회선에서 새로고침했을 때 **빈 칸도, 레이아웃 튐도 없으면** 됐습니다.

## 4. 이 기준을 어떻게 검수하나

"예쁘다"는 검수가 안 되므로, 위 판정 문장들 중 **기계가 볼 수 있는 것은 전부
테스트로** 내렸습니다.

| 판정                                          | 어디서 고정했나                                             |
| --------------------------------------------- | ----------------------------------------------------------- |
| 단면 호버가 전 계열을 낸다                    | `interaction.test.tsx` — 값 없는 계열도 줄이 남는다         |

| 클릭이 권한 경계를 안 넘는다                  | `discipline.test.tsx` — 스코프 키 없으면 핸들러가 안 붙는다 |

★**기계가 못 보는 것**(선의 굵기가 적절한가, 여백이 편한가, 색이 예쁜가)은
테스트로 못 내립니다. 그건 사장님이 화면을 보시고 판정하실 몫이고, 이 문서는
**그 판정이 필요한 항목을 그 항목들로 좁히는 것**이 목적입니다.

★그리고 이 티켓에서는 **GUI 검증을 하지 않았습니다** — Playwright·Electron 을
띄우지 않았습니다. jsdom 은 브라우저가 아니라 DOM 구현체입니다. 그래서 "실제
브라우저에서 어떻게 보이는가" 는 **못 쟀고, 쟀다고 적지 않습니다.**
