### 2.1 nivo 의 CSS 변수 문제 — 추측이 아니라 실행해서 확인

nivo 의 상속색(`{ from: 'color', modifiers: [['darker', 0.3]] }` — 점 테두리·영역·
라벨의 **기본값**)은 `@nivo/colors` 안에서 `d3-color` 의 `rgb()` 를 거친다.

```
d3-color rgb("var(--chart-series-1)")            => rgb(0, 0, 0)
d3-color rgb("var(--chart-series-1)").darker(0.3) => rgb(0, 0, 0)
d3-color rgb("#3987e5").darker(0.3)               => rgb(51, 121, 206)
```

에러가 아니라 **조용히 검정**이 된다. 두 바탕을 오가야 하는 이번 건에서 이건
치명적이다 — 밝은 화면에서 아무 경고 없이 까맣게 칠해진다.

### 2.2 recharts 가 서버에서 안 그리는 것 — 실제 빌드 산출물

```html
<!-- .next/server/app/bench/recharts-fixed.html -->
<div width="640" height="180" class="recharts-wrapper"
     style="position:relative;cursor:default;width:640px;height:180px"></div>
```

`svg` 0개, `path` 0개. 어드민은 사내용이라 참을 수 있지만 **조직 대시보드는
고객 화면**이다. 첫 페인트가 빈 칸이었다가 하이드레이션 후 튀어나오는 건
그 화면에서 값을 치른다.

recharts 가 나쁜 라이브러리라는 뜻이 아니다 — 활동성은 셋 중 최고고 접근성도
기본 제공한다. 다만 **이 두 화면에는 안 맞는다.**

### 4.1 색은 컴포넌트에 없다

차트 컴포넌트 소스에 헥사값이 **한 개도 없다**(테스트로 강제 —
`theme.test.tsx`). 전부 `var(--viz-*)` 이고, 바탕은 `data-viz-surface` 가 고른다.

```tsx
<TimeSeriesChart … surface="dark" />   {/* 어드민 */}
<TimeSeriesChart … surface="light" />  {/* 조직 대시보드 */}
```

두 바탕의 렌더 결과는 **`data-viz-surface` 한 글자만 빼고 완전히 동일**하다.
이것도 테스트로 못박았다 — 변수를 쓰더라도 바탕마다 다른 컴포넌트를 쓴다면
차트 시스템은 결국 둘로 갈리기 때문이다.

`prefers-color-scheme` 이 아니라 명시적 속성인 이유: 어드민은 OS 설정과 무관하게
항상 어둡고, 조직 대시보드는 항상 밝다. 두 화면이 한 브라우저에 동시에 열린다.

### 4.2 팔레트 검증 — 눈으로 안 보고 돌렸다

값은 dataviz 스킬 `references/palette.md` 의 light/dark 열이다(같은 8색을 각
바탕에 맞게 스텝만 다르게 잡은 것이지 다른 팔레트가 아니다). **우리 실제 바탕으로**
`validate_palette.js` 를 다시 돌렸다:

| 바탕 | 결과 |
| --- | --- |
| dark `#09090b` (어드민) | 명도대·채도·CVD·정상시야·대비 **5개 ALL PASS** |
| light `#ffffff` (조직 대시보드) | 4개 PASS + **대비 WARN** |

밝은 바탕의 WARN 은 무시 가능한 경고가 아니라 **relief 의무**다:
aqua(2.82) / yellow(2.17) / magenta(2.69) 가 3:1 미만이라, 이 슬롯을 쓰는 밝은
화면의 차트는 **직접 값 라벨이나 표 보기를 반드시 함께** 내야 한다.
`TimeSeriesChart` 는 둘 다 기본으로 낸다.

★계열 슬롯은 **순환하지 않는다.** 계열이 슬롯보다 많으면 색을 만들어내지 말고
'그 외'로 접어라. 색은 순위가 아니라 엔티티를 따라간다 — 필터로 계열 수가
바뀌어도 남은 계열의 색이 다시 칠해지면 안 된다.

★상태색(녹/노랑/주황/빨강)은 **테마를 타지 않는다.** 계열 슬롯으로 재사용하지
않고, 색만으로 뜻을 지지 않도록 항상 아이콘·라벨과 함께 쓴다.

### 4.3 ★빈 것을 0 으로 그리지 않는다

지금 어드민의 신뢰도 표기(녹/노랑/빨강 + '적재 전')는 좋은 장치다. 차트가 빈 걸
0 으로 그리면 그 장치가 무너진다. 그래서 상태를 **차트가 추론하지 않는다** —
부르는 쪽이 정해서 준다.

| `state` | 뜻 | 차트가 하는 일 |
| --- | --- | --- |
| `ready` | 그릴 값이 있다 | 그린다 |
| `empty` | 측정은 됐는데 이 구간에 값이 없다 | ★안 그린다. 축도 0 선도 없다 |
| `pending` | 파생표/소스가 아직 없다 | ★안 그린다 + **'적재 전'** 이라고 쓴다 |
| `insufficient` | 그리긴 하는데 표본이 너무 적다 | 그리되 **표본 수를 같이 박는다** |

`empty` 와 `pending` 이 둘 다 "안 그린다" 인데 왜 가르나 — **보는 사람이 할 일이
다르다.** '적재 전' 은 기다리면 채워지고, `empty` 는 기다려도 안 채워진다(그
구간엔 정말 아무 일도 없었다). 이건 빈 배열 하나로는 절대 복원할 수 없는
구분이라, 차트가 혼자 정하게 두면 안 된다.

`insufficient` 를 **숨기지 않고 표시**하는 이유: 숨기면 정보를 잃고, 표시만 하면
과장이 된다. 그려 주되 "표본 n건 — 추세로 읽지 마세요" 를 위에 박는다.

### 4.4 ★집계는 차트 안에 없다

`TimeSeriesChart` 가 계산하는 것은 **값 → 픽셀**(스케일) 뿐이다. 합계·평균·비율·
필터는 전부 밖에서 끝내고 들어온다. 라이브러리를 넣는 건 보기 좋게 만드는 일이지
숫자를 바꾸는 일이 아니다.

## 5. 대표 차트 이전 — 한 자리만

이 앱은 매일 배포된다. 그래서 어드민 차트를 한 번에 갈아엎지 않았다.

**옮긴 것: 어드민 "DAU 추이" 한 자리.** (마커 + 드릴다운 + 빈 상태를 다 가진
가장 대표적인 차트다.) 나머지 `LineChart` 호출부 4곳과 `TwoLineChart` /
`StackedBarChart` 는 **손 SVG 그대로** 두었다 — 별도 PR 로 옮긴다.

`AnalyticsPanel.tsx` 는 병행 티켓 둘이 동시에 만지고 있어서, 바꾼 것은
**import 한 줄 + JSX 한 덩이**뿐이다.

### 5.1 같은 숫자가 나온다는 증명

`TimeSeriesChart.parity.test.tsx` 는 이전 손 SVG 구현을 **한 글자도 안 고치고
얼려 두고**, 같은 데이터로 둘 다 렌더해서 대조한다:

1. 값 라벨로 찍히는 숫자 집합이 같다 (포맷까지, 순서까지)
2. x축 라벨이 같다
3. **꼭짓점 좌표가 같다** — 스케일 계산이 어긋나지 않았다
4. 푸터("범위 최대 N", "N일")가 같다
5. 빈 구간·전부 0 을 양쪽 다 안 그린다

3번이 핵심이다. 스케일이 틀리면 **숫자는 그대로인데 그림이 거짓말을 한다.**
허용오차는 0.001px 인데, 이건 값이 달라서가 아니라 손 SVG 는 좌표를 배정밀도로
박고 d3-path 는 `d` 속성을 소수 셋째 자리에서 반올림하기 때문이다. 화면에 찍히는

## 10. ★#1206 의 걱정을 코드로 닫았다

#1206 이 옳았습니다 — **recharts 의 기본값은 우리 규율과 반대입니다.** 그래서
명시적으로 끄고 테스트로 고정했습니다(`discipline.test.tsx`, 17개).

| recharts 기본 | 우리가 한 것 | 고정한 테스트 |
| --- | --- | --- |
| 결측을 이을 수 있음 | `connectNulls={false}` **명시** | 값 없는 날에 선이 실제로 끊긴다 |
| 데이터를 만드는 쪽이 0 으로 채우기 쉬움 | `toRows` 가 `null` 을 넣는다 | 꼭짓점이 축 바닥(0)에 안 닿는다 |
| 표·툴팁에 0 이 새기 쉬움 | 값 없으면 `—` | 표·툴팁 카드 둘 다 |
| **Y축 자동 스케일** | 도메인을 **숫자로 확정** | §11 |

★`connectNulls` 는 recharts 기본값도 `false` 입니다. 그래도 **명시**하는 이유:
안 적어 두면 다음 사람이 "선이 끊겨 보인다"며 켭니다. 적어 두면 그 줄 옆 주석이
왜 안 되는지 말해 줍니다.

★그리고 `ChartFrame` 은 **한 줄도 안 바꿨습니다**(주석 제외). #1208 이 프레임을
라이브러리와 무관하게 설계한 값이 정확히 여기서 나왔습니다 — 라이브러리를
갈아탔는데 "안 그리는 상태들"의 규율은 안 흔들렸습니다.

## 11. ★Y축 자동 스케일 누출을 닫았다 (org-access §3.4-10)

org-access 문서가 **파생값 15개 중 10번**으로 지목한 누출입니다:

> "최댓값이 남의 팀 값이면 그 값이 축 눈금에 인쇄된다. 라이브러리가 자동으로
> 해서 **코드에 안 보인다.**"

**한 일:**

1. `YDomainSpec` 을 도입해 도메인을 **숫자로 확정**해서 넘깁니다.
   `"auto"` / `"dataMax"` 같은 문자열은 넘기지 않습니다 — 넘기는 순간 축이
   라이브러리 것이 됩니다.
   - `{ kind: "visible" }`(기본) — **화면에 실제로 그려진 값**의 최대
   - `{ kind: "fixed", max }` — 부르는 쪽이 못박은 값
2. **범례로 끈 계열은 축에서도 빠집니다.** 안 보이는 것이 축을 밀어 올리면
   그게 §3.4-9(스택 전체 높이)·§3.4-10 이 말한 뺄셈입니다.
3. 못박은 상한이 값을 못 덮으면 **조용히 자르지 않고** 차트가 눈에 보이게
   말합니다(⚠ 축 상한을 넘는 값이 있습니다).

★★**여기서 실제로 한 번 데였습니다. 이게 이 절의 제일 중요한 사실입니다.**

`domain={[0, 100]}` 을 주고 900짜리 계열을 넣었더니 **축에 900 이 찍혔습니다.**
recharts 는 `allowDataOverflow` 가 `false`(기본)일 때 **도메인을 데이터에 맞게
늘립니다.** 즉 `domain` 을 적어도 조용히 무시됩니다.

```tsx
<YAxis domain={[0, max]} allowDataOverflow />   {/* ★이 한 줄이 없으면 domain 은 장식이다 */}
```

org-access 가 "코드에 안 보이는 누출"이라고 한 것이 정확히 이 모양입니다 —
막았다고 **적어 둔 코드가 실제로는 안 막고 있었습니다.** 테스트가 아니었으면
못 봤습니다.

## 12. ★클릭 인터랙션 — 그리고 권한 경계

사장님이 명시하신 요구입니다. recharts 는 `onClick` 이 기본으로 있으니 배선은
쉽고, **어려운 건 드릴다운이 권한 경계를 안 넘게 하는 것**입니다. 조직
대시보드에서 팀장이 차트를 클릭해 남의 팀 행으로 들어가면 그게 유출입니다.

**설계 — 차트가 드릴 대상을 지어낼 수 없게 만든다:**

```
클릭 가능 = onDrill 있음
          AND 계열에 drillScopeKey 가 붙어 있음        ← 서버가 붙여 보낸다
          AND (visibleScopes 를 안 받았거나, 그 키가 목록에 있음)
```

- **계열에 `drillScopeKey` 가 없으면 클릭 핸들러가 아예 안 붙습니다.** 커서도
  안 바뀌고 "클릭하세요" 안내도 안 뜹니다. 차트는 스코프 키를 만들지 못합니다.
- `visibleScopes` 는 "이 화면은 스코프가 걸린 화면이다" 라는 **호출부의 선언**
  입니다. 어드민(전수를 보는 사람)은 안 넘기고, **조직 대시보드는 반드시
  넘깁니다.**
- ★**정직하게 적습니다: 이건 1차 방어가 아니라 마지막 관문입니다.** 1차는
  서버 봉투(org-access §3.2 — `S ⊄ visible(u)` 이면 애초에 안 싣는다)입니다.
  차트 게이트는 심층 방어이지 그것만 믿을 물건이 아닙니다.

**두 종류의 클릭:**

| 클릭 | 나오는 것 | 언제 산다 |
| --- | --- | --- |
| 날짜 단면(그림 아무 데나) | `{ scopeKey, date }` | ★드릴 가능한 계열들이 **같은 스코프일 때만** |
| 활성 점(계열이 특정됨) | `{ scopeKey, seriesKey, date, value }` | 그 계열이 드릴 가능하면 |

★날짜 단면 클릭이 "같은 스코프일 때만" 인 이유: 그림 아무 데나 누른 클릭은
계열을 특정하지 못합니다. 계열마다 스코프가 다른 차트(팀별 계열)에서 그런
클릭에 아무 스코프나 실어 보내면 **그게 정확히 남의 팀으로 들어가는 문**입니다.
애매하면 안 엽니다.

★값이 없는 날을 클릭하면 `value: null` 이 나갑니다 — `0` 이 아닙니다. 받는 쪽이
0 을 보고 "그날은 0이었구나" 라고 읽으면 안 됩니다.

## 13. 잃은 것과 갚은 것 — 숨기지 않고

### 13.1 서버 렌더 (잃음 → 스켈레톤으로 갚음)

recharts 는 **서버 HTML 에 `<path>` 를 0개** 보냅니다(bakeoff §3.1). 사장님이
이걸 아시고 고르셨으므로, 우리 일은 **그 대가를 갚는 것**입니다.

- `ChartFrame` 이 하이드레이션 전까지 **차트와 같은 높이**의 스켈레톤을 세웁니다.
  높이가 같으므로 차트가 나타나면서 아래 내용을 밀지 않습니다(CLS 없음).
- ★스켈레톤은 **계열색을 안 씁니다.** 중립 회색(`--viz-skeleton`)만 씁니다.
  파란 선을 그리면 그건 스켈레톤이 아니라 **가짜 데이터**이고, 잠깐이라도 값처럼
  보이는 것을 그리면 이 차트 시스템의 규율을 스켈레톤이 뒤에서 깨는 셈입니다.
- 값은 이미 서버에서 왔으므로 **표 보기는 스켈레톤일 때도 나옵니다.** 밝은 바탕의
  relief 의무를 한 프레임도 안 비웁니다.
- `prefers-reduced-motion` 이면 숨쉬기 애니메이션도, 진입 애니메이션도 끕니다.

### 13.2 좌표 대조 시험 (형태가 바뀜)

★**이건 진짜로 잃은 것이라 그대로 적습니다.** §5.1 의 대조 시험은 손 SVG 와
visx 의 `renderToStaticMarkup` 산출물끼리 **꼭짓점 좌표를 0.001px 까지** 맞대
봤습니다. recharts 는 서버에서 안 그리므로 **그 형태의 대조는 불가능합니다.**

대신 마운트해서 나온 좌표로 **스케일의 성질**을 검사합니다:

```
모든 꼭짓점이  y = yBase − (v / max)·(yBase − yTop)  위에 있는가
(yBase = 값 0 의 y. 즉 0 을 바닥으로 한 선형인가)
```

이건 손 SVG 가 좌표를 만들던 식 그 자체이고, "스케일이 틀리면 숫자는 그대로인데
그림이 거짓말을 한다" 는 원래의 걱정을 그대로 겨냥합니다. 절대 픽셀은 비교하지
않습니다 — recharts 의 여백 규칙을 타고, jsdom 에는 레이아웃이 없어 상자 크기도
우리가 고정한 값이기 때문입니다. ★**못 재는 것을 잰 척하지 않습니다.**

값 라벨로 찍히는 숫자·x축 라벨·푸터는 여전히 **완전 일치**로 못박습니다.

## 14. ★새 차트를 만들 때 지킬 것 (§8 에 더한다)

12. **애니메이션은 `prefers-reduced-motion` 을 탄다.** 그리고 테스트에서는
    `animate={false}` 로 꺼라 — 애니메이션 중에는 값 라벨이 아직 안 그려져 있는데
