### 2.1 nivo 의 CSS 변수 문제 — 추측이 아니라 실행해서 확인

nivo 의 상속색(`{ from: 'color', modifiers: [['darker', 0.3]] }` — 점 테두리·영역·
라벨의 **기본값**)은 `@nivo/colors` 안에서 `d3-color` 의 `rgb()` 를 거친다.

```
d3-color rgb("var(--chart-series-1)")            => rgb(0, 0, 0)
d3-color rgb("var(--chart-series-1)").darker(0.3) => rgb(0, 0, 0)
d3-color rgb("#3987e5").darker(0.3)               => rgb(51, 121, 206)
```

에러가 아니라 **조용히 검정**이 된다. 두 바탕을 오가야 하는 이번 건에서 이건
치명적이다 — 밝은 화면에서 아무 경고 없이 까맣게 칠해진다.

### 2.2 recharts 가 서버에서 안 그리는 것 — 실제 빌드 산출물

```html
<!-- .next/server/app/bench/recharts-fixed.html -->
<div width="640" height="180" class="recharts-wrapper"
     style="position:relative;cursor:default;width:640px;height:180px"></div>
```

`svg` 0개, `path` 0개. 어드민은 사내용이라 참을 수 있지만 **조직 대시보드는
고객 화면**이다. 첫 페인트가 빈 칸이었다가 하이드레이션 후 튀어나오는 건
그 화면에서 값을 치른다.

recharts 가 나쁜 라이브러리라는 뜻이 아니다 — 활동성은 셋 중 최고고 접근성도
기본 제공한다. 다만 **이 두 화면에는 안 맞는다.**

### 4.1 색은 컴포넌트에 없다

차트 컴포넌트 소스에 헥사값이 **한 개도 없다**(테스트로 강제 —
`theme.test.tsx`). 전부 `var(--viz-*)` 이고, 바탕은 `data-viz-surface` 가 고른다.

```tsx
<TimeSeriesChart … surface="dark" />   {/* 어드민 */}
<TimeSeriesChart … surface="light" />  {/* 조직 대시보드 */}
```

두 바탕의 렌더 결과는 **`data-viz-surface` 한 글자만 빼고 완전히 동일**하다.
이것도 테스트로 못박았다 — 변수를 쓰더라도 바탕마다 다른 컴포넌트를 쓴다면
차트 시스템은 결국 둘로 갈리기 때문이다.

`prefers-color-scheme` 이 아니라 명시적 속성인 이유: 어드민은 OS 설정과 무관하게
항상 어둡고, 조직 대시보드는 항상 밝다. 두 화면이 한 브라우저에 동시에 열린다.

### 4.2 팔레트 검증 — 눈으로 안 보고 돌렸다

값은 dataviz 스킬 `references/palette.md` 의 light/dark 열이다(같은 8색을 각
바탕에 맞게 스텝만 다르게 잡은 것이지 다른 팔레트가 아니다). **우리 실제 바탕으로**
`validate_palette.js` 를 다시 돌렸다:

| 바탕 | 결과 |
| --- | --- |
| dark `#09090b` (어드민) | 명도대·채도·CVD·정상시야·대비 **5개 ALL PASS** |
| light `#ffffff` (조직 대시보드) | 4개 PASS + **대비 WARN** |

밝은 바탕의 WARN 은 무시 가능한 경고가 아니라 **relief 의무**다:
aqua(2.82) / yellow(2.17) / magenta(2.69) 가 3:1 미만이라, 이 슬롯을 쓰는 밝은
화면의 차트는 **직접 값 라벨이나 표 보기를 반드시 함께** 내야 한다.
`TimeSeriesChart` 는 둘 다 기본으로 낸다.

★계열 슬롯은 **순환하지 않는다.** 계열이 슬롯보다 많으면 색을 만들어내지 말고
'그 외'로 접어라. 색은 순위가 아니라 엔티티를 따라간다 — 필터로 계열 수가
바뀌어도 남은 계열의 색이 다시 칠해지면 안 된다.

★상태색(녹/노랑/주황/빨강)은 **테마를 타지 않는다.** 계열 슬롯으로 재사용하지
않고, 색만으로 뜻을 지지 않도록 항상 아이콘·라벨과 함께 쓴다.

### 4.3 ★빈 것을 0 으로 그리지 않는다

지금 어드민의 신뢰도 표기(녹/노랑/빨강 + '적재 전')는 좋은 장치다. 차트가 빈 걸
0 으로 그리면 그 장치가 무너진다. 그래서 상태를 **차트가 추론하지 않는다** —
부르는 쪽이 정해서 준다.

| `state` | 뜻 | 차트가 하는 일 |
| --- | --- | --- |
| `ready` | 그릴 값이 있다 | 그린다 |
| `empty` | 측정은 됐는데 이 구간에 값이 없다 | ★안 그린다. 축도 0 선도 없다 |
| `pending` | 파생표/소스가 아직 없다 | ★안 그린다 + **'적재 전'** 이라고 쓴다 |
| `insufficient` | 그리긴 하는데 표본이 너무 적다 | 그리되 **표본 수를 같이 박는다** |

`empty` 와 `pending` 이 둘 다 "안 그린다" 인데 왜 가르나 — **보는 사람이 할 일이
다르다.** '적재 전' 은 기다리면 채워지고, `empty` 는 기다려도 안 채워진다(그
구간엔 정말 아무 일도 없었다). 이건 빈 배열 하나로는 절대 복원할 수 없는
구분이라, 차트가 혼자 정하게 두면 안 된다.

`insufficient` 를 **숨기지 않고 표시**하는 이유: 숨기면 정보를 잃고, 표시만 하면
과장이 된다. 그려 주되 "표본 n건 — 추세로 읽지 마세요" 를 위에 박는다.

### 4.4 ★집계는 차트 안에 없다

`TimeSeriesChart` 가 계산하는 것은 **값 → 픽셀**(스케일) 뿐이다. 합계·평균·비율·
필터는 전부 밖에서 끝내고 들어온다. 라이브러리를 넣는 건 보기 좋게 만드는 일이지
숫자를 바꾸는 일이 아니다.

이 앱은 매일 배포된다. 그래서 어드민 차트를 한 번에 갈아엎지 않았다.

**옮긴 것: 어드민 "DAU 추이" 한 자리.** (마커 + 드릴다운 + 빈 상태를 다 가진

`AnalyticsPanel.tsx` 는 병행 티켓 둘이 동시에 만지고 있어서, 바꾼 것은
**import 한 줄 + JSX 한 덩이**뿐이다.

### 5.1 같은 숫자가 나온다는 증명

`TimeSeriesChart.parity.test.tsx` 는 이전 손 SVG 구현을 **한 글자도 안 고치고
얼려 두고**, 같은 데이터로 둘 다 렌더해서 대조한다:

1. 값 라벨로 찍히는 숫자 집합이 같다 (포맷까지, 순서까지)
2. x축 라벨이 같다
3. **꼭짓점 좌표가 같다** — 스케일 계산이 어긋나지 않았다
4. 푸터("범위 최대 N", "N일")가 같다
5. 빈 구간·전부 0 을 양쪽 다 안 그린다

3번이 핵심이다. 스케일이 틀리면 **숫자는 그대로인데 그림이 거짓말을 한다.**
허용오차는 0.001px 인데, 이건 값이 달라서가 아니라 손 SVG 는 좌표를 배정밀도로
박고 d3-path 는 `d` 속성을 소수 셋째 자리에서 반올림하기 때문이다. 화면에 찍히는
숫자는 위 1번에서 **완전 일치**로 따로 못박는다.

색도 안 바뀐다: 어두운 바탕의 `--viz-series-1` 은 어드민이 쓰던 `SERIES`
(`#3987e5`) 와 같은 값이고, `--viz-grid` 도 기존 `#2c2c2a` 그대로다 (테스트로 고정).
의도적으로 바꾼 것은 값 라벨 잉크 한 단계뿐이다(`#d4d4d8` → 팔레트가 승인한
`--viz-ink-secondary` `#c3c2b7`).

## 8. 새 차트를 만들 때 지킬 것

1. **색을 박지 마라.** `seriesVar(slot)` 또는 `var(--viz-*)` 만 쓴다.
   (`theme.test.tsx` 가 소스에 헥사가 들어오면 깨진다.)
2. **집계를 차트 안에 넣지 마라.** 값 → 픽셀만.
3. **상태를 추론하지 마라.** `empty`/`pending`/`insufficient` 는 받아서 쓴다.
4. **계열 색을 순환시키지 마라.** 슬롯이 모자라면 '그 외'로 접는다.
5. **축을 둘로 만들지 마라.** 단위가 다른 두 측정은 차트를 둘로 나눈다.
6. **`ChartFrame` 을 거쳐라.** 접근성과 안 그리는 상태가 거기 있다.
