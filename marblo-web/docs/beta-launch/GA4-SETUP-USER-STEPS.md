# GA4 — 내가 직접 해야 하는 작업 (콘솔 세팅 체크리스트)

> 코드(태깅)는 에이전트가 심어서 PR로 올립니다. **아래는 사람이 GA4 콘솔에서 해야만 하는 것들** — 측정 ID 발급, env 주입, 전환(Key Event) 지정, 검증까지.
> 이거 안 하면 페이지뷰도, 전환도 **하나도 안 잡힙니다.** 베타 홍보 트래픽 오기 전에 끝내세요.
> 소요: 약 20~30분.

---

## 0. 전체 순서 한눈에

```
① GA4 속성 만들기 → 측정 ID(G-XXXXXXX) 발급
② 측정 ID를 env에 넣기 (로컬 .env.local + 배포 환경변수) → 재배포
③ 실시간(Realtime)/DebugView 로 페이지뷰 들어오는지 확인
④ 전환 이벤트 3개를 "주요 이벤트(Key Event)"로 표시
⑤ (선택) 퍼널 탐색 만들기 — 신청→다운로드→구매
⑥ (선택) 동의·프라이버시 정합 확인
```

> ⚠️ `NEXT_PUBLIC_GA4_MEASUREMENT_ID`는 **빌드 타임에 코드에 박히는** 값입니다. 그래서 **배포 환경변수에 넣고 반드시 재배포**해야 실제 사이트에 적용됩니다. 로컬 .env.local만 넣으면 내 컴퓨터에서만 동작.

---

## ① GA4 속성 만들기 + 측정 ID 발급 (필수)

1. https://analytics.google.com 접속 → 로그인
2. 좌하단 **관리(⚙️ Admin)** → **속성 만들기(Create Property)**
   - 속성 이름: `Marblo` (또는 `marblo.app`)
   - 시간대: **대한민국(GMT+9)**, 통화: **KRW(₩)** ← 구매 금액 리포트에 중요
3. 비즈니스 정보 대충 채우고 만들기
4. **데이터 스트림(Data Streams)** → **웹(Web)** 선택
   - 웹사이트 URL: `https://marblo.app`
   - 스트림 이름: `Marblo Web`
5. 생성되면 화면에 **측정 ID `G-`로 시작하는 값**(예: `G-ABC1234XYZ`)이 나옵니다. **이걸 복사.** ← 이게 핵심.

> 📌 "향상된 측정(Enhanced measurement)"은 켜두면 스크롤·이탈클릭·파일다운로드 등을 자동으로 잡아줍니다. 켜두세요.

## ② 측정 ID를 env에 넣기 + 재배포 (필수)

### (a) 로컬 개발용 — `marblo-web/.env.local`

파일에 이 줄 추가(값은 내 측정 ID로):

```
NEXT_PUBLIC_GA4_MEASUREMENT_ID=G-여기에_내_측정ID
```

> `.env.local`은 **커밋하지 않습니다**(gitignore). 각자 로컬에만.

### (b) 배포 환경 — 여기가 진짜 (필수)

marblo.app이 배포되는 곳의 환경변수에 **똑같은 이름**으로 넣고 **재배포**:

- **Vercel인 경우**: 프로젝트 → **Settings → Environment Variables** → `NEXT_PUBLIC_GA4_MEASUREMENT_ID` = `G-...` 추가 (Production/Preview 둘 다) → **Redeploy**
- **Firebase App Hosting인 경우**: `apphosting.yaml`의 `env:` 또는 Secret에 추가 후 재배포
- **직접 빌드/서버인 경우**: 빌드 서버의 환경변수에 export 후 `next build` 다시

> 확인법: 배포 후 marblo.app 접속 → 브라우저 개발자도구 **Network** 탭에서 `googletagmanager.com/gtag/js?id=G-...` 요청이 보이면 성공. (env 없으면 코드가 no-op라 아무 요청도 안 감 = 정상 방어)

## ③ 페이지뷰 들어오는지 확인 (필수 — 배포 직후)

1. GA4 → **보고서 → 실시간(Realtime)**
2. 다른 탭/폰으로 **marblo.app 접속**해서 몇 페이지 클릭
3. 30초~1분 안에 실시간에 **활성 사용자 1명**과 페이지뷰가 뜨면 → 설치 성공 ✅

**DebugView(정밀 확인, 선택):**

- 크롬 확장 [Google Analytics Debugger] 켜고 marblo.app 접속 → GA4 → 관리 → **DebugView**에서 이벤트가 실시간으로 흐르는 걸 봅니다. 아래 ④ 전환 확인할 때 유용.

---

## ④ 전환 이벤트 3개를 "주요 이벤트(Key Event)"로 표시 (필수 — 가장 중요)

우리 코드가 쏘는 전환 이벤트는 정확히 **이 3개 이름**입니다:

| 전환            | 이벤트 이름     | 언제 발화                  | 딸려오는 값(예)                                             |
| --------------- | --------------- | -------------------------- | ----------------------------------------------------------- |
| **베타 신청**   | `generate_lead` | founders 신청 폼 제출 성공 | (PII 없음)                                                  |
| **강의 구매**   | `purchase`      | 결제 확정 성공 페이지      | `value`(금액), `currency`(KRW), `transaction_id`, 강의 정보 |
| **앱 다운로드** | `download`      | Mac/Win 다운로드 버튼 클릭 | `os`(mac/win), `arch`, `app_version`                        |

### 표시 방법

1. 먼저 이 이벤트들이 **한 번은 실제로 발생**해야 GA4 목록에 나타납니다.
   → marblo.app에서 직접 **베타 신청 1번 / 다운로드 버튼 1번 / (가능하면) 테스트 결제 1번** 해보세요. (DebugView로 발화 확인하면 확실)
2. GA4 → **관리(Admin) → 이벤트(Events)** (또는 "주요 이벤트 / Key events" 메뉴)
3. 목록에서 `generate_lead`, `purchase`, `download` 각각 옆의 **"주요 이벤트로 표시" 토글을 ON**
   - 안 보이면 24시간까지 걸릴 수 있음. 급하면 **"이벤트 만들기"가 아니라**, 미리 이름만 알고 있으니 **"주요 이벤트" 화면에서 이름 직접 입력**해 등록도 가능.
4. `purchase`는 **전자상거래 매출**로 자동 집계됩니다(통화 KRW라 원화로). value가 실려 있어 **매출 리포트**에 바로 뜸.

> 💡 "주요 이벤트(Key Event)"가 예전의 "전환(Conversion)"입니다. GA4가 용어를 바꿨어요. 이걸 켜야 전환수/전환율 리포트와 광고 최적화에 쓰입니다.

## ⑤ (선택·권장) 퍼널 탐색 만들기 — 신청 → 다운로드 → 구매

베타 성과를 한눈에 보려면:

1. GA4 → **탐색(Explore)** → **유입경로 탐색(Funnel exploration)**
2. 단계 설정:
   - 1단계: `page_view` (또는 랜딩 방문)
   - 2단계: `generate_lead` (베타 신청)
   - 3단계: `download` (앱 다운로드)
   - 4단계: `purchase` (강의 구매)
3. 각 단계 이탈률이 보입니다 → 어디서 사람이 빠지는지 = 개선 포인트.

> 이게 "데이터가 답이다" 채널 운영자용으로도 좋은 콘텐츠 소재.

---

## ⑥ (선택) 동의·프라이버시 정합 확인

- 우리 이벤트에는 **이메일·이름 같은 PII를 넣지 않습니다**(코드에서 막아둠, PIPA 준수). 그래도:
- GA4 → 관리 → **데이터 설정 → 데이터 수집**에서 **Google 신호(Google Signals)** 를 켤지 결정. 켜면 인구통계/관심사 리포트가 좋아지지만 개인화 데이터라 **개인정보처리방침에 GA 사용 명시**가 있어야 안전합니다.
- 이미 `legal/privacy` 페이지가 있으니, 거기에 "Google Analytics(GA4)로 익명 사용 통계를 수집한다"는 한 줄을 넣어두면 깔끔.
- (선택) 데이터 보존 기간: 관리 → 데이터 설정 → 데이터 보존 → **14개월**로.

- [ ] ⑤ (선택) 신청→다운로드→구매 퍼널 탐색 저장

## 자주 막히는 것 (FAQ)

- **Q. env 넣었는데 실시간에 안 떠요.** → 배포 환경변수에 넣고 **재배포**했는지 확인(로컬만 넣으면 안 됨). 광고 차단 확장/애드블록도 GA를 막으니 시크릿창·다른 기기로 테스트.
- **Q. 이벤트 이름이 목록에 없어요.** → 최소 1번은 실제로 그 행동(신청/다운로드/구매)을 해야 나타남. 반영에 몇 분~최대 24시간.
- **Q. purchase 금액이 이상해요.** → value는 원화 숫자 그대로(예: 49000). 통화가 KRW로 설정됐는지 확인.
- **Q. 측정 ID가 여러 개 필요한가요?** → 아니요. 웹은 스트림 1개 = 측정 ID 1개면 충분.
