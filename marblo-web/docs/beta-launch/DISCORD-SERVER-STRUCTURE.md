# Marblo 베타 디스코드 서버 구조 설계 (국내+해외, 한/영)

> **목표:** 국내·해외 유저가 한 서버에서 자연스럽게 섞이되, 언어 장벽 없이 각자 편한 채널을 쓰게.
> **원칙:** 공용 채널은 **이중언어(ko/en 병기)**, 대화 채널은 **언어별 분리(🇰🇷/🇬🇧)**. **봇 없이도 굴러가되**, 커지면 자동화.
> **포지셔닝:** Marblo = _control plane for AI-native teams_ — 이종(異種) 멀티에이전트를 한 화면에서 오케스트레이션하고, 티켓→PR 을 추적하며, 안전하게 병합(safe-merge)하는 데스크톱 앱. (닫힌/미공개 기능은 커뮤니티에서 홍보하지 않음.)

이 문서는 **그대로 따라 하면 서버가 완성되는** 세팅 지침서입니다. 온보딩 문안(핀 고정용 카피)은 [DISCORD-ONBOARDING.md](./DISCORD-ONBOARDING.md) 참고.

---

## 0. 두 가지 선택지 — 먼저 MVP, 나중에 확장

| 구성              | 언제                              | 채널 수   |
| ----------------- | --------------------------------- | --------- |
| **최소구성(MVP)** | 오픈 첫날 ~ 첫 몇 주 (인원 <100)  | 6~7개     |
| **권장 풀 구조**  | 인원이 늘고 언어 트래픽이 갈릴 때 | 15개 내외 |

> 첫날은 **MVP 로 시작**하세요. 채널이 비어 있으면 오히려 죽은 서버처럼 보입니다. 대화가 한 채널을 넘치기 시작할 때 §2 트리로 쪼개면 됩니다.

---

## 1. 최소구성 MVP 트리 (오픈 첫날, 이걸로 충분)

```
📢 INFO (읽기 전용, 이중언어)
├─ #start-here          ← 온보딩 가이드 핀 고정 (한/영). Welcome Screen 목적지.
├─ #rules               ← 규칙 (규칙 스크리닝으로 동의 → Founder Beta)
└─ #announcements       ← 릴리스/공지 (한·영 병기)

💬 COMMUNITY (공용, 이중언어 OK)
├─ #general             ← 잡담·자기소개·자랑 다 여기서 시작 (any language welcome)
├─ #help                ← 사용법 질문 (한/영 섞여도 OK)
└─ #bugs-and-feedback   ← 버그·기능제안·6문항 폼 링크 (템플릿 핀)

🔒 #staff (비공개, 팀 전용)
```

- 언어 분리 없이 **공용 이중언어**로 시작 → 트래픽이 한쪽으로 쏠리면 그때 🇰🇷/🇬🇧 로 분화.
- 역할은 **Founder Beta 하나만** 있어도 굴러갑니다(§3의 언어/Verified 역할은 확장 시 추가).
- 이 6~7채널이면 **첫날 운영 100% 가능**.

## 2. 권장 풀 채널 트리 (확장판)

```
📢 INFO (모두 읽기 전용, 이중언어)
├─ #start-here          ← 온보딩 가이드 핀 고정 (한/영)
├─ #rules               ← 규칙 + 규칙 스크리닝/✅ 반응 → Founder Beta 역할
├─ #roles               ← 🇰🇷/🇬🇧 반응 → 언어 채널 언락
├─ #announcements       ← 릴리스/공지 (한·영 병기)
└─ #changelog           ← 버전 업데이트 로그 (수동, 나중에 자동)

💬 GENERAL (공용)
├─ #general-🌐          ← 공용 잡담, 이중언어 OK
├─ #showcase           ← "Marblo로 만든 것" 자랑 (스크린샷/영상)
└─ #introductions      ← 자기소개

🇰🇷 한국어
├─ #일반-잡담
├─ #help-ko            ← 사용법 질문
└─ #feedback-ko        ← 피드백/제안

🇬🇧 ENGLISH
├─ #general-en
├─ #help-en
└─ #feedback-en

🐞 FEEDBACK & BUGS (공용, 이중언어)
├─ #bugs               ← 버그 신고 (템플릿 핀)
├─ #feature-requests   ← 기능 제안 (👍 투표)
└─ #feedback-form      ← 6문항 피드백 폼 링크 + Pro 혜택 안내

🔒 STAFF (비공개)
├─ #team
├─ #triage             ← 버그→Marblo 티켓 연동 논의
└─ #mod-log
```

> 언어 카테고리(🇰🇷/🇬🇧)는 `#roles`에서 해당 반응을 눌러야 보이게(권한으로 숨김). 나머지는 Founder Beta 전체 공개.

## 3. 역할(Role) 설계

| 역할                | 부여 방식                                     | 권한                                 |
| ------------------- | --------------------------------------------- | ------------------------------------ |
| **Founder Beta**    | `#rules` 규칙 동의(규칙 스크리닝 or ✅ 반응)  | 서버 기본 접근                       |
| **Lang: KO** 🇰🇷     | `#roles` 🇰🇷 반응                              | 🇰🇷 카테고리 열림                     |
| **Lang: EN** 🇬🇧     | `#roles` 🇬🇧 반응                              | ENGLISH 카테고리 열림                |
| **Verified Tester** | 앱 로그인/피드백 제출 확인 후 **수동**(or 봇) | `#showcase` 게시, 우선 지원          |
| **Pro Member**      | 피드백 선정 → Pro 지급자                      | 인지용 뱃지 (선택)                   |
| **Staff / Mod**     | 팀                                            | STAFF 카테고리, 채널 관리, 역할 관리 |

- 언어 역할은 **복수 선택 가능**(한/영 둘 다 볼 사람도 있음). 카테고리는 role 기반으로 열고 닫음.
- **@everyone 기본 권한 최소화**: `#staff`·언어 카테고리는 @everyone `채널 보기` 끄고, 해당 role 에만 허용.

### 권한 매트릭스 (요약)

| 카테고리        | @everyone | Founder Beta | Lang KO/EN    | Staff |
| --------------- | --------- | ------------ | ------------- | ----- |
| INFO            | 읽기      | 읽기         | 읽기          | 관리  |
| GENERAL         | ✕         | 읽기+쓰기    | 읽기+쓰기     | 관리  |
| 🇰🇷 / 🇬🇧         | ✕         | ✕            | 해당 role만 ✓ | 관리  |
| FEEDBACK & BUGS | ✕         | 읽기+쓰기    | 읽기+쓰기     | 관리  |
| STAFF           | ✕         | ✕            | ✕             | ✓     |

## 4. 온보딩 자동화 — **수동 폴백이 기본**, 봇은 선택

핵심: **봇이 없어도 규칙 동의 → 역할 부여가 디스코드 기본 기능만으로 완성됩니다.**

### 4-A. 봇 0개 — 디스코드 네이티브만 (권장 시작점)

디스코드 **커뮤니티 기능**을 켜면 아래가 봇 없이 동작합니다:

1. **규칙 스크리닝(Rules Screening)** — 입장 전 규칙에 동의해야 채팅 가능.
   - `서버 설정 → 참여 화면(Onboarding) / 규칙 스크리닝`에서 규칙 문구 등록.
2. **온보딩(Onboarding) → 기본 역할 자동 부여** — 디스코드 네이티브 온보딩의
   "질문/선택지"로 **언어 선택 시 Lang 역할 자동 부여**, 규칙 동의 시 **Founder Beta 자동 부여** 설정 가능.
   - `서버 설정 → 온보딩 → 기본 채널/질문` 에서 "이 옵션 선택 → 이 역할 부여" 매핑.
3. **웰컴 스크린(Welcome Screen)** — 신규 입장자에게 `#start-here` 등 3개 채널을 카드로 안내.

> 이 3개만으로 "규칙 동의 → Founder Beta, 언어 선택 → Lang role, 시작 채널 안내"가 **봇 없이** 굴러갑니다.

### 4-B. 완전 수동 폴백 (네이티브 온보딩도 안 쓰는 경우)

봇도 네이티브 온보딩도 안 쓸 때의 **가장 단순한 운영**:

- `#rules` 하단에 "읽었으면 ✅ 반응"이라고 적어두고,
- **Staff 가 하루 1~2회 새 멤버에게 수동으로 Founder Beta / 언어 role 부여** (`멤버 우클릭 → 역할`).
- 초기 인원(<100)에선 이 수동 운영으로 충분. `#mod-log`에 부여 기록만 남기면 됨.

### 4-C. 커지면 — 봇 도입 (선택)

- **Carl-bot / MEE6 무료 티어**: `#rules` ✅ → 역할, `#roles` 🇰🇷/🇬🇧 → 언어 역할 **자동 리액션 롤**.
- (선택) Marblo 앱 로그인 이메일 ↔ 디스코드 연동해 **Verified Tester** 자동 부여.
- (선택) `#bugs` 새 글 → 스레드 자동 + 내부 `#triage`에서 Marblo 티켓으로 승격.

> 봇은 **안정화·규모 대응용**이지 필수가 아님. 위 4-A/4-B 로 시작하고 필요할 때만 붙이세요.

## 5. 서버 세팅 체크리스트 (그대로 클릭)

> 순서대로 하면 빈 서버 → 운영 가능한 서버까지 30분 내 완성.

### 1) 서버 + 커뮤니티 기능

- [ ] 서버 생성 (템플릿 없이 "직접 만들기")
- [ ] `서버 설정 → 활성화 → 커뮤니티 활성화` → 안내 따라 완료
      (규칙 채널·업데이트 채널 지정 요구됨 → `#rules`·`#announcements` 지정)
- [ ] `서버 설정 → 안전 설정 → 인증 레벨`을 **중간(Medium)** 이상으로(스팸 방지)

### 2) 카테고리·채널 생성 (MVP 순서)

- [ ] 카테고리 `📢 INFO` 생성 → 그 아래 `#start-here`, `#rules`, `#announcements`
- [ ] 카테고리 `💬 COMMUNITY` 생성 → `#general`, `#help`, `#bugs-and-feedback`
- [ ] 채널 `#staff` 생성 (아래 3)에서 비공개 처리)
      _(확장 시 §2 트리로 카테고리/채널 추가)_

### 3) 권한 세팅 (클릭 경로)

- [ ] **읽기 전용 만들기**(#start-here·#rules·#announcements):
      `채널 우클릭 → 채널 편집 → 권한 → @everyone → "메시지 보내기" ✕`
- [ ] **#staff 비공개**:
      `채널 편집 → 권한 → @everyone → "채널 보기" ✕` → `+` 로 **Staff** role 추가 → "채널 보기" ✓
- [ ] (확장) **언어 카테고리 숨김**:
      `카테고리 편집 → 권한 → @everyone "채널 보기" ✕` → 해당 **Lang role** 만 ✓ →
      하위 채널은 "카테고리와 동기화" 유지

### 4) 역할 만들기

- [ ] `서버 설정 → 역할 → 역할 만들기`: **Founder Beta**, **Staff**
      (확장 시 **Lang: KO**, **Lang: EN**, **Verified Tester**, **Pro Member** 추가)
- [ ] 역할 **색상/순서** 지정 (Staff 를 위로 → 이름 색 구분)

### 5) 온보딩/역할 자동화 (봇 없이)

- [ ] `서버 설정 → 온보딩`:
      "규칙 동의 → **Founder Beta** 부여", "언어 질문(🇰🇷/🇬🇧) → **Lang role** 부여" 매핑
- [ ] `서버 설정 → 웰컴 스크린`: `#start-here`, `#rules`, `#bugs-and-feedback` 카드 등록
- [ ] _(봇 대신 수동 운영 시)_ §4-B 대로 Staff 가 수동 부여 — 별도 세팅 불필요

### 6) 문안 핀 고정 (DISCORD-ONBOARDING.md 의 카피 사용)

- [ ] `#start-here`: 온보딩 가이드(§C Welcome 메시지) 핀
- [ ] `#rules`: 규칙문(§A) 게시 + 규칙 스크리닝 등록
- [ ] `#bugs-and-feedback`(or `#bugs`): 버그 템플릿(§F) + 6문항 폼 안내(§E) 핀
- [ ] `#announcements`: 베타 오픈 공지(§D) + 버그 신고 위치 공지(§D-2) 게시·📌고정

### 7) 초대 링크

- [ ] `초대 만들기 → 만료 안 함 / 사용 횟수 무제한`(상시) 또는 캠페인별 별도 링크
- [ ] 링크는 **플레이스홀더 `[초대링크]`** 로만 문서에 두고, 실제 값은 배치처에 직접 삽입
      (문서/PR 에 실제 초대 링크·토큰 하드코딩 금지)

## 6. 이중언어 운영 팁

- **공지(#announcements)**: 항상 한국어 + English 블록 둘 다. 짧게.
- **공용 채널**: "아무 언어나 환영 / any language welcome" 핀 고정.
- **자동번역**: 무리하지 말 것. 필요 시 디스코드 자체 기능/간단 봇으로 on-demand 만.
- 국기 이모지 반응으로 언어 대응 시각화 → 해외 유저 소외감 최소화.

---

## 7. 초대 링크 배치처

- 유튜브 영상 설명란 + 고정 댓글
- `marblo.app/founders` 신청 완료 화면 & 승인 이메일(Resend)
- `#announcements` 웹 크로스포스트

> 국가 제한 없이 **하나의 서버 + (확장 시) 언어 채널 분리** = 국내/해외 커뮤니티가 한 곳에서 성장. 초기엔 MVP 구성이 가장 관리 쉽고 확장 여지 큼.
