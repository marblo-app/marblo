# SEO / GEO audit — marblo.app (2026-07-29)

Scope: the Search Console "페이지 리디렉션" / indexing complaint, plus a full
SEO + GEO sweep of the live site.

**Headline: most of what was reported as broken is not broken.** The one real
defect was domain canonicalization (`www` served the whole site a second time).
Three smaller genuine gaps were found and fixed alongside it. Everything else
below is recorded as verified-correct so the next person does not re-litigate it.

---

## 1. Not a bug — do not "fix" these

### 1.1 `/`, `/guide`, `/download` → 307 to `/en`

This is next-intl always-prefix locale negotiation working as designed
(`src/i18n/routing.ts`, `src/proxy.ts`). Search Console files these under
"페이지 리디렉션", which is a **status**, not an error — the destination
(`/en`, `/ko`, `/ja`) is what gets indexed, and it is indexed.

Verified live:

| `Accept-Language`        | Result                                                             |
| ------------------------ | ------------------------------------------------------------------ |
| `ko-KR,ko;q=0.9`         | `307 → https://marblo.app/ko`                                      |
| `en-US,en;q=0.9`         | `307 → https://marblo.app/en`                                      |
| `ja-JP,ja;q=0.9`         | `307 → https://marblo.app/ja`                                      |
| `fr-FR,fr;q=0.9`         | `307 → https://marblo.app/en` (documented default-locale fallback) |
| `Cookie: NEXT_LOCALE=ja` | `307 → https://marblo.app/ja` (override wins)                      |

**307 is the correct status here and must stay 307.** The response body varies
per request (Accept-Language, `NEXT_LOCALE` cookie). A 301/308 is permanently
cacheable, so browsers and intermediaries would pin whichever locale was
negotiated first for that client and the language switcher would stop working.
Google's own i18n guidance calls for a temporary redirect on
locale-negotiated root URLs for exactly this reason.

The response already carries `cache-control: public, max-age=0, must-revalidate`,
which forces revalidation and makes the missing `Vary: Accept-Language` header a
non-issue. Adding `Vary: Accept-Language` is **not** recommended — with
`max-age=0` it buys nothing and it fragments the CDN cache across every
Accept-Language string in the wild.

### 1.2 Sitemap, canonical, hreflang

- `src/app/sitemap.ts` emits locale-prefixed URLs only. **All 75 URLs return
  200** (swept individually, no redirects, no 404s).
- Canonicals are self-referencing and correct on every page sampled
  (`/en`, `/ko`, `/ja` × home/pricing/guide/download/faq/blog/founders/lectures).
- hreflang emits a complete `ko` / `en` / `ja` / `x-default` cluster, per page,
  pointing at each page's _own_ path. Blog posts correctly restrict the cluster
  to locales where the translation actually exists (`buildBlogAlternates`).
- `robots.txt` is correct and points at the apex sitemap.

### 1.3 Structured data

All four JSON-LD blocks on `/en` parse cleanly and resolve into one entity graph
via `@id` cross-references:

`Organization` → `WebSite` → `SoftwareApplication` → `FAQPage`

`sameAs`, `logo` (`/marblo-mark.svg`, 200) and the OG image
(`/images/product-demo.png`, 200, real 2560×1320 PNG matching the declared
dimensions) all resolve. No fabricated `aggregateRating`. The deliberate
omissions documented in `src/lib/schema.ts` (no `telephone`, no `Product` node)
are correct and were left alone.

## 2. Fixed in this PR

### 2.1 `www.marblo.app` was not canonicalized to the apex — **the real issue**

`www` is an alias domain that Vercel was **serving directly**, not redirecting:

```
BEFORE:  https://www.marblo.app/en   → 200   (full duplicate of the site)
         https://www.marblo.app/     → 307 → https://www.marblo.app/en
```

Every page therefore existed at two hostnames. The self-referencing canonical
always pointed at the apex, which is why this never became a duplicate-content
_penalty_ — but canonical is a hint, not a directive: it still splits crawl
budget and strands any link equity aimed at the `www` form.

Fixed in `next.config.ts` with a host-matched redirect:

```ts
{
  source: "/:path*",
  has: [{ type: "host", value: "www.marblo.app" }],
  destination: "https://marblo.app/:path*",
  statusCode: 301,
}
```

**301, not the `permanent: true` (308) used by the path redirects below it.**
The site is verified with Naver Search Advisor and Korean is a primary market;
Yeti's handling of 308 is not documented the way 301 is. Google and Bing treat
the two identically for canonicalization, so 301 costs nothing.

**One-directional by design.** The apex is the established canonical everywhere
(`lib/seo.ts` `SITE_URL`, `sitemap.ts`, `robots.ts` `host`, layout
`metadataBase`). Adding the mirror rule would be an infinite redirect loop.

Config redirects are evaluated ahead of middleware, so `www/guide`
canonicalizes to the apex first and only then negotiates to `/en/guide`.
Next auto-excludes `/_next` from the compiled matcher
(`^(?!/_next)…`), so static assets are unaffected.

Verified against a local production build with a spoofed `Host` header:

| Request (`Host: www.marblo.app`)   | Result                                               |
| ---------------------------------- | ---------------------------------------------------- |
| `/`                                | `301 → https://marblo.app/`                          |
| `/guide`                           | `301 → https://marblo.app/guide`                     |
| `/en/pricing`                      | `301 → https://marblo.app/en/pricing`                |
| `/en/download?utm_source=x`        | `301 → …/en/download?utm_source=x` (query preserved) |
| `/sitemap.xml`                     | `301 → https://marblo.app/sitemap.xml`               |
| **`Host: marblo.app` `/en`**       | **no redirect — loop check passes**                  |
| `Host: <preview>.vercel.app` `/en` | unaffected                                           |

> Vercel dashboard alternative: the same result can be had by setting `www` to
> "Redirect to marblo.app" under Project → Domains. Doing it in code instead
> keeps the rule reviewable, version-controlled, and visible to anyone reading
> the repo. If the dashboard redirect is ever also enabled, remove this rule —
> two layers of the same redirect is a wasted hop, not a loop.

### 2.2 Duplicate meta descriptions on three routes

`/download`, `/founders` and `/lectures` set only `title` in their layouts, so
`description` fell through to the site-wide home-page description — three
byte-identical 184-char descriptions, in all three locales.

`/download` and `/founders` are priority-0.8 conversion pages in the sitemap.
Beyond the classic duplicate-meta signal, this is a GEO problem: an answer
engine had nothing to distinguish the download page from the home page.

Each now carries a localized description drawn from what the page actually says
(`messages/*.json`), 155–160 chars EN / 92–97 chars KO-JA:

| Route       | Source of truth                                                                                              |
| ----------- | ------------------------------------------------------------------------------------------------------------ |
| `/download` | macOS Universal now, Windows coming soon, connect CLI accounts after install                                 |
| `/founders` | free beta, up to 6 months Pro for survey feedback, selective admission                                       |
| `/lectures` | course still **in production** — matches the visible 출시 예정 state and the deliberate 0.5 sitemap priority |

The `/lectures` copy deliberately does not claim a shipped course. Search
engines and answer engines would both repeat that claim.

### 2.3 RSS feed had no autodiscovery link

`/[locale]/blog/rss.xml` was already built and served correctly
(`200`, `application/rss+xml`), but nothing on the blog index pointed at it, so
feed readers and autodiscovery-based crawlers could not find it. Added via
`alternates.types` in `src/app/[locale]/blog/page.tsx`; the existing
canonical + hreflang cluster is preserved (verified in the rendered HTML).

## 3. Found, not fixed — needs an owner decision

### 3.1 `blog.categories.announcement` renders as a raw key on the live site

`content/blog/{ko,en,ja}/marblo-beta-open.mdx` use `category: "announcement"`,
but `messages/*.json` define only `mcp, agents, orchestration, news, product`.
The literal string `blog.categories.announcement` is visible on the live blog
index and is indexable text. `next-intl` logs `MISSING_MESSAGE` at build time
but it is non-fatal, which is why it shipped.

Two clean fixes, and which is right is a taxonomy call, not a code call:

1. add an `announcement` label to the three `messages/*.json` `blog.categories`, or
2. change those three posts to the existing `news` category.

Left alone deliberately — the blog category taxonomy was settled in #570/#571
and should not be re-litigated as a side effect of an SEO ticket.

### 3.2 `/guide` meta description is 307 characters

Google truncates around 155–160. Not an error and not a ranking penalty, but
roughly half of it never displays. Trimming it is a copy decision.

## 4. Keyword positioning — honest read

The two target terms are already well served on-page: `마블로` is in the KO
`<title>`, the keywords array, and `alternateName: ["마블로", "マブロ"]` on both
the `Organization` and `WebSite` nodes, so Hangul brand queries resolve to the
same entity as the Latin "Marblo". "AI 에이전트 오케스트레이션" appears in the KO
title/description and the org description.

The honest constraint is **off-page, not on-page**: `sameAs` lists exactly one
external profile (the releases repo). Brand-entity confidence for a new domain
is driven mostly by corroborating external references, which no metadata change
in this repo can manufacture. Nothing further to fix in code here.

## 5. Note on `/seo-geo-full`

The ticket suggested running the gstack `/seo-geo-full` skill. It was loaded and
**deliberately not executed**: it is a scaffolder, not an auditor, and its
pre-flight check #3 (`lib/schema.ts`, `app/sitemap.ts`, `app/robots.ts` must not
already exist) fails here. Running its Steps 1–4 would have overwritten
hand-tuned files whose comments encode specific past GSC failures. This audit
used its checklist manually instead.

Its "always use the `www` form as primary domain" guidance also does **not**
apply to this site — marblo.app committed to the apex everywhere long ago. Its
warning about root + www both claiming primary causing loops was heeded: see
the one-directional note in §2.1.
